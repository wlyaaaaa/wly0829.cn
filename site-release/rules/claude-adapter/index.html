Claude 适配 只对 Claude 桌面版有用的补充规矩：怎么认出它、档位怎么分、怎么派子代理和 GPT、各种东西怎么接在它身上。 最常用的两件事 要用本人已登录的 Chrome： Claude 自己操作不了，默认派一个 GPT 子任务在本人开着的 Chrome 里做；不用登录的一两页，Claude 可用内置浏览器看；成批采集派出去做。详见：用登录的 Chrome 给当前 Claude 开无限制授权： 在主对话里明确说要开，会弹出密码中心的授权窗口；本人填时长和范围、验证一次，下一条消息时 Claude 读回授权，用到截止为止，不自动续期。详见：开授权的四步 Codex 和 Claude 共用的规则写在别的专题里，这一页只写 Claude 不同的地方，管八件事：密码中心怎么认出 Claude 桌面版；五个思考档位各做什么；Claude 怎么派自己的子代理和 GPT 子代理；技能、临时目录、记忆、MCP、浏览器、权限怎么接在 Claude 上；每条消息前自动运行的 Hook 带进什么；无限制授权在 Claude 里怎么开；作为受信任的 AI 还能做哪些事；官方升级以后怎么继续认出它。 只在当前动作用到 Claude 桌面版特有的机制时才读这一页，比如派子代理或工作流、接技能、MCP、浏览器和权限设置；普通工作不以这些机制为前提。共同的分工原则见分工与并行施工，授权见用户授权，Codex 那边见Codex 适配；这些接线实际怎么装、怎么核验，见AI 规则与技能基座。 先认几个词 主对话：本人直接对话的那个 Claude，原文叫“根会话”。 启动链：一个程序是被谁一层层启动的（父进程链）；密码中心顺着它认出是不是 Claude 桌面版。 claude-root：密码中心给 Claude 桌面版登记的身份名。 包装器：Claude 派 GPT 子代理时统一走的脚本 Invoke-ClaudeGptChild.ps1。 Hook：本人每发一条消息，Claude 先自动运行的一段程序，把会话编号、个人资料状态这些信息带进对话；它不拦消息。 电脑 MCP：让 AI 远程操作另一台电脑的接口。 跳到：派 Claude 子代理派 GPT 子代理身份和档位宿主接线Hook 和资料状态受信任能力和升级 Claude 和 GPT 在这套规则下实际怎么分工、干过哪些活： 在整套系统里的分工 → 怎么协作
人话要点 · 最常用的两件事 要用本人已登录的 Chrome 要登录吗？ 要：派一个 GPT 子任务，它在本人开着的 Chrome 里做 不要：一两页可用内置浏览器看；成批截图、录屏和操作派出去做好送来 Claude 主对话和 Claude 子代理都操作不了本人已登录的浏览器页面。 要用本人的登录状态看网页、操作或收集数据，就经包装器派 GPT 子任务：默认的 AppServer 方式会像 Codex 桌面一样给它接上 Codex 的 Chrome 插件；改用 Exec 方式就接不上。 派哪个型号和档位、要不要 Astra 授权，照派子代理的规则定，这一条不改选型。 内置浏览器只是 Claude 的做法；Codex 照常用本人的 Chrome。 这是默认做法，不是禁令：本人当场另有指定时照本人说的办。 给当前 Claude 开无限制授权 1 本人在主对话里明确说要开无限制授权（约法 L16）。 2 Claude 不用先做别的准备，直接打开密码中心的本人接管窗口；只有主对话里本人真实的消息会弹窗，子代理和工作流不会。 3 本人在窗口里填时长（0.5～72 小时，可以有小数）和范围（默认只管当前对话，要全局生效得本人自己选），再验证一次本人。 4 验证成功后，本人下一条消息时 Claude 读回这份授权；这个对话派出的子代理和工作流也在授权内。 开着以后： 重大的事不再弹验证；在本人定的范围和时间里，本人的明确指令优先于 AI 自己的规则，AI 照样说真话、提更好的做法。 截止时间固定，不滑动续期；到点还要用，请本人续期。 不会顺带打开个人资料，资料解锁是另一件事。 当前对话的授权管不到 Codex 的对话；全局授权两边都能用。
人话要点 · Claude 派自己的子代理 先说派谁：主持的想和把关，具体活派出去；整段一两步的小事顺手做；机械活交 GPT-6 Luna（GPT 用不了时交 Claude Sonnet 5.5）；常规写代码、调研、按固定标准批量审图交 GPT-6.1 Sol，排障通常也先交它；给我看的文字和分析、读大代码库找程序为什么出错交 Claude Opus 5.5；最难、最要紧的在 Opus 和 GPT-6 Astra 里选一家，派 Astra 要我对这个对话或项目点头，点过头就沿用。没有授权时，遇到更适合 Astra 的独立复核等任务，会提醒我一次。完整的表见型号与派法；共同原则见分工与并行施工。 选档位和型号 Claude Opus 5.5 用 Agent 工具选 opus-low、opus-medium、opus-high、opus-xhigh、opus-max，model 参数只换型号、不换档位，也不用它派 Sonnet。 Claude 子代理主要做独立复核、头脑风暴、分析、抽查和惊艳类样板、关键部分；机械活交 Luna，GPT 登录、额度或工具、身份用不了时才交 sonnet-low。其他活照场景表；暂不派 Fable。 内置 general-purpose、Explore、Plan 连型号和档位都跟主对话走，主对话 max 时它们也 max。整段一两步能查完的小检索自己做；成批检索和机械小事交 Luna，GPT 用不了时交 sonnet-low 或 opus-low。Explore、Plan 不读 CLAUDE.md，只做只读检索。 GPT 子代理经包装器进入，见下一屏；不用 Codex 的 openai_child 冒充 Claude 的入口。Haiku 只用于本职的内置小任务。 工作流 工作流（Workflow）按固定步骤编排多个代理，适合分头做、交叉核对和能恢复的批量任务。 只在本人开启 Ultracode、明确要求或技能要求时用；每个 agent() 都写明 effort。 分派前估一下额度，不够就先留下能接着做的检查点。 复核和把关 独立复核默认一两个复核者，只给差异、调用点、相关规则；问题合成一次核对。 重大动作前的把关，型号、最低档位和职责统一见重大动作与本人验证；确需另派时从够格的档位子代理里选。
人话要点 · Claude 派 GPT 子代理 派出去的 GPT 子代理就是一个 Codex，由 Claude 通过包装器启动；下面三屏讲授权、选型、入口和接续。 先看授权覆盖什么 Claude 自己的子代理和 GPT-6.1 Sol、GPT-6 Luna 不用本人另行授权，任何对话都能派（约法 L23）。 GPT-6 Astra 按本人给这个对话或项目的授权；原话里的项目、对话、期限和选型限制照原样保留。 已有有效授权覆盖本任务就直接用，不逐次再问，不扩成所有对话或项目的许可。 需要 Astra 而没有授权时，只在模型清单定的场景提醒一次；等答复时继续其它工作，不授权就按场景用 Opus 或 Sol 接手。 默认分工 型号、场景和档位见型号与派法，按成品要求、厂商数据和权威评测选择；先能胜任，再快，再省，场景表不是固定身份。 整段一两步就完的小事，主对话顺手做；机械活交 Luna，常规施工、调查和复核按场景交 Sol。 做错了按主对话验收事实补材料、退回改，同一关键错再犯，或方案走不通、活变难，就重选执行者；Opus 与 Astra 同一级，一件活交一家做，没有 Astra 授权就用 Opus 或场景表的其他选择，可交叉复核。 主持的管战略、头脑风暴、抽查和最终把关；惊艳类样板、关键部分交做得最好的亲手做；本人定过由 Claude 写的成品、分析、文书和对本人的理解照旧。 每次显式写 -Model 和 -Effort；包装器未写 Astra 档位取 max，显式写了就按原值，不把缺省值当通用推荐。 分工按成品要求，哪边额度多都不改；GPT 额度少，Claude 自己施工；Claude 额度少，它判断等重置还是抽查后现在交付。不另查全部账号额度。 Astra 必要时可按 Codex 的派法再派 Sol、Luna，不扩大任务与授权。
从包装器进入 一律用 （本机路径） 派；不直接调用 codex exec，也不用 Codex 的 openai_child 或专用判断角色。 新任务默认在独立的 Codex 后台服务里运行，Claude 关闭或重启也会继续；同一任务之后的追问沿用原来的运行方式。 后台服务不行时，可以改用一条命令跑一轮的方式（Exec），仍走包装器，并显式加 -Transport Exec；Exec 不能中途插话。 要改仓库的活用 -NewWorktree -RepoPath 给它单开一个工作副本；只读的活可以用 -WorkDir 指向已有目录。 结果目录由 Start 建好，之后各命令的 -RunDir 都指向同一个目录。 插话内容长，或者含中文引号“”时，写成文件用 -PromptFile 传，替换 -Message，两者不同时传：PowerShell 会把中文引号当成字符串边界，把后面的字拆成别的参数。 插话后用 Status 核对：对方收没收到、模型看没看到、汇报里怎么处理的；不把“已排进队列”当成完成。 后台 GPT 子任务遇到失败、超时等需要恢复时，才在原线程 Resume，沿用原型号、档位和运行方式；成功完成或主动停止后的子会话已删除，不能再接续；继续改成果可另派子任务。 其余几个模式（Check 看健康、Watch 在后台盯着、WaitQuota 等额度恢复）的说明写在脚本开头的注释里；Get-Help （本机路径） -Full 能列出全部参数。 五个常用命令 Start：新派一个子代理。 Steer：它运行中插话纠偏，不打断正在跑的命令。 Status：看进度。 Resume：接续仍保留、需要恢复的后台 GPT 子任务。 Stop：停掉这个子代理和它的全部子进程。
资料与权限 派出去的就是 Codex：按本人平时的 Codex 设置和当前授权干活，只做交给它的这件事。 GPT 子任务默认独立运行，没有 Claude 桌面身份；需要密码中心凭据的动作交回主对话，先完成其余部分。 个人资料直接查全机共用的同一份状态，不按 Claude 或 Codex 会话另开一段资料期（本人验证后、私人资料可以取用的那段时间）。 不把 Claude 对话的授权值复制过去，也不额外加沙箱或审批。 私人资料只告诉它去哪找，由它按当前资料状态和授权自己取。 交代和交付 子任务不和人对话：技术做法它自己定；定不了的需求或取舍写进最终汇报，由主对话整理。 先做完不依赖那个决定的部分，不在没人回答的地方干等。 交回简短结论、必要证据和汇报的路径；除非任务明确要网页，不做可视化、不开窗口。 会影响其他会话的决定，写进对应的项目文件。 只在同改一处、出事故或确实需要协调时才发消息，不用中途进度刷屏。 保存和接续 后台 GPT 子任务运行中或需要恢复时，会话要保留，不加 --ephemeral；失败、超时等恢复后在原线程继续，不另开对话。 Claude 默认按真实恢复时间等额度。仅在 Codex 根与子任务共用额度、根仍能正常调用，而子任务单独报耗尽时，才立即原线程接续；共同耗尽或状态不明继续等恢复。图像工具、Flow 的独立额度不套用。 成功完成或主动停止后，永久删除后台 GPT 子会话及其后代，不能再接续；汇报和代码保留，主聊天不在这个清理范围；继续改成果可另派子任务。清理失败照实记下，不改变任务的成败，也不追删以前已归档的对话。 Start、Resume 用 Claude 的后台命令跑；命令返回只说明这一段等完了，不说明子任务做完了。还在跑就马上照返回的命令挂一条 Watch 接着等，每次返回后还在跑就再挂，同一任务只挂一条；到终态才读这一轮的 report.md（完整汇报）和 last-message.md（最后一条消息）验收。 包装器每次默认最多等 55 分钟，醒来仍在跑就原样重挂；这能在一小时提示缓存仍有效时接着用，不改变子任务截止时间。 时限只是起始时长：快到时会提醒一次，还在有效推进就延长，要交付就让它收尾，然后接着挂 Watch；没人处理就到点停下，记为超时。 Claude 重启或续作后，先恢复这个父会话的后台任务：执行者消失、还没交汇报的在原线程继续；已有汇报的验收，仍在跑的接着等。 后台命令显示停止，不证明子任务真停了。 会话存下了没有、命令行列表里看不看得到、桌面上能不能马上看到，三件事分开按实际结果报告。 不保证运行中的线程能在桌面里直接输入，也不为了刷新列表自动重启桌面版。
人话要点 · 怎么认出 Claude、档位怎么分 身份 Claude 桌面版是两个受信任的 AI 之一；桌面身份怎么认、怎么登记和撤销，统一见用户授权，这里只补 Claude 这条实际的启动链。 Claude 桌面直接启动的工具进程和子代理，密码中心仍按真实桌面来源识别；GPT 包装器默认由系统服务启动独立执行者，已经脱离这条桌面进程链，不再沿用 Claude 桌面身份。需要密码中心凭据的动作交回主对话，先完成其余部分；明确采用非独立运行方式时，也要按现场真实的桌面祖先判断身份。 链上嵌套的工具用什么模型（例如 GPT），都不改变这个身份。 思考档位 Opus 5.5、Sonnet 5.5 和 Fable 5.1 共用五档，从低到高： low：想得最少，只做机械、明确、结果马上能核对的小事。 medium：均衡；Opus 5.5 的默认档，常规检索、调研、实现和审查够用。 high：全面推演；跨模块调查、做完整一个子系统、实质性的审查。 xhigh：扩展推理；难的设计、疑难排障、关键审查。 max：最深、最贵也最慢；评测不一定比 xhigh 高，不当做错后的默认下一步。 Ultracode 不是比 max 更高的一档，而是 xhigh 加多代理编排（工作流），只在本会话有效。 提示词里出现“ultracode”这个词，只让这一轮改用编排，不改档位。 档位显示 auto，表示没固定档位，以实际记录为准。
