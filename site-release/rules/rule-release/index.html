人话要点 · 哪一版算数、怎么读 这一页什么时候读 只在维护、发布或回退规则时读这一页。 平时读规则只用核验入口，不跑发布流程。 本人要的效果：规则能改、有历史，改坏了能一键退回；而且不能随便打开文件管理器就被改掉。 哪一版算数 唯一的正本是私有仓库 （本机路径）。 每发布一次得到一个代号：E 加数字，只往上加，用过的不再用。 每个代号对应默认分支上一个已经推送、又从远端读回核对过的提交，外加这一版完整的文件清单和每个文件的内容指纹。 源码、候选改动、没提交的草稿都不算在用的规则；标题、AI 的记忆和旧快照也定不了哪一版在用。 一版有哪些文件，看登记表 config/control-plane-contract-catalog.json 里明确登记的规则和入口模板；文件夹里多出来的 Markdown 不会自动算规则，文件数也不固定。 每次发布都记下那一版确切的文件清单。 例（9 月 28 日核对时）：E187 这一版是 11 份规则、2 份入口模板，加 1 张由登记表生成、记着这一版有哪些文件的规则目录表，共 14 个文件；专题文件夹里的 README.md 没登记，就不在里面。 怎么读 AI 用核验入口 Invoke-EAgentRulesRelease.ps1 -Mode Inspect 核对在用的是哪一版、每个文件的内容指纹对不对；别的程序要读规则，用 -Mode Resolve 拿到同一版、核对过的规则文件位置。 核验结果只列真实能读到的规则路径。 核验通过只说明文件没被改过，不说明 AI 读懂了，也不说明什么都能做；读多少，按当时判断需要。 规则仓库里的 AGENTS.md 只是待审的源稿，不能因为“目录离得更近”就盖过在用的规则。 仓库根放着一个很短的 CLAUDE.md 指路桩：Claude Code 在项目里找不到 CLAUDE.md 时，会把 AGENTS.md 当项目规则读，有它挡着，源稿就不会这样生效。它只指向用户级入口；用户级入口缺了，就给出核验命令，不再复制一份完整入口。 读取失败，只影响依赖缺的那部分内容的决定；不会因此锁住私人资料，也不触发别的保护。
