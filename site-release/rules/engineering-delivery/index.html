人话要点 验证 没验证就说不知道（约法 L6）。 验证多严，看现实风险和这次改动的范围：普通小改只查直接相关的行为和接口、必要的回归（旧功能有没有弄坏）和生效回读；对应关系不明，或者运行环境、安装、权限受影响时，相应扩大。 只报实际验证过的部分：只跑了测试，就不说已经装好或真能用；也不为此把每件事拆成好几层分别证明。 安全深度扫描已经关掉：不跑 Codex Security、GitHub 式安全审计、deep scan、TAC access check 和它们的发现报告流程，本人以后明确撤回时除外。项目自带的测试、聚焦的代码审查、架构审查和产品验收照常做。 测试提示要像本人平时说话：一句很短的需求，不附一堆提示和答案，不点名预期该用的工具或内部路径。 客观的接口用程序测；本人要简单验收时，用少量有代表性的真实用例。 本人会碰到的改动，安装或部署前按涉及的场景验：在新开的对话里试一次、真点一下按钮、真用一下手机。验的是本人实际怎么用，只跑测试不算验收。 网页在真实浏览器里按常用屏幕从上到下看比例和版式，图放到要用的位置看大小。半成品早给本人看，先做一个从头到尾的样板、本人看过再批量做，不闷头做完再一起返工；逐条核对可以派人做，主持的看整体、拍板。 要惊艳的成品，样板定稿前和交付前各一轮头脑风暴：专想从良好到惊艳还差什么，主持的挑一到三处值得的提升。便宜见效的当场做；冲突或明显加成本的做候选或放下一版，写清怎么改、花多少、建议这轮做不做；一轮就停。能用就行的活照样做对、做稳，不加这一步。 AI 自己能做的真实使用验收，AI 做完报告结果，不列成本人的步骤。例如用 AICLI（AI工具配置管理）给同一厂商的两个模型各发一个小请求，这点费用本人接受。 只有必须本人在场的（本人验证、本人设备上的操作、主观体验）和要在软件界面上点选的（见能力与运行方式），才请本人。 规则和文档的测试，查真实的字段、来源、引用和关键意思，不逐字锁句子，也不锁文件数量或固定编号。 重大改动要独立复核（约法 L22）：实质重新规划、同类失败反复出现或阶段交付前，划得来就做一次足够独立的复核，看原意、本人的更正、有没有偷加目标、有没有能删的实现；怎么做见分工与并行施工。 复核工具用不了，就如实说没做独立复核，不拿自己审自己冒充。 版本、数量和运行状态的结论，要分清是以前成立还是现在成立；新证据推翻旧结论时，标明旧结论已过时。 会改变当前决定的动态事实，去对应的来源现场再读一次。 基座的只读体检脚本是按需跑的，不是每个任务都要过的后台关卡。
仓库和过程材料 仓库里在用的源码只留当前的代码、配置、规范和有现实用途的测试；过时的设计和流水账留在 Git 历史里。 真实恢复要用的材料可以留，注明用途和什么时候可以删；不因为贴了“历史”“输出”“备份”的标签就永久留着。 退役就是删除：退役的代码、测试和说明直接删，历史留在 Git，不另做归档副本。 删除或挪走文件时，当场把指向它的链接和路径一起改掉，不留断链。 拿不准还有没有人用，就问本人；不自己把“退役”改成“归档”。 工作副本里要删的东西，也按下一组放进回收站。 下载、临时文件和清理 这次任务下载、生成、复制或解压出来的任何文件都归它负责，不按扩展名、目录或“临时”这类名字来判断。 落盘前先定好去处：下载和临时内容按“日常技术默认”的位置放；工具或项目确实要工作区时，用它的任务工作目录；交付目录只放本人真要取用的结果。 工具不能指定位置时，记住实际落到了哪，一样收尾。 整理默认是移动；只有本人的原件、别处还在用或确实需要备份时，才复制并保留源文件。 先复制再删源时，先确认目标完整可用、引用已经更新，再处理源副本。 用完放进 Windows 回收站，不先试直接删除（约法 L13）：用AI 规则与技能基座自带的回收站工具 Move-TaskItemToRecycleBin，并核对回执里的原路径和回收站里的实物对得上。 回收站满了，由 Windows 自动清掉最旧的。 单个文件大到回收站放不下时，工具会拒绝、不会改成永久删除：先留着，在结果里写明路径和大小请本人决定，任务照常做完。 AI 不自己清空回收站，也不改用永久删除去绕开。 要留的必须有具体用途、确实需要本机副本：本人待取的交付物、项目运行和维护要用的、必要的恢复材料；“以后可能有用”不算。 暂时要留的，在任务状态里写明路径、理由和什么时候清。 本人的原件、别的任务的文件、归属不明的、正在用的、必要的恢复材料都不动；不按时间、文件名或目录整库清空。 文件被占用时：确认属于本任务、也没有本人没保存的内容，就自己解除占用再清；查不清就保留并说明。 能无损清掉的残留直接清，不另请本人决定或汇报；其他清理受阻，要说清剩下什么、原因和下一步，不谎称清完。
Git 收尾 长期授权：让 AI 在仓库里干活，就包括验证后只暂存这次的改动、提交、正常推送到已有上游，不再问（约法 L13，见用户授权）。 本人说只留本地、不提交或不推送时，照办。 仓库或目标不明、没有上游、不能快进、同步有冲突，或者公开内容的审查没过，就停下；强制推送不在长期授权里。 做到默认分支才算完成：本人的仓库要合进实际的默认分支、正常推送，再回读远端默认分支确认看得到；只在 AI 的分支或工作副本上的改动不算完成。 合并推送后，把计划任务或技能直接在用的那份检出（活动检出）快进到最新（见分工与并行施工）。 本人明确只要本地、保留实验分支或只要方案时，按本人说的验收：排除掉的动作不算没收尾，没发生的同步也不说成已完成。 每个改过的仓库都收尾：结束前按实际改动的位置逐个仓库回读，连同链接指向的私人配套库；有改动就验证、提交、推送、回读默认分支。 接手时发现没人在做的旧改动，先弄清来源和用意，再纳入一起完善；只有真冲突、归属不明或本人明确不推送时，才保留并说明。 不为表面干净去强制推送、泄密、删除来历不明的内容、覆盖别人没提交的改动，或把失败的产物推进默认分支。 用过的分支和工作副本，要么合并后删掉，要么证明多余后删掉，要么写明用途、固定名字和什么时候删再保留；查不清就说清卡在哪。 维护或准备公开一个仓库时，用GitHub 项目总索引现有的私人配套查询找到真实的对应关系；新克隆的仓库本机没有链接，不代表没有配套材料。 内容怎么迁，按个人资料与数据处理里的“私人仓库收口”办；挪走当前文件，不等于清理了 Git 历史。 日常技术默认 Windows 上用 PowerShell 7。 Markdown、JSON、YAML 存成 UTF-8 不带 BOM；含中文常量的 .ps1 脚本带 BOM。 不需要交互的命令不弹控制台窗口。 重型显卡任务走现有的串行入口：一次只让一个任务占用显卡，先领到用显卡的许可再跑，免得几个模型同时抢显存（本机现在是电脑配置与恢复里的 LocalGpuBroker）。 下载放 （本机路径）。 自己产生的脚本、日志、预览、测试和中间文件，放本任务自己的临时目录：Codex 用 （本机路径）<任务号>；Claude 的会话目录、子代理怎么分、长路径的坑见Claude 适配。 子进程的 TEMP、TMP、TMPDIR 也指向本任务的临时目录；收尾只清本任务的内容。 给本人写时间换成北京时间（约法 L1），本机时区可能不同。 读带时区的 JSON 时保留原来的时间字符串（PowerShell 用 -DateKind String），不先按本机时区换算再解读。
