Codex 适配 只对 Codex 有用的细则：规则从哪进、无限制授权怎么开、子代理怎么派、升级后怎么认身份。 这个专题只补 Codex 和别处不一样的地方，AI 只在用到 Codex 特有机制时才读。共同原则都在别的专题：派不派、派谁看分工与并行施工，能不能做看用户授权，重大的事动手前怎么把关看重大动作与本人验证；Claude 那边的同类细则在Claude 适配。 先认几个词 Hook：本人每发一条新消息、Codex 每启动一个子代理时，自动运行的一小段检查程序，把当前状态写进对话给 AI 看。 个人资料状态：本人的私人资料现在锁着还是在解锁期，见个人资料与数据处理。 无限制授权：本人给某个对话开的限时授权，也叫本人接管，见约法 L16。 主对话：本人直接对话的那个 AI，原文也叫“根会话”。Codex 的主对话可以是 GPT，也可以借AI工具配置管理换成别家模型，例如 DeepSeek、GLM、通义千问或本机模型。 把关：重大的事动手前，由够格的模型确认一遍该不该做、要不要请本人验证。 codex-root、claude-root：密码中心认得的两个受信任身份，分别是 Codex 桌面版和 Claude 桌面版。 跳到：入口和新消息无限制授权派子代理新消息里的状态官方升级 Codex 在整套系统里干什么、和 Claude 怎么分工：在整套系统里的分工 → 怎么协作
人话要点 · 入口和无限制授权 入口和新消息 Codex 自己目录里的 AGENTS.md 只是指路：叫 AI 先核验当前生效的规则版本，再从那一版读规则。 本人真发来的新消息，和自动续作、上下文压缩、工具返回的消息分开看；后三种不算新消息。 个人资料状态由 Hook 带进来；Hook 缺了、或者说不清有没有送到，就按“状态不明”办：不取用私人资料，普通工作照常。 通过 MCP（外接工具接口）调用时，本机 Codex 原来的任务入口不变。 新消息、Hook、子代理的真实身份和执行结果，都在本机正在用的入口核实；不凭标题、模型自称或别的 AI 留下的环境借身份。 Codex 的自动记忆关着：memories、generate_memories、use_memories 三个开关都是 false。当轮要留下的经验按共享经验的落点写；Codex 工具本身已核实的教训写进本专题。 无限制授权 本人要给当前 Codex 对话开无限制授权时，AI 直接打开密码中心的接管入口（由电脑配置与恢复装在本机），不先派个模型判断该不该开。 实例：本人打“给这个对话开 8 小时无限制授权”或只打“无限制授权”，Hook 就当场替当前对话打开窗口；问“无限制授权是什么？”或者说“你需要无限制授权”，不会弹窗。 只绑当前这个对话真实的编号，不借历史任务、MCP 连接或别的对话。 入口生成这一次的配对和请求编号，借 Windows 自带的提权弹出一个独立窗口，本人只填时长（0.5–72 小时，默认时长照密码中心当前的设置）；回执要写明这是无限制授权。 本人验证完成后，由 Hook 自动读回并使用这份授权；AI 不手动一步步走配置、准备、激活、查状态，也不反复开窗口。 确有必要的子代理沿用同一份请求和原来的截止时间；本地命令带上同一组三个接管值（会话引用、请求编号、截止时间），不改用户级或全机的环境变量。 回执丢了先查原请求，不自动重新弹窗、也不让本人重新验证；入口真的报错才去针对性排查。
人话要点 · 派子代理：Codex 的不同处 先说派谁：主持的想和把关，具体活派出去；整段一两步小事顺手做；机械活交 GPT-6 Luna max，照写好的提示生图、落盘用 Luna low；常规写代码、排障、调研、按固定标准批量审图交 GPT-6.1 Sol，更难的按场景升级；疑难、最难、要紧审图交 GPT-6 Astra。主对话是别家模型时只派 Sol、Luna，本该交 Astra 的活改用 Sol ultra 或自己做。惊艳类的样板、关键部分交做得最好的亲手做；能力只看厂商和 AA 等权威评测。型号、档位换代时按公开数据重新评估、直接更新，不沿用旧设置。完整的表见型号与派法；共同原则见分工与并行施工。 桌面子代理名额真满了，才自动改用现成的 GPT 包装器接能做的活；登录、参数、网络这类故障先修真原因，不当成满了。它仍是当前主对话管的后台任务，不另开顶层对话；型号、权限和任务范围不放宽。包装器记的是 Codex 当前任务的完整编号，不借 Claude 的会话号；接着做时接回原来那一份，不重开一份。等候、额度和停止的共同办法见分工与并行施工。 主对话是 GPT 时 桌面子代理有空位时，用 spawn_agent，按任务选 GPT-6 Luna、GPT-6.1 Sol 或 GPT-6 Astra，显式写 model 和 reasoning_effort，派完核对实际启动值。 跨型号、跨档位时不带或只带有限历史；只有参数相同、完整历史确有用时才全带。 主对话是别家模型时 桌面子代理有空位时，用 openai_child 只派 Sol、Luna，不派 Astra；入口由AI工具配置管理提供。 写明类型、型号、档位、任务名和交代，不传 fork_turns。续聊走同一入口；回话、查看、等待、停止各走它对应的控制入口。 子代理要再分工，回原父任务安排。Claude 派 Astra 的授权条件不套到这里，见约法 L23。 鉴权、参数、上下文等入口故障先修真实原因；主对话继续能做的部分，不乱换型号或绕过真实限制。 重大动作前的把关 资格与职责见重大动作与本人验证。主对话够格就自己判断；确需另派只交这次判断，不顺手实施或再委派。 别家主模型的可派范围仍是 Sol、Luna，不因把关职责扩大；独立复核另按共同原则安排。 新开一个顶层对话 create_thread 可见时调用一次；失败或拿不到可追踪编号就说明，不盲目重试。
人话要点 · 状态和升级 新消息里的状态 本人每发一条真消息、Codex 每启动一个子代理，Hook 读一次当前的个人资料状态和本人接管状态，并告诉 Codex 本会话能核实的型号和思考档位。 这一轮读不到的就写“未知”；子代理启动时档位一律写“未知”，不借父会话的记录。为什么：派生的子代理，记录开头复制了一份父会话的设置，照着读就会把父会话的档位当成自己的。 资料状态确认不了：不取用私人资料，普通工作继续。 本人接管只认正式入口读回的那份授权和原来的截止时间。 Hook 不替 AI 选型号和档位，不决定要不要派子代理，也不另设一本“派发许可”的登记。 不装 Stop Hook（每轮结束时自动运行的检查）；这台电脑上 Codex 的 Stop 一栏是空的。 官方升级 Codex 的版本号、构建号、带版本号的安装目录和更新批次，都不能拿来卡“能不能用”。 密码中心顺着本人 Windows 账户里真实的进程祖先链往上找，找到登记过的 Codex 桌面应用本体，日常调用就自动认作 codex-root。 实例：认的是 OpenAI.Codex 这个软件包里的 ChatGPT.exe 本体；同一个包里的命令行程序单独跑，不算。 从 Claude 桌面版启动的 Codex 子进程，按它上面的 Claude 桌面版认作 claude-root，不按模型名字换身份。 官方更新后仍按同一账户、同一软件包和桌面本体核验，不用重新绑定密钥。 受管 Hook 的内容哈希只保护 Hook 自己：Hook 启动时先比对自己的哈希，对不上就只报“状态未知”，普通工作照常。 缺了可选的宿主信息，只让依赖它的那一项变成不明或不可用，普通项目照常。
原文 · E216 版，公开副本 Codex 适配 owner: （本机路径） 只在当前动作用到 Codex 特有机制时读。这里只补充 Codex 的不同处；共同原则在其他专题里，不在这里另立一套。本专题只补充 Codex 的调用方式；Claude 的调用方式见 Claude 适配。 入口和新消息 Codex home 里的 AGENTS.md 只是入口，规则从核验过的活动版本读。真实的新消息和自动续作、上下文压缩、工具消息分开看；Hook 会把个人资料状态带进来，Hook 缺失或投递不明时，资料状态按不明处理（不取用私人资料），普通工作照常。调用 MCP 不改变本机 Codex 原来的任务入口。新消息、Hook、子代理的真实身份和执行结果从本机现役入口核实，不从标题、模型自述或别的宿主遗留的环境借身份。 Codex 自动记忆的关闭配置是 memories=false、generate_memories=false、use_memories=false；当轮需要留下的内容统一按共享经验的落点处理，Codex 工具的已核实教训归本专题。 无限制授权 本人要给当前 Codex 对话开无限制授权时，直接运行 PCConfig 安装好的 Invoke-OwnerTakeover.ps1 -Operation Open，不先派模型判断。HostTaskId 只传当前宿主真实的线程 ID，不借历史任务、MCP 连接或别的对话。Open 会生成这次的配对和请求编号，用 Windows 现有的提权能力，弹出独立窗口让本人只填时长；回执里应有 grant_type=unrestricted。本人验证完成后，由 Hook 自动回读并使用这份授权（CheckHost）；模型不手动串 Configure/Prepare/Activate/Status/Check，也不反复打开窗口。必要的子代理沿用同一请求和原截止；本地命令带同一组三个接管环境值，不改用户级或机器级环境变量。回执丢了先查原请求，不自动重弹窗口或重新验证。入口真的报错时才去定向诊断。

重大动作前的把关：型号、最低档位和职责统一见重大动作与本人验证。确实需要另派时，用当前宿主的普通子代理入口明确填写符合要求的型号和思考档位；主对话为其他公司的模型时仍从上面的可派范围选择，不凭把关职责扩大可派型号。独立复核按分工原则另行安排。 AICLI 配置和其他后端任务不是桌面原生子代理，不用来代替因鉴权、参数、上下文或真实能力限制而失败的 openai_child。仅宿主原生容量不足时，按下面的已授权例外转用共用包装器；其他失败按真实原因修好后继续，不随意换型号或通道。 新开有独立成果和责任的顶层对话时，工具可见就调用一次 create_thread，不预判失败、不要求本人重说；工具报错或拿不到可追踪的编号就停下说明，不盲目重试。原生槽满时的后台子任务仍由当前根对话管理，不用 create_thread 建顶层替身。
