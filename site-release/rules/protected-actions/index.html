重大动作与本人验证 哪些事算重大，动手前怎么把关，什么时候、用什么方式请本人验证。 这是 Codex 和 Claude 共用的规则，管四件事：哪些动作算“重大的事”；这类事动手前由谁把一遍关；什么时候必须请本人验证、有哪几种验证方式；GitHub 上删库、转移、改公开这类动作怎么办。它是约法L16 限时的“无限制授权”和L17 重大的事的细则。平时干活不因为这份规则多一道审批。 先认几个词 重大的事：约法 L17 列出的七类高风险动作，例如删库、把私人资料发到外面、删掉只有一份的数据。 本人验证：在密码中心弹出的窗口里，用四种方式之一证明“现在点头的是本人”。 无限制授权：本人给某个对话开的一段限时授权（0.5–72 小时，默认时长照密码中心当前设置）；开着时本人的明确指令优先于 AI 自己的规则，也算已经确认是本人。 个人资料解锁期：本人验证一次后开的一段时间，时长本人定；期间 AI 可以用本人的私人资料。 受信任的 AI：只有登记过的 Codex 桌面版和 Claude 桌面版两个。 把关：重大的事动手前，由够格的模型再确认一遍：做不做、要不要先请本人验证。 主对话：本人直接对话的那个 AI，原文叫“根会话”；它派出去单独干一段活的叫子代理。 跳到：哪些算重大什么时候请本人验证动手前的把关GitHub 重大动作本人验证的四种方式各管各的 现在开没开无限制授权、个人资料解没解锁：现在的授权状态 → 授权与状态

人话要点 · 重大的事 哪些算重大的事 约法L17列了七类： 批量导出私人资料或聊天记录； 把私人资料发到外面：上传、发邮件、发消息； 查看或导出密码明文、银行卡； 改本人的验证方式或恢复方式； 关掉或绕过保护； 删库、转移仓库、把私人仓库改成公开； 删除只有一份的数据。 算不算重大看实际后果，不看字眼：带“密码”“删除”“私人”的动作不一定重大。普通改代码、跑测试、只提交这次相关的改动并正常推送、发布规则、清理能重新生成的东西，都不算。 什么时候请本人验证 开着无限制授权：已经算确认是本人，重大的事不再弹验证（约法 L16）。 没开无限制授权、个人资料也不在解锁期内：先请本人验证一次。解锁期内不再为此打断。 没开无限制授权时，对话里的一句话，包括“别验证了”，都不能代替验证。 上面这些免验证只给受信任的 AI（见用户授权）；别的 AI 做重大的事，一律先请本人验证。 普通聊天、普通干活、查本人的资料来回答问题，都不打断。 个人资料锁着时，查资料仍要先请本人解锁，见个人资料与数据处理。 这份清单怎么来的 早先设计过“起疑”：AI 发现可疑的动作就停手、请本人验证，还一度要锁屏、锁整块硬盘。本人 9 月 26 日答复：不能莫名其妙锁屏，个人资料解锁期内发邮件本来很正常。于是起疑整套删掉，这份高风险动作清单留了下来，成了约法 L17，只用来回答“什么时候必须请本人验证”。密码中心页的已停用功能里还能看到当年的起疑就锁盘。
人话要点 · 动手前的把关 谁来把关、把什么 重大的事动手前，由一个够格的模型把一遍关，确认三件事：这确实是本人要的；目标和影响都对；需要本人验证的，先请本人验证。 够格的模型：Claude 使用 Claude Opus 5.5，至少 medium；Codex 按现行模型清单使用 GPT-6.1 Sol 或 GPT-6 Astra，至少 high。 主对话自己够格，就自己判断；不够格，就派一个够格的子代理只做这一次判断：它不动手，也不再往下派。Claude 可选 medium 或更高档的子代理；具体把关资格以现行专题为准。 把关没做完时，只停那一步撤不回的最后动作；其余思考、能撤回的工作、修复和测试照常做。 把关不是独立复核 把关只管动手前这一步：做不做、要不要请本人验证。 独立复核（约法 L22）管一项重大改动或决定本身对不对：交给另一个独立的上下文，看原始材料重新检查，做法见分工与并行施工。 打个比方：要删一个旧仓库，把关看“是不是本人要删、删的是不是这个库、要不要先验证”；独立复核看“这个库该不该删、删了会丢什么”。
人话要点 · GitHub 重大动作 要本人验证的四种动作 删除仓库、转移仓库、把非公开仓库改成公开、新建公开仓库。 开着有效的无限制授权：不重复弹验证；没开：验证一次。 这一条不看个人资料解没解锁：解锁期代替不了这次验证。 验证过不等于可以发布：对外发布和第一次公开发布，仍要本人明确同意。 普通收尾，不验证 合并进主线、分支或仓库改名、新建私有仓库、公开仓库改成私有、改默认分支、把远端改成本人 GitHub 账号下的仓库。 删除分支和标签、改写分支指向的提交：只要旧提交还在别的分支或标签里留着，也算普通收尾。 普通收尾不请本人验证，也不逐项向本人报告技术细节。 删除或改写前，程序自动核对旧提交还被别的本地或 GitHub 分支、标签留着；核对不过就停下说原因，不改成找本人验证。 仓库改名时，一并更新GitHub 项目总索引和真正调用这个仓库的地方。 由来：本人 9 月 27 日说，把删分支、合进主线也当成要验证的动作太严了，让 AI 找个最优解。Claude 按本人授权定下：要本人验证的只留约法 L17 的删库、转移、私有改公开，加上新建公开仓库（等于对外发布）和真正删掉只有一份的数据；合进主线、删内容已在别处保存的分支、改名、改默认分支这些都归普通收尾。本人未否决前照此执行。
人话要点 · 删库和转移 删库和转移前先备好 AI 先自动确认本地副本是全的：GitHub 上的所有分支都在本地，缺的先拉下来。 把只在 GitHub 网页上、不在 Git 里的东西（例如 issue、发布包）列给本人看。 现在的执行入口具体这样做：把所有分支和标签拉到本地，另外各留一个备份记号，免得以后清理本地时顺手丢掉；列出全部 issue、PR、Release 和发布包的标题和链接；Wiki、讨论区、项目看板、Actions 只列入口和开没开。这份清单只是列出来，不会替本人备份网页上的内容。拉到本地的 Git 副本也不自动包括 Git LFS 大文件、子模块仓库、Actions 产物和软件包仓库里的包；删的仓库用到这些时，由动手的 AI 另外保全，并说清保住了哪些。 谁来执行、回执怎么写 执行入口归GitHub 项目总索引：有有效的无限制授权，就直接执行已授权的动作；没有，就调用密码中心验证一次。普通 Git 收尾不找密码中心。 这个入口一共能做 10 种 Git 和 GitHub 动作（有的只动本地分支），只有删库、转移、改公开、新建公开仓库这四种情形要本人验证，其余只做自动核对。 本人验证可能要等一会儿；验证完，入口会重新读一遍仓库现状，这期间仓库变了就停下。 回执分开写两件事：权限核验过没有；这次是本人真做了一次验证，还是复用了已有的授权。复用不能说成刚验证过。 真要销毁只有一份的数据，仍要本人明确同意、按重大的事办；普通清理核对不过时，不会自动改走销毁这条路。 这道验证靠 AI 按规矩走入口：入口负责核对、请本人验证和事后读回，并不能在技术上挡住已经登录 GitHub 的程序直接删库。
人话要点 · 本人验证方式 本人验证的四种方式 通行密钥（Passkey）、手机验证码（TOTP）、恢复码、Google 或微软账号；任一种已登记、能用的验证成功就算完成。 四种都在密码中心同一个“四选一”窗口里选，选账号时再在窗口里选 Google 还是微软；四种地位平等，用任一种都能重新登记其余三种，见密码中心的四选一验证。 本人没指定方式时，一种坏了不挡住其他能用的方式，坏的照实说明。 本人指定的方式坏了，就修好它；暂时修不好就说清原因，不擅自换别的方式。 本人取消、拒绝或超时，只结束这一次，不自动重试；软件故障要和这几种情况分开说。 四种都丢了时，AI 不自己建立新的验证方式。 Windows 登录密码、PIN 和指纹、人脸这类生物识别，都不算这四种。 改了本人验证的方式（四种验证方式本身、请求验证的窗口或相关入口），就请本人实际验证一次；代码测试和模拟不能冒充本人验证。 请本人验证、锁定资料这些具体操作，走local-secret-broker技能里现行的入口。 各产品各管各的 密码中心、本人验证和 BitLocker（Windows 整盘加密）各按自己现在在用的入口办。 规则读取、发布、校验或 Hook（AI 程序在固定时机自动跑的检查脚本）出了故障：不自动锁任何东西，也不去读秘密。 规则核验通过，只说明规则文件是对的；不说明操作的人可信，也不说明这个动作已经被允许。

原文 · E216 版 · 续 GitHub 重大动作 GitHub 的删除仓库、转移仓库、把非公开仓库改成公开，按约法 L17 的专门规则执行：开着有效无限制授权时不重复弹本人验证，否则验证一次，个人资料是否解锁不影响这一条。新建公开仓库按同样的验证规则；对外发布和第一次公开发布仍须本人明确同意。 合并主线、内容已有保留的本地或远端分支和标签删除、旧提交仍由其他分支或标签保留的指针改写、分支或仓库改名、新建私有仓库、把公开仓库改为私有、改默认分支、把远端改成本人 GitHub 账号下的仓库，都是普通收尾，不请本人验证，也不逐项向本人报告技术细节。程序在删除或改写前自动核对旧提交仍由其他本地或 GitHub 分支、标签保留；检查不过就停止并说明原因，不改成找本人验证。改名时一并更新总索引和真实调用方。 删库和转移前，AI 先自动确认本地副本是全的：所有分支都在本地，缺的先拉下来；并把只在 GitHub 网页上的东西（例如 issue、发布包）列给本人看。执行入口归 GitHub 总索引：有有效无限制授权时直接执行已授权的动作，否则调用密码中心的 Invoke-SecretBroker.ps1 -Action VerifyAuthority 验证一次；普通 Git 收尾不调用密码中心。回执的 highest_authority_verified 表示权限核验结果，human_factor_performed 如实区分本次真人验证和复用授权，不能把复用说成刚做过一次真人验证。真正销毁唯一数据仍按明确同意和重大动作的规则处理，不作为普通清理的自动回退。 本人验证方式 一共四种：通行密钥（Passkey）、手机验证码（TOTP）、恢复码、Google 或微软账号。任一种已登记、能正常用的方式成功就算完成。 本人没指定方式时，一种坏了不挡住其他正常的方式，坏的如实说明。 本人指定了某种方式而它坏了，就修好这种方式；暂时修不好就说清原因，不擅自换别的方式。 取消、拒绝或超时只结束这一次，不自动重试；软件故障和这些情况分开说。 四种都丢了时，AI 不自己建立新的验证方式。 Windows 登录密码、PIN 和生物识别不是这四种之一。 改了本人验证的方式（验证因子、请求窗口或相关入口），就请本人实际验证一次；代码测试和模拟不能冒充本人验证。 请本人验证、锁定资料等具体操作，走 local-secret-broker 技能里的现行入口。 各产品各管各的 密码中心（SecretBroker）、本人验证和 BitLocker 各按自己的现役入口办。规则读取、发布、哈希校验或 Hook 出故障，不自动锁任何东西，也不读取秘密。规则核验通过只说明规则文件是对的，不说明操作者可信或动作已获允许。
