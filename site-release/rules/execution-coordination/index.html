人话要点 · 派子代理的原则 要不要派 主对话管想和把关：战略、头脑风暴、抽查、质量检查和最终成品。 具体活派出去做完送回来；只有整段一两步的小事顺手做。 看整段目的和总量，不看每次操作多容易；50 张截图不能拆成 50 件小事。 相关动作合成一单，一次交代清楚；只有判断或一两步的整件事，零个子代理也正常。 派谁、花多少 先按成品选人：能用就行的，交能胜任里最划算的；要惊艳的，样板和关键部分交做得最好的亲手做。 谁能胜任、谁做得最好，只看厂商数据和 AA（权威评测）；不自己测，也不拿本人说的强弱作证。 档位按剩下的真实难点选；质量需要时，子代理可以比主对话更强，不用每次问本人。 算今后的总投入：自己做要花的执行、验证和返工，对比派出去要花的交代、重建上下文、来回沟通、审阅整合和返工；已经花掉的不算。 每次派都写明型号和档位，不让子代理悄悄沿用主对话的设置；Luna 用最高 max，照写好的提示生图、落盘才用 low；派完核对实际启动的型号和档位。 重大的事独立复核 重大的改动、设计或决定，交给一个独立的上下文重新检查（约法 L22）。 给复核者原始材料：本人原话、相关事实、改动本身；分清哪些是本人原话、已核实的事实、未知和派活一方的推断，不预设结论。 复核者先独立形成意见，给出证据、反例或会失败的路径；没有实质问题就直说，不为凑问题去改东西。 按需要复核，不让每一步都变成审批。 复核不是重大动作前的“把关”：把关只管动手前这一步做不做、要不要请本人验证，见重大动作与本人验证。
怎么交代、怎么交付 一次交代清楚：目标、已知事实、限制和怎么验收，用中文、说人话。 不灌全部历史，也不替子代理写死每一步；它能自己查的自己查。 遇到关键事实冲突或超出范围的决定，子代理带着证据回来问。 交付时分清已核实的事实和推断，带上结果、实际做过的验证、有分量的反面证据和没解决的风险。 用了什么型号、别人说了“同意”，都证明不了结果是对的。 全局规则只引用，资料锁着时不凑 派活说明和项目说明里，公开范围、个人资料锁、授权这类全局规则只写引用，例如“公开范围按约法 L20 和《个人资料与数据处理》的公开分级表”，让子代理自己去读原文。 不写自己的摘要或改写版，也不照抄决定记录里的旧说法：旧决定可能已被取代，以现行规则为准。 要写成公开内容（网站、GitHub 主页、公开仓库、对外发布）的，交代子代理先读公开分级表原文再判断。 子代理需要本人私人资料而资料锁着时，不让它拿已记下的事实凑，也不收降级的结论：它写明缺什么交回，主对话按约法 L18请本人验证，解锁后再派。 只为举例不算需要：公开内容里的例子可以是假设的，或直接用亮点，不为找真实例子去读私人资料；假设的例子也不写成真发生过。 派活说明里固定写这一句：“需要本人私人资料而资料锁着时，只写明缺什么交回，不用已知事实凑、不降级回答（约法 L18）。” 本人的限制优先 本人明确限定的型号、厂商、档位或预算，子代理和它再派出的都照样遵守，谁也不能自己放宽。 子代理的业务范围和授权只能比派它的一方窄，见用户授权。 可派模型清单 各家现在能派哪些型号、各适合什么活，列在一份模型清单里；它只作参考，不当门禁。 清单怎么更新、本人定过的型号限制，以约法 L23为准：本人说有新型号，AI 查厂商数据和权威评测，按需更新、直接生效。授权、预算仍先问本人；Claude 暂不派 Fable 5.1，新 Fable 同样按数据判断；Codex 主对话用别家模型时仍不派 Astra。 模型能力只凭厂商公布的数据和 AA 等权威评测，不在本机试跑比较。先弄清评测考什么，再和现用选择比；惊艳类还看审美和成品质量。AA 没数据时先按厂商数据暂定，数据够就定稿；AA 出数据后短复核。宿主支不支持、实际派出型号和运行快慢，照真实记录；没有数据就说明缺口。 某个项目专用的分工只在那个项目里适用，不自动变成全局默认。 完整型号、按场景的档位与三种宿主派法，统一见本页型号与派法。Claude 能直接派 Sol、Luna；Astra 仍按本人给对话或项目的授权。 本网站专用分工：照写好的提示交 GPT-6 Luna low 画、落盘，GPT-6.1 Sol ultra 审；只适用于本项目。通用任务也只有照写好的提示生图、落盘用 Luna low，其他活用最高 max。
主对话的责任 主对话管战略、头脑风暴、抽查、QA（质量检查）和最终把关；具体活派出去，一两步小事顺手做，惊艳类样板和关键部分可以亲手做。 几段接力做同一个成品（写、画、审、拼）时，由主对话或指定的一个人对成品负责，亲自在真正用的地方看整体，截图、录屏可以派人采好送来；各段自查代替不了。先做完整样板再批量，共用规格只写一处；惊艳类在样板定稿前、交付前各一轮头脑风暴，主持的最后拿主意。 派出去以后接着做不冲突的事，不空等；但后台还有子任务时要一直盯到交付：每次等候返回后还在跑就接着等，快到时限还在推进就延长，不能因为后台还在跑就结束主任务。 子代理创建成功只说明任务发出去了，不说明做完了；它交回的结果由主对话核对。 做错看主对话验收事实：缺材料或工具出错先补，知道怎么改就退回原人；同一关键错再犯、方案被推翻或难度变了才换人。两家都失败再用一次 max；只缺本人材料、取舍或授权就直接问。 本人叫停主任务时，已知的子代理和后台任务一起停掉，再查一遍确认真停了。执行者中途没了，先看已有成果和汇报，再在原任务上接着做。 Claude 和 GPT 一起干时 Claude 主持时，按成品要求想和把关，也亲手做场景表交它的惊艳类样板和关键部分；本人定过由 Claude 写的成品、分析、文案、正式文书和对本人的理解照旧。 施工、采集、按清单审查和核对执行者汇报照场景表派；GPT 可以提清单外的实质问题，出主意时给原始材料，不先写死结论。 Claude 抽查风险和看最终成品，GPT 交完整材料清单；Claude 也可自己挑没被推荐的样本。 Codex 单独主持的任务，由它的主对话负同样的最终责任，不拿以前的分工当理由去等 Claude。 事实报告可以当证据用，但产品是不是真满足需求，仍要验收。 分工按成品要求，哪边额度多都不改；GPT 额度少，Claude 自己施工；Claude 额度少，由它判断等重置还是抽查后现在交付。只用一边时，那边既把关也施工，不查全部账号额度。 Claude 派 GPT 的具体入口见Claude 适配。 快速模式、故障和额度 没有本人许可，不开 fast 快速模式。 出故障后先核对并接回被打断的任务；排查可以另外并行做。 同一份 Codex 额度下，主对话还能正常用、只有子代理报额度用完时，立即在原任务上接着做，不等恢复（Claude 默认不这样接）。真的都用完了、或确认不了主对话还能用时才等；恢复后还有价值的原任务在原对话接着做，并告诉本人额度已恢复、任务已继续，不另起替身。 要换上下文时，先核对原任务真实做到哪，交接或停掉以后再安排，不重复做。 什么时候新开对话 只有确实有独立的成果和责任，才新开一个顶层任务（新对话）；项目多、活多、能同时开的名额满了都不是理由。 子代理名额真满了，Codex 自动改用 GPT 包装器接着派，仍是原主对话管的后台任务，型号、范围和授权都不放宽；登录、参数、网络这类故障先修真正的原因，不当成满了。拿不准刚才派没派出去，先查清，已经启动就接回来，不重派一份。 AI 新开的对话默认不挂到任何已保存的项目下，本人指定项目时除外。
人话要点 · 多个任务同时改东西 各用各的工作副本 每个任务在自己的工作副本里改，验证后自己合并回默认分支并推送。 合并遇到冲突，先弄懂对方的改动再整合，不覆盖。 合并、推送、读回确认以后，把计划任务或技能直接在用的那份目录（原文叫“活动检出”，例如 （本机路径））快进到最新提交；那里有别人没提交的改动、快进不了时，不动它，并说明。 最后把本任务已经合并回去、又没有未提交改动的工作副本放进回收站：按工程与交付的清理入口，用 Move-TaskItemToRecycleBin.ps1 -AllowLinkedWorktree；工具确认回收站里确实收到了，再清掉这个副本在 Git 里的登记，不用 git worktree remove 直接删。 只读查看和跑测试，不用单开工作副本。 单点动作前加一把短锁 安装或升级软件、发布规则、改计划任务这类会互相影响的动作，动手前用 （本机路径） 里的短锁工具领锁（原文示例领 30 分钟，工具默认也是 30 分钟），做完马上释放。 同一种动作共用一个清楚、固定的锁名；持有人写清是哪个 AI（Codex 还是 Claude）和真实任务号。 先看锁的现状，领到了才动手；别人的有效锁还在时，等它结束或先核对情况，不抢。 要续期就由同一持有人再领一次；结束时写在 finally 里释放，不管成没成功都放掉。 短锁只防同时撞车，不给本人没给过的权限。 不动别人的东西 保留其他任务的改动和没提交的内容，不用 git add . 一把全加。 不从标题、目录或历史推断某处归自己。 停下时留好接续状态 没做完就停时，写清在哪个工作副本或分支、做到哪、还差什么，让后来的任务能接着做。
