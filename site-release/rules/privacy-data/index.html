人话要点 · 个人资料的锁和解锁 一张图：这次能不能用私人资料 每条新消息先读一次资料状态： Codex、Claude 由 Hook 读，电脑 MCP 由它自带的状态查询 ComputerContext 读。 这次要用私人资料吗？ 不用 → 照常做：普通代码、天气、学习和项目实施、电脑配置（PCConfig）、性能排查都不用解锁。 要用 → 往下看状态。用私人资料不等于要先把隐私盘点一遍。 状态开着吗？ 开着 → 直接用，到截止时间为止。 锁着、过期或说不清 → 请本人验证一次：本机四种方式任选一种（通行密钥、手机验证码、恢复码、Google 或微软账号，同约法 L17），手机上用现有的验证器；不先派别的模型批准，也不让本人验证两次。 验证结果 通过、资料读得到 → 接着处理原来的问题。 本人取消、拒绝或超时 → 只结束这一次：锁着的还锁着，已开的照样有效，不连带锁别的；不自动重试，也不换个入口重来，本人之后明确再要才重新办。缺资料的部分不换来源凑，见锁着的时候；普通工作照做。 只有一份状态 本人的资料只有一份解锁状态和截止时间，由密码中心的 SecretBroker 管；本机、图形界面、所有 AI 和已认证的电脑 MCP 共用这一份。 MCP 连上了、文件读得到、硬盘加密了，都不等于资料已经解锁。 不先翻私人库、索引或摘要来判断要不要解锁；也不因为某个字眼或某个文件属于本人，就升级保护。 实例：Claude 桌面版每收到本人一条消息，Hook 就向密码中心查一次状态；20 秒内查不到，就当“未知”，这一轮不取用私人资料。 开多久 默认时长以密码中心里当前的设置为准，程序出厂的 8 小时不算当前设置；本人可以填 0.5～72 小时，可以带小数。 只改这一次不改默认；改了默认，也不影响已经开着的这一次。 电脑重启、到期或本人明确锁定，这一次就结束。 重开窗口、新消息、子代理、换模型、续作，都不会延长它。 实例：9 月 28 日读到密码中心现在的默认是 24 小时，预设 0.5、1、2、4、8、24、72 小时七档。
锁着的时候 这是约法 L18的细则。 不用私人资料回答，也不换来源绕过去：目录外的文件、云盘、已登录的网站、索引和记忆、以前的聊天内容都不行。 不拿降级的、不完整的回答糊弄本人；需要资料就请本人验证。 派出去的子代理也一样：它写明缺什么交回，由主对话请本人验证后再派，不让它拿已记下的事实凑，见分工与并行施工。 本人明确要通用版本时，可以只用通用知识回答。 普通工程、规则维护、不私密的状态，以及必要的验证和恢复，照常做。 已经交给别的应用、模型或外人的明文追不回来，不假装能追回。 各管各的权限 重大动作能不能复用还有效的解锁期、GitHub 的重大动作怎么验证，统一见重大动作与本人验证。 资料解锁、无限制授权、Windows 锁屏和新设备恢复，各有各的状态，不能从一个推出另一个；资料解锁也代替不了新设备恢复时的本人验证。 本人要同时开无限制授权和资料解锁时，用用户授权里的全局接管入口，一次验证开两份，但仍分别读回各自的状态和截止时间。 本人在别的可信设备上自己用已经允许的副本，本机锁定不会远程收回。 入口 查状态、业务检查、锁定，分别是密码中心的 StatusPersonalEnvironment、CheckPersonalDataAccess、LockPersonalEnvironment，都经本机已安装的 Invoke-SecretBroker.ps1 调用。 已经在解锁期内又验证一次（VerifyPersonalEnvironment），沿用原来的截止时间，不重新计时。 本人明确要解锁或续期时，用 EnrollPersonalPrivacyWaiver，用法见local-secret-broker技能。 查资料状态直接读共用的那一份，不需要对话号、消息号或对话记录；只读地查一下，不算用掉无限制授权。 本人说“锁定个人资料”“冻结个人资料”，就把资料锁上；“冻结项目”“冻结设计”说的是项目，不是锁资料。 Hook、技能和电脑 MCP 只读这份状态，不另建权限记录。
