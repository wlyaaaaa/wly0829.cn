能力与基础设施体检

规则、软件环境或项目入口不正常时，找出究竟坏在来源、安装、当前运行还是实际使用，再交给真正负责的项目处理；不为一个局部故障重修整台电脑。

范围检查与供应分层已有回归；实际点名能力时才读取其当前来源。装好了、当前能运行和真实任务已成功会分开说明。
产品用法技术与依据

先看怎么用

你不需要记住 Skill 名，直接说需求就行

什么时候用

  • 想知道某个能力的安装、当前运行、新任务使用和真实效果分别验到哪里
  • 明确检查规则、Git 仓库或电脑配置的健康状态
  • 发现配置、来源或安装不一致，需要定位责任
  • 恢复或迁移后核对相关入口是否一致

可以直接这样说

我可以问“原件查找能力现在装好了没有，真任务到底验过什么”。它只检查这个具名入口，分开说明源码安装是否健康，以及当前、全新任务和真实场景还缺哪层；不会为答状态先跑全仓测试。

最后会得到什么

我会得到按责任来源分开的健康、警告和阻塞结果；它自己不修改系统，真正修复交给对应项目。

不适合这样用

  • 普通项目实现
  • 直接实施修复
  • 没有选定相关责任来源就扫描全部基础设施
  • 把旧缓存警告当成当前阻断

正常时

点名能力或基础入口的相关证据可读且相互一致时，说明哪些层已经正常、哪些还没验证。

发现问题时

来源、安装、配置或运行结果不一致时，指出具体差异和负责项目；旧缓存只作带日期的参考，不夸大成当前阻断。

入口不可用或证据不足时

某一来源无法检查时，只报告那一项缺口，其他结果继续保留。默认缓存检查零写入；明确 Live 时可能更新本地 Git 元数据。

从哪里开始

在当前 AI 对话问某个 Skill 是否装好、这台机器现在能否用，或指定 .agents、PCConfig、Git 索引的健康问题；AI 只检查相关范围。

需要准备什么

  • 一个明确的 Skill 名称、控制面组件或具体异常
  • 若需要当前运行能力或最新远端引用，直接说明现场决策是什么

为什么需要这个能力

同一个异常可能来自 Agent 规则、Git 仓库状态或本机配置。直接在眼前的仓库里改代码，可能修错地方。

从需求到结果

1

可以直接问某个能力装好了没有、真实任务验过什么，或点名规则、Git 与电脑配置中的问题；AI 自己选择相关检查，不要求你记内部检查编号。

2

先把来源与安装是否健康、当前运行、全新任务发现和真实业务使用分开。未测不等于坏了，已经安装也不等于能完成所有场景。

3

正常具名问题只检查对应范围。只有当前机器状态会改变答案时再查该能力的运行配置，不把全机扫描当成前置。

4

缓存证据标明原时间；需要实时远端判断时才取新引用，这会更新本地 Git 元数据，结果会单独标明。检查入口缺依赖意味着这一层没执行，不直接判源代码损坏。

5

读回时分开报告结构健康、当前是否能同步、安装与真实使用覆盖。发现差异交给真正负责的项目修复；诊断不自行安装、改任务、备份恢复或执行邮件文件业务。

失败时会怎样恢复

某个负责来源的检查入口不可读

系统反应：该来源标明无法检查，其余来源的结果仍分别保留。

恢复方式：由对应项目修复入口，体检自身不修改系统。

只有旧缓存证据

系统反应：说明这是带原观察时间的提醒。

恢复方式：真正需要现场判断时再取得对应来源的实时证据。

发现来源、安装或配置不一致

系统反应：体检不自动修改。

恢复方式：把具体差异与证据交给真正负责的项目修复。

这个 Skill 用到的名词

SkillName（具名能力检查）
单独给名称会选择agents/skill_supply；显式Owner/CheckId继续限制真实范围，退役或未知名称不会被安装。
Supply health / verification coverage（供应健康 / 使用验证覆盖）
源码、安装、事务是否健康，与当前任务、全新任务、领域E2E（端到端验证）是否验过分开；Unknown（未验证）覆盖不把健康供应判坏。
Health（健康状态）
当前被检查 Owner 是否可读、结构完整、关键入口可用。
Convergence（收敛状态）
这里专指所选Git目标此刻是否具备收口条件；它与控制面结构健康分开，非Git提供器为not_applicable。
Drift（漂移）
登记事实、机器状态、仓库或安装与期望不一致。
Cached warning（缓存警告）
结果来自缓存，可能需要 live refresh；它不是自动 BLOCK。
Provider（Owner 入口）
各控制面负责返回自身动态事实的固定脚本或 API。
按需运行检查
只有所选Skill的当前机器状态会改变答案时才显式CheckRuntime；配置、运行、全新会话和端到端分别留证。
合同消费者检查
固定检查现有恢复/Google接口是否一致，不执行其业务效果；普通体检不会因此扩成全量工作。

专业定义

问“这个能力现在能用吗”时，可先只查具名Skill的源码、安装和使用验证覆盖；当前机器状态会影响答案时，再明确加运行检查。恢复或Google接口变化可选择对应合同检查，不用全机扫描。配置、运行、新会话与端到端分别说明，诊断不代替业务任务，也不自动修复。

执行参考

下面保留 AI 和工具实际使用的参数、步骤与依赖。日常使用可以直接提出需求，不需要先手工准备这些协议。

输入

  • 可单独给 SkillName；不必知道控制面内部 check 名
  • Owner、check 和 freshness（证据新鲜度）

输出

  • 各 Owner 的 health、convergence、warning 和 block
  • 精确 remediation owner
  • supply_health 与 verification_coverage 分开；未知的使用覆盖不把健康供应判坏，也不声称真实可用

执行顺序

  1. 1

    具名 Skill 可只用 -SkillName，等价于 agents/skill_supply；显式 Owner/CheckId 会保留并验证所选范围

  2. 2

    按选择的 Owner 调用精确 provider

  3. 3

    默认 cached 和 zero-write

  4. 4

    聚合而不篡改原状态

  5. 5

    需要修复时退出 Doctor 并交给真实 Owner

  6. 6

    具名Skill的-CheckRuntime显式选择agents/pcconfig及skill_supply/skill_runtime；仅复用该能力的既有配置、零网络Google或Tailscale状态检查，不运行全机漂移。

  7. 7

    确需核对协议时，显式选择agents,pcconfig及core_recovery_consumers或google_workspace_contract；前者运行已有三项manifest（清单）/maintenance/task检查，后者两次零网络配置接口核对，不执行复制、恢复、邮件或文件业务。

操作边界

  • 不修复、不安装、不改任务
  • 不 commit 或 push
  • 未选择的 Owner 连 provider 路径都不读取
  • warning 与 block 分开
  • 未安装意图、退役或未知名称只报告限制，不自动安装或复活
  • 普通状态问题不先跑仓库测试；只有当前实现改动或怀疑缺陷才验证相应代码
  • 默认不传 Owner 时兼容选择三个责任源；正常具名问题主动收窄，不把全扫作为前置门
  • SYSTEM观察者读取登记的用户安装或显式ObservedUserProfile，不把systemprofile空目录当用户未安装，也不冒充登录用户。依赖/Python/validator缺失表示验证没执行，不表示源损坏。
  • 当前运行检查不证明全新会话或业务端到端；规范接口一致不证明有效OAuth（账号授权协议）、目标设备可达或还原成功。

依赖

  • Personal Skill validator（校验器）
  • Git admission（仓库准入检查）
  • PCConfig drift provider

缓存只读与现场Git刷新不同

默认-Freshness Cached不fetch，write_mode=zero_write。仅远端引用的新鲜度影响判断时选择Live；它通过admission（仓库准入检查） -Fetch更新本地.git元数据，返回mode=read_with_local_git_metadata_write及write_mode=local_git_metadata_write，不是零写。两种模式都不改工作树、业务资料、任务、安装、commit或push。

top-level status是控制面健康，convergence_status是所选Git目标此刻能否收口；缓存、公开性未知、无关dirty或公开冲突可能阻收口但健康仅warn。退出非零只针对health block，不能用它抹去convergence block。非Git provider为not_applicable。

selected_check_ids、providers_invoked、freshness_mode和write_mode保留真实范围。普通-SkillName只选agents/skill_supply；-CheckRuntime才显式选agents,pcconfig/skill_supply,skill_runtime。显式Owner/CheckId范围不会被扩大，排除PCConfig时供应不读其外部证据。

# 具名能力安装与使用覆盖
pwsh -NoProfile -File E:\.agents\tools\Invoke-ControlPlaneDoctor.ps1 -SkillName <精确名称> -Json
# 当前运行确会改变判断时
pwsh -NoProfile -File E:\.agents\tools\Invoke-ControlPlaneDoctor.ps1 -SkillName <精确名称> -CheckRuntime -Json
# 确需新鲜Git引用
pwsh -NoProfile -File E:\.agents\tools\Invoke-ControlPlaneDoctor.ps1 -Owner git -Freshness Live -Json

观察身份、提供方与下一次真实验收

机器事实由Test-PCConfigDrift.ps1 -NoWrite返回pcconfig.drift.v1/v2，个人供应由Test-PersonalSkillSupply.ps1 -RequireInstalled返回，Git由Get-ProjectAdmission.ps1负责；聚合不改原状态。

SYSTEM维护进程依manifest（清单）或ObservedUserProfile检查目标安装，不能用systemprofile空目录判本人没安装。需要时显式PythonPath/ValidatorRoot，记录observer_environment，不持久改HOME/PATH、不冒充用户或安装另一份。缺Python/PyYAML/validator意味着未执行，状态unknown（未验证）。

恢复/Google接口检查只有显式选择对应owner/check才做，不执行Hot/Cold复制、还原、邮件、文件或真实OAuth（账号授权协议）。next_verification指向最小相关真实任务；自然发现需无预期工具提示的新上下文，精确调用只证明该命令。
