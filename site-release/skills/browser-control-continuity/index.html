浏览器连续操作与本地预览

让我能继续已经授权的网页工作：登录页先复用会话或选择匹配的已保存账号，验证需要本人时保留同页接续；控制因更新、缺文件或异步表单中断时，保住已登录、填写和上传的现场，再用真实页面与平台记录证明结果。

已安装 / Fresh 自然路由已验 / 真实浏览证据分层
产品用法技术与依据

先看怎么用

你不需要记住 Skill 名，直接说需求就行

什么时候用

  • 已授权网站操作停在登录页，需要选择 Chrome 已保存账号或继续云端安全登录交接
  • 需要真实浏览本地 HTML，或本人未另选浏览器时应复用外部 Chrome
  • 浏览控制工具报错或缺少运行文件，需要保住原标签页与登录态
  • 表单下拉项依赖前一层异步加载，连续点击会丢状态
  • 需要逐个上传文件并确认页面真正进入成功态
  • 点击提交后必须从新生成的平台记录核对字段和附件
  • 一次跨项目浏览故障已经完成真实恢复，需要判断是否沉淀可复用教训

可以直接这样说

“表单已经填好，附件也传了，刚才连接断了。接着完成，别让我重填，也别重复提交。”先找回同一页面，核对已填内容与每个附件的真实状态，再继续未完成步骤；需要本人验证时保留现场，提交后查看平台留下的记录。

最后会得到什么

我会得到可继续使用的已登录页面、每个文件实际上传成功与否、提交前的字段和附件清单，以及平台最终记录里的实际内容。浏览控制中途故障时，会说明现场保留到哪一步和准确的接续条件。

不适合这样用

  • 页面专属字段、收件人、业务规则或提交内容，应留在所属项目
  • 现有浏览控制能力确实不可用时，不能自造另一套浏览器控制工具
  • 想用本地恢复权限绕过登录、验证码、网站权限或外部动作授权
  • 用未经核对的猜测冒充通用故障结论
  • 需要任意下载第三方二进制或覆盖现有运行文件

正常时

本次确实需要的页面动作和真实回读完成时交付结果；仅可选预览未做则说明有意义的未验证行为。

发现问题时

按真实失败层定位并修复，保留用户页面和已完成步骤，修好后继续原目标；上传或平台记录有缺口就明确未完成。

入口不可用或证据不足时

完成支持的能力发现与合理恢复后，实际必要组件或网站仍不可用时，保留现场、精确错误与续作条件；不自造客户端、登录或成功记录。

从哪里开始

在当前 AI 对话说明要在现有网页继续做什么，或指出受控 Chrome 页面卡在登录、上传、填写、预览哪一步；AI 会先保留原标签页和已完成状态。

需要准备什么

  • 网站或当前标签页、最终要完成的动作及已做到哪一步
  • 上传时给出精确文件；提交、发送或外部修改需有明确目标和动作

为什么需要这个能力

浏览器里的‘看见文件名’、‘100%’和‘页面跳转’都可能是假完成；直接刷新或关闭又会丢掉已填写状态。把恢复、上传和提交回读分层，才能既不重做有效工作，也不把失败冒充成功。

先确定网页操作对结果是否必要

请在真实网页完成这件事，并核对最后结果。

说明最终要做的事，以及是否明确要求真实网页、交互或线上提交。

明确要网站操作时，AI 使用当前可控制的浏览器完成并读回结果；只要生成文件时，才根据质量需要决定是否额外预览。本人没指定别的浏览器时，先复用现有 Chrome 和标签页。

你会得到实际页面操作与核对结论，或已完成文件和仍未验证的页面行为。

AI 自己想预览不会给你增加新要求；浏览器出了问题也不能把原本必须完成的线上操作改称可选。

登录时先利用已经有的账号状态

继续这个登录页，试试我已经保存的账号。

目标网站和账号，以及本次已授权的登录动作；已有填好的表单会保留。

AI 先看是否已登录。确需登录时，在本机 Chrome 观察保存账号建议并选择匹配的一项；如果当前浏览能力操作不了建议，再看是否有已授权的密码中心直接填入路线。

你会分别知道账号建议是否选中、表单是否可靠填好、网站是否真的登录；密码不会交给模型。

同名账号不能猜。看到密码圆点不足以证明登录成功；可通过现有授权通道取得验证码时继续，真正需要本人操作的验证则停在原页等待。云端浏览器不继承本机登录。

控制中断时先保留当前页面

刚才浏览器控制断了，表单别丢，接着完成。

现有页面、已经填写或上传的内容、实际错误与最终目标。

AI 先找回原标签页，判断问题出在控制工具、连接、单个页面还是网站。修复后回到原动作；确实不能在原页继续时，也先保留它，再决定是否值得在同一登录环境开新页。

你会得到恢复后的真实网页结果；仍不能继续时会保留当前工作、具体错误和下一次接续条件。

修好控制工具不等于表单已提交，新页可操作也不等于旧事务恢复。不会为局部故障直接重置整个浏览器或反复重复失败动作。

填表、上传与提交分别验收

把这份材料上传并提交，确认平台里真的有。

要填的准确内容、精确文件和外部提交的实际授权。

AI 等页面上一层选择完成再选下一层，一次上传一个文件。每个文件真正显示成功后，重读关键字段与附件清单；提交后打开平台生成的记录再核对。

你会得到实际保存的字段、附件数量和文件名，缺一项会说明哪一步未完成。

仅看到文件名、上传进度到头或页面跳转都不足以证明成功。补件、撤回或重新提交各按真实平台能力与精确授权处理，不重复点击来试恢复。

需要时查看本地网页实际效果

把这个本地 HTML 打开看看布局和交互。

具体网页文件或项目，以及希望检查的页面行为。

AI 先使用项目已有的开发或预览入口；确需临时预览时启动一段可关闭的本机服务，再用浏览器看真实页面。

你会得到实际页面观察。预览结束后只关闭本任务启动的服务；要继续看时会保留明确停止方式。

只要生成文件时不自动开服务，独立 HTML 仍以原文件交付；不改浏览器保护设置来强行预览。

失败时会怎样恢复

当前浏览工具无法操作 Chrome 的保存账号建议

系统反应：只说明浏览器弹窗的具体限制；网页内容里看不见，不等于账号建议不存在。

恢复方式：若已有授权的密码中心凭据，可用现成的直接填入方式；否则保留当前页面，让本人完成这一小步。

登录出现验证码或验证步骤

系统反应：先区分已有获准通道可以继续的验证码，与确实需要本人操作的验证或同意；不因出现验证码就一律停止。

恢复方式：已有授权且当前浏览工具与规则允许时继续获取或填入；否则说明精确缺口。真实本人步骤保持同页等待，完成后接续，不禁用验证、改密码管理器或导出本地凭据。

浏览器运行配置的最新入口暂时无法替换

系统反应：保留仍可用的配置，不为了修复覆盖别的文件。

恢复方式：用现有官方安装与配置恢复入口核对准确缺口，修好后在同一浏览器里重新读到原标签页。

新页面可控制，原页面却仍失去控制

系统反应：这是原标签页的问题，不能说整套浏览器都坏了。

恢复方式：保留原页与未提交内容；确实需要时在同一登录环境的新页继续，不反复重置或冒充旧事务已恢复。

浏览器控制会话重置

系统反应：先保留已打开、已填的页面，不重载或关掉。

恢复方式：重新列出原来受控的标签页，优先接回同一页；旧页确实无法继续时再衡量新页。

官方浏览组件缺少运行文件

系统反应：不下载来路不明的程序，也不覆盖仍存在的文件。

恢复方式：先用官方刷新；仍不可用且能确认只是同一官方版本缺文件时，才按现有修复入口补齐并核对，临时文件仍在使用就保留。

依赖下拉项尚未加载

系统反应：不连续点击尚不存在的选项。

恢复方式：读取实时依赖顺序，一次展开一层，等待下一层具名选项出现后再选择。

上传显示文件名或 100%

系统反应：仍不称为上传完成。

恢复方式：读取页面权威成功状态与精确文件名；一次只上传一个，前一个完成后再开始下一个。

点击后页面跳转

系统反应：跳转本身不证明提交成功或附件齐全。

恢复方式：打开平台最终记录，回读关键字段、附件数量与名称；缺附件立即报告，补充、撤回或替换分别走各自能力与授权。

想把一次故障写成通用规则

系统反应：未核实的猜测不写成通用结论；已核实的故障/恢复或本人明确要求可按真实证据沉淀。

恢复方式：页面字段、收件人和业务含义留在所属项目；本 Skill 只保留跨项目浏览机制，并替换已过期教训而不是追加矛盾。

这个 Skill 用到的名词

已保存账号与登录接续
本地 Chrome 先复用登录态，点击登录字段并观察、选择任务匹配的保存账号；弹窗可能在浏览器界面而非 DOM，账号歧义不猜。云端使用自己的安全登录交接，不继承本地会话。 验证码可沿已有授权且当前Provider允许的获取/填入通道继续；只有真实human gate才交给本人并保持同页，不能绕过或禁用验证。
填充与登录分层
普通账号选择不向模型显示密码；可靠非秘密填充信号、真实弹窗选择和网站登录成功分别验证。密码圆点、单独 :autofill 或遮盖后的空值不能证明填好。
外部 Chrome 默认
本人没有另选时复用现有外部 Chrome 与登录/标签页；browser-client 默认或应用内偏好不替本人选择。
本地 HTTP 预览
首次导航复用已有开发服务，必要临时服务只绑定127.0.0.1、有就绪期限和可清理会话；不先试file://或建立常驻服务。
当前官方 Host 闭合
当前App manifest（清单）、执行文件、installer与四条appServerRuntimePaths一起核对；注册存在或source ready都不等于新控制会话能工作。
Controlled tab（受控标签页）
当前浏览 Provider 已经能读取和操作的页面；控制内核重置后先尝试重新取得同一标签页。
Managed runtime（受管运行时）
宿主正式提供的浏览脚本与资源；先修复当前官方 source/installation；只有这条路线不可用且满足同包族、只补缺失、禁止覆盖时才做临时兼容恢复。
Authoritative success（权威成功态）
页面真正给出的成功 class、绿色完成标记或最终记录，而不是文件名、进度文字、100% 或页面跳转。
File chooser（文件选择器）
由浏览器在点击上传按钮时发出的文件选择事件；必须先等待它，再设置一个绝对本地路径。
Post-submit readback（提交后回读）
提交完成后打开平台实际生成的记录，再核对字段、附件数与文件名。
Durable lesson（可持续教训）
保留已经核实、会改变以后决定的故障/恢复，或本人明确要求；写清触发、范围、证据和退出条件，替换过期指导，不保存私人页面或完整日志。

专业定义

默认接着本人现有外部 Chrome 工作。遇到登录页，先复用已登录会话或选择匹配的已保存账号，保留已填表单；遇到升级断连、本地预览、异步表单或上传假完成时，再按真实缺口恢复和回读。填充、登录、上传与最终提交各自验证。

执行参考

下面保留 AI 和工具实际使用的参数、步骤与依赖。日常使用可以直接提出需求，不需要先手工准备这些协议。

输入

  • 当前受管浏览 Provider 的原生操作说明
  • 现有标签页、控制会话与页面的实时状态
  • 运行缺口报错中精确的 canonical browser scripts 目录
  • 用户明确选择的单个上传文件和目标表单
  • 真实失败、最小恢复与最终页面回读证据

输出

  • 保留或重新接管的同一已登录标签页，必要时同 Profile（浏览器配置档）的新标签页
  • 当前Host四个运行路径的精确修复、二次无改动与可回退回执；临时兼容文件按实际引用保留或清理
  • 逐文件 authoritative success（权威成功态）与精确附件数回读
  • 提交前字段快照、提交后平台记录与实际附件核对
  • 达到真实证据阈值后原位更新且带退出条件的跨项目浏览教训

执行顺序

  1. 1

    先复用有效登录态；本地 Chrome 登录表单点击用户名或密码框，保留已自动填入内容，否则观察建议弹窗并选择与当前任务匹配的账号行，不点管理密码

  2. 2

    弹窗属于 Chrome 界面，DOM 未见不等于没有；用当前提供方支持的界面观察与操作，只有焦点和弹窗已确认才用键盘，不盲按方向键或猜自动填充接口

  3. 3

    填入后只看可靠的非秘密填充信号或授权登录结果；密码圆点、单独 :autofill 或被遮盖工具返回空值不能证明成功，不复制字段值或在填充后导出可能含秘密的页面结构

  4. 4

    验证码已有获授权获取/填入通道，且当前浏览Provider和适用规则允许时，沿该通道继续；验证码提示本身不触发一律交回本人。设备本地验证、通行密钥、二维码、CAPTCHA、同意或设备批准确实要求本人时才停在该步，完成后沿同页接续。云端浏览器使用自身安全登录交接，不继承本地Chrome或应用内浏览器会话。

  5. 5

    默认外部 Chrome，先检查本人现有配置和标签页；用户明确另选时服从选择

  6. 6

    本地 HTML 首次导航走已有 HTTP 开发/预览服务；必要临时服务只绑定 127.0.0.1，保留 PID/session、就绪期限与准确清理路径

  7. 7

    浏览运行缺口先读当前 App 的 .codex-plugin/plugin.json，核对 service/files、manifest（清单） executable、installer 及四条 appServerRuntimePaths，不相信版本号、.tmp、旧 globals 或 latest 别名

  8. 8

    允许的本地修复先保存 allowed_origins；latest 无法替换时保留别名，使用当前 Host 旁安装器生成的 extension-host-config.json，设置 manifest（清单） path、恢复 origins 并回读

  9. 9

    旧Host配置仍指向存在的旧文件时，Inspect比对当前App配置；RepairHostConfig只更新codexCliPath、nodePath、nodeReplPath、browserClientPath，保留channel、代理、未知字段与浏览器现场，重复执行already_current；RollbackHostConfig只在修复后hash（内容指纹）仍匹配时回退

  10. 10

    先读当前受管浏览能力的原生说明并列出现有受控标签页

  11. 11

    控制重置后优先重新取得同一标签页；锁定页保留为备份，只有继续价值更高时才在同一已登录 Profile 新开标签

  12. 12

    运行文件缺失时先走官方刷新；无支持路线且满足同官方包族、只补缺失、禁止覆盖时，先 Inspect 再 Repair

  13. 13

    helper只补精确缺失的受管官方运行文件，不覆盖既有目标；AppX只读源复制只取字节，不搬运加密元数据，并逐一回读SHA-256

  14. 14

    JavaScript内核重置不会刷新MCP Provider已初始化的运行路径，子任务也可能继承旧环境；改好路径后重新连接宿主MCP，或从更新GUI中的新任务真实读取Chrome标签页，不能靠再reset一次证明恢复

  15. 15

    当前登记Host配置仍引用临时运行文件时保留文件与receipt（回执）；官方安装已补齐或登记配置不再引用时才Cleanup，避免刚恢复又断开

  16. 16

    有专用文件选择器接口时先等待再点击；没有时只点一次上传并立即看真实屏幕，先处理已出现的 Windows 文件对话框，不因界面树漏报而反复点击，再回读页面文件名

  17. 17

    每个文件要求页面 authoritative success 与精确文件名回读后才继续

  18. 18

    异步控件按实时依赖一层层展开，下一层标签出现后再选择

  19. 19

    提交前重读关键字段、附件数与文件名；提交后打开平台记录再次核对

  20. 20

    只沉淀会改变后续决定的已核实故障/恢复或本人明确要求，记录触发、范围、证据和退出条件；替换旧指导，不保存私人页面或日志

操作边界

  • 已保存账号选择不是索取密码明文；账号确实歧义时才问，不任意选择第一项
  • 当前提供方不能操作 Chrome 建议弹窗时，只说明该限制；有获授权 Password Center（密码中心） 凭据才走既有盲填，否则保留准确步骤给本人
  • 指令发现、真实弹窗选择、可靠填入和网站登录分别验收；只填充测试不提交，空表单测试必须先目视确认真正为空
  • 云端会话不继承本地密码、Cookie、扩展、文件或密码中心；不导出凭据或新建本地到云端中继
  • 这是受管浏览能力之上的连续性层，不是第二浏览器客户端、原始自动化服务器或授权旁路
  • 优先保护已填写、已登录和用户拥有的标签页，不先重载、导航或关闭
  • 文件名、100% 进度或页面跳转都不是成功；必须读取页面成功态和最终记录
  • 临时恢复只补精确缺失文件，核对 source/target SHA-256 一致，不覆盖现有目标，并在原生路径恢复后清理
  • 本地恢复本身不产生登录、传输、上传、验证码取用/填入、删除或提交授权；已有精确授权与当前Provider允许的验证码通道可继续，不能禁用验证或换控制面绕过真实本人步骤。
  • 不公开标签页正文、附件名、平台记录 ID、截图、秘密或临时回执内容
  • 跨项目浏览机制归本 Skill，页面字段与业务含义归具体项目
  • browser-disconnected 表示新会话也无法读取标签页；stale-debugger-unattached 表示新会话正常、仅旧页脱离调试，保留旧页并用同 Profile 新页，不反复 claim/reset
  • status=ready 只说明 source 路线，不证明可执行健康；临时缓存恢复是官方 source/install 修复之后的窄后备
  • 纯文件生成不启动预览服务；独立 HTML 保持独立文件，临时预览结束只清本任务进程，不建常驻服务

一般故障恢复与已知修复配方的关系

按实际调用区分发现、调用、依赖、Provider初始化/transport、单页、网页与业务动作。参数错误不等于坏安装，健康安装也不等于活会话。修前明确改哪一层、保留什么、必要撤销路径与什么观察能检验假设。

调用参数修正、状态变化或有依据恢复才重试；无变化失败应重审原因，不按固定次数堆修复。必要时删除已证无价值的坏层；保留标签、未存内容、登录和无关任务，不为局部故障重置profile、全局网络或整机升级。

取不到策略/配置与明确策略拒绝是不同事实；前者可诊断实际依赖，后者不能靠换面绕过。修复要回到最初用户动作，留下准确错误、已试方法与下一支持路径，而不是用新tab可控证明旧事务恢复。
