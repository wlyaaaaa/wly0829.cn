一个完整例子 真事：对规则与技能基座的仓库实际跑了一次，北京时间 9 月 28 日 22:23 我：“要在 .agents 里改点东西，先看看这个仓库现在什么情况。” AI 做了什么 1 用总索引的入口查 wlyaaaaa/.agents；默认不联网，GitHub 那边用上次记下的情况，远端分支也不刷新。 2 读到：私有；默认分支 main；本机只有 （本机路径） 这一个工作目录，main 和 GitHub 上的 main 一致；目录里有 1 个 Git 还没管的新文件。 3 另外两个本地分支：archive/lockdown-review-notes-20260926 有 1 个提交不在 main 里；codex/threebase-continue-20260927 已经全部并进 main，可以收掉。 4 结论是“注意”，建议的提交方式是“先收拾干净，或只挑自己的文件提交”。这个结论只是事实，不是推送许可。 AI 交回 “可以改。仓库是私有的，本机 main 和网上一致（按上次记录，这次没联网）。三件事要注意： 有 1 个没被 Git 管的新文件，还没查是谁的；提交时只挑自己的改动，不用 git add .，查清之前不动它； 一个存档分支上有 1 个提交没进 main，先留着； 一个已经并进 main 的旧分支可以收掉，要收我再单独办。” 另一种问法 我：“文字识别那个公开项目，有没有私下的说明文档？” AI：“登记了私有去处：私有仓库 public-project-private-backup，但还没对上具体文件，所以这次没有要读的。以后要往里写，得先联网再确认一次它还是私有。”
能做的事 这个技能能做的事，就是 GitHub 项目总索引的“认仓库、查同步、找配套说明、公开前核对”那几组功能。去看全部功能 用这个技能时，AI 守的规矩 只在事实会改变做法时才查：目标不清、有好几个工作目录、恢复或迁移、合并分支、推送、公开。 查出的结论是证据，不是许可：写着“可以推送”也不等于能推送，推送和发布照授权规矩办。 Git 没读出来算“不知道”，不算“对不上”；不为这个去改远端地址、放宽 Git 的信任设置。 默认用本机记录、不联网；要最新情况才联网：只问 GitHub 的公开性，或连远端分支一起刷新；准备公开时两样都要。 收尾把这次真正改过的每个仓库都查一遍，经链接改到的配套说明仓库也算；有没提交的改动不等于有人正在写，先看是谁的；提交照常挑文件、推送、读回默认分支。 配套说明按总索引的登记找，只读用得着的；仓库改公开前，先查它登记的私有去处，还没对上具体文件也要查。 只有换电脑、计划任务、端口、本机数据、备份恢复、开机启动、运行环境、快捷方式、共享目录这类要看电脑实际情况的事，才去查电脑配置；看到一个本机路径不算。 放加密文件的 wlyaaaaa/Key 仓库，克隆前先认清放到哪里：只能放进授权的私有位置，里面只有加密包和能公开的说明，不能把解密后的内容、密码和密钥文件带进去。
