文稿转 PDF 把 Markdown 文稿变成能打印、能交出去的 PDF，查过再交。 AI 写的说明、讲义、报告大多是 Markdown。这个技能告诉 AI 怎么把它转成 PDF：用这台电脑登记好的 Python，由 Playwright 驱动本机 Edge 按 A4 打印（Playwright 和 Node 单独装在 （本机路径），也按电脑配置里的登记找，不再借 Codex 自带的运行环境）；打完先查——PDF 读得开、页数对、要求的字都在、原文和样式文件没被改——全过才替换旧文件，任何一样不过，旧 PDF 原样留着。转换成功不等于排版没问题，要看排版再交给PDF 逐页检查。 可以这样说： “这份讲义转成 PDF，我要打印。” “导出来必须正好 3 页，封面上的标题要在。” “这个文件夹里的说明文档全部转一遍。” “用公司版的样式导一份 PDF 给同事。” “文稿里的图一张都不能少，缺了就别交。” “公司版”“个人版”这类样式归Typora 薄荷主题，这个技能只管转换和把关。
一个完整例子 9 月 28 日写这页时实跑的，文稿是公开样例《项目简报》。 我：“这份简报转成 PDF，要正好 1 页，‘三项原则’这几个字必须在。” AI：“好了，1 页，‘三项原则’在第 1 页；原文没被改动，用的是默认中性样式。” 我：“改成要求 2 页再试一次。” AI：“没通过：实际 1 页，要求 2 页。上一份 1 页的 PDF 原样留着，没被换掉。” 回执里记了什么 状态：succeeded　页数：1　样式：neutral　打印：Playwright　原文未变：是　联网：否 第二次：生成失败：PDF page count mismatch: actual=1, expected=2 两次之后 PDF 的指纹都是 2319f76a51d6…，文件夹里没有留下暂存文件。 背后发生了什么 1 AI 用登记好的 Python 运行转换入口，带上“要 1 页”“要有这几个字”两个要求。 2 转换器先记下原文的 SHA-256 指纹，把 Markdown 转成网页，交给 Edge 打印到临时文件。 3 查临时文件：确实是 PDF、读得开、没加密、页数和文字都对、原文指纹没变。 4 第一次全过，换上正式文件；第二次页数不对，临时文件删掉，正式文件不动。
样式从哪来 默认：中性 黑字、灰线、A4、页边约 1.5 厘米、正文 12 像素。表格每行不拆到两页，标题不孤零零落在页底。什么都不说，就是这个样子。 老绿色：只给老文稿 早期一批项目说明用过绿色标题。那些文稿重新导出时才用它，不当所有 PDF 的统一风格。 项目自己的 CSS 项目或文稿有自己的样子，就把它的 CSS 交给转换器，可以交好几份。Typora 薄荷主题的原版、个人、公司三种样式，要用主题项目自己的导出入口。 文稿里自己写的样式默认保留；也可以让它忽略或者直接拒绝。代码块和注释里举例用的样式代码只当文字，不会被当成样式。
能做的事（18 项） 图例：● 在用　● 待验收　○ 待实施　● 没用过　● 说不准　✕ 已停用 在用＝9 月的真实转换里确实起了作用（看回执）；待验收＝做好了，只在验证里跑过；说不准＝AI 的会话记录最早只到 9 月 1 日，回执里又看不出这一项用没用。 转换 1 单篇转换 一份 .md 转成一份 PDF，中文文件名、中文内容都行 2 一个文件夹一起转 文件夹里每份 .md 各出一份同名 PDF，最后报几份成功；只能用中性或老绿色样式 3 用登记好的 Python 跑 不管命令行里碰巧是哪个 python，都用电脑配置里登记的那一个 4 打印工具按登记找 Node 和 Playwright 装在 （本机路径），位置记在电脑配置里；登记或文件缺了就说缺哪一项，不去 Codex 的缓存里找 样式 5 默认中性样式 黑字灰线、A4、表格行不拆页 6 老绿色样式 早期项目说明的绿色标题，只给老文稿重新导出 7 套项目自己的 CSS 交一份或几份 CSS，PDF 按它排 8 文稿自带样式怎么办 保留、忽略或拒绝三选一，默认保留；代码块里的样式示例不算 9 手动分页 文稿里写 <!-- PDF_PAGE_BREAK --> 或 page-break 的 div，就在那里换页 交之前查 10 页数要求 要求正好几页，实际页数不对就不交 11 必须有的字 列出必须能从 PDF 里读出的字，少一个就不交 12 缺图缺样式就失败 图片、样式只从文稿和 CSS 所在的文件夹读，加载不上就整份失败 13 查过才替换 是 PDF、读得开、没加密、至少 1 页、原文和 CSS 指纹没变，全过才换上 不出乱子 14 默认不联网、不跑脚本 网上的图和文稿里的脚本默认挡掉，可信文稿才明确打开 15 不盖掉原文和样式 输出路径等于 Markdown 或 CSS 时直接拒绝 16 同一份输出只让一个任务写 两个任务同时写同一个 PDF，后来的直接报错 17 超时连进程一起停 默认 120 秒，最多 600 秒；超时把浏览器进程树一起结束 18 回执 每次成功打印一份 JSON：原文和 PDF 的指纹、页数、样式、打印方式、资源文件夹
边界 交给它 Markdown 文稿要变成能打印、能发出去的 PDF 有硬要求：几页、哪些字必须在、图一张不能少 已有一份好的 PDF，这次重导出不能把它弄坏 不交给它 / 它不做 Word、PPT、Excel：用各自的工具 已经是 PDF 的文件改内容、拆分合并：用 PDF 工具 排得好不好看：样子由选的 CSS 定，它只保证照样打出来 看排版有没有乱：交给 PDF 逐页检查 转完提交、发邮件、上传、分享：转换不等于同意发出去 查过只说明“这个 PDF 是这份原文、这个样式打出来的、页数和字对得上”，不说明每一页都好看。它和 PDF 逐页检查是同一个插件里的两个技能，一起装进 Codex 和 Claude；插件怎么发布、装到各个 AI 上，见AI 规则与技能基座。
