Google 邮件、云盘与待办固定入口

让 AI 在已连接的同一 Google 账号里找邮件、云盘文件和待办任务，读到实际内容后继续处理。明确对象和动作后，可沿现有入口回复邮件、修改文件，或创建、更新、完成及整理任务。日历仍冻结。

Gmail/Drive 的旧业务证据保留原日期；Google Tasks 的正式入口已登记，本轮没有实际授权、读取或写入任务。首次使用可能需要本人在同账号完成授权；日历仍冻结。
产品用法技术与依据

先看怎么用

你不需要记住 Skill 名，直接说需求就行

什么时候用

  • 按条件查邮件并读取实际正文或同一线程
  • 查找、读取或导出Drive文件
  • 查找任务列表和任务，或明确创建、更新、完成、移动及删除一项待办
  • 本人明确要找刚刚发来的Gmail验证码
  • 需要原生Google文档导出或普通TXT/DOCX/PDF正文
  • 已明确授权发送、回复、上传、修改或分享，而且当前 Google 入口确实支持这个动作

可以直接这样说

我可以说：“找到刚发给我的方案邮件，读一下附件；再看看 Google Tasks 里相关待办。”它分别定位邮件、文件和任务列表，读实际内容；我明确指定任务后，才在同一连接里完成或修改它。

最后会得到什么

得到同一账号下的邮件、文件或任务内容与覆盖范围；授权写入另回读真实对象。任务的到期日只表示日期，不冒充几点钟的提醒。首次 Tasks 授权若缺失，会提示同账号前台授权，其他已可用服务可继续。

不适合这样用

  • 切换其他账号
  • 不说明就改用别的账号、浏览器或外部连接
  • 当前 Google 入口没有提供这项写操作
  • Google Photos、Admin 或支付
  • 把已登记 Tasks 入口当作 OAuth（账号授权协议） 已授权或远端任务操作已完成的证明；日历仍冻结

正常时

固定账号和对应操作可用时执行精确读取或已授权写入，并返回真实结果。

发现问题时

操作未暴露、权限范围不匹配或目标不唯一时停止并说明缺少哪项能力。

入口不可用或证据不足时

固定服务入口或账号绑定实际不可用时，报告该项缺口，不静默换账号或连接；Tasks 首次需补授权只暂停 Tasks。日历保持冻结。

从哪里开始

在当前 AI 对话提出 Gmail、Google Drive 或 Google Tasks 的具体任务；既有私人 Google 连接会按同一账号查找并继续读实际内容。要写入时说明精确对象和动作。日历仍冻结。

需要准备什么

  • 邮件的人、主题、时间，Drive 文件名或链接，或任务列表与任务的名称、日期等线索
  • 发送、回复、上传、修改、分享、完成或删除时的精确目标、内容与明确动作；找验证码时有服务线索可附上

为什么需要这个能力

同一台电脑可能有多个 Google 登录和多条访问路线。账号或入口用错，会查不到文件，也可能把写操作发到错误账号。

从需求到结果

1

告诉我邮件的人、主题、时间，Drive 文件名称与链接，或 Google Tasks 的列表、任务和大致日期。AI 使用既有固定账号继续搜索、读实际内容和必要上下文，不能只交一个标题或搜索列表就算完成。

2

私人邮件与文件共用本机和已认证电脑连接的同一资料期限。有效期内不逐入口重复验证；取消另一项请求不撤销原期限，到期或主动锁定后停止私人取用。

3

普通文件下载后用对应读取器阅读，原生 Google 文档通过正式导出取得内容；工具菜单没显示下载，不等于同一连接完全没有能力。

4

搜索仍有下一页或覆盖不全时，按问题继续查并说明未覆盖部分。无结果先核对别名和过窄条件，不据几个候选就声称全库没有。

5

已明确授权且当前连接实际支持的发送、回复、上传、修改、分享或删除，按精确目标完成并回读。结果不明先查原对象，不盲目重复发送或创建。

6

找刚收到的验证码时，只在近期窗口核对服务、收件时间与正文，并在同一次请求内有限等待；旧码或不相关邮件不当答案，也不自行完成登录或本人验证。

7

Google Tasks 先找准确列表，再读任务；创建、更新、完成、移动或删除时以精确任务为目标并回读。隐藏状态能查，但当前没有‘隐藏任务’写操作；日期不是带时间的截止。

8

Tasks 首次缺 OAuth（账号授权协议） 范围时，由本人在同账号前台完成一次授权后再读回；不能代点同意页。账号或操作不可用时说清缺口，不静默换账号、连接或浏览器。日历仍冻结。

失败时会怎样恢复

搜索只给标题，或暂时看不到下载动作

系统反应：标题和候选文件还不是实际内容；工具列表也未必列出同一连接的全部操作。

恢复方式：先检查现有同账号入口：普通文件按实际可用方式读取，Google 文档按正式导出读取；仍不可用就说明缺口，不换账号。

现有 Google 连接未就绪或登录失效

系统反应：指出是哪一个账号和动作不可用，不把空结果说成邮件或文件不存在。

恢复方式：修好原连接后接着完成同一请求，不偷偷切到另一账号。

当前连接确实没有请求的写入能力

系统反应：停止该动作，不借浏览器或另一连接暗中完成。

恢复方式：由连接的负责项目补齐并验证这个精确操作；在此之前明确报告无法执行。

读取请求瞬时超时

系统反应：只读请求可按失败性质和既有提供方规则进行有界重试。

恢复方式：继续失败就保留原错误和目标文件或邮件，不另建一条连接绕过去。

写入后没有收到明确结果

系统反应：先重读同一个邮件、线程或文件；没有回执不等于没有写进去。

恢复方式：实际状态仍不清楚就保留未知，不直接重发或重建，避免重复发送和创建。

Tasks 首次提示需补 OAuth（账号授权协议） 授权

系统反应：只暂停 Tasks，不把 Gmail/Drive 的既有连接写成失效，也不代本人点击同意。

恢复方式：本人经同一账号前台授权后再读回；未完成时保留 Tasks 在线效果未知。日历仍冻结。

发送或回复的结果不确定

系统反应：保留原邮件、会话和已得到的回执，不马上发第二封。

恢复方式：从同一账号入口回读收件人、线程和附件；确认没发生后才判断下一步。

这个 Skill 用到的名词

DriveDownload（普通文件下载）
固定Provider的CLI（命令行工具）可读取Drive内TXT、DOCX、PDF等普通文件，再用原生reader；它不是原生Google Docs导出。
Provider（固定服务入口）
固定同账号入口现在列出 Gmail、Drive 和 Google Tasks；不是任意 Google API 代理。Tasks 的在线 OAuth（账号授权协议） 与远端结果仍需实际任务确认，日历冻结。
Operation（精确操作）
既有入口明确支持的一项动作，例如搜索邮件、读取同一邮件线程或导出文档；本页不据此推断其他服务已经可用。
Drive export（原生文档导出）
Google Docs 不能当普通文件下载，必须通过 Drive export 转成目标格式。
Read-back（正式回读）
写入后用同一个 Provider 重新读取对象，确认外部状态真的改变。
有界验证码等待
本人明确找新验证码时，在同一个近期邮件窗口内有限等待，核对实际正文、服务与时间；不是后台收码或身份验证。
实际正文与候选
邮件ID、主题、Drive文件名或一页候选只能定位，不能证明内容已读、全范围已找齐或操作已完成。
Google Tasks 的日期与授权
先确认任务列表再读任务；due_date 只表示日期。首次缺 Tasks scope 时在同账号前台授权，当前零网络 Status 不证明真实任务已读或已改。

专业定义

在本人既有 Google 账号中找邮件和云盘文件，也能按任务列表读取、创建、修改、完成或整理 Google Tasks；明确写入对象和动作后沿同一连接处理并回读。Tasks 首次可能需要本人在同账号前台补 OAuth（账号授权协议） 授权；日历保持冻结。

执行参考

下面保留 AI 和工具实际使用的参数、步骤与依赖。日常使用可以直接提出需求，不需要先手工准备这些协议。

输入

  • 邮件/文件的窄查询、对象 ID 或时间范围；Tasks 的列表与任务线索
  • 写操作时的精确对象、内容和动作授权；首次 Tasks 缺 scope 时由本人完成同账号前台同意

输出

  • 最小必要邮件正文、线程或文件结果；验证码注明服务、收件时间及未解决的冲突
  • 任务列表、任务和分页覆盖；due_date 只表示日期
  • 原生文档导出
  • 写操作的 Provider 回执与 read-back（正式回读）
  • 普通存储文件经固定 Provider 的 DriveDownload 下载后的原生读取结果

执行顺序

  1. 1

    已知任务直接走对应窄入口；gmail_read.py search按实际请求取得正文，不把只含ID/主题的搜索页当成读过邮件，也不先枚举所有工具。

  2. 2

    选择固定 Provider 的精确 operation

  3. 3

    读取实际需要的正文和上下文后完成当前请求；写操作仅在用户确切授权及已暴露能力内执行，同一线程回复、附件与最终对象分别回读。

  4. 4

    原生文档必须走 Drive export

  5. 5

    Google Tasks 先列任务列表取得准确 ID，再分页读取或取得目标任务；更新仅 PATCH 指定字段，完成/移动/删除使用精确 ID 和明确动作授权

  6. 6

    Tasks 缺 OAuth（账号授权协议） 范围时由本人同账号前台授权后再读回；这项等待不影响已有 Gmail/Drive 任务

  7. 7

    写入前核对 Provider 能力和授权

  8. 8

    按同一 Provider read-back（正式回读）

  9. 9

    Drive已知名称先准确找；只有当前完整搜索结果确实未命中才扩大条件，不能把第一页或最多五个候选当成所有文件。

  10. 10

    “Gmail验证码”沿现有gmail_read入口看最近10分钟、相同服务及当前上下文；首次未见时每5秒查看、至少等待120秒并做最后一次回读，不重复算旧码，也不把过期邮件混成新验证码。

  11. 11

    发生投递不确定时回读原对象和回执，不盲目重新发送；验证码候选须由当前任务读正文判明用途，不自动完成账号登录或真人验证。

操作边界

  • 不落中央库
  • 不自动同步
  • 不换账号或第二 Provider
  • 删除、发送和公开分享仍需精确授权；Google Tasks typed 入口已登记但本轮未验在线 OAuth（账号授权协议） 或任务结果，日历仍冻结。
  • Tasks 的 due_date 不是带时刻的提醒；可读隐藏状态但没有虚构的隐藏写入。Tasks 授权缺失只暂停 Tasks，不抹去 Gmail/Drive 既有连接。
  • MCP 只暴露元数据或没有 drive_download，不等于固定 Provider 没能力；普通文件可走已登记 CLI（命令行工具） DriveDownload
  • 普通文件用 files.get?alt=media，原生 Google Docs 必须 files.export；不能混用或切换第二 Provider
  • 取用本人背景、邮件或私人样本前消费 PCConfig 的同一 B2 资料状态与原截止；screen/factor 仅表示业务分类，不另建锁屏期、任务期或 MCP 期。独立 MCP 与本机共用该记录，连接认证不免资料检查；有效期内按需取用，到期或主动锁定后停止，取消只结束本次未完成请求。 邮件主题、正文和验证码均按私人内容处理，Drive按实际内容判断，不按扩展名降级。
  • 不因这个Skill存在而启动轮询服务、同步库或第二账号连接；有限等待只发生在本次明确验证码请求内。

依赖

  • PCConfig 的 google-workspace.primary Provider
  • 已登记 OAuth（账号授权协议） 绑定

同一次验证码请求怎样继续

Gmail 验证码沿既有来源说明；Google Tasks 是当前已发布的另一项 typed 能力，不参与取验证码。“验证码”默认最近10分钟，不先反问类别；服务未指定时选最新相关码，旧引用/过期/不相关邮件排除。

candidates_require_review只是候选。AI读取正文后直接给码、服务和接收时间；候选全不合适就累计--exclude-id继续。同一回执已返回非空deadline_utc时必须传原--deadline-utc，不能重新开始120秒等待。

首次确认无合适新消息后每5秒刷新、至少等120秒，到期最后查一次；新候选即时返回。只有no_new_candidate_after_wait才说等候后未收到。本人停止或真实工具故障可以提前结束，“不是这个/新的呢”排除旧消息立即刷新，修Skill本身不取验证码。

# 本次有界等待
python -B E:\.agents\skills\google-workspace-direct\scripts\gmail_read.py wait
# 排除已核候选并保留原截止
python -B E:\.agents\skills\google-workspace-direct\scripts\gmail_read.py wait --exclude-id <已核消息ID> --deadline-utc <原返回截止>

正文、分页和写入的精确接口

gmail_read.py search一次取正文，只定位才--metadata-only；已有消息ID用read或gmail_get_message，需要往来才get_thread。原始gmail_search只有ID。Drive已知ID直接get，名称用drive_find.py精确名称，完整未命中才放宽，默认最多5个候选；不完整/分页范围限制“全部、最新、唯一”等结论。

只读瞬时传输故障最多重试一次，账号/权限/schema（数据结构）错误原样说明；不静默换账号。相关CLI（命令行工具）可复用-StdinJsonLines。回复用GmailReply/GmailDraftReply保留原线程，附件用-AttachmentPaths，按references/reply-and-attachments.md核对象、大小、原草稿与回读；effect_unknown不重发。

明确目标和动作的写入直接按实际支持能力办理，不增加逐步确认；取邮件主题、验证码和私人文件都消费同一现役资料期。安装/零网络配置/旧业务快照不证明本轮OAuth（账号授权协议）与业务成功。

Google Tasks 的列表、写入与当前证据

先 TasksListTaskLists 确认列表 ID，再 TasksList/TasksGet；列表保留 PageToken、UpdatedMin、完成/隐藏及 assignment metadata（元数据）。due_date 是日期，不是带时刻的 deadline。

TasksCreate/TasksUpdate/TasksComplete/TasksMove/TasksDelete 都要精确列表和任务 ID；写入沿 -ActionAuthorizationConfirmed，删除还需 -Force。Update 只 PATCH 点名字段，Move 用明确 parent/previous ID；隐藏只有只读状态。

Tasks 首次缺 scope 返回 tasks_oauth_reauthorization_required；本人通过同账号前台 Start-GoogleWorkspaceOAuthEnrollment.ps1 完成同意后再读回，不代点授权页。2026-09-24 零网络 Status 不证明 OAuth（账号授权协议） 已授权、远端身份匹配或真实任务结果；Calendar 仍冻结。

pwsh -NoProfile -File E:\PCConfig\tools\Invoke-GoogleWorkspaceProvider.ps1 -Action TasksListTaskLists -BindingId google-workspace.primary -Json
