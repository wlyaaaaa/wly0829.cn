PDF 读写、表单与逐页验收

读取、制作或填写 PDF，既检查真实页面，也确认填写的值已经保存。防止看起来填好了，重新打开或交给对方时却丢值、缺字或显示错误。

宿主已集成 / 本轮未跑真实 PDF
产品用法技术与依据

先看怎么用

你不需要记住 Skill 名，直接说需求就行

什么时候用

  • 读取或审阅版面重要的 PDF
  • 制作正式 PDF
  • 填写仍可继续修改的 PDF 表单
  • 需要逐页检查裁切、重叠、字体、表格或页码

可以直接这样说

“把这份多页申请表按这些信息填好，保留能继续修改的表单，不要只把文字贴在页面上。”AI 填完后重新打开核对，再逐页检查文字有没有完整显示。

最后会得到什么

得到最终 PDF、阅读结果或已填写的表单。表单默认保留可继续填写的能力；明确需要固定内容时才转成不可编辑的表单外观，并说明具体字段或页码仍有什么问题。

不适合这样用

  • 只需编辑 DOCX 源文书
  • 只看文本提取就判断版面正确
  • 未经明确要求把可编辑表单压平
  • 把旧页面图或成功退出码当成本轮 PDF 验收

正常时

内容结构、字段逻辑和最后一轮逐页渲染都一致时交付最终 PDF。

发现问题时

字段、控件、外观或页面版面不一致时停止交付，修复后重新打开并逐页验证。

入口不可用或证据不足时

正式 PDF 依赖或渲染器不可用时保留原件和当前输出，不用旧页面图、成功退出码或文字提取冒充验收。

从哪里开始

在当前 AI 对话交给 AI 一份 PDF，或说明要制作、填写怎样的 PDF。可直接指出页码、字段、版面或是否需要保留可填写表单。

需要准备什么

  • PDF 原件或要制作的内容及目标用途
  • 要读取、填写、修改的页或表单字段；若确需固定为静态件，明确说出

为什么需要这个能力

PDF 视觉结果和逻辑结构是两层证据。普通文件可能裁切或缺字，交互表单还可能出现字段树、页面控件、字段值和显示外观彼此不一致。

从需求到结果

1

给出 PDF 原件或要制作的内容，说明是阅读、生成还是填写表单；格式、页数、关键文字和是否保留交互按真实用途确定。

2

阅读保留页码、表格、图与脚注的关系；制作或填写后重新打开文件，检查实际保存的值与页面显示是否一致。

3

默认保留表单交互性，只有明确要求才固定为静态内容。字段身份冲突或值没有真正保存时先修复，不用一张看似正确的页面冒充成功。

4

每次有意义更新后重新检查全部页面，核对字体、裁切、重叠、表格和页码；结构检查与页面检查都不能代替内容是否正确。

5

依赖不可用或页面仍有问题时保留原件和当前结果，说明未完成位置，不拿旧页面图或命令成功当本轮通过。

失败时会怎样恢复

表单里出现两个看似同名、实际不同的填写位置

系统反应：先停下自动填写，避免把答案写进错误字段。

恢复方式：核清实际字段关系；确实不能可靠保留可填写结构时，只在你接受静态文件后再按该目标制作。

页面看得到填写内容，重新打开却没有保存

系统反应：这份表单没有通过验收，不能交付。

恢复方式：重新打开核对真实字段值和页面显示，修复后再次检查每一页。

明确要静态 PDF，但文件仍可填写

系统反应：仍是交互表单，不能当已固定的成品。

恢复方式：去掉全部可填写字段，再重新打开并逐页查看。

这个 Skill 用到的名词

AcroForm（PDF 表单字段树）
PDF 中保存字段名称、类型、值和层级的规范结构；页面上看见文字不代表字段树已经正确更新。
Widget（页面表单控件）
字段在某一页的可交互外观与点击区域；可能通过 Parent（父字段）继承真实值。
Appearance stream（字段外观流）
PDF 阅读器用来画出字段当前值的图形内容；逻辑值正确但外观为空时，页面仍可能显示错误。
Flatten（压平表单）
把当前字段外观画进页面并删除交互控件；默认不做，只有用户明确要静态成品时才使用。
Page render（逐页渲染）
把最终 PDF 每页转成 PNG 检查版面、字体、裁切和表单外观；它仍不能替代字段树验证。

专业定义

读取、生成、检查或填写 PDF 时，同时核对内容结构与真实页面；交互表单还要检查 AcroForm（PDF 表单字段树）、页面控件、字段值和外观流，不能用“画面看见值”冒充字段已经正确写入。

执行参考

下面保留 AI 和工具实际使用的参数、步骤与依赖。日常使用可以直接提出需求，不需要先手工准备这些协议。

输入

  • PDF 原件或要生成的内容与版式要求
  • 表单字段名、目标值和是否明确要求压平
  • 页数、关键文本、交互性与视觉验收条件

输出

  • 读取结果、生成 PDF 或已填写表单
  • 字段树、页面控件、字段值与外观的一致性检查
  • 全部页面的 PNG 目检结论

  1. 1

    读取结构与页数

  2. 2

    按任务选择生成、提取或表单路线

  3. 3

    表单同时核对字段树和页面控件

  4. 4

    写入后重新打开并验证逻辑值

  5. 5

    渲染全部页面检查真实外观

  6. 6

操作边界

  • bundle 版本只记录本次观察，不作为未来准入
  • 视觉通过不能替代表单字段树和逻辑值检查
  • 默认保留表单交互性；只有用户明确要求才压平
  • 每次有意义更新后重新渲染并检查全部页面

依赖

  • Codex bundled workspace dependencies
  • Poppler
  • reportlab、pdfplumber 与 pypdf
