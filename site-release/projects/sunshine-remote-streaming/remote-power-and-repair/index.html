Sunshine 远程串流 · 功能说明

比较智能插座 AC（交流电）自启与有线 WoL（网络唤醒），并用脚本修复网络和服务

电脑已经开着但网络抽风时，有脚本帮助收敛服务与代理残留；电脑彻底关机时，则要从智能插座 + BIOS 或有线 WoL 中选一条并做实物验收，不能把两件事混成“一键修复”。

当前情况：软件服务和日常巡检有成功记录；智能插座、主板来电启动和网络唤醒的整条远程开机路径尚未验收。

用途与实际影响

这项功能怎样使用

为什么需要它

无线网卡在关机或睡眠后未必保持可唤醒供电，且 Tailscale 会随主机关机离线；因此不能仅凭在线状态假定外网 WoWLAN 可用。Windows 还可能因代理软件异常退出而留下服务环境变量，让 Tailscale 持续停在离线状态。硬件开机与在线修复必须分开处理。

举个实际例子

“我想在外地把关机电脑叫醒。”候选流程是智能插座重新上电、BIOS 来电自启、Windows 启动服务，再由手机连接；每一段都要实测。本轮只确认服务与巡检，不代表这条链已经跑通。

最后我会得到什么

已交付远程开机选择依据、在线故障修复脚本和当前每日巡检；尚未交付经过实物验证的远程冷启动或手机自动进入桌面。

正常时

上次软件侧看到两项服务在运行、巡检正常；主机从关机到手机看到画面的整条链仍未验。

发现问题时

网络设置残留或服务异常时，修复脚本按已识别范围处理并回读；结果不满足就报告失败，不宣称远程已恢复。

入口不可用或证据不足时

主机没电、物理断网或硬件开机条件不存在时，需要先在现场恢复这些基础条件。

从哪里开始

需要远程开机时先核对 BIOS、智能插座或有线 WoL 条件；日常用现有 verify-path-lite 检查服务，故障再明确运行 repair-stream。

需要准备什么

  • 想用智能插座还是有线 WoL 开机
  • 本次遇到开机、发现主机还是画面输入故障

从开始到拿到结果

  1. 1

    先选真正能开机的方式

    智能插座复电要主板支持来电启动；有线网络唤醒也需硬件与路由条件。选好后用真实关机试。

  2. 2

    电脑启动后查服务

    再看 Tailscale 和 Sunshine 是否运行、网络能否到达；服务在运行不等于登录前已经有画面。

  3. 3

    最后由手机验收

    Moonlight/Artemis 要真正发现、连接、看到画面并试输入；本轮没有完成时保持未知。

关键规则与设计选择

1

比较三种远程唤醒路线：优先实测“智能插座 + BIOS 来电自启（Restore on AC Power Loss）”；有线 Realtek 2.5GbE WoL（网络唤醒）是另一候选；纯无线 WoWLAN（无线局域网唤醒）不作为可靠默认。

2

坚决不默认开启 Windows 自动登录，守住物理主机的本地身份安全底线；串流服务本身具备系统级捕获能力。

3

编写 repair-stream.ps1 提供完全幂等的修复流程：自动重开 WLAN 网卡 IPv6 绑定、清理被污染的环境变量、拉起服务并固化 unattended 模式。

4

现役任务保持原触发与用户停用意图；注册失败明确报错，不自动创建另一种调度。历史每日23:30任务与未来实际安装分别回读。

本模块用到的名词

Restore on AC Power Loss（来电自动开机）
主板 BIOS 的电源管理功能；当交流电插头重新通电时，主板自动触发开机信号，无需人按开机按键。
幂等修复（Idempotent Repair）
无论运行一次还是多次，最终系统的状态都收敛到一致的健康配置，不产生重复副作用。

专业定义

它先讲清一个物理事实：电脑关机后，离线的 Tailscale 不能替你送入唤醒包；然后再把硬件开机方案与在线后的软件修复分开。

解决什么

解决离家后电脑关机无法唤醒、以及系统更新或网络代理异常导致的服务离线问题。

当前怎样实现

  • 硬件候选：确认主板支持并显式启用 Restore on AC Power Loss = Power On，再用智能插座做完整断电/上电循环；本轮未验证。
  • 网卡候选：插入有线网络，确认 Realtek 2.5GbE 的魔术包与关机网络唤醒，再从家内可达设备发包；本轮未验证。
  • 网络修改需精确选择ServiceProxy、AdapterIPv6或IPv6Policy；网卡需名称，服务代理重启Tailscale还需AllowNetworkRestart。保存原值与收据，失败逆序恢复，回滚失败不假定恢复默认即成功；任务注册失败不改投另一种触发。

执行流程

  1. 1

    候选冷启动：手机操作智能插座重新上电；只有 BIOS 已正确配置时主板才应启动。

  2. 2

    服务启动：Windows 起来后，Tailscale 与 Sunshine 的 Auto 配置应拉起服务；Running 不等于登录前画面可捕获。

  3. 3

    客户端验收：Moonlight/Artemis 需要真实发现、鉴权、进入画面并测试输入；本轮没有执行。

  4. 4

    日常维护：当前每日任务执行 verify-path-lite.ps1，记录服务、编码、无人值守与公网入口提示。

边界

  • 不强行修改或弱化 Windows 的系统登录密码与锁屏策略。
  • 修复脚本只清理有明确故障特征的固定代理端口环境变量，不随意删除用户的正常应用配置。

失败与恢复

智能插座通电后电脑未开机
现场确认 BIOS 的 AC 恢复选项、插座供电和主板行为；不要远程反复断电尝试。
Tailscale 服务无法启动
以管理员权限运行 repair-stream.ps1，检查服务依赖与网络协议绑定。
