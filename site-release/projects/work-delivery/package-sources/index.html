用途与实际影响

这项功能怎样使用

为什么需要它

每次重新建一套或顺手读同目录其他文件，会让事实和旧成品的版本分叉，也可能把无关资料带入结果。

举个实际例子

我可以说：“只用这份立项说明、评审纪要和执行计划建交付包，同目录其他文件不要读。”项目会固定这三份来源，并先交回覆盖范围和冲突。

最后我会得到什么

得到这件工作明确选定的资料版本和可继续的交付包；这一步还不是读完材料、确认事实或生成正式文件。

可以正式构建

目标和选定的2至5份文件都清楚且可读时，保存这一件工作的来源版本和初始判断，再告知下一步。保存来源不等于已经生成文件。

需要确认

文件数量、内容或标识不合要求时，在加入新事实前指出具体问题；同一工作已有交付包就从原包继续。

当前不可用

无法读文件或保存状态时保留原件。若超时发生在保存之后，先查看原包实际是否已建立，再继续后续步骤，避免重复新建。

从哪里开始

说清这件工作要交付什么，并点名持续使用的几份资料。

需要准备什么

  • 稳定的事项目标
  • 本人选定的 2 至 5 份来源
  • 本轮真正需要的格式

从开始到拿到结果

  1. 1

    先判断是否真的需要包

    AI 判断这件事是否依赖多份会变化的资料；一次性工作直接交付，确需建包才进入版本保存。

  2. 2

    保存本轮版本

    只保存选中的文件与来源关系，不顺带读取同目录资料；告诉我哪些已保存、哪些仍要分析。

  3. 3

    交回可接续的包

    说明本轮冻结了哪些版本、接下来要核对哪些事实。来源数量或身份不合要求时不留下半成品，改正选择后再开始。

本模块用到的名词

Package ID（交付包标识）
一个持续工作事项的稳定非空身份；不是每次运行重新生成的临时编号。
SourceSnapshot（来源快照）
一份已选资料在某次导入时的不可变版本；新版本通过 supersedes 关系接续。
Provider label（来源标签）
说明文件怎样进入；当前只是惰性追溯标签，不是账号连接器。
China defaults（中国工作默认值）
简体中文、Asia/Shanghai、YYYY-MM-DD、人民币 CNY、中国企业角色和完整 PRD 章节结构；它们影响事实解释与成品，而不是装饰性格式。

专业定义

交付包不是一个文件夹：它只在持续来源关系成立时出现，并只保存本人本次明确选择的 2–5 份资料。

解决什么

解决随机重建、来源范围失控、未选文件混入和一个事项出现两套状态的问题。

当前怎样实现

  • work-delivery.batch.v1 在写库前校验 package、sources、facts 和 build。
  • run_batch 的 store._transaction 一起提交新包、来源、事实和审阅；随后才检查第一次 15 秒时间门，超时不会回滚已经提交的事务。
  • Package 保存标题、目标、locale、timezone、currency 和 fact revision；默认值为 zh-CN、Asia/Shanghai 与 CNY。
  • SourceSnapshot 保存 source key、名称、provider label、版本、字节数、SHA-256 和 supersedes。
  • 文本支持 UTF-8 与 GB18030；CSV 后续由证据层计算行列。
  • 标准 OOXML 输出使用 YYYY-MM-DD 与中国企业常用角色/章节语义，兼顾 WPS 与 Microsoft Office。
  • 单个 SQLite 是唯一状态库，没有 watcher、后台同步或第二数据库。

边界

  • 只读本人明确选择的资料
  • 不扫描目录或账号
  • 不做任意Office输入解析
  • 不建立多人协作或云租户
  • 一次性文件不建包

失败与恢复

Package ID 已存在
任何新事实写入前拒绝，使用原 package 的更新入口。
来源少于 2 或多于 5
schema（数据结构） 校验失败，不创建数据库或半成品。
来源在读取中变化
导入失败；重新选择当前文件，不把两个版本拼成一个快照。
新包事务提交后的时间检查失败
返回时间失败，但该稳定 ID、来源和事实可能已持久化；先核对原包，再从已存在状态继续，不用新建命令重复导入。
