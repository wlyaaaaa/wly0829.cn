DevConfig Backup

重装电脑最难找回的往往不是软件，而是设置、密钥、安装线索和应用数据。这套备份选择这些难重建内容，配置打成带清单的包，体积大的微信数据另做文件级增量；本地、G盘、云端和H冷备分别报告结果。恢复前先看计划，失败保留上一次成功副本，不把旧系统全部灌回新电脑。

用途与结果

最快了解这个项目

为什么需要它

电脑真坏时，安装软件并不难，难的是找回散在几十个目录里的配置、密钥、环境变量、Wi-Fi、终端会话和应用数据。这个项目把采集、打包、热备、云端尝试、任务重建和微信回填顺序写清并自动化；恢复时仍要按版本、兼容性和现场状态选择材料，不能把旧系统原样倒进新系统。

举个实际例子

“准备重装了。先告诉我最近哪份配置包完整、微信备到哪里，还有什么没保住；不要现在覆盖任何东西。”系统会核对各层副本和清单，给出可以隔离恢复的材料与真实缺口；新机重新登录和官方微信验收仍另做。

最后我会得到什么

得到版本化配置包及其可携带哈希/清单、微信当前与前一成功副本、各层最近尝试和最后成功状态，以及明确的恢复计划和替换前回滚点。恢复入口能逐文件验真，但不会自动导入所有旧任务、恢复登录或替我确认微信历史。

正常时

只有一份配置或微信副本完整核对后才标为这一次成功；电脑本地、G 盘、云端和 H 盘分别展示自己的日期。

发现问题时

网络或云端目标有问题时保留已经完成的本地副本；微信恢复目标已有文件时先留可回退副本，绝不直接覆盖。

入口不可用或证据不足时

G 盘、云端账号或 H 盘暂不可用时，只把相应副本标成未完成；H 盘未解锁不触发冷拷贝，也不影响已验本地版本。

从哪里开始

双击本机 Open-BackupStatus.vbs 看图形状态，或用 Backup-Status.ps1 查看各介质；在已接入的 AI 对话中明确提出备份、微信原件保护或换机恢复，恢复默认先只读预检。

需要准备什么

  • 要保护或恢复的配置类别
  • 当前本地、G、H 或 Drive 可用情况
  • 恢复时的新机路径和目标是否已有文件

它负责

  • 按清单收难重建的设置和凭据，逐文件核对后生成可带走的配置包。
  • 分别把已完成配置包留在本机、G 盘和已登记的 Google Drive 目标，并各自确认是否真的到达。
  • 让微信原应用文件单独增量备份，源中真实删除在能完整读取时才跟随。
  • 恢复前先只读预览，明确执行后才解包或复制；已有目标先保留，应用能否打开再单独验。
  • 维护已经登记的 Windows 自动备份任务和启动方式，不把任务显示就绪当成文件已备好。

它不负责

  • 可重新下载安装的软件、插件和缓存不挤进配置包。
  • Docker 等程序的大型虚拟磁盘和运行中数据库不当作普通设置备份。
  • 这个项目只做本地、G 盘和云端；H 盘冷副本由 PCConfig 已有任务在解锁后处理。
  • 文件复制完整仍不等于微信官方客户端已登录并读到旧历史。
  • 真实备份包、聊天和密钥留在受保护介质，不进入公开代码仓库。

产品思想与设计核心

01

先保住难重建的东西

软件下载得回来，私人设置、密钥和会话往往不行。必需来源读不到时不发布看似完整的新包；包体大小随真正有用的资料变化，不为好看而删恢复材料。

02

本地、G 盘、云端和 H 盘各算各的

电脑本地最快取，G 盘是日常第二份，Google Drive 提供异地副本；H 盘平时不在线，只在本人解锁且条件满足时由 PCConfig 冷备任务复制。一层成功不让其他层自动变绿。

03

微信先形成独立副本再上传

默认从同一文件系统时点取得微信文件，再逐项核对；完整源中真正删除的文件才从备份中清理。文件齐全仍不证明微信数据库同一事务可用，最终要在官方客户端试读。

04

恢复先检查，再决定覆盖什么

先验备份包和文件清单，正式操作先解到独立目录；微信还须确认客户端关闭，目标已有内容要留回退副本。复制完仍需逐应用登录和核对。

系统从哪里采集配置，如何保障边界安全

按已经登记的来源清单收设置、系统导出和微信原应用文件，公开网页只解释材料类别与恢复结果，不读取私人正文。

01
电脑上的应用和 AI 工具设置

按清单收密钥、终端会话、编辑器和应用配置；排除可重下的插件与缓存。

形成带文件清单的配置包；恢复时按新系统实际路径选择回填，不整包覆盖。

02
Windows 环境与网络设置

保存需要重建的系统环境、精选自动任务、Wi-Fi 和终端连接设置。

换机时逐项核对兼容性再恢复；旧任务不整批导入。

03
已装软件和扩展的名称清单

导出可重新安装的软件与扩展清单，而不保存全部安装程序。

重装时知道要补哪些软件，减少包体而不丢失选择记录。

04
微信原应用文件

包括数据库、图片和音视频；最近一次来源回执与每层副本仍各有自己的日期。

形成可逐文件核对的本地副本，再由云端取已验版本；真正能否读回聊天须在微信客户端确认。

05
已登记的云端目标

只使用本次绑定的 Google Drive 位置和当前网络条件。

上传与文件比对各自回读；目标错了或网络断开就停，不自动换账号。

备份包可能含凭据和私人聊天，只留在可信副本位置；文件名排除和公开仓库检查不能代替逐值保护。

当前缺口

  • 本轮只读Backup-Status的零写入结果、G盘现存wechat-hot-last.json和PCConfig既有cold-last；没有重新压缩、创建VSS、全树重哈希、访问Drive或复制H。生产回执完成不等于网页再次验真所有载荷；配置Drive本次运行终态与云端实际对象仍未知。
  • 当前来源已经增加配置包、清单、同名漂移、微信源删除和恢复事务的回归；本轮未重跑源码全套。9 月 4 日 8 个测试及当时因微信运行而跳过的分支只是历史，不再用于宣称当前所有路径通过。
  • VSS捕获只保证文件系统时点的crash-consistent快照，不证明微信已经提交所有应用事务；手动无UseVss仍可能跨时刻读取。rclone check只核对远端与已选本地文件字节，真实客户端恢复必须另行验收。

完整执行流程

  1. 1
    每日定时采集与精选打包

    21:05 从声明清单生成独立候选，导出必要系统信息；检查必需源、最多三次稳定读取、文件哈希与结束时源集合，再经 7-Zip 测试，写入随包清单与成功回执。

  2. 2
    零流量本地与 G 盘热备落盘

    只有完整成功代才更新current.json；配置包复制到G后再验真，成功前保留旧代。微信独立Hot任务从VSS固定时点读取、核验后切换当前与前一成功集合；快照创建失败就报告失败，不静默降为活动源复制。

  3. 3
    夜间上传一个完整新代

    22:00 读取已成功且锁定的本地代，先发布日期包与附属校验文件、核对，再更新 latest 兼容别名和 current（当前状态） 指针。独立失败留住已有本地/G 成果，不能用本地完成提前代报云端成功。

  4. 4
    新机按兼容性选择回填

    先用 Restore-DevConfig 的默认只读模式核验 SHA-256、回执、清单和解包路径，显式执行后只落入独立目标并逐文件核对；账户、注册表、任务和 home/AppData 回填仍按 PCConfig 与新系统兼容性选择。

  5. 5
    微信数据预检与安全接管

    运行 Restore-WeChat.ps1 只读检查，确认官方微信关闭后，显式执行回填；若目标已有数据自动备份为 .pre-restore-* 回滚目录，最后由人工启动微信确认历史。

本页用到的名词

需要核对专业含义时，可以在这里查看它在 DevConfig Backup 项目中的具体用法。

rclone（云同步工具）
支持多云存储协议的命令行工具。配置按成功代发布包和附属校验文件；微信从已验本地集合做内容增量并在同一范围内核对删除。
robocopy（Windows 健壮文件复制工具）
Windows 文件复制工具，本项目用于受控采集与微信候选复制；单独的复制退出码不替代随后全树比对或成功指针。
checksum（校验和）
基于文件内容的哈希计算值；rclone 通过比对内容哈希决定是否传输，避免单纯依赖修改时间导致漏传或重复上传。
WAL（Write-Ahead Logging，预写式日志）
SQLite 可能把尚未合并进主库的已提交事务放在 -wal 文件里；备份规则不应过滤它，但运行中逐文件复制仍可能跨越不同写入时刻。
SHM（Shared Memory，共享内存索引）
SQLite 在 WAL 模式下使用的共享内存索引文件；本项目不将它排除，但是否可由客户端使用仍需恢复验收。
fail-closed（失败关闭）
当环境出现不可预期故障（如 binding 文件损坏、代理不可达、目标已存在非空文件）时，系统立即安全退出并阻断写入，绝不盲目降级。
binding（远端别名绑定）
保存在本地非秘密 state 中的 rclone remote 别名映射；确保云端同步只传向用户指定的准确云盘，严禁 fallback（降级）到默认第一个远端。
BitLocker（Windows 驱动器加密）
Windows 原生全盘加密技术；本项目冷备介质 H 盘默认处于锁定状态，防止物理介质丢失造成敏感凭据泄露。
Task Scheduler（Windows 任务计划程序）
Windows 系统内置的定时任务管理服务；当前驱动四个常规备份任务。首次云端补齐监控是独立临时任务，当前已禁用。

系统里实际有什么

下面是当前产品组件，不是概念分类。每一项都对应真实文件、入口或验证链。

01
Backup-DevConfig.ps1

配置采集、系统现导出、清单生成、7z 压缩打包与分层分发（Local/Hot/Drive）。

兼容 PowerShell 5.1/7，支持 Tier 和零写入 Plan；独立候选经稳定文件采集、结束集合检查、7z 测试与随包成功回执后，才能原子发布 current.json。失败不替换旧成功代。

02
sources.psd1

配置采集与排除规则的数据驱动清单，定义散件、各工具目录、避坑黑名单与计划任务白名单。

受限PowerShell数据文件，纯声明式数组与哈希表；新版额外排除Codex瞬态sandbox-bin和aicli-background-children协调租约，避免把不可恢复的活动状态当作配置备份。

03
Backup-WeChat.ps1

微信原应用数据的独立文件级增量与可信原件保留集合收敛，支持 Hot、Local、Drive。

默认隐藏Hot入口带-UseVss，从受约束创建的VSS时点副本捕获；只清理本次创建的快照。手动无UseVss仍是live_source。候选全树SHA-256通过后保留前一成功代；回执分别记录capture_consistency、application_consistency与application_recovery，Drive仍只消费已验本地代。

04
Restore-WeChat.ps1

微信原生目录的灾难恢复总线，提供默认只读预检、目标非空回滚保护与人工在场状态标记。

多步安全校验，支持 -Execute 与 -ReplaceExisting，返回 COPY_COMPLETE_AWAITING_HUMAN_ACCEPTANCE。

05
Initialize-BackupNetwork.ps1

为无窗口计划任务提供网络代理自动继承与 rclone 远端绑定安全解析。

读取注册表系统代理配置，解析 rclone-remote-binding.json，提供 fail-closed 安全保障。

06
Setup-ScheduledTasks.ps1

在 Windows Task Scheduler 幂等注册 4 项常规备份任务；临时小时监控由独立安装脚本管理。

四个任务的Action为wscript.exe，隐藏VBS优先PowerShell 7、缺失才回退5.1。微信Hot定义使用当前交互用户Highest以创建VSS，其余为Limited；注册可只更新选定已登记任务并保留原时序、设置与暂停意图。旧临时监控仍停用。

07
Backup-Status.ps1

零写入查看配置包、微信、各层生产回执与任务；可选明确 LiveDrive 才查询云端元数据。

devconfig.backup-status.v2 区分最后成功、最近尝试、已由生产者验真但未在状态查询重哈希的载荷。Backup-Plan 提供零写入差分，现有控制窗口定期展示状态，不另建常驻服务。

08
tests/ 自动化合同套件

检查 Git 文件候选、Docker allowlist、本仓库 H 目标、任务代理/事务注册、rclone 内容变化 fixture 和微信恢复保护。

当前测试覆盖候选、必需源、同名漂移、清单、保留、微信事务与恢复等边界；9 月 4 日 8 脚本仅为历史基线，本轮没有重新运行来源全套。

09
Restore-DevConfig.ps1 / Backup-Plan.ps1

先以零写入方式解释包是否完整、会恢复哪些内容，再明确执行隔离恢复。

成功回执与外部/内部清单绑定；路径和包哈希校验通过后，执行才解包并全树回验，非空目标必须明确替换且保留前像。系统导入仍归 PCConfig。
