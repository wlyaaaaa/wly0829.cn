点下去之后会发生什么 检查并修复上网问题 1 重新读一遍设置，列出要改的几项和原因 2 你点“开始修复”后再核一遍：设置没被别人改过、那个代理也没重新开起来；有变化就停 3 先把原样加密存在本机，再一项一项改，每改一项读回来对一下 4 改到一半失败，把这次已经改的倒着改回去 5 通知 Windows 用新设置，再分别测国内、海外和 AI 服务，区分 IPv4、IPv6 与正在监听的 HTTP 代理；“设置改好了”和“网页打得开”分两行报 关闭代理，恢复普通上网 1 先请它正常退出，再停它的辅助服务（代理程序自带的 Windows 后台服务，打开代理时要用它，它本身不代理上网；先停掉，免得它把代理重新拉起来） 2 等 4 秒还没退，只结束刚才核对过身份的那几个进程 3 代理退干净后，先把原来在跑的辅助服务开回来，再连查几次、确认代理没有自己又起来，下次手动开代理才不会失败 4 确认端口没被别的程序接走，才清掉指向它的设置，并刷新域名缓存 5 没退干净或又冒出来，就不说“已关闭” 出事怎么办 修完不对劲：点首页的“恢复上次修改”，只改回仍是这次改动结果的设置，别人后来又改过的保留；已结束的程序不会被重新打开。 上次修改没恢复完：新的修改会被挡住，先恢复。 还是上不了网：别反复点修复。窗口会分开说是域名解析失败还是网页连不上；可以把“复制脱敏诊断”的内容交给 AI 看。 关掉代理后，原来要靠代理才打得开的网站仍然打不开，这是正常的；手机和副机经这台电脑用代理的入口也会一起停（入口归电脑配置与恢复管）。 没有自动提醒：失败只显示在窗口里，出问题直接跟 AI 说。

怎么搭的、为什么这样设计 一个 PowerShell 小程序 用 PowerShell 写，界面是 Windows 自己的 WPF 窗口：首页、检查详情、维护工具各一个。约 2,200 行程序、1,900 行测试。Windows 自带的 PowerShell 5.1 和 PowerShell 7 都能跑，装了 7 就用 7。检查在后台跑，窗口不卡，进度条上的字就是正在做的那一步。 不用 AI 模型 判断全靠本机规则：读注册表、端口监听表、路由表、进程和服务列表。会主动连外网的只有网页测试（国内、海外、AI 服务，分 IPv4、IPv6 和设置里正在监听的 HTTP 代理）和比较联网出口（ipify），都在你点了按钮之后；打开窗口的检查不连外网。 原样存在哪 改之前，原值用 Windows 当前用户的加密（DPAPI）存进 %LOCALAPPDATA%\ProxyClean\last-operation.dpapi，只有这台电脑、这个 Windows 账户能解开。它只管撤销最近这一次，不是备份，换电脑不带走。 只清掉，不改成指向别的代理 失效的设置只清成直连，从不改成指向另一个代理端口：那个端口哪天一关，设置又成了新的残留。6 月为这个断过网，见演进。 要管理员权限的 删默认路线、刷新或重启网卡、改 IPv6、结束以系统身份运行的代理进程。会弹一次 Windows 授权，新窗口用同一个账户、带着你刚才的选择接着做，不用再确认一遍。 特意不碰的 自动代理脚本（PAC）、Windows 服务代理、系统级变量、NO_PROXY、Docker 和各个应用自己的代理设置、Tailscale 和虚拟机网卡。普通修复也不刷新域名缓存、不重启网卡、不换 DNS 服务器。 诊断不落盘 默认不写日志。“复制脱敏诊断”不带代理密码、公网 IP 和设置原值；远程代理只写成“远程”。 277 项测试怎么测 用临时注册表子键、临时 Git 配置和假进程、假服务，不碰正在用的代理。9 月 25 日两种 PowerShell 都全过；真的关掉正在用的开机自启的那个代理程序再打开，还没测过。
亮点 认代理靠进程关系，不靠端口表 麻烦：代理的端口会变。6 月的脚本里写死“7892 是手动开的那个代理程序、7897 是开机自启的那个代理程序、7890 是另一家的代理程序”，现在开机自启的那个代理程序用 18091、另一家的代理程序的旧快捷方式写的是 18090，手动开的那个代理程序内核的监听端口每次启动都可能不同；通用代理内核，从名字也看不出是谁开的。按旧表认，就会把 A 的端口当成 B。 解法：每次打开都现查哪个程序在本机哪个端口上听，再顺着进程的父子关系往上找：内核是谁启动的就归谁。名字像但不是它启动的，不归过去。首页因此能直接说“Windows 当前代理：手动开的那个代理程序”。 打开只看，不动手 麻烦：第一版双击“一键修复网络”就要管理员权限，马上改路线、代理和变量；有一次删路线时把 WLAN 的默认路线也删了，网彻底断掉。修网的工具反而断了网。 解法：现在打开窗口只读本机：不连外网、不改设置、不要管理员权限，看完没问题直接关掉就行。
