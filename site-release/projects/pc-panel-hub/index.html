用途与结果

最快了解这个项目

为什么需要它

主屏要留给工作和游戏，两块实体副屏应让我抬眼看到电脑状态与真正需要注意的事。只看到程序在运行，机箱屏却可能已冻住；换机沿用旧端口或显示器编号还可能把画面送错。项目分别核对数据来源、两块屏的显示和故障后恢复，最后仍以实体画面为准。

举个实际例子

我可以说：“主屏只留给工作和游戏，电脑状态放到机箱屏上。”温度、负载、流畅度、网络和磁盘会持续排在 480×1920 的竖屏里；没开游戏时明确显示正在等待帧，不会伪造一个 0 FPS。最后我抬眼就能看见电脑现在忙不忙、热不热，主屏不用常驻监控窗口。

最后我会得到什么

抬眼能看见温度、负载、帧表现、网络和磁盘，另一块屏只在有意义的事件出现时提醒；还能直接清场或切换时钟。指标缺失、串口刷新、窗口归属和实体画面各自给出状态，软件演示不能代替肉眼确认屏幕真的更新。

正常时

机箱屏持续更新真实指标，水冷屏把事件放在正确位置；软件状态和本人看到的实体画面分别确认。

发现问题时

读数过期、画面冻结、浮层跑到错屏或壁纸停动时，只修对应部分，保留失败原因，不反复重启整台电脑。

入口不可用或证据不足时

设备或显示器无法唯一确认、数据来源缺失或桌面未就绪时，停下相应显示与恢复，不抢端口，也不拿旧预览图说现在正常。

从哪里开始

日常直接看机箱竖屏和水冷 HS2 副屏；HS2 的 Win+F1 清理可清卡片、Win+F2 切换时钟。新机安装与故障修复则在已接入项目的本机 AI 对话中点名设备。

需要准备什么

  • 要看的指标或通知
  • 具体是哪块屏和当前症状
  • 安装时的本机串口、网卡、天气及显示器身份

从开始到拿到结果

  1. 1
    认出两块屏各自的工作

    系统先确认机箱竖屏和水冷副屏当前绑定，避免把指标或通知送错显示器。

  2. 2
    从本机来源取值

    软件按各自来源读取指标或事件，过期、歧义与不可用明确标注。

  3. 3
    显示并受控刷新

    竖屏按已验串口发送画面，HS2 浮层只落在目标显示器并限制卡片数量。

  4. 4
    以实体结果验收

    启动、睡眠或设备重枚举后核对真实屏幕；软件预览或发送成功不能替代肉眼看到更新。

它负责

  • 从本机硬件、网络、磁盘、天气与帧率来源取得当前数值，并标出过期或估算。
  • 把持续状态清楚地排在机箱竖屏上，长名字和没有游戏帧时也能看懂。
  • 让机箱屏按实际设备稳定刷新，画面冻结时重建完整画面。
  • 在水冷副屏上放媒体、手机、任务与必要告警，不把它变成第二块监控墙。
  • 保持事件卡片透明地叠在现有背景上；显示器变动后只对符合条件的原动态壁纸做一次重绑。
  • Win+F1 清理可清卡片，Win+F2 切换并记住时钟；长任务在同一张卡上更新进度。
  • 协调登录、睡眠、唤醒、关机和屏幕重新连接时两块屏的正确状态。
  • 防止两个程序同时写机箱屏，并根据真实画面与程序状态找出静默冻结。
  • 换机从干净源码和合法厂商文件重建，每台电脑重新确认端口、网卡、天气和显示器。
  • 把软件演示、主机发送和本人看到的实体像素分别记录，不互相顶替。

它不负责

  • 它负责眼前两块屏的显示，不替 TimeAudit 保存长期电脑历史。
  • 不是多机监控、远程管理、通用通知仓库或壁纸制作软件。
  • 主机说“已发送”、程序在跑或任务正常，不等于实体屏实际更新。
  • 普通故障恢复不重置整套 USB 设备，不改主屏或动态壁纸设置。
  • 特定设备的刷新方式不能承诺适用于所有机箱屏。
  • 厂商程序、真实天气位置、物理网卡和设备绑定留在本机，不进公开源码包。
  • 换机时不照搬旧端口或显示器编号，必须在新电脑重新认设备。
  • 验证码、密码和真正的私人通知正文不放到公开页面；普通设备身份和错误信息按实际用途说明。

产品思想与设计核心

01

两块屏承担不同工作

机箱屏负责持续状态，水冷屏负责低频事件；同一信息不在两块屏重复堆叠。

02

先保证一眼可读，再显示更多

信息层级、字号、间距和状态含义优先于指标数量，副屏不能变成缩小版监控墙。

03

有效空状态也要被设计

没有游戏帧、没有通知和没有告警都是真实状态，不制造零值、空卡或假异常。

04

每个数字说明从哪来、何时更新

过期、估算和不知道的值不能画成当前实测；有疑问时能找到对应来源。

05

实体像素才是最终验收

进程、日志、发送成功和心跳只能证明主机侧，不能替代对真实屏幕持续更新的观察。

06

只恢复出问题的那一块

同一机箱屏只有一个发送程序；屏冻了修发送链，壁纸停动只在确认正确显示器后让已有场景重新绑定一次，不靠整机重启碰运气。

07

动态壁纸与事件浮层互不绑架

浮层透明、低频且可退出；找不到精确副屏时绝不回退到主屏。

08

公开源码不等于换机已经装好

代码和无真实值示例可以公开；厂商运行文件、天气位置、网卡与两块屏的绑定要在每台电脑合法取得并重新确认。

09

人在屏前可以立即收束信息

Win+F1 只清已结束或短时内容，活动媒体、游戏、任务、传输、来电和硬件告警继续保留；Win+F2 只切换时钟并记住选择。

10

普通窗口回主屏，壁纸仍归壁纸

显示器变化后，只处理确认属于普通应用的窗口；泡泡、壁纸和副屏仪表由各自程序负责，不为修窗口误关它们。

完整执行流程

  1. 1
    先建立本机安装态

    从 clean clone 补齐合法取得的厂商运行文件，把无真实值示例复制为 ignored（Git 忽略）的 config.json，重新确认串口、物理公网接口、天气与 HS2 拓扑，再让 runtime（运行环境） check 决定能否安装启动任务。

  2. 2
    先从真实来源采样

    metrics agent（指标代理）按来源读取硬件、网络、磁盘、天气、FPS 和前台信息；进程排行独立每 3 秒采样，避免拖住 1 秒主循环。

  3. 3
    给每个值保留时效与可信度

    来源不可达、陈旧或歧义时使用空值、旧快照或失败状态，不把 0 冒充真实传感器值。

  4. 4
    渲染机箱屏

    C# 渲染器把 snapshot（快照）变成 480×1920 位图；网络、磁盘、FPS 和长名称都按真实版面有界显示。

  5. 5
    按当前刷新合同发送

    启动先建立 command 200 全帧基线，再以 command 204 增量维持 1 Hz；60、120、180 和每 900 帧重开会话并补全帧。

  6. 6
    在动态壁纸上独立组织和控制 HS2 事件

    底层背景由动态壁纸应用负责；透明浮层从本地媒体、命名管道任务、Windows 通知和硬件状态形成最多六张卡。Win+F1 清理可清内容并抑制同一中继内容复活，Win+F2 持久切换时钟。

  7. 7
    由一个看门狗协调电源和恢复

    看门狗拥有启动、睡眠、关机和恢复；先证明旧串口写入者退出。显示器身份或主屏归属变化时先等待 30 秒并确认当前显示路径绑定健康，再通过当前用户 shell 对既有 Wallpaper Engine 做一次 stop/play，不修改拓扑或壁纸设置。

  8. 8
    分层验收并诚实标注

    源码、测试、安装、运行、演示、协议与实体观察分别记录；9月7日TURZX软件启停、异常退出恢复已实测，本人随后确认实体屏正常刷新。HS2动态壁纸仍只沿用8月30日本人历史确认，睡眠、断电和拓扑重绑没有借这次恢复升级为通过。

本页用到的名词

需要核对专业含义时，可以在这里查看它在 PC Panel Hub 项目中的具体用法。

TURZX case panel（TURZX 机箱屏）
480×1920 USB 竖屏，负责高密度、持续刷新的硬件与系统状态。
HS2 Crystal Overlay（HS2 水晶浮层）
2288×1048 曲面 OLED 上的透明事件层，只在真实内容存在时创建卡片。
dynamic wallpaper layer（动态壁纸层）
由独立动态壁纸应用绘制的底层画面；浮层只叠加信息。真实拓扑变化后看门狗只调用既有控制客户端重绑渲染，不修改场景或设置；应用退出时可由 Windows 静态背景接替。
snapshot（快照）
某一时刻经过来源和新鲜度处理的本机指标集合，不是长期历史库。
trust score（可信度分数）
说明当前快照有多少来源仍新鲜、可解释；不是安全评分。
command 200 / 204（全帧 / 增量命令）
前者发送完整画面并已有本机协议验证；后者只发差异，延迟更低但没有设备 ACK。
Hybrid refresh（混合刷新）
先用全帧建立基线，再用增量保持 1 Hz，并按固定边界重开会话和补全帧。
heartbeat（心跳）
记录主机最近一次真实发送尝试、节拍和恢复基线的无私人正文状态文件。
one writer（唯一写入者）
同一时刻只能有一个 stream 进程拥有目标串口，避免交错写入和错误恢复。
circuit breaker（熔断）
连续失败后先冷却并证明旧进程已释放资源，再创建一次新链路。
device ACK（设备确认）
设备明确回报已接收并显示画面；当前协议没有这样的可信回执。
physical acceptance（实体观察验收）
直接观察真实副屏刷新、位置、睡眠和恢复；软件日志或截图不能替代。
clean clone（干净克隆）
只从公开仓库取得被 Git 跟踪的源码、文档和无真实值示例，不携带旧机器的运行输出或绑定。
local installation state（本机安装态）
合法取得的厂商运行文件、私有 config、设备绑定、计划任务和当前机器验收共同组成的可重建状态。
named pipe（命名管道）
同一台 Windows 机器上让任务生产者把有界 JSON 更新交给 HS2 浮层的进程间通道。
lease（租约）
活动任务必须周期续报的最长保留时间；默认五分钟，生产者异常退出后卡片会自动收起。
narrow fallback hook（窄范围回退钩子）
只有 Win+F1 被其他程序占用时启用，只接管真实键盘的 Win+F1 且要求不带 Ctrl/Alt，不吞掉注入按键或其他冲突组合。
topology fingerprint（拓扑指纹）
只由当前活动显示器设备名与唯一主屏标志组成；分辨率、位置和 HDR 变化不在指纹内，因此不会误触发壁纸重绑。
render rebind（渲染重绑）
通过当前用户桌面外壳对同一安装目录下的 wallpaper32.exe 依次发送 stop 与 play，让既有场景重新绑定当前显示面；不启动新的常驻渲染器。

系统里实际有什么

下面是当前产品组件，不是概念分类。每一项都对应真实文件、入口或验证链。

01
公开源码包与 private（私有） config（私有配置）

把可公开重建的源码/示例与每台机器的串口、物理网卡、天气、厂商运行文件和 HS2 拓扑绑定分开。

公开 ZIP 只允许 config.example.json；config.json、vendor EXE/DLL、out、bin、obj 与设备绑定保持在 Git 外。

02
check-runtime.ps1 + startup installer（启动安装器）

在注册登录启动任务前检查 Python、C# 编译器、RJCP、TURZX 运行文件和 stack 入口。

缺项即拒绝安装；通过后用 wscript 无窗口父适配器为当前交互用户注册 Highest 任务，并禁用旧并行 Owner。

03
metrics_agent.py

提供 127.0.0.1:18765/snapshot 的硬件、网络、磁盘、天气、FPS、前台和健康快照。

主指标目标 1 秒；物理公网出口歧义时失败关闭，虚拟接口不重复计数。

04
top_processes_helper.py

独立采集进程 CPU / RAM 排行。

约 3 秒节拍写有界结果，不阻塞主 snapshot 请求。

05
TURZX.SideScreen.Stream

取得快照、渲染 480×1920 位图并发送到机箱屏。

完整 HTTP body 有墙钟 deadline（截止时间）；失败时可复用最后一份好快照，PNG 预览异步低优先级生成。

06
command 200 / 204 transport（传输层）

在完整基线、1 Hz 增量和周期恢复之间保持明确合同。

全帧 10 秒上限、增量 900 ms 上限；首次发送失败即退出给看门狗重建。

07
HS2.CrystalOverlay.Core

拥有事件、优先级、寿命、去重、布局和告警规则。

不依赖显示器，可用合成数据做确定性单元测试。

08
HS2.CrystalOverlay

在唯一非主 2288×1048 显示器上创建透明、鼠标穿透的事件浮层。

单实例；找不到精确目标时不回退到主屏。

09
GlobalHotkeyCoordinator + GlanceSource

提供 Win+F1 清场与 Win+F2 时钟开关。

F1 被占用时只启用精确物理组合的窄回退；时钟状态写入应用本地设置并在重启后继续。

10
Publish-HS2Task.ps1 + task pipe（任务管道）

让复制、下载、渲染或安装脚本显式发布标题、详情、进度、预计剩余和结束状态。

命名管道逐条接收有界 JSON；同 Id 更新，默认五分钟租约，静默生产者到期自动清卡。

11
动态壁纸 / Windows 背景层

在 HS2 浮层下方提供连续背景，动态壁纸应用退出时由 Windows 当前静态背景降级。

这是独立显示内容提供者；PC Panel Hub 不修改壁纸资产或设置，也不把背景资源打进仓库。显示拓扑真实变化后只通过既有 wallpaper32 控制客户端请求一次渲染重绑。

12
StartSideScreenWatchdog.ps1

统一管理 stream、HS2、电源事件、串口所有权、模式保留、活动显示拓扑观察和故障恢复。

串口链连续三次失败进入 30 秒熔断；壁纸链使用 15 秒探测、30 秒稳定、900 秒冷却与一次 stop/play 分派，不因一次失败退出长期 Owner 或形成循环重启。

13
Windows startup task（启动任务）

在交互用户登录后以Highest运行无可见控制台的长期看门狗；看门狗自己崩溃时也能接回。

同一wscript入口同步等watchdog退出，非0退出等30秒再启动，0退出则结束；IncludeWatchdog明确停止也结束该入口，旧resume任务继续禁用，不增加并行恢复者。

14
纯软件测试与 demo

验证指标口径、渲染、HTTP、节拍、浮层布局、恢复合同和公开发布边界。

fixture 值和 demo 场景不触碰设备，也不会被标成实体屏证据。

7 层证据分别证明什么

Source（源码）

能证明：9月9日PUBLIC（公开） main=9eda10a7bbf0dde8a5de8268a6633b2d6ed1a925，远端同值；保留发送、隐藏入口恢复及两屏原能力，新增普通窗口从MTT1337回到PHLC34B，以及窗口仍归主屏但可见框跨入VDD时的约束。TestPowerWatchdog纯软件回归通过。

不能证明：新源码和软件回归不证明当前窗口搬移、显示拓扑、串流、睡眠或实体像素。

Tests（测试）

能证明：a4d8e22完整原生检查通过：指标87、天气8，以及渲染、HTTP、电源、快捷方式、刷新默认值、节拍、运行可靠性、4个真实VBS行为和公开ZIP；保留HDR-only、唯一MTT/Root\MttVDD、三屏健康、稳定/冷却等原有合同。生产流存在时跳过TestVideoStream，另做精确生产链恢复测试。

不能证明：纯软件用例不证明真实显示拓扑变化、wallpaper32 stop/play、HS2事件或像素级确认。

Installation contract（安装合同）

能证明：公开ZIP可解包且不带厂商文件或私有绑定；本机既有任务已重新启动，并实际执行新VBS异常退出恢复。PCConfig安装powershell.exe单个RTSS应用配置，官方SDK回读AppDetectionLevel=0。

不能证明：配置回读不证明已驻留DLL被卸载，也不保证原生崩溃永不复发；另一台电脑、系统重装、新硬件或断电后的自然启动仍未验收。

Runtime（运行）

能证明：9月7日显式停止观察34.69秒不反弹；软件重新启动31.06秒恢复；强制结束watchdog后63.33秒由同一VBS接回，旧sender退出。23:24心跳285/285、failed=0、period=1010ms、唯一sender存在，HS2浮层0、wallpaper64为1。

不能证明：强制结束测试没有复现原RTSSHooks64.dll崩溃或Device Error；这不是Windows重启、断电、睡眠、壁纸拓扑重绑或HS2实体恢复测试。

Demo / render（演示 / 渲染）

能证明：软件能在固定合成数据上生成机箱屏版面，并能用 HS2 场景检查六卡、缺项、重排和长文本。

不能证明：截图来自实体硬件或当前机器现场。

Protocol observation（协议观察）

能证明：command 200 全帧和 command 123 亮度路径有本机验证；混合刷新有主机侧有界实现。

不能证明：command 204 是厂商保证的通用协议或有设备 ACK。

Physical / Owner observation（实体 / 本人现场观察）

能证明：9月7日恢复测试后，本人直接回答“能看到，已正常刷新”，确认TURZX实体屏上的时间或数字正常变化；8月30日HS2显示缓冲区同画面曾由本人确认在实体屏生效，仍保留为历史。

不能证明：本人当前观察不提供设备逐像素ACK，不证明长期无故障、睡眠唤醒、断电开机、HS2当前像素或壁纸拓扑重绑。
