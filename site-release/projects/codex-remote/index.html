Codex Remote

Codex Remote 曾让手机浏览器继续电脑上同一个 Codex Desktop 任务：查看进展、命令、文件改动与父子智能体，处理审批、补充要求、停止回复或排队下一件事。它不传输桌面画面，也不另开聊天；可回退运行代和共享任务设计均保留，但 Windows 接管未达到可重复恢复要求，当前控制入口不可用且冻结，本页只供理解历史产品与实现。

用途与结果

最快了解这个项目

为什么需要它

过去，长任务在电脑上继续运行时，手机需要看同一个任务、处理审批和补充要求，不能靠另开聊天复制历史。Codex Remote 曾为此提供手机控制设计；当前控制入口已冻结且不可用，页面只帮助理解历史功能和证据。

举个实际例子

我现在若问：“电脑上的 Codex 任务还在跑，能不能用手机接着看，再补一句要求？”答案必须先说清：不能。Codex Remote 当前冻结且不可用；这张筛选展示只能让我看懂它过去怎样让手机和电脑共享同一个任务，以及当时留下了哪些证据，不会连接、探测或发送任何东西。

最后我会得到什么

现在能得到的是按版本和日期说明的历史产品参考：曾怎样查看同一任务、子任务、审批、文件和更新，以及哪些步骤真正验收过。当前不能登录、连接或执行 Remote。

正常时

历史证据说明手机与电脑曾共享同一任务并完成部分真实操作；今天只可按原版本和日期阅读这些结果。

发现问题时

旧 Windows 接管方案无法重复、可靠地恢复，所以当前不运行它的重连、补偿或更新流程。

入口不可用或证据不足时

Codex Remote 当前冻结且不可用。只能阅读获准的历史源码、文档和图片；恢复须由本人另行明确启动独立项目并重新做真实验收。

它负责

  • 历史上让手机查看并继续电脑上的同一任务，而不是复制一份新聊天。
  • 展示运行时允许公开的回复、进度、工具和文件活动。
  • 把运行中、已结束或归档的子任务放在同一父子结构里查看。
  • 在手机处理真实提供的审批，并把当前轮补充、停止和下一轮草稿分开。
  • 从实际运行时读取可选模型、权限和额度，不用演示值充当当前状态。
  • 分开处理登记项目内的任务和本人电脑文件，覆盖与删除各有明确选择。
  • 通过已认证的手机入口接入本机任务，不把底层控制服务直接公开。
  • 历史更新方案先登记新版本、再切换兼容组件，失败时保留恢复依据。
  • 断线或操作结果不明时先核对，不自动重复发送或执行。

它不负责

  • 不提供远程桌面画面，也不把电脑命令行或底层任务服务直接放到公网。
  • 不显示模型隐藏的完整思考，只展示运行时允许公开的内容。
  • 不会在正在生成的一轮中途换模型或权限；选择留给下一轮。
  • 手机待发草稿未被同一任务接受前，不算电脑任务记录。
  • 子任务只读查看；补充要求回到可控制的父任务转交。
  • 新版本已登记不等于已运行，兼容界面更新也不自动重启底层电脑任务。
  • 审批选项、模型目录和额度未知时就显示未知，不制造可点的假按钮。
  • 公开资料不含密码、会话令牌或已确认敏感的私人值。

产品思想与设计核心

01

冻结事实先于历史能力

每个直达模块都保留当前不可用边界。历史功能、测试或一次成功不能授权状态探测、安装或重启；恢复另作明确项目和新验收。

02

两端共享同一个任务事实

手机与 Desktop 使用同一任务和轮次，不复制聊天历史制造看似同步的第二份任务。

03

移动端只保留真正需要的控制

优先查看、审批、引导、停止、排队和回读，不把整套桌面界面机械缩小到手机。

04

当前轮和下一轮严格分开

当前回复怎样继续、下一轮换什么模型和做什么是两种状态，不能热切换出无法解释的中间结果。

05

界面只显示运行时真实提供的值

模型、审批选项、额度、上下文和工具状态不写死，也不为了界面完整补造按钮。

06

待发队列不是任务记录

Web草稿只有真正派发并被同一任务接受后，才成为任务的一部分。

07

项目任务和所有者文件是两条边界

任务工作区受项目身份约束，文件工作台使用 Windows 所有者能力；两者不能互相冒充权限。

08

公网只看到产品接口

认证、同源和确认边界挡在前面，底层任务协议、回环服务与敏感载荷留在本机。

09

结果不清就先回读，不自动重放

断线、重复提交或状态不确定时保留草稿和幂等身份，先确认权威状态再决定是否继续。

10

子智能体是任务树，不是会消失的通知

运行、等待、完成和失败都留在父子层级与历史中；手机可进入只读查看，补充要求仍回到可控制的父任务。

11

新版本准备好，不等于电脑已经换过去

新构建先成为可检查、可撤回的候选；手机页面可以在不打断任务时更新，底层任务连接变化必须另外明确交接。

12

通用智能来自运行时，Remote 负责同任务控制

理解、推理、工具和代码执行来自已集成的 AI/智能体运行时；Codex Remote 负责把同一任务、审批、文件和恢复语义带到手机，不冒充基础智能的作者。

当前缺口

  • 历史真实链路与产品证据已形成，但当前控制入口不可用且冻结；页面与本轮任务没有访问任何 Remote 运行态。
  • 恢复不是普通状态检查或重启：必须由用户明确启动独立恢复项目，重新决定实现并完成 fresh E2E（端到端验证）；静态证据、旧制品和历史成功都不能改变当前不可用状态。
  • v0.1.5 的测试和历史真实验收只证明对应版本与场景，不自动覆盖当前 Desktop、Codex、网络或浏览器版本。
  • 当前 main 最新 CI 未闭合；它不推翻 v0.1.5 的历史正式证据，但也不能从旧 release 推导当前 main 已通过。
  • 本轮没有读取已安装 runtime-current.json、Supervisor 或 Sidecar（认证侧车服务） 状态，也没有执行安装、滚动更新、回滚、显式 handoff 或无人值守接管验收。
  • 产品设计要求从子任务返回父任务并恢复阅读位置；现有源码与浏览器场景证明可进入子任务和返回父任务，但本轮没有取得精确滚动位置恢复的独立验收结果。
  • 公开合成截图证明 UI 与状态合同，不证明真实任务执行；历史真实截图也只代表拍摄时刻。
  • 文件工作台继承单一 Windows 所有者权限，不提供多用户隔离，也不能抵御同一 Windows 用户下的恶意软件。

完整执行流程

  1. 1
    先确认当前冻结，不进入操作

    当前控制入口不可用且冻结：不调用 Status、Open、Close、重启、登记、回滚、dispatcher（分派器）、计划任务、Sidecar（认证侧车）、Broker（共享代理）或公网端点，也不走替代启动路径。仅可只读查看获准的具名源码、文档、测试定义与历史图片；恢复须由用户另行明确启动独立项目并重新完成端到端验收。 后续条目只说明历史实现的职责与次序，不是现行执行步骤。

  2. 2
    安装先生成可回退运行代

    构建与检查通过后，注册器把 Web、Sidecar（认证侧车服务）、Broker（代理服务） 和 Windows 脚本复制到内容寻址目录，验证 manifest（清单），再原子记录 current（当前状态）/previous；登记本身不打开 Remote。

  3. 3
    浏览器先通过认证入口

    手机只访问 HTTPS 反向代理后的 Sidecar（认证侧车服务）；登录、会话、Origin（请求来源）、CSRF 与限速在产品 API 之前生效。

  4. 4
    选择同一个任务或创建有界任务

    已有任务按 threadId（任务标识） 恢复；新任务只能使用本机登记项目或隔离无项目根。

  5. 5
    Broker（代理服务） 完成 Desktop 订阅屏障

    需要新首轮时，先让任务壳持久化并确认 Desktop 已 resume；没有 Desktop 证据就拒绝 turn/start。

  6. 6
    实时投影公开任务事件

    Sidecar（认证侧车服务） 将正文、公开摘要、工具、文件、审批、计划和子智能体投影为浏览器能读的产品状态。

  7. 7
    进入子任务后仍沿父子关系返回

    手机从父任务打开缩进列表，进入任一仍有记录的子任务只读查看消息、工具和文件；补充要求回到父任务转交，历史不完整时明确提示。

  8. 8
    用户选择当前轮或下一轮动作

    steer、interrupt、审批是当前实时动作；队列、模型和模式属于下一轮，界面明确分开。

  9. 9
    文件动作逐步确认并回读

    浏览、预览、上传、编辑、移动和删除都按不透明根与相对路径执行；覆盖、永久删除需要明确选择。

  10. 10
    断线只恢复可证明的部分

    SSE 用事件 ID 重连，草稿和加密队列保持；实时动作缺连接时失败关闭，不静默重放。

  11. 11
    更新只切换兼容的公网层

    显式租约内先排空已接纳写入，再短切换 Web/Sidecar（认证侧车服务）；浏览器以同一幂等键续接，新 Sidecar（认证侧车服务） 失败则恢复旧 Sidecar（认证侧车服务）。Broker（代理服务） 或 app-server（任务协议服务） 变化必须另走显式交接。

  12. 12
    人工取证后更新网页

    只有本人明确要求时，网页才重新读取 PUBLIC（公开） Git、版本、测试和获准图片；不建立在线探针或自动刷新。

本页用到的名词

需要核对专业含义时，可以在这里查看它在 Codex Remote 项目中的具体用法。

Sidecar（认证侧车服务）
对浏览器提供登录、产品 API、SSE 事件、文件能力和领域投影；公网只到这一层。
Broker（共享代理服务）
只在本机回环上连接 Desktop、Sidecar 与单一 app-server，并维护 RPC 对应与订阅屏障。
app-server（任务协议服务）
Codex 的任务、轮次、审批、模型和事件来源；原始接口不会直接暴露公网。
threadId / turnId（任务 / 轮次标识）
证明手机与 Desktop 指向同一任务和同一轮执行的稳定身份。
Work Log（公开工作记录）
按顺序呈现公开进展、工具、命令、文件和子智能体活动，不含隐藏推理。
steer（当前轮引导）
在当前回复仍运行时追加要求；它不同于排队下一轮。
outbox（加密待发队列）
Sidecar 保存尚未派发的下一轮消息；内容以当前 Windows 用户 DPAPI 密文落盘。
runtime generation（运行代）
由运行文件内容和兼容身份共同计算 SHA-256 的不可变目录；同样内容复用同一代。
current / previous pointer（当前 / 上一运行代指针）
原子记录待采用版本、上一可回退版本及两个 manifest 哈希，不等于当前进程已经切换。
drain（排空）
更新前拒绝新写入与下一轮派发，等待已经接纳的活动结束，再签发绑定同一 update id 的回执。
subagent history integrity（子智能体历史完整性）
分别说明当前与归档记录是否读尽、部分、未知或失败，避免把短列表冒充全部历史。
SSE（服务器事件流）
浏览器接收实时任务更新的单向事件通道；断线后按事件序号续接或重读快照。
CSRF（跨站请求伪造防护）
写请求必须同时满足登录、可信来源和一次性校验，避免第三方网页借用会话操作电脑。
opaque grant（不透明短时授权）
任务正文中的本地绝对路径换成短时文件引用，避免形成可复用公网裸链接。
owner file manager（所有者文件工作台）
继承 Sidecar 当前 Windows 身份的文件能力，不是多用户沙箱。

系统里实际有什么

下面是当前产品组件，不是概念分类。每一项都对应真实文件、入口或验证链。

01
Web PWA（手机网页应用）

提供任务、对话、审批、文件、设置与离线草稿界面。

React + Vite + TypeScript；中文优先、响应式、主要触控目标至少44×44 CSS像素。

02
Sidecar（认证侧车）

拥有登录会话、产品 API、SSE、领域投影、队列与文件能力。

默认仅监听本机；不记录已发送对话和文件正文，待发队列用 DPAPI 加密。

03
Broker（共享代理）

让 Desktop 与 Sidecar（认证侧车服务） 连接同一个 app-server（任务协议服务） 并维护订阅屏障。

回环 WebSocket；注入 RPC id 不向产品客户端泄露，Sidecar（认证侧车服务） 断开不终止 Desktop。

04
单一 app-server（任务协议服务）

提供任务、轮次、模型、审批、额度和事件协议。

由 Broker（代理服务） 独占；原始 WebSocket 不监听 LAN 或公网。

05
Domain projection（领域投影）

把协议事件变成稳定的任务、消息、工具、文件和审批产品模型。

浏览器只依赖项目合同，不直接依赖底层 app-server（任务协议服务） 类型；原始 reasoning 被丢弃。

06
Turn queue（下一轮队列）

保存、排序、编辑和派发尚未发送的下一轮要求。

稳定消息 id、revision、串行 claim 与幂等键；不确定状态保持 ambiguous 而不重复发。

07
Subagent navigation（子智能体导航）

恢复父子层级、运行状态、当前与归档历史，并提供进入子任务与返回父任务的只读旅程。

domain 合并 current（当前状态）/archived 与任务内活动，计算 depth；Web 显示完整性元数据、分页和失败提示。

08
Immutable runtime（运行环境） manager（不可变运行代管理）

安装、选择、验证与回退 Remote 自身版本。

RuntimeVersions/<content-sha256> + runtime-manifest.json + 原子 runtime-current.json；稳定 dispatcher 每次先验证再调用。

09
Supervisor maintenance drain（监督器维护排空）

在运行中任务不动的前提下切换兼容 Web/Sidecar（认证侧车服务）。

受保护维护 capability、绑定 update id 的 drain receipt（执行回执）、owner/compatibility 复核与旧 Sidecar（认证侧车服务） 补偿启动。

10
Owner file manager（所有者文件工作台）

按当前 Windows 身份浏览和操作检测到的磁盘。

不透明 root id + 卷内相对路径；拒绝 traversal、UNC、设备路径、ADS 与未确认覆盖。

11
Security package（安全组件）

提供密码哈希、会话、限速、Origin（请求来源）/CSRF、下载与 Windows 路径检查。

Secure/HttpOnly/SameSite=Strict Cookie；写入需认证和同源证据。

12
PUBLIC（公开） demo fixtures（公开演示材料）

用合成任务展示界面而不复制真实主机、对话、路径或凭据。

静态 demo.ts 与浏览器验收共享类型合同；截图不接触 Remote runtime（运行环境）。
