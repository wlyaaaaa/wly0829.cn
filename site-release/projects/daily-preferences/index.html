用途与结果

最快了解这个项目

为什么需要它

只有记录会越存越多，却未必更懂人；每个领域各写一份当前档案，又容易互相矛盾。这个项目把原话、来源事实、模型判断和当前行动授权分开：认识要从完整语境、真实取舍、结果与反例中形成，既敢给有依据的评价，也能在新证据出现后改正。原件、历史版本和已签署成果继续保留，不为摘要顺畅抹掉失败或后来修正。

举个实际例子

我可以说：“结合你知道的经历、最近实际用过的东西和我这次的限制，帮我想几个选择，并指出哪里只是推测。”AI先取相关认识，再按问题补看实际使用、购买或音乐等来源；必要时才读完整卡和原文。若我指出旧手机时长不可靠，它会撤回受影响的强度判断，保留有独立依据的经历，而不是让我从头解释一遍。

最后我会得到什么

得到与当前问题有关、能说明理由也允许纠正的回答：事实问题给时间、覆盖和缺口，选择问题给熟悉、相邻和新鲜候选及推测标记。确有必要才展开完整经历或原话；本次触发来源更新时，逐项说明取得、阅读和认识变化的范围。手机上的AI经已接通的电脑连接使用同一原库，只有确需离线材料才导出文件。

可以用于当前帮助

先用相关认识回答，再按问题补足已有来源；设备活动分手机和电脑报告。有实际更新触发才取得相应新材料，可靠的新认识保存并回读，推荐说明依据与推测。

需要分辨

新表达和旧认识冲突时先看语境、时间和反例，受影响旧结论撤回或修订。资料只读到一部分、旧手机时长失真、退款关系不明或平台窗口有限时，只对已核实部分下结论。

当前不可用

资料或入口暂不可用时说明具体缺口，不把没取得材料说成没有经历。账号登录失效才请本人在原浏览器处理；保存中断先查已完成部分，不盲目重来。

怎样把经历用于眼前问题 · 8 步

先用有关认识回答，需要更新时才读新材料

本人提出沟通、选择、设备使用或纠正；AI先用相关认识，再按问题补看已接入来源与必要原文。确有来源更新触发时才取得并阅读相应新材料，最后把可靠变化保存回同一份理解。

  1. 01本人开口说出现在要判断什么

    可以问沟通、吃喝、商品或出行，也可以直接更正以前的说法。

  2. 02AI先回答只取与这次相关的认识

    给出最有依据的判断、重要反例和未知；缺关键语境才继续查看完整经历或原话。

  3. 03处理更正分清临时取舍与长期变化

    本人说“这次例外”时不改写成永久喜好，历史原话仍能按原时间和语境复核。

  4. 04推荐分支选择时只核对相关事实

    日常推荐不顺手刷新账号；买过、付过、后来退过和真正喜欢分别看。

  5. 05需要更新时只读这次相关的新来源

    按需查看浏览、游戏、已连接Google来源或手机日志；微信和新导出从实际读到的位置继续，取到文件以后还要真正阅读。

  6. 06需要更多依据只查会改变选择的细节

    具体商品核对同一订单的有效结局；不把没记录或很久没买解释成不喜欢。

  7. 07交回可选择的结果熟悉、相邻和新鲜都讲理由

    新鲜项可以没买过，但要标成推测；价格和库存若会影响选择再查当前来源。

  8. 08本人决定选择、拒绝或再纠正

    AI不代下单；可靠的新理解保存回原库并读回，不另建手机档案。

  • 按眼前问题选相关核心认识，确实缺关键背景才回到完整经历或原文。
  • 出现来源更新触发时，按本次账号或来源取得材料、实际阅读，再说明认识的变化或有理由的无变化。
  • 区分订单、支付、退款和真实满意度，可靠全额退款会让对应购买退出普通推荐依据。

  • 推荐时同时考虑熟悉、相邻与合理新鲜的方向，说明依据、取舍和未证实的猜测。
  • 手机和电脑使用同一份现行理解；确需离线交接时才生成完整文件。
  • 查原件前先确认当前文件未变化；失败时说明实际读到哪一步，不拿旧缓存冒充原文。

  • 不把人固定成性格标签，也不替工作、健康、材料等领域维护专业事实和原件。

产品思想与设计核心

01

先保护资料，再用于理解

私人原话只在当前有效的共享资料权限内读取；取消一次验证不改写已有状态，到期或本人锁定后停止私人取用。背景用于帮助本人，不用于识别操作者。

02

行动决定与长期认识分开

本人这次明确的选择约束这次行动；一句新话或一笔旧订单都不自动推翻仍有依据的长期理解。

03

敢作有依据的判断，也能改正

AI可结合经历、结果和反例给最倾向的理解，同时把直接记载和推断分开；新证据出现就修订。

04

时间与角色不能混写

当时怎么选、后来怎么想、这次为什么例外各按原语境保存；一次模型误读引发的纠正不写成本人长期执着。

05

交易与喜欢是两种事实

订单、支付与退款各证明自己的部分；可靠全额退款让此前成功购买退出普通推荐依据，部分退款或关联不明保持未知。

06

具体名字胜过宽泛标签

商品、菜品、口味和规格保留原意，不能把一种苏打水泛化成所有矿泉水。

07

普通问题先直接交流

相关核心认识已足够时就回答；只有会改变判断才打开完整卡或原文，不按固定字数走仪式。

08

近期帮助排序，不把旧事实判作过期

其他条件相近时近期经历更靠前；久远有效事实和未更正明示仍在，没有记录不产生负面偏好。

09

历史帮助探索，不围住选择

除熟悉内容，还给相邻和合理的新鲜方向；新东西可只是有依据的尝试。

10

真实选择由本人作出

AI说明推荐理由与取舍，必要时按请求只给一个，但不会自行下单或付款。

11

实时价格交给当前来源

没有稳定价格接口时给相关平台和搜索词，不假称最低价。

12

来源更新要有实际触发

确有更新触发才取得这次适用的新材料；人工资料无新包就保持原截止，不假装实时。

13

取得材料还要真正读懂

拿到文件后还要检查覆盖、实际阅读、修订认识并回验，或者说明为什么认识不变。

14

行为证据有不同力度

游戏玩过比只在库里更有力；视频播放、收藏和追番也不是同一强度，未玩不等于不喜欢。

15

手机使用同一个原库

通过现有电脑连接读取和回写当前认识，只有明确需要离线文件才导出；连接失败从已有结果接续。

16

保护敏感值不抹掉普通事实

某些本地索引会遮住邮箱和支付数字；这不等于把真实商品、平台、时间或偏好语义全部删去。

17

各领域保留自己的责任

健康、资产、支付原件、正式材料、媒体和工作执行仍回到各自项目；个人理解库只保存共同背景和依据。

  2. 2
    先取 current（当前状态） 快路径

    先使用与眼前问题相关的核心认识、本人当前表达和仍有效的依据；需要时再展开详卡或原文。讨论沟通与取舍时直接形成理解和建议，推荐分支才进一步核对偏好快照；缺快照不等于没有经历或偏好。

  3. 3
    更新触发后按来源处理

    Chrome、Steam和现有B站快照走原入口；Keep复用Chrome，Tasks/Gmail复用Google连接，手机日志按已登记原件和完整范围取用。网易云没有新人工快照就保留旧截止，Google Play/航空也不伪装实时，铁路按当前登录窗口说明范围。

  4. 4
    按问题补证

    profile/evidence先发现实际登记来源；吃喝、购买、音乐、出行、设备活动、Steam与B站按问题组合。明确来源可用facts无关键词浏览；activity分设备取完整所问期间，device-inventory查安装清单，mobility保留停留/移动/空档。行为观察不直接变成喜欢或人的净注意力。

  5. 5
    需要原因时核对 facts

    具体商品返回原下单/支付、全额退款传播后的有效结局、时间与文本变体；facts 仍能说明曾买后来退，普通推荐则排除 refunded_full。支付旁证不重复购买，partial/Unknown（未验证） 不猜整单。

  6. 6
    必要时有界回原件

    先核对制品存在和 SHA-256；ChatGPT 再核消息 hash（内容指纹） 并返回对应原文，PDF 重新抽取后做窄掩码，其他类型明确返回已验制品的缓存片段。

  7. 7
    组织选择菜单

    需要选吃喝、商品、出行或娱乐时，才组织熟悉、相邻与新鲜候选，说明理由、取舍和推测，并补查实时信息。解释经历或讨论沟通时，交回的是有依据的理解与建议，不强行生成商品菜单。

  8. 8
    回验并允许纠正

    refresh 或 ingest 后判断新增、增强、减弱或无语义变化，重建仍有充分证据的相关快照并用普通自然问题回验；新的明确表达随时更新 current（当前状态）。

本页用到的名词

需要核对专业含义时，可以在这里查看它在 个人理解库 项目中的具体用法。

current（当前）
同一个精确偏好键下现在生效的明示、记录版本或推定；旧版本仍保留历史。
historical（历史）
保留的旧表述或记录版本；版本较旧不自动意味撤回或失去证据价值，必须结合时间、语境及明确更正判断。
Preference snapshot（偏好快照）
绑定材料或明示及 supports/contradicts/context 角色的可重建认识；来源或证据变化可能 stale，需要复核受影响的摘要和详述。
Evidence role（证据角色）
订单观察、支付旁证、行程观察和本人表达分别说明自己能证明什么，不能横向等权。
Effective outcome（有效结局）
订单/支付后来被可靠同订单链全额退款覆盖时标为 refunded_full；原事实保留，但退出普通偏好、复购和快照支持。部分退款、组单或关联不唯一保持 partial/Unknown。
Recency signal（近期排序信号）
来源、语义和状态相当时给近期记录更高分；它不删除久远有效事实，也不能把低频或无记录改写成负向偏好。
Semantic completion（偏好语义闭环）
材料接入后继续完成覆盖/缺口回读、偏好变化判断、快照重建与普通问题回验；无变化也要明确报告。
AppID（Steam 应用标识）
Steam 内容的稳定编号；多账号看到同一 AppID 时合并成一个人的统一项目，同时保留账号观察边。
game observation（游戏观察）
已分类游戏的库内选择或实际游玩记录；未玩观察比游玩弱，二者都不自动证明喜欢。购买归属可有本人明示，具体历史取得方式另行判断。
store price class（商店当前分类）
Steam 官方商店在观察时给出的当前付费、免费或不可购买状态；不是历史直购、礼物、激活码、限免或家庭共享结论。
conversation-on-demand refresh（对话内按需刷新）
本次有实际来源更新触发时，同步完成所需采集、导入和回验；进程结束后不留下新的后台服务、队列或定时器。
Bilibili stream（哔哩哔哩行为流）
播放、收藏、稍后看、点赞、投币和追番/追剧六类独立证据；强度不同，也都受平台当前可见范围限制。
full / incremental / snapshot / manual
完整权威快照、普通增量、只能说明某个截面的快照、用户直接表达四种接入模式。
Source revision（来源修订）
与某个偏好领域有关的 current 记录、来源状态、解析版本、缺口和明示共同形成的哈希。
verified_artifact_cached_excerpt（制品已验真的缓存片段）
原文件仍存在且 SHA-256 一致，但当前入口没有逐行重解析，只返回绑定到该制品的索引片段。

daily-preferences Skill

03
PowerShell wrapper（PowerShell 启动入口）

让自然路由和人工维护从项目根使用同一个 Windows 入口，而不要求用户寻找 Python。

先使用 PATH 中的 python，再查 LocalAppData 下最新 Python*，最后查 bundled runtime（随工作区提供的运行时）；三处都不存在时明确抛出 Python runtime（运行环境） not found，不静默换执行器。

04

保存来源实例、制品、来源出现关系、导入、记录版本、明示、推定与证据关系。

schema（数据结构） 6、WAL、外键、STRICT 表和 current（当前状态） 唯一索引；同一制品可绑定两个来源 occurrence，没有第二数据库或后台进程。

05
CURRENT.md / PROFILE.md

从同一数据库生成短概览与长详档，先提供核心理解，再按需展开完整经历、推理和原话依据。

summary/detail/evidence 同源，不手工维护第二份本人档案；SQLite 提交和两个视图的原子替换不是跨文件事务，缓存失败先查已提交状态。

06
按需来源采集与连接

有实际来源更新触发时按范围取得当前材料；普通问答直接读取已有原件与认识。

Chrome History/WAL/SHM与Steam非秘密元数据按原入口读取；Keep用现有Chrome、Tasks/Gmail用已连接Google、手机用当前Drive原件与已登记范围；TimeAudit活动按问题从现有Owner只读，不复制其数据库。每项采集仍需后续导入、阅读与语义复核。

Bilibili browser collector（哔哩哔哩浏览器采集器）

在用户现有登录会话中取得六类当前可见行为流。

通过当前标签页的 CDP（Chrome 开发者协议）执行带现有 Cookie 的同源 API 请求；输出稳定匿名账号 ref 与材料库快照，登录失效和接口部分失败分别报告。

把各自已取得的浏览、订单/支付、Google、手机、桌面、哔哩哔哩、网易云与人工材料转成可溯源记录。

活动、安装与移动读取器

按所问期间回答双设备使用、手机安装软件和GPS区域级出行事实。

activity使用手机AppUsage及TimeAudit Owner只读期间结果，按北京时间分天并单列异常/覆盖；device-inventory以最新导出时间选App CSV；mobility按期间汇总停留、移动、空档和本人声明，详细端点按需展开。三者不推定行为动机，也不以GPS空档推定没有出行。

10
Steam 库与商店关联

把同一人的多账号库内选择、游戏行为与当前公开商店分类连接，而不猜历史取得方式。

电脑 MCP 与现有命令入口

让手机和云端 AI 在电脑上直接读取、更新同一原库。

复用 daily-preferences.ps1 与现有 profile/evidence/facts/original、record/snapshot/snapshot-batch；按需读取当前 Skill 和项目合同，不新增手机接口、规则副本或数据库。

确需离线材料或交给未接入 MCP 的 AI 时，完整导出概括和详述。

自然问题取证：返回与问题相关的 current（当前状态） 明示、有效推定和行为证据；查询连接只读。

pwsh -NoProfile -File .\daily-preferences.ps1 facts --term <品牌> --term <品类> --json

核对具体事实：统计事实角色、状态、时间与文本变体，不自动宣布喜欢；指定来源时可省略term并用limit/offset浏览。

pwsh -NoProfile -File .\daily-preferences.ps1 facts --logical-source <来源类型> --limit 20 --offset 0 --json

按来源浏览现有事实：不用预猜关键词即可分页看指定来源，长正文默认预览；完整已存内容显式加--full或沿original定位。

pwsh -NoProfile -File .\daily-preferences.ps1 activity --after <带时区起点> --until <带时区终点> --device all --top 10 --json

双设备期间活动：完整覆盖所问期间，分别给手机/电脑日变化、应用、覆盖和异常；不把两设备时长相加。
