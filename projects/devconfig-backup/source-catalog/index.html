这项功能怎样使用

用途与实际影响

为什么需要它

安装包和插件大多还能重下，私人设置、密钥和终端连接记录更难重建。清单优先保留这些材料；它是供换机时逐项选择的包，不是一键覆盖新电脑。

举个实际例子

我说“重装时别把十几 G 插件都打进去，但密钥和设置不要漏”：清单保留难重建资产、导出可重装软件列表；必需来源不可读直接失败，可选来源未安装则明确记缺席，正在用的 AI 工具数据库先取一份一致副本再收。

最后我会得到什么

得到带日期和完整性清单的配置包、要重新安装的软件列表、哪些来源没有收入，以及哪些文件只记了警告。包可能包含凭据，只能保存在可信介质；恢复前按清单确认所选副本的来源范围。

结果怎么看
正常时

清单列出的必需配置都能读取，排除的安装本体、插件和缓存没有混入；采集结束再次核对来源范围和逐文件完整性后，才交回可选择恢复的这一代配置包与软件补齐清单。每个文件各自核对，不声称整包来自同一时刻。

发现问题时

来源集合在采集中有增删，就在新的候选里整轮重采，默认最多 3 轮，用完仍在变才失败并保留旧包；单个文件扫描后消失或被杀毒软件拦下，记成警告，警告文件不算进这一代的完整性承诺；文件读完后又被应用修改会单列说明。

入口不可用或证据不足时

必需磁盘或软件配置不可读、数据库一致副本做不出来、包或清单无法核对时，保留上次成功包并说明本轮不能形成新版本；可选软件未安装则记录缺席，不用空目录冒充已经备份。

当前怎样实现
1
Backup-DevConfig.ps1 读取 sources.psd1，初始化 staging 临时目录。
2
逐项采集用户根目录散件、SSH 会话、GPG 私钥与各 AI 工具设置；登记的活动数据库走一致副本流程。
  • sources.psd1 声明采集与排除范围：HomeDirs 等目录 19 项、单文件 17 项、AppData 33 项、Scoop persist 1 项，共 70 个来源；必需来源 6 条，系统注册表导出 3 项，计划任务名字规则 11 条（10 月 11 日实际匹配 16 个任务，其中 8 个已停用）。
  • 普通文件由 DevConfig.Sources.ps1 按清单枚举，逐个只读打开、写独立临时副本、SHA-256 核对后再放进候选；每个文件最多三次有界稳定读取。来源集合有增删就整轮重采，默认 3 轮、可设 1—10 轮，回执记录轮次、失败阶段和增删数量；同路径读完后又被修改记 changed_after_capture_count，不承诺全应用同一时点。
  • DevConfig.Sqlite.py 处理登记的活动数据库（home/.codex/*.sqlite 和 FlyingBird 的 database.sqlite）：只读打开、固定一个读事务快照，用 SQLite 自带的在线备份做副本，完整性检查通过才进包；在线备份和完整性检查共用每库 120 秒硬期限，另有 30 秒无进展期限（只有待复制页数真的下降才刷新进度），宿主再给 5 秒退出余量、到 125 秒不退就终止子进程，忙或超时最多试 3 次，失败不跳过、也不退回直接复制原文件。失败回执写固定的阶段、原因、退出码和数字错误码，不输出数据库正文。这套期限是 10 月 29 日 12:05 那次超时失败（等子进程约 22.8 秒时超时）之后改的，之前是单次检查限时 15 秒、子进程 20 秒；改后还没有新的成功采集。最新成功包是否含 5 个完整性检查通过的数据库副本，本轮未重新解包核对，当前为 Unknown。
  • 系统导出生成 env-user.reg, env-machine.reg 与 path-machine.txt 注册表导出，以及 Xshell、hosts 等。
  • 通过 netsh wlan export profile 自动导出全部 Wi-Fi 配置文件（含密码 XML）；_manifests 目录现场执行 scoop export, winget export 与 code --list-extensions 生成软件补齐清单。
  • tests/Assert-DockerScope.ps1 验证 Docker 采集只引用 allowlist（允许清单）的配置文件与 contexts，不递归收整个数据树。

  • 普通文件由 DevConfig.Sources.ps1 按清单枚举，逐个只读打开、写独立临时副本、SHA-256 核对后再放进候选；每个文件最多三次有界稳定读取。来源集合有增删就整轮重采，默认 3 轮、可设 1—10 轮，回执记录轮次、失败阶段和增删数量；同路径读完后又被修改记 changed_after_capture_count，不承诺全应用同一时点。
  • DevConfig.Sqlite.py 处理登记的活动数据库（home/.codex/*.sqlite 和 FlyingBird 的 database.sqlite）：只读打开、固定一个读事务快照，用 SQLite 自带的在线备份做副本，完整性检查通过才进包；在线备份和完整性检查共用每库 120 秒硬期限，另有 30 秒无进展期限（只有待复制页数真的下降才刷新进度），宿主再给 5 秒退出余量、到 125 秒不退就终止子进程，忙或超时最多试 3 次，失败不跳过、也不退回直接复制原文件。失败回执写固定的阶段、原因、退出码和数字错误码，不输出数据库正文。这套期限是 10 月 29 日 12:05 那次超时失败（等子进程约 22.8 秒时超时）之后改的，之前是单次检查限时 15 秒、子进程 20 秒；改后还没有新的成功采集。最新成功包是否含 5 个完整性检查通过的数据库副本，本轮未重新解包核对，当前为 Unknown。
  • 系统导出生成 env-user.reg, env-machine.reg 与 path-machine.txt 注册表导出，以及 Xshell、hosts 等。
  • 通过 netsh wlan export profile 自动导出全部 Wi-Fi 配置文件（含密码 XML）；_manifests 目录现场执行 scoop export, winget export 与 code --list-extensions 生成软件补齐清单。
  • tests/Assert-DockerScope.ps1 验证 Docker 采集只引用 allowlist（允许清单）的配置文件与 contexts，不递归收整个数据树。

名词和入口
本模块用到的名词
名词意思
Data-Driven Manifest（数据驱动清单）配置规则与代码逻辑解耦，增删备份项只需修改 psd1 数据文件，不动任何执行脚本。
Signal-to-Noise Ratio（高信噪比备份）优先剔除可重建的大体积二进制与缓存，同时允许真实恢复状态随使用增长；目标不是永远维持某个包体数字。
Public Artifact Gate（公开制品门）提交前检查 Git 文件候选的已知备份目录、归档扩展名和微信数据库路径；更广的公开正文检查由网站发布门单独完成。
专业定义

安装包、插件和缓存可以再下载；配置与恢复状态按必需/可选清单采集，缺重要来源就不发一个假完整包。

出问题时

解决什么

防止将数十 GB 的 node_modules、浏览器缓存、软件本体与 Docker 磁盘镜像打进备份包，并防止把明文 API Key 与私钥误提交至开源仓库。

边界
  • 严格禁止把软件安装目录、IDE 插件二进制包、缓存与 node_modules 打进备份。
  • 严格禁止 Docker Desktop 的 VHDX 磁盘镜像、容器层与运行态进入配置包。
  • 真实备份包可能含明文凭据，但不得进入 Git；不可轮换的 GPG 私钥需要比普通可轮换 token 更谨慎地选择加密与介质。
失败与恢复
  • sources.psd1 存在语法错误或非 UTF-8 BOM 编码： PowerShell 5.1 无法解析时本轮采集停止；先修复数据文件，再重新生成包。
  • Git 暂存区中误加入了备份 zip、reg 或敏感数据库文件： Assert-NoBackupArtifacts.ps1 门禁测试失败，阻断任何提交与发布流程。
  • Docker Desktop 正在生成新的大文件或临时日志： 采集只读取明确列出的 CLI（命令行工具）/Desktop 小配置和 contexts，不递归收整个 Docker 数据树。
