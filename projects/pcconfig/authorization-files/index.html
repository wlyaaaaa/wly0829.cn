这项功能怎样使用

用途与实际影响

为什么需要它

给明确选中的文件加密时，最怕中断后重头来、密文坏了直到恢复才发现，或把同名原件直接覆盖；换电脑后也怕必须先把整台机器恢复好才能打开它们。这个入口只处理本次点名的路径，保存进度、核对文件，在不伤原件的前提下恢复，并能凭恢复集单独打开。

举个实际例子

我说：“只加密这个目录和这两个文件；中断后接着做，恢复时别盖掉已有文件。”没指定输出位置时，加密包默认放进文档文件夹里的专用目录，每次一个独立的包，之后会随文档的常规备份进入 G 盘和 H 盘；我另选了位置，就要另外确认那里有没有备份。

最后我会得到什么

加密后得到可逐项核对的包；恢复到指定位置时不覆盖不同内容；查看文本只在本地窗口呈现，可以复制出来用，编辑则得到一份重新验证的新加密包。“已加密”“G 盘读回过”“H 盘读回过”是三件分别证明的事，一次加密不等于三端都备份好了。

技术实现与依据（二）
关键规则与设计选择
1
只处理我本次明确点名的路径和输出；不自动扫描下载、文档、整盘或仓库集合。
2
来源文件和授权包默认都保留；删除、上传、同步和迁移都是独立动作。没有专门的加密包后台写入程序，备份来自文档文件夹已有的常规备份。
3
凭据、授权文件域和 vault-tool 彼此独立：文件域使用自己的随机根密钥、包密钥、文件密钥、续作状态、索引和恢复，不与密码库合并；旧 P0—P7 退役不影响授权文件。
4
普通受保护入口按密码中心当前规则复用有效权限（有效无限制授权或共享资料期），否则四类本人验证任选一次；界面不再额外加一关。有资料期也不会自动解开任意恢复集。
5
凭指定恢复集单独打开：先核对正式安装或完整程序包，只打开文件域，由我四选一验证，只解封文件域、不打开密码库；不需要整机恢复、Git 登录，也不要求新电脑或 AI 预先登记。用恢复码时可以完全离线。范围只限本次选定的路径，不变成扫描器。
6
比如“打开这个加密包里的说明让我看，把改好的内容保存成另一份加密包”。先验证完整包和精确成员，再在受保护进程的本地窗口显示；可以复制，编辑状态下也可以剪切；取消不创建输出，编辑只保存到尚不存在的新目录，原包保留。正文不进入 AI、JSON、标准输出或明文临时文件。

技术实现与依据（三）
当前怎样实现
  • 正式受保护入口暴露 AuthorizationFileEncrypt、Verify、Decrypt、View、Edit 五项操作；Encrypt 只接收选定路径和输出路径，Verify 接收输入包，Decrypt 接收输入包和输出路径。
  • 独立文件会话：同一受保护入口的文件操作加上 RecoverySetDirectory 参数，进入 Open-AuthorizationFileSelected.ps1，只处理本次的选定、输入、输出和成员路径。
  • 本地窗口（authorization_file_local_ui.py）先验完整包与认证索引，再选单一文本成员，严格 UTF-8、可保留 BOM、无 NUL、最大 64 MiB；目录包凭清单识别，不靠后缀猜格式。
  • 复制与剪切：选择后写入受保护剪贴板，60 秒后或关窗时按本次所有权标记清理；只读文本可复制不可剪切，编辑文本可剪切；失败不删除选中文字，清理只处理本次内容。这和普通密码窗口“不定时清理”是两套不同实现。
  • 保存只替换新副本内的选定成员，重验整包、解密回查修改哈希、原子提交新目录后再验证；失败清理本次候选，原包不替换。
  • 显式展开有界：拒绝符号链接、目录联接、特殊条目、输出位于来源内部和大小写碰撞；默认上限 10000 个文件、100 GiB。
  • 随机 256 位域根下每包生成包密钥、每文件生成文件密钥；AES-256-GCM 保护根封装、密钥、状态、索引和默认 4 MiB 内容块。
  • 每完成一个文件原子更新加密续作状态；全部完成后生成索引并删除状态，已完成的重入返回 already_complete。

名词和入口（一）
本模块用到的名词
名词意思
Authorization file domain（授权文件域）只处理明确选择文件的独立产品域，有自己的密钥和恢复；不属于密码库、vault-tool 或旧 P0—P7。
Authorization file bundle（授权文件包）清单、密钥封装、分块密文、加密索引和无正文回执组成的目录；来源默认不删。
Resume state（续作状态）用包密钥认证加密的逐文件进度；中断后只继续未完成项，完成后删除。
AES-GCM（带完整性校验的加密）每个密文块同时提供保密和防篡改，块身份、序号和长度一起认证。
独立文件会话凭指定的完整恢复集和一次本人验证，只解封文件域、不打开密码库的打开方式。

出问题时（一）

解决什么

解决明确选择被扩大、中断重做、来源版本混合、密文篡改、恢复覆盖冲突、文件域与密码库混线，以及换机时必须先整机恢复才能打开文件的问题。

边界
  • 模型不读取、摘要或发送文件正文；本地查看编辑只在受保护进程中解释所选 UTF-8 文本
  • 不搜索未点名目录发现候选
  • 拒绝符号链接、目录联接和读取期间变化
  • 来源与包默认不删、不上传；备份只来自文档文件夹已有的常规备份，另选位置要另外确认
  • 不同内容绝不覆盖
  • 与凭据库、vault-tool 不共享根、会话、索引或恢复

出问题时（二）
失败与恢复
  • 输入为空、不可用、越界或含重解析点： 创建包前拒绝，不扩大选择。
  • 输出位于来源内部、路径碰撞或已有不匹配包： 返回精确冲突，保留来源与输出。
  • 加密中断： 保留清单、密钥封装、已完成对象和加密状态，同一选择只续未完成项。
  • 来源读取前后变化： 该项返回 source_changed，不把两个版本混成完成。
  • 索引、密钥封装、对象哈希或认证标签被改动： 精确报告失败项，拒绝明文落地。
  • 恢复目标已有不同内容： 返回 restore_conflict 并保留双方。
  • 独立会话缺完整程序、选定集不完整或与加密包不匹配： 不打开文件域，说明缺哪样。
  • 复制写入失败： 选中文字保留，只清理本次写入的内容。
