这项功能怎样使用

用途与实际影响

为什么需要它

我需要知道为什么被要求验证、验证后能继续什么。删仓库、把私人资料发出去、看密码明文这类事撤不回来，所以动手前要确认真是我要的；但普通干活不该被反复打断。现在的做法是：只有重大的事或资料锁着时才请我验证一次，验证本身不会连带锁盘或重启。

举个实际例子

我说：“帮我把这个旧仓库删了。”AI 先确认是哪个仓库、本地是否已有全部分支，并把只在 GitHub 网页上的 issue 和发布包列给我看；如果我没开无限制授权，就请我用一种已登记方式验证一次，然后才删除。我问一件需要私人资料的事而资料锁着，AI 会先请我解锁，解锁后再查资料作答。

最后我会得到什么

我拿到清楚的结果：这次验证是否成功、是刚做了一次真人验证还是复用了有效授权、动作本身是否真的完成。取消一次验证只结束这一次；不会出现“验证失败就锁住电脑”的情况。

常见动作分别会怎样处理

删除 GitHub 仓库

开着有效无限制授权就不再弹验证，否则验证一次，资料是否解锁不影响这一条。删除或转移前先确认本地有全部分支，缺的先拉下来，再把只在 GitHub 网页上的 issue、发布包列给我看；删除本身由 GitHub 总索引执行，不会触发任何锁盘。

清理生成文件或一份本地副本

能重建的生成物、确实有可靠副本的文件属于普通清理，不请我验证；如果所谓“副本”其实是唯一的一份，就按“删除只有一份的数据”处理，要我明确同意。

重装、重置电脑或格式化磁盘

先查清会擦掉哪些数据、是否影响恢复材料；真正擦盘属于撤不回的事，要我明确同意，执行交给负责系统安装或恢复的模块。讨论方法、只读检查和普通修复不算已获准擦盘。

查资料、改代码、测试或正常推送

普通源码编辑、测试、定向提交和正常推送、规则发布都不算重大，照常进行；只有真正改变公开范围、外发私人资料或造成撤不回的后果时才另行判断。

资料到期、主动锁屏或取消验证

资料到期只结束旧的资料访问，主动锁屏只锁 Windows 桌面，取消只结束这次验证。它们不是同一个开关，也不再会引出“设备不可信、磁盘应锁定”。

出现与操作者或隐私有关的真实疑点

暂停与疑点有关的资料取用和撤不回的步骤，需要时请我验证；不先读私人档案来“考身份”。旧的“疑点锁屏、十分钟后锁盘”已经退役，无关的可撤回工作照常。

4
