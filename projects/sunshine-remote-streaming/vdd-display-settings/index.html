“把手机用的虚拟屏调成我指定的清晰度和刷新率，别动家里主屏。”先只读查看当前值与驱动支持的可选模式（默认仍用 60 Hz，不强推最高刷新率）；本人确认后才应用，并分别回读虚拟屏和主屏。

技术实现与依据（一）

这里保留实现、关键条件、精确入口、历史记录和验证结果。

现存驱动配置（vdd_settings.xml）：首项 2880×1800@60、HDRPlus 关闭。实际模式、缩放与 Windows HDR 截止前没有新的回读；9 月 18 日隔离测试回执保留，本轮未重跑

关键规则与设计选择
1
项目初始 profile（配置组合）保留 2880×1800、60 Hz、150% 缩放与 HDR；后续显式调整可以覆盖。默认请求 HDR 不等于 Windows 里已经开了，实际开没开要回读才知道。
2
持久化首选项会把选定模式写在 VDD 驱动模式列表首位，目的是减少驱动重枚举时回退到 800×600；当前首项确为 2880×1800@60，但重枚举后是否保持仍未实测。
3
严格区分 Windows Advanced Color（高级颜色）/HDR 开关与 VDD 驱动内部的 12-bit HDRPlus 能力开关，避免概念混淆造成色彩异常；驱动配置里 HDRPlus 现在是关的，这和 Windows HDR 是两回事，32 位色深也不等于 10 位或 HDR 验收。
4
脚本默认只读：会读本地 VDD XML 和原生显示状态，但不写显示也不写文件；只有显式传入 -Apply，且显卡近期安静、串流连续空闲 5 秒、目标是同一个唯一 VDD、模式受支持、原值齐全时，才执行 Win32 变更与文件原子落盘。
当前怎样实现
  • Set-SunshineVddDisplayProfile.ps1 负责参数校验与事务编排；sunshine-vdd-display-settings.psm1 负责身份、计划与 XML 候选。
  • Get-SetVddDisplayMode.ps1 实现 ChangeDisplaySettingsEx/CDS_TEST 与模式回读；Get-SetVddScaleHdr.ps1 实现缩放和 Advanced Color（高级颜色）应用/回读，两者都有各自的独立恢复。
  • tests/Test-SunshineVddDisplaySettings.ps1 现定义 19 个测试，Test-SunshineVddNativeAdapter.ps1 为静态核对，另有 Test-SunshineVddTransactions.ps1 定义 38 个事务测试。
  • 完整VDD profile按命名参数哈希表分阶段执行实时模式、DPI/HDR及最终XML，每阶段都核对是不是同一块虚拟屏；完整预检先于效果，原值和回滚结果分别保存。回滚是有条件的：XML只回滚本次写入的版本，发现别处已经改过就保留对方的改动并报告“未恢复”，不保证任何失败都自动回到原样。回滚前重验GPU/会话/同一VDD，新增阻断保留未恢复项。

技术实现与依据（二）
执行流程
1
用户或上层脚本调用入口并传入期望的宽高、刷新率、缩放与 HDR 模式。
2
脚本扫描系统显示设备，严格通过 MTT1337 硬件 ID、驱动绑定和 EDID 锁定专用虚拟屏，拒绝物理屏与水冷屏；临时的 DISPLAY 序号不当长期身份。
3
默认路径只回读身份、当前模式、支持模式、缩放与 HDR，不调用显示写 API。
4
若包含 -Apply，先过显卡、串流空闲和身份门，再调用 ChangeDisplaySettingsEx/CDS_TEST，随后才提交模式、用 DisplayConfigSetDeviceInfo 应用缩放与 HDR，并原子更新持久化 XML。
5
执行写后回读，确认生效参数与请求完全一致。

名词和入口
本模块用到的名词
名词意思
CDS_TEST（显示设置预检）Win32 API 的安全测试标志；只验证系统能否接受该模式，不产生真实的屏幕闪烁或参数改动。
Advanced Color（高级颜色）Windows 官方的 HDR 渲染控制架构；只有在此处开启 HDR，系统才会向串流客户端输出宽色域信号。
专业定义

它把虚拟屏参数从物理主屏中拆开：先认准唯一 MTT1337，再回读，只在显式 Apply（应用）事务中预检并向 VDD 写入；物理屏不变要另做前后验收。

出问题时

解决什么

降低虚拟显示器分辨率回退、HDR 色彩异常和多屏设置互相影响的风险。

边界
  • 入口绝不改写 Sunshine 的 output_name GUID 标识；所以调虚拟屏参数修不了“配置要抓的屏对不上”这类捕获问题。
  • 绝对不触碰物理主屏（PHLC34B 等）、LIAN LI 水冷屏或 HS2 机箱副屏；主屏前后是否真的没变，仍要单独对照，源码测试代替不了。
  • 不强行写入未经驱动支持的非标非常规显示模式；原生列出的高刷新档只说明驱动支持，能不能应用还要过参数校验和本人选择。
失败与恢复
  • 传入非法或未经支持的分辨率/刷新率 预检直接报错退出，不调用 Win32 写入 API，保持现有显示模式。
  • 设备名被模拟或重命名为非安全格式 安全过滤层拒绝执行并抛出异常，防止向错误显示设备发送指令。
  • XML 配置文件写入中途失败 只回滚本次写入的版本；如果发现文件已被别处改过，就保留对方的改动并明确报告未恢复，不硬盖回去。
