这项功能怎样使用

用途与实际影响

为什么需要它

把所有事实一起过期会制造重复劳动；但只看原话还找不找得到也不够：两项工作的日期在新版里互相对调后，每个日期仍然只出现一次，却已经属于另一件事。只重新生成文件却不标旧结果，又会让失效证据继续被引用。

举个实际例子

我可以说：“执行计划换成新版了，告诉我哪些结论还能用、哪些文件要重做。”整行换了位置、前面多了一段说明，原话仍在同一事项下的，会自动接到新版；原话被删、出现两次，或者两个系统的上线日期互相对调了，相关事实交回给我重新判断，用到它们的旧版文件标为过期。

最后我会得到什么

得到这次换版的处理记录：哪些结论接到了新版、哪些失效待审、哪些旧版交付物不能再当当前版使用。它不是逐字对比的差异文件。处理新增问题后另存新版本；目前影响范围能指出整次构建，尚不能精确到某一页或表格单元。

结果怎么看
可以正式构建

新资料读得完整，旧结论引用的原话在新版中仍只出现一次、并且还在原来的事项或列下，就自动接到新位置；真正失去依据的结论标为过期。用到变化事实的旧交付版本都不再算当前版，包括刚刚自动接上的事实：结论还能用，但它的证据已经换到新版位置，旧文件要重新生成。

需要确认

原话消失、出现多处、被挪到别的事项或列，或新旧说法冲突时，保留两版资料和待确认结论，只让负责人处理对应事实。这时直接“确认”旧证据也会被拒绝，要从新版里补上可靠的原话。

当前不可用

新版资料不能可靠读取或保存更新失败时，继续保留上一可靠版本，不假装已经完成换版。

关键规则与设计选择
1
相同字节更新是 no-op，不制造 change set 或 stale。
2
自动 rebound 要同时满足两条：旧 EvidenceSpan 的原文在新版本中唯一存在，并且结构锚点一致（同一事项的位置标记）。CSV 认首列唯一非空的行键和唯一列头；文本认 Markdown 标题层级、所在行或段落的上下文，或完整的“键：值”事项。
3
任一证据片段原文消失、出现多个匹配，或仍然唯一但已挪到别的事项/列，事实都 stale，不半猜半接。
4
显式 confirm 旧证据同样检查结构锚点，失配就拒绝；只能登记新事实或补当前可靠证据，人工确认不能绕过失配。
5
过期 build 的范围是“过期事实 ∪ 重绑事实”：重绑的事实本身保持 fresh，但引用它的旧 current（当前状态） build 仍标 stale。没被该 build 使用、也不改变其正式语义的变化不废旧 build，它仍按自己的修订号 verify；新 build 生成后旧 current 才转 stale。
6
未关联事实保持 fresh，不要求重复确认；当前 impact 只报告 facts 与 whole builds，没有文件、block、页面或工作表级影响。
7
下一版仍需处理新增冲突并通过同一 quality gate；来源更新不自动生成下一版。

名词和入口
本模块用到的名词
名词意思
ChangeSet（变更集）一次来源版本变化的持久结果，分别记录重新绑定事实、过期事实和过期 build；不是逐字差异文件。
rebound（重新绑定）旧原文在新版本中仍唯一存在，而且结构锚点一致（同一行键和列、同一标题或同一事项下），证据换到新 SourceSnapshot，事实保持有效。
stale build（过期构建）引用了过期或重新绑定事实的旧构建；文件仍保留，但不能再作为当前正式版本。
专业定义

来源更新不是全文重做：先比较每个证据原文，只出现一次、并且仍在原事项、原列或一致的文档上下文里，才接到新版本；找不到、不唯一或换了事项，都要求重新登记或补当前证据。

解决什么
解决一改全废、旧证据继续冒充当前、日期对调后被错接到别的事项、无关事实被误改和重新生成冒充影响分析的问题。
边界
  • 只做精确原文加结构锚点匹配，不做语义相似重绑
  • 多处匹配或事项上下文不足时不猜
  • 影响不精确到单Office文件
  • 旧build不自动删除
  • 来源更新不自动生成下一版
失败与恢复
  • 新来源与旧版本字节相同： 返回 no-op，不创建人工变化或过期记录。
  • 旧原文在新版本出现多次，或仍唯一但已移到别的事项/列： 事实保持 stale，显式确认旧证据也被拒绝；要求登记新事实或补当前可靠证据，不按第一个匹配猜测。
  • 更新事务中断： SQLite 回滚，current（当前状态） snapshot、facts 和 builds 保持上一可靠状态。

依据与来源
真实入口
  • PRIVATE source · store.py update_source快照更新、精确匹配、结构锚点、rebound、stale和事务
  • PRIVATE source · acceptance.py两套合成来源变化与未关联事实回归（合成验收为 2026-09-01，之后未重跑）
  • PRIVATE tests · core change tests真实失效、唯一重绑、结构换版案例、无关事实隔离和旧build过期
如何验证
  • 真实失效事实和引用它们的旧 build 同时 stale；重绑事实保持有效，但引用它的旧 build 仍过期。
  • 测试里有 14 种结构换版案例：5 种允许自动接续（如整行挪动、前面插入一段说明），9 种必须过期或拒绝确认旧证据（如两个系统的日期对调、原事项换了列、行键重复、跨标题或同标题下不同事项对调、没有事项的裸日期）。这是 2026-10-11 读源码得到的案例数，本轮没有重跑。
  • 未关联事实不被误改；语义不受影响的旧 current build 仍可按原修订号 verify。
  • 显式重新确认会再查结构锚点，失配时拒绝。
