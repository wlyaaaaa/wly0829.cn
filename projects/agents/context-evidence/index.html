这项功能怎样使用

用途与实际影响

为什么需要它

长任务会经历对话压缩、换人接手和外部状态变化；源码、测试、安装、发布、公网与用户结果又各自证明不同的事。只看摘要或一个“通过”，很容易在过期前提上继续忙，或者悄悄漏掉我早先提过的要求。

举个实际例子

我可以说：“只检查 Git 总索引，别刷新引用，也别修。”系统只做这项零写入诊断，分别告诉我结构是否健康、现在能否收口。又比如一个长任务压缩了三次后我说“接着做”，AI 先读回最近的原话、现行要求和上次的任务状态，按项目位置找回原来的仓库和工作副本，再继续；压缩后的后台复核如果发现漏了某条要求，会提醒它补上。

最后我会得到什么

我会看到这次查了哪些真实来源、有没有改动，本地、远端和用户结果各自到哪一步；长任务收尾时，每条要求是做完了（附证据）、还是延后（附原因）。读不到的那一层保留“未知”和下次核对入口，不拿摘要补空白。

结果怎么看
正常时

所需来源可读、各层证据一致、要求表逐条对上时，形成一份能接手的当前结论。

发现问题时

摘要、源码、运行状态或外部回读冲突时，以现场责任来源为准，把冲突层单独列出，只停依赖它的判断；要求缺完成证据或延后原因时，长任务不让收尾。

入口不可用或证据不足时

必要来源读不到时，对应结论标成未知或明确阻断；不恢复退役的中央系统，也不从旧摘要猜现状。后台复核失败或超时，不推进已覆盖进度，原批续作。

3原话唯一存档：
新原话只写进月卷 docs/owner-decisions/YYYY-MM.md；旧 owner-decisions.md 只是导航，order.json 保原序。写入在共同的跨进程锁内校验 UTF-8 和换行、原样追加并定向提交，格式不对就拒写。
4现行要求唯一表：
requirements/register.jsonl，按全局、项目、任务标签查询；每条有状态（现行、完成、被取代、撤回、延后）、来源消息编号和原话片段、完成证据或延后原因。这是明确采用的现成要求表，不是“绝不建任何台账”。
5决定短投影：
现行决定按分类生成短投影，上限 6,500 字节（UTF-8），不手抄长索引。
6长任务收尾对账：
Close 时缺要求、缺交付证据或缺延后原因，就拒绝收尾。
7
压缩、交接、更正、反复失败或扩架构前先恢复原意；有冲突改方案，不改用户要求。

  • 消息分类统计：　源码 daily_owner_corrections.py 现在分 9 类：禁令、纠正、授权、要求、建议、偏好、事实、询问、好奇。按意思单元分，一条消息可属多类，同类只计一次；默认补最近 7 天加今天截至现在（今天标未完结），不混类别次数和消息条数；资料锁着不读不数。本轮没有运行分类。
  • 控制面诊断（Doctor）：　-CheckId 现有 6 个可选项：skill_supply、skill_runtime、google_workspace_contract、project_admission_agents、project_admission_pcconfig、project_admission_index（旧的 pcconfig_drift 已不在）。默认三个控制面时跑 4 项；Google 合同检查要显式选，不出网、不解密凭据，不证明授权有效。默认 Cached、零写入，显式 Live 且选了 Git 准入才刷新本地引用；同时给出健康与收口两个结论，退出码 0 不是发布许可。每个提供器默认 60 秒、输出 262,144 字节上限。供应健康和真实运行覆盖分开，后三层（当前任务、新任务、端到端）写未知。
  • 三个控制面：　.agents、Git 总索引、PCConfig；具体项目拥有业务事实。Get-FourBaseDecisionContext.ps1 只是兼容旧名，不代表第四个控制面。冻结项目批量维护时不读不改，本人点名具体需求只处理那一项。
  • 备份跟随删除：　受管 G 备份跟随登记上游，H 跟随 G；源根正常可读时，消失的项按本人删除处理，不从下游复活。离线、锁定、读取失败不当空源；新增和修改复制核验后才清旧副本。照片、视频、音乐、个人资料和 G 盘项目与软件唯一原件有 30 天后悔期（具体以 PCConfig 登记为准）。日常治理只查计划是否按时，不补跑。

出问题时（一）
解决什么

长任务会压缩，责任方会变化，同一结论又可能来自文档、源码、测试、运行时或外部回执。系统要让重要状态可重建，防止把摘要、历史命名或某一层“通过”当成全部完成，也防止压缩后悄悄丢掉早先的要求。

边界
  • 普通单项目问题不机械进入三控制面全景。
  • Doctor 默认不刷新远端；显式 Live 可能写本地 Git 引用，必须明示。Doctor 不修复、不安装、不改工作树或计划任务，也不提交推送。
  • 兼容名称不恢复已退役的第四基座或中央个人上下文。
  • 续作状态不保存秘密、隐藏推理和无关私人内容；后台复核在资料锁着时不借工作目录放行私人历史。
  • 测试、回执和状态字段不能代替用户看得见的验收；短时通过不能证明长程不偏离原意。
