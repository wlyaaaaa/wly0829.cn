这项功能怎样使用

用途与实际影响

为什么需要它

“把网站发布好”不等于任何子代理都能改任何仓库。两项任务若碰到同一文件，还可能互相覆盖、各自声称完成，或者在交接时把没做完的事丢掉。

举个实际例子

“这个网站修好后发布到原地址，别每次再问，也别盖掉其他任务。”这项授权跨轮次、压缩和子代理都继续有效。AI 在自己的工作副本里改，合并时先看懂别人的改动再并；真正扩大到新账号、公开、花钱或不可撤回的事，才另行判断。第一次公开发布 Release 要我明确同意，“保持最新”不算首次发布的同意。

最后我会得到什么

普通任务持续推进，谁改了什么、还剩什么清楚。限时授权返回真实范围、原到期时间和撤销状态；取消本次申请不会撤回其他有效权限，也不会替我执行下一项业务。

这里保留实现、关键条件、精确入口、历史记录和验证结果。

当前规则依据为 E280（2026-10-22 08:43:25 激活，上一版 E279；本轮核验通过）。E279 的授权专题有实质变化：新建本人 GitHub 私有仓库、把远端改成本人 GitHub 账号下的仓库、核对过不丢提交的历史改写（含强制推送）归入普通 Git 收尾，可能丢提交的强制推送仍要本人明确同意；下面“当前怎样实现”的多任务协作一条已按此改写。早先这里写的“E258（2026-10-12 02:18 激活，10 月 12 日 04:41 核验通过；授权专题与 E257 相同）”是那天的历史观察。本人接管入口只核对了存在和安装清单：AuthorityHost 安装批次 365，安装于 2026-10-11 16:41（10 月 12 日 04:39 观察）。本网页没有运行接管窗口，也没有做本人验证。

关键规则与设计选择
1
本机低风险、可逆、范围内的读取、编辑和测试直接推进；发消息、外部写入、发布、部署和付费需要明确授权。
2
本人明确给出的长期授权，在原目标和范围内跨轮次、压缩、主对话、全部子代理和新顶层任务持续有效；项目只能定义客观前提，不能把它降为没有，也不能要求本人重说。
3
授权已覆盖、前提成立时，真实调用一次工具，不先猜平台会拒绝而停下；工具真的拒绝、要求再验证或报错，就按真实结果处理，不伪造成功。
4
子代理和后续任务的范围、授权、沙箱和资料访问，只取本人授权、父代理授权、适用规则和宿主真实限制的交集，不能扩大。
5
Windows 提权、资料解锁、短锁和用户授权是四件事，互相不产生授权。本人给的长期提权许可也适用于子代理：宿主支持时可以静默提权，确实需要本人在场的，交回根会话安排。
6
受信任的桌面 AI 现在有两个：codex-root 和 claude-root，各自登记、各自可撤销。密码中心按当前 Windows 账户和实际同账户的桌面祖先进程链认人；型号、管理员权限、工具名、环境变量、电脑 MCP 登录都不是桌面身份。这两个已登记的桌面 AI 可以免本人验证，做密码中心里已登记、且不属于重大动作的凭据操作；重大动作仍按保护策略办。这不会让隐藏的执行者获得桌面身份，也不扩大任务本身的动作授权。
7
本人私人账号空间在没有公开或分享信号时，与本机私密目标同样可信；可信不等于已授权写入。公开个人数据只按唯一的公开分级表判断，项目想收紧 L1/L2 须本人对具体项目和范围明确指示。
当前怎样实现
  • 多任务协作：　每个任务有自己的 worktree（Git 的独立工作副本）；合并时理解对方变更，正常推送默认分支并回读后，快进活动检出。有别人未提交的改动、真实同步冲突或目标不明时不动，也不拿强推盖掉别人的成果。没有上游或不能快进时，先看是不是普通收尾：新建本人 GitHub 私有仓库、把远端改成本人账号下的仓库、核对过旧提交仍由其他分支或标签保留的历史改写（含强推），直接做；核对不过就停下说明，不改成找本人验证；可能丢提交的强推仍要本人明确同意。安装、升级、发布规则、改计划任务用 Invoke-ShortLock：Inspect → Acquire → 用完在 finally 里 Release。短锁不授予业务权限，只锁这一个单点动作，准备工作不用等整单。

出问题时（一）
解决什么

用户说要完成一件事，不等于任何代理都能对任何对象做所有动作。系统要分清：用户授权、操作系统权限、受信任身份、目标是否仍是原目标、别人是否正在改同一处，以及动作完成后有没有正式回读。

边界
  • UAC（Windows 管理员确认）只提升进程权限，不扩大任务授权。长期提权许可对子代理同样适用；需要本人在场确认的，交回根会话安排。
  • 受信任的桌面 AI 免本人验证的，只是密码中心里已登记、不属于重大动作的凭据操作；重大动作仍按保护策略把关和验证。
  • 长期授权不覆盖系统、开发者和平台限制，也不扩大目标、账号、公开面、付费、秘密或不可逆边界；首次公开发布要本人明确许可。
  • 限时接管只用本人实际选的范围和原截止；新对话或另一台电脑不自动继承。
  • 子代理、shell、worktree 和插件都不能绕过别人未提交的改动或不能快进的冲突。
  • force-push、新公开面、付费和不可恢复动作不在默认授权内。
  • 私有或可信目标不等于已授权写入。

本人取消或验证未成功
结束本次请求，不自动重开、不换因子，也不撤回其他有效授权。
