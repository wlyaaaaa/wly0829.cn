  • owner-baseline-store.v3 把完整 identity snapshot 与 nullable（可为空） local-root snapshot 分开；current（当前状态）、previous、hash（内容指纹） 和 receipt（执行回执） 原子读写。当前基线保存于 10 月 27 日 14:19（48 个仓库），上一版为 10 月 21 日 20:54（48 个），history_gap=false；9 月 28 日 01:41 那版（45 个）已是更早的历史。统一导航最近一次保存于 10 月 27 日 14:21，为 46 项（即在本机有副本的仓库）。
  • Refresh-GitHubLocalIndex.ps1先验证既有v3基线是否为missing或current（当前状态）；invalid在任何写入前拒绝。正常full refresh取完全部观察后，先写统一导航和单页看板（逐个文件替换），再调用Invoke-RefreshGitOwnerBaselineAdvance推进基线；推进时重新读一次Owner inventory，并在推进前、迁移和回读之间复用它。这三步不是一个跨文件的整体事务。
  • 零delta返回owner_baseline.status=current（当前状态）；完整有效的真实delta触发原子advance，必须execution_status=completed、domain_status=current（当前状态）、history_gap=false，再回读delta=0、issue=0才返回advanced。基线missing只返回skipped/owner_baseline_missing_requires_explicit_bootstrap，不静默建立首次历史。
  • Get-GitOwnerStatus.ps1 只比较稳定 Owner 事实，排除工作树 dirty、ahead/behind（领先/落后提交数）、观察时间、索引 HEAD 和任务状态等高频噪声。
  • governance registry（登记清单） 只输出规范化有效性和 fingerprint，不把内部条目内容放进 compact status。
  • 单页看板 00_总览/当前同步看板.md 和统一导航都标 authoritative=false：它们是派生快照，Git 和 GitHub 现场才是权威。
  • 旧的八文档公开代际和 current-generation 指针也在 9 月 26 日退役，详见“快照与恢复”模块；现在没有“当前公开代际”这一层。

名词和入口
本模块用到的名词
名词意思
Owner baseline（责任源基线）完整仓库 identity 的受管 current（当前状态）/previous 快照；不是 PUBLIC（公开） 子集，也不是一次 live 自比。
domain_status（领域状态）事实是 current（当前状态）、review_needed、blocked 还是 unknown（未验证）；与 Provider 是否成功执行分开。
history_gap（历史缺口）第一次迁移没有可信 previous 全量基线；即使 current（当前状态） 内容有效，也不能伪装成连续历史。当前为 false。
clone occurrence（clone 出现记录）统一导航给出候选路径后，实际 .git origin 与 repo identity 一致的本机副本关联。
semantic fingerprint（语义指纹）对稳定事实规范化后计算的 SHA-256；字段顺序、观察时间和工作树噪声不会改变它。
Milestone record（里程碑记录，已退役）原来外层确认的少量 Git 发布节点；2026-09-26 随推送记录功能一起删除，现在的状态输出不再包含它。

统一导航给出候选路径后，实际 .git origin 与 repo identity 一致的本机副本关联。
semantic fingerprint（语义指纹）
意思：
对稳定事实规范化后计算的 SHA-256；字段顺序、观察时间和工作树噪声不会改变它。
Milestone record（里程碑记录，已退役）
意思：
原来外层确认的少量 Git 发布节点；2026-09-26 随推送记录功能一起删除，现在的状态输出不再包含它。
专业定义

把仓库身份、公开属性和本地副本放进同一张账；当前基线 48 个、现场 48 个，零写查询只报告变化，完整刷新才推进基线。

出问题时（一）
解决什么
人类需要可读总账，机器需要结构化完整身份。若把派生看板当完整权威，新仓库会被漏掉；若把本机目录当仓库身份，旧 clone、重命名和 origin 错配会制造假事实。
边界
  • compact Owner status 不返回私有 local root、branch（分支）、worktree（Git 工作树）、dirty 或 task 状态
  • 不扫描未声明的磁盘根；新 root 由显式 refresh 发现
  • 单页看板和导航是派生快照（authoritative=false），不是完整 owner baseline
  • 普通status保持zero_write=true、fetch_performed=false；full refresh是独立写操作，会自动收敛已有有效基线，-MigrateBaseline仅为显式bootstrap/repair兼容入口
  • 推送里程碑记录已退役，状态输出里没有发布事件流，也不再补写
失败与恢复
  • 总索引自身 origin 缺失或不匹配： 返回 completed/blocked 与有界 issue，阻止所有不可信下游读取。
  • v3 baseline 缺失、无效或第一次 history gap： 返回 unknown（未验证）；不回退到看板 Markdown 或伪造 previous。
  • 现场身份集合与基线不同： 零写status返回review_needed和delta；用户发起正常完整刷新时，事实完整且已有有效基线就自动推进并回读，不再要求另跑迁移。

  • 完整刷新时基线缺失、无效或推进回读失败： 缺失时baseline推进标skipped并要求显式bootstrap；无效时在任何写入前停止。若导航和看板已写成而随后基线推进失败，分别保留实际状态、报告未收口阶段，不谎称整体回滚。
  • registry（登记清单） schema（数据结构）、重复 ref 或 retention 条目无效： Owner current（当前状态） 失败关闭，只公开稳定问题代码。
  • GitHub CLI（命令行工具） 不可用、非零退出或 JSON 无效： 返回 execution_status=error、domain_status=unknown（未验证），供调用者决定重试。
  • 刷新时某个文件写入失败： 直接报错，并说清导航和看板哪一份已换、哪一份没换；不说成整体回滚。
