为什么需要它

可读的工作成果和原始会话不是一类材料。以前单独备份它，是为了换机时能找回项目说明和笔记。现在这条线已停，只剩旧副本可查；要找的是 Antigravity 的设置，现在去开发配置备份。

最后我会得到什么

我会得到一份旧的项目清单、设置或可读笔记，以及它的大致日期；原始聊天、媒体和登录不在里面。旧副本最新一份的完整性没有确认，AI 会把这一点一起告诉我。

技术实现与依据（一）

这里保留退役事实、旧材料现状和旧实现的历史说明。

已退役：原名 Gemini Memory Backup 的任务 2026-09-28 23:26（北京时间）停用，当前为 Disabled。旧材料：G、H 两盘各有 30 个旧快照目录，较新的目录名为 20260928-001005；但两盘根部都没有 current.json，这个目录里也没有快照回执，所以最新有效保存点、文件数和字节数都不确定（16:35 只读元数据观察，不代表原文件丢失）。

关键规则与设计选择
1
不再生成新副本；任务停用不删除，换机不重建，重新启用须本人另提。
2
开发配置备份从 2026-09-29 起照常带上 Antigravity 设置、桌面状态、项目和插件登记，但明确排除命令行的 conversations、implicit、annotations、brain、knowledge 及相应历史库。所以“当前工作成果也随配置恢复”不成立。
3
旧副本照旧可用：本机和 G 盘各轮换上限 30 份，私有 Git 有提交历史。
4
没有专用自动还原器；先保留目标文件，再按相对路径放回，之后重核安装、项目路径、登录和应用结果。
