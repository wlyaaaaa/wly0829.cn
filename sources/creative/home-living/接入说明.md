# 把活画接进首页

这份包让首页第一屏那幅水彩画“活”起来：叠在首页原图上面，原图负责最先出现，也负责一切出问题时的样子。没有 JavaScript、脚本出错、配置或素材读不到、没有 WebGL、系统设了“减少动态”，看网页的人看到的都是那张静止的原图。

整件事分四步：换首页原图 → 放文件 → 挂载 → 接状态。最后两节是怎么退回原来的视频版、怎么整体撤回。

## 一、包里有什么、哪些要上网站

所有文件名都带内容指纹（文件名中间那段十位的十六进制），内容一变文件名就变，可以放心长缓存。

| 文件 | 用途 | 要不要上网站 |
| --- | --- | --- |
| `hero-live.39017e2ca9.js` | 引擎，不内嵌图片 | 要 |
| `hero-live.346b811704.css` | 只作用于引擎层的样式（字体已写死） | 要 |
| `hero-live.config.6a31ab346c.json` | 横竖版素材文件名、位置数据、唯一的速度 `speed: 2.5` | 要 |
| `assets/` 下全部 WebP | 横竖版底图（带鸟、去鸟各一张）和鸟的九个姿势 | 要 |
| `hero-live.files.json` | 本版各文件的指纹名清单，给网站的构建流程读 | 不用 |
| `接入说明.md` | 本文 | 不用 |

## 二、首页原图换成包里的白色版

网站现在首页用的是黑色显示器、黑机箱、黑键盘的旧图（`home-01-h-2880-9442e7824a16.avif`、`home-01-v-1280-fae12132939e.avif`）。活画用的是本人审过的白色版。**首页原图必须换成包里的白色带鸟底图**，否则不开脚本的人看到旧图，活画出现那一下还会从黑色版跳到白色版。

- 横版：`assets/plate-h-white.b070be7ae2.webp`，2880×1621，是最高分辨率的一张。
- 竖版：`assets/plate-v-white.f7c51f4ae1.webp`，1280×2227，是最高分辨率的一张。

这两张就是活画自己的静态底图。首页原图**直接用这两个地址**，引擎就不会再下载第二次。

网站如果要按屏幕宽度准备多档尺寸（AVIF、WebP、1440 宽等），由网站按自己的流程从上面这两张生成，本包不提供。生成时**宽高比必须和原图完全一致、不裁切**。挂载时把首页那张 `<img>` 交给引擎（见下面的 `plateImage`），引擎会直接用浏览器已经选好、已经下载的那一档当静态底图；只有那张图的比例和当前横竖版对不上时，引擎才另取包里的底图。

去鸟底图（`assets/plate-h-white-nobird.514d1c2580.webp`、`assets/plate-v-white-nobird.fe751b8e95.webp`）只给引擎当贴图用，首页 HTML 里不要引用它。

## 三、首页怎么挂

保留第一屏现有的容器、`<picture>` 或 `<img>`、链接和按钮，在这个容器上挂载。下面用 `HERO` 代表包所在目录的地址（可以是网站自己的路径，也可以是 OSS 的地址，见第五节）。

```html
<link rel="stylesheet" href="HERO/hero-live.346b811704.css">

<div id="home-hero">
  <picture>
    <source media="(orientation: portrait)" srcset="HERO/assets/plate-v-white.f7c51f4ae1.webp">
    <img id="home-hero-img" src="HERO/assets/plate-h-white.b070be7ae2.webp" alt="吴乐阳的书桌：窗外是湖和山，桌上是白色电脑">
  </picture>
  <!-- 现有的链接热区、按钮照旧放在这里 -->
</div>

<script src="HERO/hero-live.39017e2ca9.js" defer></script>
<script>
  document.addEventListener('DOMContentLoaded', () => {
    if (!window.HeroLive) return;               // 脚本没读到：原图已经在那里
    HeroLive.mount(document.querySelector('#home-hero'), {
      plateImage: document.querySelector('#home-hero-img'),   // 复用首页这张图当静态底图，不再下载第二次
      status: { state: 'off', title: '暂时读不到电脑', detail: '状态读取结果不可用' }
    });
  });
</script>
```

- **配置地址可以不写。** 引擎按自己的脚本地址找到同目录的 `hero-live.config.6a31ab346c.json`。要写的话用 `configUrl: 'HERO/hero-live.config.6a31ab346c.json'`。
- **容器的比例必须和整幅画一致**，引擎把整幅画铺满容器，不裁切。原图也要占满容器；比例对时用 `object-fit: fill`。不要让原图用 `cover` 裁掉一部分、引擎又画完整幅，那样显示器和鸟会错位。

```css
#home-hero { position: relative; overflow: hidden; aspect-ratio: 2880 / 1621; }
#home-hero picture, #home-hero picture > img { display: block; width: 100%; height: 100%; object-fit: fill; }
@media (orientation: portrait) { #home-hero { aspect-ratio: 1280 / 2227; } }
```

- **横竖怎么选：** 引擎按容器的宽高选，高大于宽用竖版，否则横版；会监听容器尺寸，转屏时换底图和位置数据。上面的 CSS 让容器比例和 `<picture>` 的选图都跟着屏幕方向走，两边一致。
- `HeroLive.mount` 返回一个对象：`ready` 可以等素材准备好，`destroy()` 供前端路由离开首页时清掉这一层。

## 四、叠放顺序、点击、键盘焦点、字体

- 引擎层插在容器的最后，样式里是 `position:absolute; inset:0; z-index:0`。它自己成一层，内部的画布和屏幕层级不会跑到外面去。
- 整层 `pointer-events: none`，点击会穿过去落到下面的链接上。引擎只在容器上监听：开场中点一下画面跳到演完、点鸟叫一声。
- 首页的链接热区、按钮、文字要显示在画的上面（包括键盘 Tab 的焦点框），给它们加 `position: relative; z-index: 1`（或更高）。不加的话它们仍可点，但会被画盖住、看不见焦点框。
- 引擎层带 `aria-hidden="true"`，没有可聚焦的元素，读屏软件和键盘 Tab 都会跳过它；首页的无障碍文字仍由原图的 `alt` 和原有链接负责。
- 画里显示器上的字体写死在 `hero-live.346b811704.css`：`"Noto Sans SC","Microsoft YaHei","PingFang SC",sans-serif`，不跟随网站字体，样子和审过的小样一致。

## 五、放在阿里云 OSS 时怎么配

**地址：** 把整个包按原样传到 OSS 的一个目录，例如 `https://<OSS 或 CDN 域名>/hero-live/`，上面代码里的 `HERO` 就写这个地址。文件名已带指纹，以后每一版传到同一目录即可，新旧文件名不会冲突。

**跨域许可（素材和网页不在同一个域名时必须配）：** 引擎要把去鸟底图上传给显卡（WebGL），浏览器只允许上传按跨域方式读到、并且服务器明确许可的图；配置文件也是按跨域方式读的。OSS 控制台 → 该 Bucket → 数据安全 → 跨域设置（CORS）→ 创建规则：

| 项 | 填 |
| --- | --- |
| 来源 | `https://wly0829.cn`、`https://www.wly0829.cn`（还有本地预览用的地址就一并加上） |
| 允许 Methods | `GET`、`HEAD` |
| 允许 Headers | `*` |
| 暴露 Headers | 留空 |
| 缓存时间 | `86400` |
| 返回 Vary: Origin | 勾选 |

OSS 前面如果还有 CDN，要让 CDN 回源时带上 `Origin` 并按 `Vary: Origin` 区分缓存（或在 CDN 上配同样的跨域响应头），否则 CDN 可能把不带许可头的响应缓存下来给所有人。

**没配好会怎样：** 不会白屏、不会报页面错误，看网页的人看到的就是静止的原图；浏览器控制台会有一条跨域被拒的网络错误。挂载对象的 `diagnostics()` 里 `reason` 会是 `config-error`（配置读不到）或 `asset-or-webgl-error`（贴图被拒）。

**同一个域名时：** 如果 OSS 通过 CDN 挂在网站自己的域名下（例如 `https://wly0829.cn/static/hero-live/`），就是同源，不需要跨域规则。

## 六、缓存

- 带指纹的文件（引擎、样式、配置、全部 WebP）可以设很长的缓存：`Cache-Control: public, max-age=31536000, immutable`。
- 首页 HTML 本身不要长缓存，这样换新版时大家能拿到新的文件名。
- 换新版：把新包整目录传上去，首页改引用新的引擎和样式文件名（从新包的 `hero-live.files.json` 读）；旧文件先留着，给还开着旧页面的人，过几天再删。

## 七、状态从哪来

用驾驶舱**现成的状态读取结果**，映射成三种状态后调用：

```js
HeroLive.setStatus({ state: 'ok',   title: '一切正常',     detail: '这里填驾驶舱实际读到的简短说明' });
HeroLive.setStatus({ state: 'warn', title: '有事要处理',   detail: '这里填实际异常摘要' });
HeroLive.setStatus({ state: 'off',  title: '暂时读不到电脑', detail: '这里填实际的不可用原因或最近一次读取时间' });
```

`state` 只接受 `ok`、`warn`、`off`。首次挂载默认 `off`；读不到、读取失败、超时或结果不可用都给 `off`，不能把读不到当作正常。没有登录之类的分支。

画里右上角的小消息保留原来的出现、停留、淡出编排，显示本次 `setStatus` 传来的 `title`；`ok` 带一个对勾，`warn` 不带对勾，`off` 不出小消息。显示器上的时间按北京时间走，机箱灯随状态变色。

## 八、默认效果、减少动态、防卡死的保险

默认全效果，没有中档，页面上没有任何动效开关，没有配乐。点鸟会叫一声（声音是点了才合成的）。触屏可点；触屏不做鼠标纵深；手机上画布按设备像素比封顶 1.5。整体速度只有配置里的 `speed: 2.5` 一个数。

系统设了“减少动态”：不演开场、画面静止，只显示带鸟的原图和屏幕上的时间、状态；时间到了下一分钟才改那一个数字。

页面在后台、或这幅画滚出屏幕时暂停，回来再继续。

**防卡死的保险**，口径是“宁可不触发，不能误触发”。只看页面可见、画在屏幕内、动画在播时**实际画出来的帧**，满足下面任意一条才退回静态画：

1. 最近约 6 秒、至少 5 个帧间隔里，帧间隔的中位数超过 100 毫秒，也就是实际帧率的中位数低于 10；
2. 连续 3 帧以上、每帧都超过 1 秒，而且这几帧加起来超过 5 秒（一帧接一帧的长帧，就是卡死）。

不算的：刚开始播的头 2 秒；滚动中和最后一次滚动后 1.5 秒；页面隐藏或画滚出屏幕（浏览器自己暂停）；单次长帧（它只占窗口里的一个间隔，拉不动中位数，也凑不成连续 3 帧）。

退回静态只管这一次、这一页，不写 localStorage、sessionStorage 或任何浏览器存储，刷新就恢复全效果。触发时控制台留一句原因（哪条规则、实际帧率或长帧的时长）。退回后画里的时间和状态仍然显示。WebGL 上下文丢失也立即退回静态。

本版实测（无窗口 Chrome 154，RTX 5090 D 渲染，CPU 降速用 Chrome 开发者协议真实降速；手机是仿真，不是实机）：

| 场景 | 结果 |
| --- | --- |
| 电脑 1440×900，正常浏览 40 秒（开场、移动鼠标、点鸟、滚动） | 约 60 帧，不触发 |
| 电脑，4 倍降速，同样浏览 40 秒 | 约 61 帧，不触发 |
| 小米 15 Pro 仿真（432×960，像素比 3.33，画布封顶 1.5），正常浏览 40 秒 | 约 61 帧，不触发 |
| 小米 15 Pro 仿真，4 倍降速，浏览 45 秒 | 约 61 帧，不触发 |
| 小米 15 Pro 仿真，20 倍降速 | 触发（中位数规则：最近 6.1 秒帧率中位数 10.0） |
| 电脑，20 倍降速 | 触发（中位数规则：帧率中位数 7.5） |
| 单次 2.5 秒长任务 | 不触发 |
| 连续两帧各 2.5 秒，然后恢复 | 不触发 |
| 每帧卡 180 毫秒，只持续 4 秒 | 不触发 |
| 滚动期间每帧卡 180 毫秒，持续 12 秒 | 不触发 |
| 每帧卡 180 毫秒一直持续 | 触发（帧率中位数 6.0） |
| 每帧卡 1.1 秒一直持续 | 触发（长帧规则：连续 4 帧共 5.5 秒） |
| 每帧卡 2.5 秒一直持续 | 触发（长帧规则：连续 3 帧共 10.0 秒） |

所有场景浏览器存储写入为 0，触发时控制台恰好一句原因。

**帧节奏：** 本人主显示器是 4K、240 赫兹。按 2560×1440 页面、像素比 1.5（画布 3840×2162）取消限帧实测，着色器在 RTX 5090 D 上每画一帧约 0.6 毫秒，每帧脚本耗时 p99 约 0.4 毫秒，帧耗时 p95 不到 1 毫秒，远低于 240 赫兹每帧的 4.2 毫秒，所以没有加“每几次刷新画一格”的节奏控制。实测细节和没能测到的部分（真实窗口的显示合成）见本轮验收汇报。

## 九、退回原来的视频版

接入时请把“换原图 + 挂活画 + 停掉视频”做成网站仓库里**单独的一次提交**，退回就简单：

1. **最快：** 在网站仓库对这次提交执行 `git revert`，重新构建、发布。首页原图、视频的创建和加载代码都回到接入前。
2. **手动：** 删掉挂载代码、引擎脚本和样式的引用；从接入前那一版恢复首页视频的创建、赋 `src`、预加载代码；首页原图恢复成旧的 `home-01-h-2880-9442e7824a16.avif`、`home-01-v-1280-fae12132939e.avif`。

视频文件（`hero-64ed36342c7b310c-e181492b.mp4`）和它的蒙版图在活画稳定上线之前**不要从 OSS 或网站资源里删**，留着退回用。

## 十、只撤掉活画、保留白色静态图

删掉挂载代码、引擎脚本和样式这三处引用即可，首页就是那张白色静态原图。前端路由离开首页时也可以调用挂载对象的 `destroy()`。不需要恢复旧视频，也不需要改素材。
