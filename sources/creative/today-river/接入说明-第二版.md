## 画面的规矩（接的时候别改掉）

- **浮标是“现在”**，固定在河的 47% 处。右边是今天还没跑的，左边是今天跑完的。
- **河面上只放最近的几条**：浮标两边各 5 条，写着时间和名字；领头要来的那条多写一行“还有多久”。更早跑完的靠在左上的码头，更晚出发的在右下的码头等着，每个码头最多画 16 条，全部的数写在木牌上。这样不管哪个钟点、同一分钟有多少任务，船都不会叠成一竖排。
- **没升旗的船还没到点；升了旗的跑完了**，旗的颜色就是结果：绿正常、黄要留意、红出错、灰是跑了但没读到结果。
- **出错和要留意的船永远排在浮标左边最前面**，纸条是红色或黄色；河上方另有一行一行的提醒，带原因。
- **一直在岗的守护是岸边的灯**，不是船：状态是“正在运行”的、每隔半小时以内就查一趟的、写着“常驻”的，都算守护。守护出错时那盏灯变红并闪。
- **岸上的船**是今天没有安排的和停用、从没跑过的，只各画几条，数在木牌上。
- **雾里的船**是这次没读到运行结果的，不代表出错。
- **天色跟着杭州的日出日落**：夜里河偏蓝偏暗、灯更亮，小鸟在睡觉；纸的留白不跟着变暗。
- **小鸟**和首页是同一只，站在“现在”的牌子上，点它会叫（和首页同一种叫声）。
- 只看，不能操作。没有任何动效开关，没有配乐。

## 数据怎么传进来

沿用驾驶舱已经读到的 `automation` 这一块，不另建接口：

```js
todayRiver.setSnapshot({ captured_at: automation.observed_at, sample_kind: 'live', automation });
```

`setSnapshot(数据)` 默认不重放开场；`setSnapshot(数据, true)` 或 `todayRiver.replay()` 重放。用到的字段：`automation.state`、`observed_at`、`groups[].id/name`、`items[]` 里的 `group`、`enabled`、`state`、`last_run_at`、`next_run_at`、`schedule_zh`、`status_note`（或 `plain.status_note`、`reason`）、`plain.name/what/stop/impact`。时间只认带时区的 ISO 字符串，一律按北京时间显示。所有文字都先转义再放进页面。

每个任务分到哪里（`river2.template.html` 里的 `sort()`）：

1. `enabled === false` 或 `state === 'disabled'`：岸上（停用）。
2. 守护：`state` 不是 `unknown/never`，并且 `state === 'running'`、或 `schedule_zh` 写着每分钟／每 N 分钟（N ≤ 30）／每 N 秒一次、或写着“常驻”。
3. 今天跑过（`last_run_at` 是今天且不晚于读到的时间）：浮标左边的一条船。
4. 今天还要跑（`next_run_at` 是今天）：浮标右边的一条船。一个任务今天既跑过又还要跑，就是左右各一条。
5. `failed`、`warn/overdue/stale` 而今天没跑的：也放到浮标左边最前面，纸条写它上次的时间。
6. 其余：`unknown` 进雾里；`never` 且没有下一次的算岸上（从没跑过）；剩下的算岸上（今天不出航）。

**第 2 条靠读 `schedule_zh` 的文字来认守护，是权宜的办法。** 更稳的做法是在电脑那边的只读采集里给每个任务加一个“是不是常驻或高频守护”的字段（AI 建议，没做，本轮没有动 PCConfig）。

整块 `automation.state` 是 `unknown / unavailable / stale` 时：河变灰、停住、灯灭，顶上写“现在读不到电脑”和最后一次读到的时间。`partial` 照常画，没读到的进雾里。

## 动效和保险

- `river2.template.html` 里只有一个 `SPEED = 2.5`，水流、船、灯、旗、开场都按它走。各项动效自己的时长写在样式（`calc(Xs / var(--speed))`）、开场常量 `I` 和水面着色器里，下面写的都是 SPEED = 2.5 时的真实秒数。
- 开场约 6 秒：河从浮标那里晕开（约 1.2 秒），牌子上的钟从 00:00 走到现在（4 秒），今天跑完的船按各自的时间一条一条穿过浮标并升旗（每条从出现到停稳 1.8 秒，靠码头的 2.2 秒），要来的船从右边划进来（每条 1.6 秒，前后错开 0.2 秒），灯一盏一盏点亮（前后约 2 秒），木牌淡入，小鸟最后落下。
- 平时：水往右流，1460 宽的画面上每秒约 9—10 像素；水面的光网、微微晃动、船尾水痕都按同样的慢节奏走；碎光每一粒一亮一灭 2.6—3 秒；船起伏一个来回 5—7 秒，小旗摆一个来回 2.4 秒；灯的明暗 6—7 秒一个来回，高频守护那盏灯约 8 秒跳一下，出错的灯约 1.9 秒闪一下；浮标起伏 4.5 秒；雾飘一个来回 20—26 秒；纸条、木牌、灯的淡入约 0.5 秒。
- 系统设了“减少动态”：直接是最终画面，一格不动（已验证没有任何动画在跑，水也不重画，整页截图隔 1.5 秒完全一样；单拍舞台那一块的截图第一张和第二张会差几个灰度，是截图工具自己的问题，调慢前后都这样）。
- 防卡死的保险和首页同一个口径：页面看得见、动画在播、连着大约 5 秒帧率的中位数低于 10 帧，才退回静止；头 2 秒不算，单次长帧不算，页面隐藏不算；只管这一次这一页，不写任何存储，控制台留一句原因。
- 不支持 WebGL 或图读不出来时，自动改用静止的原画，船、灯、木牌、日志照常。

本机实测（RTX 5090 D，无窗口 Chrome；帧率两行是调慢之前测的，调慢只改了时长，不改每格的工作量）：

| 项目 | 结果 |
|---|---|
| 不限帧率时，电脑 1760 宽 | 开场每秒 287 帧，平时每秒 887 帧 |
| 不限帧率时，手机 393 宽、3 倍屏 | 开场每秒 241 帧，平时每秒 827 帧 |
| 电脑、小米 15 Pro 模拟，CPU 降速 4 倍 | 每秒 51—52 帧，保险没有触发（10 月 3 日调慢后复测） |
| 电脑，CPU 降速 20 倍 | 之前测到帧率中位数 3 帧、保险触发；10 月 4 日复测时调慢前后两版都一样，9 秒里只走出 1—2 格（重放开场这一步本身就卡住了），保险来不及判断。这一项和调慢无关，按下一行的人为拖慢为准 |
| 人为把每格拖到 150 毫秒 | 保险触发（帧率中位数 6.0 帧），本地存储和会话存储都是 0 条（调慢后复测） |
| 中途单次卡 1.5 秒 | 保险没有触发（调慢后复测） |

弱显卡上的真实帧率没有实测过，只有上面的降速模拟。

## 录像

`python tools/record_river2.py all` 逐格录两段 12 秒的录像（1500×900，每秒 60 格，H.264、yuv420p、crf 18、+faststart）。录像时页面自己的循环不跑，脚本每一格用 `todayRiver.seek(t)` 定格脚本算的部分（船、钟、灯、水面），用 Web Animations API 把样式动画和过渡逐格往前推 1/60 秒，小鸟换姿势的定时器也按录像时间走；页面本身的行为没有为录像改。录完会用 ffprobe 核对帧率和格数，并数相邻两格完全相同的有几对，结果在 `shots2/record60-result.json`，抽格图在 `shots2/record60-*-sheet.jpg`。

## 正式接入时要改的

- 小样把河图、水面范围图、四条船、小鸟都用 base64 装在网页里（每个网页约 960 KB）。正式接入时改成 `assets2/` 里的文件走相对路径（河图 503 KB、水面范围图 26 KB、每条船约 20 KB、小鸟每个姿势约 6 KB），注意要从同一个来源加载，否则水面动效开不起来、会退回静止原画。
- 删掉页面底下那句“这是本地小样”的说明和两张验收页；`todayRiver.seek()`、`resume()` 是验收用的入口，可以留着也可以删。
- 页面标题区（“驾驶舱 / 自动任务”、标题）用驾驶舱原有的，不用小样里的。
- 小鸟以后由全站统一的那一套来管时，把这里的 `perch()` 换掉即可，位置是“现在”牌子的左上角。
