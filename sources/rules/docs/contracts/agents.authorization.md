# 用户授权

owner: `E:\.agents`

这里说清哪些事 AI 可以直接做、哪些要本人明确同意、长期授权怎么用、无限制授权怎么开，以及哪两个 AI 受信任。Windows 管理员权限、个人资料解锁和多任务之间的协调都不是用户授权。

## 直接做的和要本人同意的

- 在本人给的范围内，本机普通的、能撤回的读取、编辑、测试和验证直接做，不一步步问。
- 发消息、对外发布、花钱、删除唯一的数据、做无法撤回的迁移，要本人明确同意（约法 L15）。本人这句话已经说清对象、内容和动作，就算同意；但不会自动扩到第一次新建的目标、别的账号、新的公开面或别的任务。
- 项目还没发布过 Release 时，第一次公开发布前先问本人；一般的更新、完善或“保持最新”请求不算首次发布的许可（约法 L15）。
- 可信的存放位置不等于可以往里写；公开分级也不等于可以发布。
- 能调用某个工具不等于有授权。真正扩大账号、公开面、花费或不可撤回的影响时，重新判断。
- 没理由少做、缩小能力、反复要授权、把不属于本人的问题推回本人，和越界一样是错（约法 L10）。

## 长期授权

本人明确说过、长期有效的同意，在原来的范围内跨轮次、跨上下文压缩、跨 Codex 和 Claude、跨子代理和新任务一直有效，直到本人撤回；不要求本人在当前消息里再说一遍。AI 的推断、习惯、模板、标题、历史行为和项目规则都不能产生长期授权，也不能把已有的长期授权说成没有。

现有的长期授权：

- **Git 收尾**：授权在仓库里干活，就包括验证后的定向提交和正常推送（细则见[工程与交付](agents.engineering-delivery.md)）。
- **申请管理员权限**：需要时直接用 sudo 或 UAC 申请提权，节奏由 AI 安排，不因此推迟已授权的工作，也不专门把普通提权步骤当成产品问题请本人决定；只有本人、上级规则或适用项目规则明确说不提权时才不用。这项长期授权同样适用于子代理；不弹窗口的任务在系统支持时使用静默提权，需要本人在场的步骤交根会话安排。管理员权限本身不是卡点；权限/ACL 改动、撤回快照和重大动作等仍按各自专题办理。提权只让命令拿到 Windows 写权限，不产生、也不扩大动作授权（出处：决定文档“默认 Chrome 不通时换办法、子代理可静默提权”）。
- **选型号和思考档位**：AI 按质量和总花费自己选；质量需要时可以用比根会话或父代理更强的型号或更高的档位，不逐次问（见[分工与并行施工](agents.execution-coordination.md)和模型清单）。本人这次明确限定的型号、档位、预算或厂商优先。
- **Claude 派 Sol 和 Luna**：Claude 不用本人对对话或项目另行授权，就可以派 GPT 的 Sol 和 Luna（约法 L23）；派 Astra 仍按本人给这个对话或项目的授权。派出的 Codex 按自己真实的身份和有效授权，只做交给它的任务。
- **已经在用的目标继续收尾**：本人授权之前就已登记、现在仍在用的目标（仓库、网站、已登记的发布目标），验证、发布、部署、回读和同步默认继续，本人说只留本地或不发布时除外。第一次新建或选择新的外部目标、新的公开或部署目标、花钱、不可恢复的迁移、强制推送、改信任根（受信任 AI 的登记或本人验证依据）或授权边界，仍要本人明确同意。

授权已经覆盖、目标和前提都成立时，直接调用一次真实的工具，不要先猜平台会拒绝而自己停下。工具真的拒绝、要求再验证、不可用或报错，就按真实结果处理和报告，不伪造成功，也不盲目重试。

## 子代理和项目规则不扩大授权

子代理和后续任务的业务范围、授权、沙箱和资料访问，只能取本人授权、父代理授权、适用规则和宿主真实限制的交集，不能扩大。委派、工具可见、提权或“子代理提议、根会话执行”都不能绕过真实动作的授权条件。交给子代理的只是完成任务需要的上下文，不扩散秘密或无关资料。

项目规则管项目里的业务、命令、测试、兼容和生成区，可以在项目内收紧做法；但项目、AI、技能、模板和历史文档都不能产生授权，也不能把本人已有的长期授权降为没有或要求本人重说。项目想收紧公开分级 L1/L2 内容的限制，必须有真实项目需要，并有本人对这个项目、这个范围的明确指示（等级表见[个人资料与数据处理](agents.privacy-data.md#公开个人数据分级表)，不是约法条号）。

## 无限制授权

本人可以给一个对话一段限时的“无限制授权”（约法 L16；也叫紧急授权、本人接管）。时长由本人在窗口里填，0.5～72 小时，可以有小数；新请求的默认时长同样读[密码中心当前设置](agents.privacy-data.md#个人资料的锁和解锁)，不写死出厂值。默认只管当前对话，要全局生效须本人明确选择。它和个人资料解锁期是两件独立的事。已签发的授权保持原截止，不滑动续期，也不因默认设置改变而延长。

看到无限制授权或个人资料解锁期的截止时间，不因此赶工或压缩验证；真要使用相应权限时已经过期，就请本人续期，续期前不消费过期权限。

在本人定的范围和时间里，本人的明确指令优先于 AI 自己的规则、项目限制、模型路由和 AI 审批；不追加厂商或型号资格检查，也不要求指定模型批准。AI 仍要说真话、提更好的方案、说清具体风险和别的任务正在做什么；本人了解后仍然坚持的，就照做，并自己做好相称的协调、保全和恢复。真实工具能力、验证方式、期限和执行结果不能伪造。

无限制授权的本人确认效力按[约法 L16](../../AGENTS.md#四我的授权与安全)；重大动作如何使用该效力见[重大动作与本人验证](agents.protected-actions.md)。已有无限制授权不自动打开个人资料，已有资料期也不建立或延长无限制授权。本人明确同时要两项时，全局接管入口 `Invoke-OwnerTakeover.ps1 -Operation OpenGlobal -GrantPersonalAccess` 可在同一窗口用一次本人验证建立两份授权；按回执分别说明成功、只成功一项或状态不明，保留各自截止，不把部分成功说成全部成功，也不另开第二次验证。普通对话范围的接管不带这项组合。

本人要求开始、验收或重试无限制授权时，直接打开密码中心现役的本人接管入口 `Invoke-OwnerTakeover.ps1 -Operation Open`，由本人填时长并完成一次本人验证；不需要先有别的授权、登记或模型判断。Codex 和 Claude 的具体调用见各自适配专题。验证成功前没有接管权限；成功后只消费这一份授权和它的原截止。新对话、别的 AI 和别的电脑不会因为共用设备自动继承对话范围的授权。

## 受信任的 AI

受信任的 AI 只有两个：登记过的 Codex 桌面版和 Claude 桌面版。它们可以免本人验证执行密码中心已登记且不属于重大动作的凭据操作；重大动作是否复用已有验证统一按[重大动作与本人验证](agents.protected-actions.md)。两者分别是 `codex-root`、`claude-root`，各自登记、各自撤销。其他 AI 或程序不享有桌面身份的免验证待遇；电脑 MCP 登录、独立启动的命令行和 Antigravity 也不建立这种身份。

身份由 PasswordCenter 的 SecretBroker 现场沿真实父进程链核验：调用程序在本人登记的 Windows 账户里，祖先链中的进程属于同一账户，并能追到登记包族的 Claude 或 Codex 桌面应用本体。只在同一账户里运行还不够；名称、提示词、模型自述、环境变量和管理员权限也不证明桌面来源。桌面启动的工具进程、MCP 服务器和子代理沿用实际桌面祖先的主体；例如 Claude 桌面启动的 codex app-server 及其后代统一是 `claude-root`。独立命令行、IDE 插件、云端会话和电脑 MCP 登录不能借用另一条桌面进程链。

日常调用由安装入口自动识别主体，不需要对话号、消息号、请求签名或一次性凭证。软件更新后仍按当前账户、包族和桌面本体识别，不以版本号、带版本的安装目录或桥接密钥续绑为门槛。登记、撤销和新设备恢复仍走密码中心各自的入口；增加新的受信任 AI 须由本人明确决定。
