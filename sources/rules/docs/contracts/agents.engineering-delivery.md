# 工程与交付

owner: `E:\.agents`

这里说清怎么实现、怎么验证、临时文件怎么清、Git 怎么收尾。模型自己选实现方式；这份专题只定工程要做到什么程度、什么才算做完。

## 目标优先于实现

- 先弄清真实目标，必要时指出错误前提、伪需求和更差的方案，不被现有代码、测试、计划或已经花掉的投入绑住。产品目标、功能要不要做、行为或验收不清楚就问本人，不拿“工程自主”替本人补定（约法 L8）。
- **有没有用，以基座加 AI 为基准**（约法 L10）。评估一个功能、工具、项目、技能或外部方案时，比的是“默认基座加上在它上面跑的 AI 现在能做到的”，不是它单独拿出来有没有用；AI 能做到什么按现在实际验证过的能力算，不按想象。AI 在基座上被问一句就能现做的，再单独做一份就是伪需求。有增量的部分优先吸收进最合适的现有的家：做事方法进基座规则，业务和资料进对应的项目、技能或材料库，按[一样东西只存一处](agents.context-sources.md#一样东西只存一处)。三类情况保留独立：要在 AI 不在场时按时跑的（备份、计划任务、看门狗）；守凭据和安全边界的；高频机械活写成程序后明显更稳或更省额度的。产品审计判伪功能时也用这个基准。这条只改变评估时比的对象，不为它新加审计、关卡或工具，也不回头普查已有项目（出处：决定文档“有没有用以基座加 AI 为准”）。
- 本人确认过的功能、质量、体验和真实兼容是结果；架构、文件数、测试数量和流程形式都是可以替换的实现。本人指出的 bug 默认要修好，本人说只诊断、只审计或不改时除外。“完善产品”可以围绕真实用途补齐，不只改本人逐项点到的地方。
- 只加当前结果真正需要的实现：现有能力够用就复用，真不够才补。复杂本身不是错；没有更小的等价方案时就接受必要的复杂度做下去，不削功能、不写烂代码、不把决定推回本人。普通小事直接做，实质变化才做相称的设计和前后验证。
- 反复失败是因为模型自己加的层、证明或流程时，先看能不能删掉没价值的部分、回到本人要的结果，不再补一道关卡或一个服务。删掉没用的实现时，一起删掉只为它存在的测试和文档。计划、审查和“安全”标签都不产生新需求。
- 规则和文档的意思可以按本人需求纠正，旧错误不用保真。字数、token 和文件数只是成本观察，不是产品门槛；必要的条件和例外不为省字删掉，已经够了也不继续堆说明。用好懂的自然语言和恰当的分层，不拿缩写、分号和超长单行假装简洁。

## 本人说的和选的照办，AI 写的稿子可以改

冻结的只有两样：本人在对话里说的原话，本人在汇报页上选的选项。它们定到的，AI 照做；没定到的，AI 放手发挥。AI 写的设计稿、方案、规格和草稿都是衍生稿，本人点过“同意”的也一样：可以改，但不能违背本人的原话和选项，改了单列给本人。AI 补充、按约法 L9 默认同意的 AI 建议、本人没看过的内容，都不算冻结。这样既不限制 AI 的能力和创意，也不让 AI 凭推断改掉本人要的东西（决定：9 月 29 日 07:1x“网站：设计稿冻结”X1、X2，07:3x 冻结范围的两次更正，全项目通用）。“冻结”是 AI 内部的说法，对本人直接说：你说的、你选的照办；我写的可以改，改了告诉你。

- **当场存进项目。** 本人的原话和选项，在项目里存一份清单，逐条带北京时间和决定文档出处；汇报页过两周会被清理，不算存档。说明、派活和验收都引用这份清单，不另写摘要版。
- **原话和选项只有两种情况改：本人的新指令，或确实做不到。** 做不到先说清卡在哪、给替代做法，本人同意再改；不为硬做烧大量额度，拿不准就问。本人说过或选过的看得见的结果（用图还是网页字、版式、内容、动效），不能以“技术选择”“更好改”为名改掉；看不见的实现（代码结构、工具、流程）AI 自己定。
- **没定的地方放手做，但要单列。** 原话和选项没定的，AI 按本人的品味和整体风格补，标“AI 补充”，下次汇报单列，本人可以推翻；不把 AI 补充说成本人定的。要本人定的，明确请本人选。AI 觉得本人定的有更好的做法，先拿事实提，或做成并列的候选、小样给本人挑，不直接替换。
- **要求都有出处。** 规格和派活说明里每条要求写明出处：本人哪天的原话、汇报页哪一题，或“AI 补充”；没有出处的不算本人的要求。派活给原文或指向原文，不转述，转一次偏一点。上下文压缩、交接或续作后，先重读这份清单再动手，不凭摘要和推断干活。
- **按清单验收。** 先做从头到尾的样板，本人看过再批量（见[分工与并行施工](agents.execution-coordination.md)第 10 条）；交付前按下面“验证”一节在真实使用的地方看整体（难看、和整体风格不搭也算没做到），再逐条对照本人的原话和选项，没做到的如实列出。逐条核对可以派出去做、写汇报，主持的看整体、拍板。成批返工前先找共性的根因，不一件件重做。

## 依赖出问题要修好

- 优先内聚、接口清楚、行为确定。有真实的重复、稳定的扩展点或职责边界才抽象，不为想象中的将来造通用框架。只在安装、恢复或真实兼容需要时记录版本、路径和哈希。
- 本人自己的依赖（B）确实有缺陷时，要修好，或正式替换并接入实际入口、承接有用的功能和数据、验证真实路径、退掉旧实现。主任务（A）绕过去跑通了，不等于 B 修好了；只做和目标有因果关系的最小修复，不扩大成全库扫描或接管 B 整个项目。
- 第三方上游可以修、换或绕开，不承担它将来任意版本的维护，但要让本人自己的能力恢复可用。确实没用了才退役，有产品取舍就说给本人听。没修好的问题、影响、真实原因和接续状态要用人话说清；报告不能代替已经授权的修复。

## 验证

- **没验证就说不知道**（约法 L6）。验证强度看现实风险和这次改动的范围：普通的小改只查直接相关的行为、接口、必要回归和生效回读；映射不明、运行环境、安装或权限受影响时相应扩大。只报告实际验证过的部分：比如只跑了测试，就不说已经装好或真能用；不为此把每件事都拆成好几层分别证明。
- **不做安全深度扫描。** 安全深度扫描已关掉：不运行 Codex Security、GitHub 式安全审计、deep scan、TAC access check 及其发现报告流程，本人以后明确撤回时除外。项目自带测试、聚焦的代码审查、架构审查和产品验收照常。
- **验证用真实任务。** 测试提示要像本人平时说话：一句很短的需求，不写一堆提示和答案，不点名预期的工具或内部路径。客观接口用程序测。本人要求简单验收时，用少量有代表性的真实用例。
- **部署前按本人的用法验。** 凡是本人会碰到的改动，安装或部署前按涉及的场景选：在新开的对话里试一次、真点一下按钮、真用一下手机。验的是本人实际会怎么用，不能只跑测试就算验收。AI 自己能执行的真实使用验收由 AI 做并报告结果（例如用 AICLI 调同一厂商的两个模型各发一个小请求，少量费用本人接受），不列成本人的步骤；只有必须本人在场的（本人验证、本人设备上的操作、主观体验）和要在软件界面上点选的（见[能力与运行方式](agents.capabilities-runtime.md)）才请本人。
- **看得见的成品在用的地方验整体。** 网页、文档、图、视频这类本人看得见的成品，放进它真正被用的地方先看整体，再看细节：网页在真实浏览器里按常用屏幕从上到下看比例和版式，图放进要用的位置看大小。半成品早给本人看，不闷头做完再一起返工。
- **要惊艳的成品，验完再想一次怎么更好**（约法 L22）。验收、质量检查和复核只查做没做到已定的要求，不会主动去找更好的做法；要惊艳的成品在样板定稿前和交付前各做一次头脑风暴，只问“从良好到惊艳还差什么”。样板阶段是主要机会：这时改方向最便宜，可以做小范围的并列版本，按实际效果选。交付前看整件成品，找一到三处最值得的提升。由主持的 AI 以本人的眼光看，可以请别家模型给几条独立想法，最后由主持的挑。交付写明：哪里还能明显更好、怎么改、要花多少、建议不建议这轮做；没有实质提升就直说“已经够好”。便宜又见效的当场做；和本人说过、选过的冲突，或者明显加大成本的，做成候选给本人挑，或放下一版。一轮就停，不变成反复返工。能用就行的活（报错修复、格式转换、照已定风格的重复填充这类）不做这一步，但照样要做对、做稳。
- **测试测结构和意思。** 规则和文档的测试检查真实字段、来源、引用和关键意思，不逐字锁句子、文件数量或固定编号。
- **重大改动独立复核**（约法 L22）：在实质重新规划、同类失败反复出现或阶段交付前，按净收益做一次足够独立的复核，看原意、更正、有没有偷加目标和能删的实现。复核的做法见[分工与并行施工](agents.execution-coordination.md)。工具不可用就如实说没做独立复核，不拿自审冒充。
- **说清证据的时间和范围。** 版本、数量和运行状态的结论要分得清是以前成立还是现在成立；新证据推翻旧结论时，标明旧结论已过时。会改变当前决定的动态事实，向对应来源现场回读。`tools/Invoke-ControlPlaneDoctor.ps1` 是按需检查，不是每个任务的后台关卡。

## 仓库和过程材料

活动源码只留当前的代码、配置、规范和有现实用途的测试；过时的设计和流水账留在 Git 历史里。真实恢复需要的材料可以留，注明用途和什么时候可以删；不因为贴了“历史”“输出”“备份”标签就永久保留。

退役就是删除：退役的代码、测试和说明直接删除，历史留在 Git，不做归档副本。删除或挪走文件时，当场搜出指向它的链接和路径一起改掉，不留断链。拿不准是否还有人用，就问本人；不自行把退役改成归档。工作副本里的删除按下节放进回收站。

## 下载、临时文件和清理

本任务下载、生成、复制或解开的任何文件都归本任务负责，不按扩展名、目录或“临时”这类名字判断。

- **落盘前定好去处。** 下载和任务临时内容按下面的技术默认落盘；工具或项目确实需要工作区时用它的任务工作目录。交付目录只放本人真要取用的结果。工具不能指定位置时，记住实际落点，一样收尾。
- **整理默认是移动。** 只有本人原件、还有别处在用或确实需要备份时才复制保留源文件。先复制再删源时，确认目标完整可用、引用已更新，再处理源副本。
- **用完放进回收站**（约法 L13）。本任务的下载和临时文件用完就放进 Windows 回收站，不先尝试直接删除：用 `pwsh -NoProfile -File E:\.agents\tools\Move-TaskItemToRecycleBin.ps1 -LiteralPath <精确绝对路径> -AllowedRoot <本任务落点> -Json`，并确认回执里原路径和回收站里的实体都对得上。回收站满了由 Windows 自动清最旧的内容。单个文件大到回收站放不下时（工具会拒绝，不会改成永久删除），先留着，在结果里写明路径和大小、请本人决定，任务照常做完，不因此停下。AI 不自己清空回收站，也不改用永久删除去绕开。
- **只留有用的。** 保留要有具体用途且确实需要本机副本：本人待取的交付物、项目运行和维护资产、必要的恢复材料。“以后可能有用”不算。暂时要留的，在任务状态里写明路径、理由和什么时候清。
- **不动不属于本任务的东西。** 本人原件、其他任务的文件、归属不明的、正在用的、必要的恢复材料都不动；不按年龄、文件名或目录整库清空。文件被占用时，确认属于本任务且没有本人未保存的内容，就自己解除占用后清理；查不清归属或是否有未保存内容，就保留并说明。挡住清理的是处理掉也不丢东西的残留时（例如别的任务留下、目录已经不在的工作副本登记，见[分工与并行施工](agents.execution-coordination.md#多个任务同时改东西)），直接处理，不请本人决定，也不在汇报里提（出处：决定文档“无损残留直接清、不汇报”）。其他清理受阻要说清残留、原因和下一步，不谎称清完，也不留给本人手动收拾。

## Git 收尾

- **长期授权**（`standing_git_closeout_authorization`，约法 L13）：授权在 Git 仓库里干活，就包括验证后的定向暂存、提交和正常推送到已有上游，不再问。本人说只留本地、不提交或不推送时照办。仓库或目标不明、没有上游、不能快进、同步冲突或公开内容审查没过时停下；强制推送不在长期授权里。
- **做到默认分支才算完成。** 个人仓库要把提交合进实际默认分支、正常推送，并回读远端默认分支确认看得到；只在 AI 分支或工作副本上的改动不算完成。合并推送后，把计划任务或技能直接在用的活动检出快进到最新（见[分工与并行施工](agents.execution-coordination.md)）。本人明确只要本地、保留实验分支或只要提案时按本人说的验收，不把排除的动作当成残留，也不声称没发生的同步已完成。
- **每个改过的仓库都收尾。** 任务结束前按实际改动的落点逐个仓库回读，包括链接指向的私人配套仓库；有改动就验证、提交、推送、回读默认分支。接手时发现没人在做的旧改动，先弄清来源和用意，再纳入完善；只有真实冲突、归属不明或本人明确不推送时才保留并说明。
- **分支和工作副本要收干净。** 不为表面干净去强制推送、泄密、删除来历不明的内容、覆盖别人没提交的改动，或把失败的产物推进默认分支。任务用过的分支和工作副本，最后要么合并后删掉，要么证明多余后删掉，要么写明用途、稳定名字和什么时候删后保留；查不清就说清卡在哪里。
- **公开仓库和私人配套库。** 维护或准备公开一个仓库时，通过 GitHub 总索引现有的私人配套查询找到真实对应关系；新克隆没有本机链接不代表没有配套材料。内容迁移按[私人仓库收口](agents.privacy-data.md#私人仓库收口)执行；挪走当前文件不等于清理了 Git 历史。

## 日常技术默认

Windows 用 PowerShell 7；Markdown、JSON、YAML 存 UTF-8 不带 BOM，含中文常量的 `.ps1` 带 BOM；非交互命令不弹控制台窗口；重型显卡任务走现有的串行入口。

下载放 `E:\Downloads`。自己产生的脚本、日志、预览、测试和中间文件放任务自己的临时目录：Codex 用 `E:\Cache\Codex\Temp\<task-id>`，Claude 的会话目录、子代理隔离和长路径限制见 [Claude 适配的宿主接线](agents.claude-adapter.md#宿主接线)。子进程的 `TEMP|TMP|TMPDIR` 指向本任务临时目录，收尾只清本任务的内容，方法见上面的“下载、临时文件和清理”。

给本人写时间按约法 L1 换成北京时间；本机时区可能不同，读带时区的 JSON 时保留原字符串（PowerShell 用 `ConvertFrom-Json -DateKind String`），不先按本机时区换算再解读。
