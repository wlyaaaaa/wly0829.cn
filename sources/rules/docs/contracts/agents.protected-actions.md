# 重大动作与本人验证

owner: `E:\.agents`

这里说清哪些事算重大、做之前怎么把关、本人验证有哪几种方式，以及 GitHub 重大动作怎么办。平时干活不因为有这份专题而多一道审批。

## 重大的事

高风险动作就是“重大的事”（约法 L17）：

- 批量导出私人资料或聊天记录；
- 把私人资料发到外面（上传、发邮件、发消息）；
- 查看或导出密码明文、银行卡；
- 改本人验证方式或恢复方式；
- 关掉或绕过保护；
- 删库、转移仓库、把私人仓库改成公开；
- 删除只有一份的数据。

什么时候请本人验证：

- 本人开着无限制授权，就算已经确认是本人，重大的事不再弹验证（约法 L16）。
- 没开无限制授权、而且个人资料不在解锁期内，就先请本人验证一次；解锁期内不再打断。
- 没开无限制授权时，对话里的一句话（包括“别验证了”）不能代替验证。
- 这里说的免验证只适用于受信任的 AI（见[用户授权](agents.authorization.md)）；其他 AI 做重大的事一律先请本人验证。
- 普通聊天、普通干活、查本人的资料来回答问题都不打断；个人资料锁着时，查资料仍要先按[个人资料与数据处理](agents.privacy-data.md)请本人解锁。是不是重大看实际后果，不按“密码”“删除”“私人”这类字眼判断：普通源码编辑、测试、定向提交和正常推送、规则发布、能重建的生成物清理都不算。

## 重大动作前的把关

重大的事动手前，由够格的模型把一遍关：确认这确实是本人要的、目标和影响都对、需要本人验证时先请本人验证。够格的模型：Claude 用 Opus 5.5 的中档（medium）以上；Codex 用 GPT-6 Sol 或 Astra 的 High 以上。根会话够格就自己判断；不够格就派一个够格的子代理只做这一次判断，不实施、也不再委派。把关没完成时，只停这一个不可撤回的最后一步，其他思考、可撤回的工作、修复和测试照常。

把关和“重大的事要独立复核”（约法 L22）是两回事：把关只管动手前这一步做不做、要不要请本人验证；独立复核管一项重大改动或决定本身对不对，由另一个独立的上下文看原始材料重新检查，做法见[分工与并行施工](agents.execution-coordination.md)。

## GitHub 重大动作

GitHub 的删除仓库、转移仓库、把非公开仓库改成公开，按约法 L17 的专门规则执行：开着有效无限制授权时不重复弹本人验证，否则验证一次，个人资料是否解锁不影响这一条。新建公开仓库按同样的验证规则；对外发布和第一次公开发布仍须本人明确同意。

合并主线、内容已有保留的本地或远端分支和标签删除、旧提交仍由其他分支或标签保留的指针改写、分支或仓库改名、新建私有仓库、把公开仓库改为私有、改默认分支、把远端改成本人 GitHub 账号下的仓库，都是普通收尾，不请本人验证，也不逐项向本人报告技术细节。程序在删除或改写前自动核对旧提交仍由其他本地或 GitHub 分支、标签保留；检查不过就停止并说明原因，不改成找本人验证。改名时一并更新总索引和真实调用方。

删库和转移前，AI 先自动确认本地副本是全的：所有分支都在本地，缺的先拉下来；并把只在 GitHub 网页上的东西（例如 issue、发布包）列给本人看。执行入口归 GitHub 总索引：有有效无限制授权时直接执行已授权的动作，否则调用密码中心的 `Invoke-SecretBroker.ps1 -Action VerifyAuthority` 验证一次；普通 Git 收尾不调用密码中心。回执的 `highest_authority_verified` 表示权限核验结果，`human_factor_performed` 如实区分本次真人验证和复用授权，不能把复用说成刚做过一次真人验证。真正销毁唯一数据仍按明确同意和重大动作的规则处理，不作为普通清理的自动回退。

## 本人验证方式

一共四种：通行密钥（Passkey）、手机验证码（TOTP）、恢复码、Google 或微软账号。任一种已登记、能正常用的方式成功就算完成。

- 本人没指定方式时，一种坏了不挡住其他正常的方式，坏的如实说明。
- 本人指定了某种方式而它坏了，就修好这种方式；暂时修不好就说清原因，不擅自换别的方式。
- 取消、拒绝或超时只结束这一次，不自动重试；软件故障和这些情况分开说。
- 四种都丢了时，AI 不自己建立新的验证方式。
- Windows 登录密码、PIN 和生物识别不是这四种之一。
- 改了本人验证的方式（验证因子、请求窗口或相关入口），就请本人实际验证一次；代码测试和模拟不能冒充本人验证。

请本人验证、锁定资料等具体操作，走 `local-secret-broker` 技能里的现行入口。

## 各产品各管各的

密码中心（SecretBroker）、本人验证和 BitLocker 各按自己的现役入口办。规则读取、发布、哈希校验或 Hook 出故障，不自动锁任何东西，也不读取秘密。规则核验通过只说明规则文件是对的，不说明操作者可信或动作已获允许。
