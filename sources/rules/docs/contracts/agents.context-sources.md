# 事实来源与任务上下文

owner: `E:\.agents`

这里说清事实找谁、哪些项目冻结、项目分几档维护，以及长任务怎么接续。授权、施工和执行结果由各自专题负责。

## 事实找谁

- `E:\.agents`：AI 的行为规则、授权、能力路由、规则发布、个人技能和插件、跨项目协作。
- `E:\GitHub总索引`：仓库身份、公开或私有、远端、分支和工作副本、同步、恢复和发布事实。它只提供事实，公开分级和授权结论用本仓库的规则，不自己另定等级。
- `E:\PCConfig`：机器路径、端口、计划任务、运行环境、数据源、迁移、备份和恢复事实。
- 具体项目：业务含义、领域数据、兼容、启动、测试、部署和生成区。

按需要一步步读：看到绝对路径不等于要把三个基座全扫一遍。普通项目先读目录链上的规则和本地状态；只有 Git 事实会改变决定时才问 GitHub 总索引，只有机器事实会改变决定时才问 PCConfig，只有规则、能力或授权会改变决定时才读本仓库对应的专题。不知道的就说不知道，不从别的来源猜。

三个基座的日常治理是发现并修好有事实依据的问题，不是补跑备份。计划任务机制正常时，只看它有没有按时跑、回执对不对（约法 L21）；不为了刷新成功时间或让报表变绿去额外运行备份。已经证实的机制缺陷在原项目里修好并做相应的局部验证；本人暂停的任务保持暂停。

## 冻结的项目

冻结的项目（约法 L24）：本人没主动提这个项目的具体需求时，AI 不主动看代码、研究、审计、修复、升级或优化；它们的计划任务停用，换电脑时也不重建。本人说“全部项目”“全局完善”这类批量指令时，默认不包括冻结项目，也不先读它们的代码再决定。本人点名提具体需求时，只按这次需求取材和处理，不需要说“解冻”，也不因此恢复日常维护；只提到名字不算需求。活动项目引用了它、模型升级了或发现能优化，都不是去碰它的理由；真需要改冻结项目时，说清依赖和缺口，等本人提出。识别和排除冻结项目时，只读最小的身份和状态信息。

## 三档维护

- **日用**：出错就修，也可以改进。
- **偶用**：只修报错，不加功能。
- **存档**：不维护，也就是上面的冻结名单。

新项目默认是日用，本人另说的除外。

## 长任务接续

根会话派活、提问或请本人决定前，按任务取回必要现行决定；普通回复不自动注入。Claude、Codex 压缩或恢复共用 `tools/current_decision_context.py`，短表只留禁令和当前项目相关条目，其余按查询入口取回。原生子代理跳过 SessionStart 时从派单和原任务状态接续，不额外读原话。相同边界去重，不改全局窗口、不强制换对话。

用现有的任务状态分清：本人原话和更正、已确认的结果和授权、现场事实和未知、可替换的方案、真正做完的和还剩的。做取舍前先看现行决定索引，详情按出处查。摘要和计划不产生新需求；转述会改变意思的关键原话保留原句。会影响其他 AI 做决定或理解情况的经验、教训、本人决定和必要事实，按共享经验的落点（`#共享经验的落点`）归位到对应的项目或基座文件（例如项目的 AGENTS.md、说明文档、登记表），不写进 Codex 或 Claude 自己的记忆区；写的是结论，不是日志和过程记录（约法 L30）。简单任务不机械建文档，不建全景个人库或新的记忆服务，不记录隐藏推理。停下时还有没做完的，留下能接着做的状态：在哪里、做到哪、还差什么。

README 只给 AI 和维护使用，简短列出现行入口，不再另写一份给本人看的长文档。给本人看的说明、指南和急救步骤统一由网站 `wly0829.cn` 从各自唯一来源生成；电脑离线时，网站的急救页也必须可读。项目的 AGENTS 只写这个项目真正不同的地方；实现或入口变了、影响到它写的承诺时同步更新。网站取材和去副本按下一节执行。

第三方 CLI 长任务由 AICLI 和具体项目负责接续，不再交给个人技能。到自然边界保存压缩前 checkpoint；恢复时重读项目规则、当前状态、`git status` / `git diff` 和待改源码，摘要只作线索。

通过电脑 MCP 操作项目，以及个人项目中需要电脑智能体执行的后续事项，归入电脑端对应项目现有需求、待办或接续入口，由电脑 Codex／Claude 在相应操作时承接并提醒。无论本人从手机还是通过 MCP 发起，包括媒体库按需更新，都不在 ChatGPT 新增任务，也不另建 ChatGPT 定时提醒来代替项目接续；本人另行明确指定提醒方式时按新指示。记录后续条件不等于立即执行，也不等于获准向另一个现有会话发送任务。

### 压缩后的后台复核

Claude、Codex 根会话压缩后，复用现有原话存档和 GPT 后台任务做增量复核；正常工作不等它。根会话持续维护并在压缩前更新项目已有的短任务状态；没有现成入口时用本任务 `work/task-state.md`，保留当前目标、要求出处、已完成与未结事项、下一步和证据位置，不再复制整段历史。当前用 Sol ultra，资料定位优先脚本；不让 Luna 的初筛成为跳过最终复核的唯一依据。

纯技术工作不依赖资料解锁（约法 L18）。资料锁着或未知、又到了压缩预警时，根会话若已确认整个现有会话确为纯技术，可用技术范围登记（`E:/.agents/docs/operations/context-hooks.md#锁定时的技术复核`）记录当前原话边界及确为技术资料的证据位置，命令见该运维文档。登记由 AI 做，不请本人另行批准；新增或改写的真人消息不继承旧判断。旧历史混有私人内容或范围不明时不登记整段技术，仍走原资料入口，不先读私人历史来补这个判断。该登记不解锁资料、不放行私人库；未读取的部分继续列为未覆盖。

- 每个新压缩边界只排一次，同根会话最多一批在跑；普通新消息不新开复核，子代理的压缩不递归派发。未覆盖部分保留，不把重复恢复当成新一批。
- 按本批新增消息查交接或待办漏记的小要求，对照旧未结要求，检查实际完成证据、擅改决定及接续。本人原话出处由根认定，复核者不另查、不报无出处；按[分类表](/rules/engineering-delivery/#本人的话怎么分类怎么对待ai-写的稿子可以改)核对，只有禁令边界上的分类分歧作为提醒交回，不阻塞工作，审查意见不产生用户决定。
- 按原文和产物位置分段读取，不把整个窗口塞给复核者。覆盖位置和未结项落在现有任务状态，只有有效覆盖回执才推进；失败、超时、资料缺口和未检查的摘要如实列明，不写成通过。
- 复核只读，短结果在原根会话下一可投递的工具或消息边界送回，详细证据按需读取。根先对照当前版本，再处理仍存在的问题；已经修好的不重复打扰。普通提醒不阻塞主任务，影响当前决定或交付的实质问题由根核实处理，重大动作仍按原把关规则。
- 每批有效工作预算当前为 8 分钟，正常短回报目标 500 字；这是可调的 AI 实现参数，不是牺牲覆盖或删除关键问题的理由。排队、重试和收尾宽限单列；不自动无限延时。中断在原批次接续，不反复新建替身。

程序入口、暂停开关和两宿主实际支持的事件见上下文 Hook 运维（`E:/.agents/docs/operations/context-hooks.md`）。纯模型主动换窗与原生压缩分别验收，不能从一种事件的成功推定另一种也已接通。

### 一样东西只存一处

规则、事实、决定和本人原话各只存一处，就是上面“事实找谁”分给它的家；本人的决定原话存决定文档，本人自己的事实存理解库明示。别处用到时，写一句现行结论并指向那一处（路径、章节或编号），不整段抄。会变的数（版本、数量、剩余空间、“第几行”、部署或运行状态）的家是能查到它的命令、配置或系统本身：说明、规则、手册这类长期文档写去哪查，非写不可就注明是哪天看到的；带日期的决定记录、汇报、计划和评测保留当时的值，不回头改。发现副本时，先把副本里更新或多出来的内容并回它的家，再把副本改成指针。由工具从唯一来源生成、并核对一致的副本（例如规则发布快照、装到用户目录的入口文件、网站生成的说明页面）不算副本。急救步骤的来源在 PCConfig，网站照它生成，并保证电脑离线时仍能在网站读到急救页；给本人看的内容不再在仓库 README 或另一份长指南里手写维护。过时的历史报告和设计稿不改写，没人再用就移出工作区。跨文件查重用 [Find-DuplicateContent.ps1](/source-tools/Find-DuplicateContent.ps1)，结果逐组判断后再收副本。

### 共享经验的落点

记忆的使用边界按[约法 L30](/rules/charter/#十关于规则本身)，两个宿主的关闭配置见各自适配专题。需要留下的原话、经验和教训按下述时点写到对应的共享位置，写完在回复里一句话说明写在哪；不能因为记忆关了就不记。

本人对 AI、项目和电脑的决定原话存 `docs/owner-decisions/YYYY-MM.md`，索引 `docs/owner-decisions.md` 只作导航。新增用 `python -B -X utf8 tools/owner_decision_store.py append --input <原话节.md>`：记录时只写盘，不传 `--commit`。禁令、纠正和长期授权当场原样写盘，带北京时间；其余在交付收尾或压缩前一次归位。本会话钩子已存的本人消息也算出处，标“本人原话（待归位）”，不因未分类、未写月卷或未提交报警。要求登记同样只写盘，不逐条提交，也不为两种记录各做提交；在交付收尾或压缩前批量提交，推送随任务正常收尾。

后台每 3 小时只补已归档或最后活动超过 3 小时且有未归位原话的根会话，源消息 UUID 已引用就跳过；资料锁着或未知时记录跳过，不解锁、不降级。分类统一按[工程与交付](/rules/engineering-delivery/#本人的话怎么分类怎么对待ai-写的稿子可以改)。索引标来源、性质、范围、取代关系；同主题新决定覆盖旧决定，被取代或已办完的一次性记录整节原样移入 `docs/archive/`，默认搜索排除，历史留在 Git。别处只写现行结论和指针。移动时标取代、修旧编号和节名引用，不用行号；别的负责人管的发给对应会话。拿不准的留现行交本人定。编号写法见索引，个人事实、偏好和价值记理解库明示。

原话整条原样放引用块，连发各占一块，写来源（会话、源消息 UUID）；分类行写 `- 分类：①类别〔范围·修饰〕「片段」；②…`，每单元带范围（本次、项目或主题名、长期、至 YYYY-MM-DD，可组合），片段必须是同节某个引用块一字不差的子串，尽量在 20 字以内。选项、纠正、询问或回答 AI 请示的，写回答对象；新主题新开带北京时间的节，不追加到按会话命名的节。

记录原话的根会话按上述时点归位并分类，两个宿主一致，不设审批；后台补漏 GPT 按同一分类表执行，其他子代理不记原话、不改分类。“性质和范围／性质与范围”等旧段落原样保留。按类别搜 `rg -n "^- 分类：.*禁令〔" E:\.agents\docs\owner-decisions -g "*.md"`，换类别词即可。
