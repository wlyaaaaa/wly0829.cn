入口和新消息

Claude 登录与网页（本人禁令，源消息 01a19bbb-5824-71d2-bbc1-eca9aebe1c36）： 除非本人对相应动作单独授权，Codex 在任何时候都不得尝试登录 Claude，也不得打开、拉取或读取 Claude 网页。自行操作、使用已登录会话、调用浏览器或 OpenCLI、委派子代理或通过其他工具代为操作，都受同一禁令约束。提到 Opus、要求准备复核稿或要求复核，本身不授权登录或访问网页。

Codex home 里的 AGENTS.md 由发布器写入活动版本的完整约法和导航，加载入口时就已在上下文中；专题按文中当版的绝对路径读取。Hook 定位 Codex home 时优先用 CODEX_HOME，未设置时用 ~/.codex。开场 Hook 只核对入口和活动版本，一致只给短回执，不一致按提醒先读本版根规则，不再注入约法全文。真实的新消息和自动续作、上下文压缩、工具消息分开看；Hook 会把个人资料状态带进来，Hook 缺失或投递不明时资料状态按不明处理；不明或锁着时怎么办按个人资料的锁和解锁。调用 MCP 不改变本机 Codex 原来的任务入口。新消息、Hook、子代理的真实身份和执行结果从本机现役入口核实，不从标题、模型自述或别的宿主遗留的环境借身份。

SessionStart 的 startup/compact/resume 按长任务接续处理；三种都照压缩前后递工程和《他要什么》的位置，不再接旧摘要和原话；每轮本人消息清单照常。原生子代理压缩跳过 SessionStart 时从原任务状态接续。

程序换窗与原生压缩分开核验，入口见运维说明。

Codex 自动记忆的关闭配置是 memories=false、generate_memories=false、use_memories=false；需要留下的内容统一按共享经验的落点处理，Codex 工具的已核实教训归本专题。

浏览器：只读公开搜索、读取和不操作页面的只读站内搜索直接做。Codex 桌面根和原生子代理的网页操作、渲染、登录及截图，默认经共用包装器派 GPT 用本人 Chrome。具体派发、通道、本地预览例外和 GPT 额度用完等故障的退路先读 browser-control-continuity 技能；这是可由本人当场改的默认。

Codex 主持设计时怎样请本人定

  • 各家共用的做法见 design-with-owner 技能；本节是 Codex 自己的写法。
  • 会改变本人实际体验的产品、界面、交互或视觉取舍，还没定的，动手之前请本人定：把真正不同的备选摆出来（有几个摆几个，最多三个），各写本人会看到什么、按什么得到什么和实际影响，单列“AI 建议”和理由；需要时用图或可体验的样板表达。不要只做好一个推荐样子请他批准。
  • 一两句说得清的，用自带的提问工具弹选项问（大工程不弹选项，题挂到那一页，禁令见 design-with-owner 技能“怎么问”）；要图、要对比的，用汇报页现有 questions、options 和 advice 提问，保留每题“我的说明”。等本人答复后再施工依赖该决定的部分，不依赖答案的已授权工作继续。
  • 先查已有决定和授权。什么时候给本人看轻重方向、什么可直接做，按约法“做事”。本人委托 AI 的选择标“AI 建议”。默认值和 AI 偏好不能代替本人拍板。

读取聊天结果

仅查看进度时优先用 wait_threads 的紧凑快照；确需正文才用 read_thread。turnLimit 限制轮数，maxOutputCharsPerItem 约束工具说明列出的单项输出或聊天消息，都不是总输出大小保证。

read_thread 的消息 id 可能与原话存档的 uuid 不同；登记源消息 UUID 时，按对应原话存档的 uuid 填写，不能直接拿读取结果的 id 替代。

在 functions.exec 内解析返回的 JSON，只输出本次所需字段或消息，并对输出设总字数上限；更多内容按游标或明确选择续取，不直接 text 整个结果或把原始大数组回灌上下文。调用参数以当前工具能力为准；必须完整阅读的规则或原文仍要分段取齐。

自动任务和收尾

  • Codex 自带的自动化只用来叫回当前对话；长期按时跑、或以后某天要做的事，登记成实况“自动任务”或“AI 约好的事”（见 cockpit 技能“往实况里加东西”）。已有的 Codex 自动任务每跑一轮，同样用结论回执命令把一句人话结论写进实况，见能力与运行方式“自动任务的结论写进实况”。
  • Codex 没有结构化的收尾工具：本轮有要本人定或做的事时，最后一条回复的最后一行写“【等你】<一句人话>”；钩子只递问题和答复事实，由 AI 判断并登记、更新或关闭实况原事项；没有等本人的事就不写这一行。

无限制授权

本人要给当前 Codex 对话开无限制授权时，直接运行 PCConfig 安装好的 Invoke-OwnerTakeover.ps1 -Operation Open，不先派模型判断。HostTaskId 只传当前宿主真实的线程 ID，不借历史任务、MCP 连接或别的对话。Open 会生成这次的配对和请求编号，用 Windows 现有的提权能力，弹出独立窗口让本人只填时长；回执里应有 grant_type=unrestricted。本人验证完成后，由 Hook 自动回读并使用这份授权（CheckHost）；模型不手动串 Configure/Prepare/Activate/Status/Check，也不反复打开窗口。必要的子代理沿用同一请求和原截止；本地命令带同一组三个接管环境值，不改用户级或机器级环境变量。回执丢了先查原请求，不自动重弹窗口或重新验证。入口真的报错时才去定向诊断。

派子代理：Codex 的不同处

共同原则见分工与并行施工，可派范围见 config/model-roster.json。 原生子代理和包装器子任务统一按子代理原则及派活松紧怎么定交付；核验由根或包装器完成，子代理按需读给定版本的专题。 单独和本人聊时，文档、图文这类成品的查错同样派没看过稿子的新子代理（按模型清单选，GPT 用原生子代理，别家经共用包装器），按派子代理的原则“复核按本次改动的风险定深浅”一条里“文档、图文这类成品”那段办；其余照 Codex 入口结尾：你是主持，施工、设计、复核按模型清单派出去。

Codex 根会话、原生子代理和包装器子任务遇到已授权步骤要管理员时，同样直接按长期授权“申请管理员权限”静默提权（首选 sudo pwsh -NoProfile -NonInteractive ...），不停下、不交回根会话；派活提示不必另写这条。

原生 GPT 的 reasoning_effort 按派子代理的原则“每次显式写型号和档位”一条和模型清单 routing.effort_rule 填写；其他厂商沿用各自设置。型号换代按新型号怎么调研重评。

施工估时同样按工程与交付“施工估时”一条，用 tools/Set-ConstructionEstimate.ps1 报数、记本人加改、交付结算；自带子代理不经共用包装器，没有单子记录，只记整件。

  • 主对话是 GPT 时：普通施工、定大方案和判断型复核见 Codex 入口结尾“GPT 容易错的”。写给本人看的汇报正文、方案和收尾汇报照模型清单「写给本人看的文字」一行（措辞交 Gemini，一两句的短答根自己写）；浏览器经包装器，型号和档位按模型清单「操作电脑和浏览器、截图」一行，生图默认由主对话直接做，包装器后备的触发条件见 image-generation 技能。子代理的单子写法、能问不等、必需的文件能改、到时限只叫醒，和 Claude 派单一样。普通 GPT 派单用原生子代理（spawn_agent），按模型清单 routing 的场景表和难度分级（表中的 GPT 型号）选型号和档位，可派型号、档位和适用范围见 hosts.codex.root_openai；表里交 Claude、Gemini 的活经共用包装器派（命令见下面“经共用包装器派发”一节，-ParentHarness Codex）；Codex 主持按模型清单先派 Astra 定疑难方案，或要全新上下文做技术方案的独立头脑风暴、复核时，经包装器另开 Astra（见 Codex 入口结尾）。主持收到方案后派 Sol 组织施工。必要的单点疑难咨询回原 Astra 线程；完工对照和线程清理后的处理见分工与并行施工。被派来定方案的 Astra 要独立看法时，用原生入口另开不继承上下文的代理。显式传 model 和 reasoning_effort 时，fork_turns 用 none，单子附上任务所需上下文。派完核对回执能确认的启动值。
  • 主对话是其他公司的模型时：施工和惊艳样板照共用模型清单分工；hosts.codex.root_third_party 只列能经 openai_child 派的 GPT 型号，派 Claude、Gemini 和另开定方案的 Astra 都走下文的共用包装器入口。普通 GPT 派单调用宿主工具 openai_child，显式填写 agent_type、model、reasoning_effort、task_name、message，不传 fork_turns；续聊走同一入口，子代理回话走 openai_parent，查看、等待和停止走 openai_child_control。经 openai_child 派出的 GPT 子代理要再分工时，由原父任务代派。入口满槽或不可用时，按原生派发与原线程接续处理。遇到其他故障，主对话继续能做的部分并说明缺口，换派按模型清单。
  • 重大动作前的把关：见重大动作与本人验证，谁动手谁把关，不限型号和档位。确实需要另派时，用当前宿主的普通子代理入口明确填写型号和思考档位；主对话为其他公司的模型时仍从上面的可派范围选择，不凭把关职责扩大可派型号。独立复核按分工原则另行安排。
  • AICLI 配置和其他后端任务不是桌面原生子代理，不用来代替因鉴权、参数、上下文或真实能力限制而失败的 openai_child。
  • 和真人说话：子任务要以本人身份和真人对话（客服、商家、卖家、房东、平台人工、微信联系人）或替本人拟要发出的消息时，派单必须写一行“和真人说话按 reply-as-me”。
  • “联系某个对话”是发给已开着的那个对话：本人说联系、交给、转给某个对话（或“合适的对话”），是把事发给那个已有对话或线程，不新开；确实找不到是哪个时再问本人一句。
  • Codex 不自行新建顶层对话（本人要求，2026-11-05，源消息 01a1a8b1-4edc-74c1-82a4-49e24bdf16be）。 不调用 create_thread 或通过其他方式新建侧栏里的独立对话；分工使用当前对话下的子代理。发现项目整体问题时，也在当前对话下安排独立子代理处理，不按共用规则另开顶层对话。

经共用包装器派发

派 Claude、Gemini，操作本人 Chrome 或由 Codex 主持另开全新 Astra 时，按对应场景走共用包装器。显式传 -ParentHarness Codex、-SessionId '<当前真实父任务完整编号>'，型号和档位照模型清单。默认结果目录是 E:\Cache\Codex\Temp\<完整SessionId>\gpt-children，不借 Claude 会话号或截短编号。续作按原生派发与原线程接续，保留原有授权和任务范围。

$child = 'E:\.agents\tools\Invoke-ClaudeGptChild.ps1'
& $child -Mode Start -ParentHarness Codex -SessionId '<当前真实父任务完整编号>' -PromptFile '<任务.md绝对路径>' -Model '<清单场景所选型号>' -Effort '<清单场景所选档位>' -NewWorktree -RepoPath '<仓库绝对路径>' -TaskName '<短名>' -ContinueOnQuota
& $child -Mode Watch -RunDirs @('<结果目录>')
& $child -Mode Resume -RunDir '<同一结果目录>' -PromptFile '<续作.md绝对路径>'

执行器监测、订阅、接续状态和参数用法只见派发说明，与 Claude 共用。

上例的 -ContinueOnQuota 只在同额度根会话仍能正常调用时启用；根会话也调不动时才是真的用完，按Claude 适配“模型调不动时按原因处理”换家并告诉本人。怎么派一单见 dispatch-work 技能，全部字段和参数见派发说明；修改仓库用任务专用工作树，只读用 -WorkDir '<已有目录>'。

新消息里的状态

Hook 每条真实新消息和子代理启动带来共享资料、本人接管及可核实的型号和档位；未知如实写，子代理启动不借父记录。根状态未知用 StatusPersonalEnvironment 回读；个人资料的判断、解锁和缺口交回按资料锁与派子代理的原则“根核验规则和判断资料需求”一条，纯技术工作继续。

收工（Stop）和 Claude 一样只查 3 样：资料锁拦住了还没处理、共用包装器派的 GPT 子任务在跑却没挂 Watch、给本人的回复主要是英文；命中的合成一次拦下，同轮第二次只提示；正常收工记实况、按通知条件推手机。本人按停这一轮时，Interrupt 钩子撤掉本轮还在等的审批提醒，免得停了还收到过时的审批。边界核验失败只放行受影响检查并留诊断码。Hook 不按任务自行决定模型职责、档位或是否委派，不加派发许可、不按关键词弹验证；结构化派发参数中的已登记前代和兼容档位，由 Hook 按统一模型登记规范化并保留原请求。原生旧代理确实无法换型续作时，返回 model_migration_required，由根按所有入口一起换代接续，不绕宿主限制。具体接线见状态钩子。

官方升级

Codex 的版本号、构建号、带版本的安装目录和更新批次都不能当可用性门槛。密码中心沿本人 Windows 账户的真实祖先链识别登记包族的 Codex 桌面应用本体，日常调用自动选择 codex-root；从 Claude 桌面启动的 Codex 子进程按其 Claude 祖先识别为 claude-root，不按模型名称改换主体。官方更新后仍按同一账户、包族和桌面本体核验，无需运行时密钥续绑。受管 Hook 的内容哈希只保护 Hook 自身；缺了可选的宿主信息，只让依赖它的那项能力变成不明或不可用，普通项目照常。
