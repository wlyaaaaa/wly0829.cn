身份

桌面身份、登记和撤销按用户授权。Claude 桌面及其真实后代沿桌面祖先识别为 claude-root，嵌套模型不改变主体。GPT 包装器默认起独立执行者，没有该桌面身份；真正需要桌面身份的密码中心凭据步骤交回根会话。

思考档位

Opus 5.5、Sonnet 5.5 和 Fable 5.2 用同一套档位，从低到高是 low、medium、high、xhigh、max：

档位 含义
low 思考最少，只做机械、明确、结果能马上核对的小事
medium 均衡；Opus 5.5 的默认档，常规检索、调研、实现和审查够用
high 全面推演，跨模块调查、完整子系统、实质审查
xhigh 扩展推理，困难设计、疑难排障、关键审查
max 最深推理、最贵、最慢；评测分数不一定比 xhigh 高，不当做错后的默认下一步（见分工与并行施工）

本人定过主对话的起步选择：Fable high（2026-11-10），Opus xhigh，难题、完善底座这类难活临时升到 max（2026-10-30）。本人新开对话时选一次，App 会记住。AI 自己开的新对话按模型清单通用档位规则：Opus 做明确的任务用 medium，要判断用 xhigh，最难的用 max；Fable 只有本人点名才开，一般 high。AI 用 start_session 另开对话时，档位只能给到发起对话自己的档位或更低，写高了会被悄悄压低（Fable high 的对话开 Opus xhigh，实际是 high）；要更高的，开完马上用 set_session_effort 调，下一轮起生效。

Ultracode 不是比 max 更高的档，而是 xhigh 加多智能体编排（工作流），只在本会话有效；提示词里出现“ultracode”一词只让这一轮改用编排，不改变档位。auto 表示没固定档位，以实际记录为准。

派子代理：Claude 的不同处

共同原则见分工与并行施工，可派范围见 config/model-roster.json。

  • Claude 自己的子代理默认用 Agent 工具派桌面子代理。Agent 工具没有档位参数，按模型清单 routing.scenarios 对应场景选人，再从 hosts.claude.dispatchable 取相应的子代理类型。本人点名的类型看 hosts.claude.owner_named，专门的验收选「Claude 装没装好的验收清单」一行。做错了换人时仍可换到 Claude（见分工与并行施工）。
  • 模型调不动时按原因处理。 派出的 GPT（Sol、Terra、Luna、Astra）、Gemini 或 Claude 子代理调不动时，不降型号、不降思考档位，也不收回来自己写（模型清单那一行另写了候选顺序或后备的，照那一行）。额度或订阅用完（结构化 usageLimitExceeded，或 usage limit、credits、spend cap、quota 等明确额度报错）或模型对该账号失效（账号被停、该账号用不了该型号，如 model not found、not supported、does not have access）时，这款这会儿算用不了（经包装器派的 Claude 型号调不通时，按模型清单 model_unavailable 查 Antigravity 的同一型号、同一档位；Claude 已有未到期的拒绝记录时不先派 Claude，直接走同型号、同档位的后备，Antigravity 的 Claude 和 GPT 池也有未到期的拒绝记录时回用尽和重置时间）：照模型清单那一行“用不了交谁”换人接着做（那一行列的同家别的池子、免费后备或别家），并照报错原样告诉本人。本人在对话里就当面说一声；本人不在时，由 AI 判断后用 E:\PCConfig\tools\Set-OwnerItem.ps1 按出错账号去重登记实况一条，写清哪家、哪个账号用不了、活已换给谁。那家恢复后新活回原来的分工，接手者已经做完的那单不再续，由 AI 用一次实际调用核实可用后关闭该事项。登录失效（401）是能修的原因：先重新登录修好，再接回原任务，不换家；经包装器实际派出的 Claude 型号报登录失效时，可试 Antigravity 同型号，能用就这一轮先在那边做完，登录照样要修。不预先查额度；所需工具或身份不可用时按实际原因修复，仍不通交回卡点。
  • 短时限流自动重试。 经包装器派的，没有额度标记的 429、rate limit、too many requests，和满载、5xx 一样交包装器自动重试；报错给了等待时间就按它退避，不算这家用不了，仍不降型号、不降思考档位、不换家。Agent 工具派的原生子代理靠宿主自己的重试，仍不通按上一条的原因处理。
  • 本人说“派API”才走 API。 没有这句话时默认派桌面子代理，不自己提议或改走 API，钩子也不拦 Agent 工具。本人在当前对话说“派API”后，接下来的前 3 个 Claude 档位子代理走 API，第 4 个起回桌面；要再用本人再说一次，只在当前对话有效。开始时告诉本人一句“接下来 3 个走 API”。不为选路预查 API 余额或记账期；本人明确开口要看余额时照分工与并行施工。走 API 时用 PowerShell 工具在后台（run_in_background:true，timeout 7200000）运行 E:\.agents\tools\Invoke-ClaudeApiChild.ps1 -Agent <同名档位类型> -PromptFile <派单绝对路径> -WorkDir <工作目录绝对路径> -TaskName <短名，只用字母、数字和连字符>；型号、档位、派单内容和分工都和桌面一样，换通道不算降级。API 子代理不加载 MCP，要用浏览器、Google、副机这类 MCP 工具的活不占名额，直接派桌面并说一句。读回执：succeeded 就读 result_file 验收；use_desktop=true 时按回执的 next_step 用 Agent 工具派同一档位类型，did_work=false 原样重派，did_work=true 派单后附回执里的 handoff_note 接着做；没拿到回执也按 use_desktop=true 处理，派单后加一句“先看工作目录的 git 状态，已经做过的不重做”。quota_exhausted 时告诉本人一句“API 余额没了，已转桌面”，这个对话余下的名额直接走桌面，不再试；key_problem、key_delivery_failed 另外告诉本人一句。
  • 内置的 general-purpose、Explore、Plan 连型号带档位都跟根会话走，根会话开 max 时它们也按 max 跑，拿来做检索很贵；20 分钟内能查完的检索根会话自己做（见分工与并行施工的“本人定的分工和型号规矩”）；成批的只读检索和机械小事按模型清单「查资料、取原文、筛选、批量核对」和 routing.current_generation_defaults.gpt_mechanical 选，调不动时按“模型调不动时按原因处理”和“短时限流自动重试”两条办理。Explore、Plan 不读 CLAUDE.md，只做只读检索。Agent 工具的 model 参数只换型号、不换档位，不用它派 Sonnet。
  • 派 GPT、Gemini 时走下面的包装器入口，不把 Codex 的 openai_child 或它的专用判断角色当作 Claude 的接口。
  • 工作流（Workflow）是确定性的多代理编排，适合大范围扇出、交叉核对和可恢复的批量活；只在本人开启 Ultracode、明确要求或技能要求时用，每个 agent() 显式传 effort。扇出规模按任务、风险和实际可用容量定，按需保存可接续的检查点，不查询剩余额度，也不按额度削减分工或质量。开着 Ultracode 时，系统每轮会催“实质的活都开工作流、不计成本”；以约法为准，值不值照算。本人没开口要的，先说目标（见 dispatch-work 技能“派之前”）；商量方向的对话用不着工作流。
  • 独立复核按共同原则安排；重大动作前的把关见重大动作与本人验证，谁动手谁把关，不限型号和档位。

派 GPT

  • 照清单派，摘要写清。 GPT、Gemini 的型号照模型清单都能派，不另要授权（约法 L23「本人定的分工和型号规矩」）；思考摘要写清“我要派 GPT-6.2 Sol（max）”这样的一句。本人另给的限制（型号、厂商、项目、期限）照办：“本对话直到叫停”不跨对话，“一个项目”不跨项目，同时限定项目和期限就同时遵守。不为这事查询或估算本人账号额度。
  • 默认分工和选型。 按模型清单 routing 和共同选型原则，每次显式传 -Model、-Effort；档位及旧值映射只见清单。GPT 涉及本人价值、偏好和理解的内容单列后由 Claude 把关。施工按模型清单 routing.current_generation_defaults.gpt_build 默认交 Sol。遇到 build_supervision 的四种情况，由主持先派 Astra 定方案，交回后再派 Sol 组织施工。生图按「凡是看得见的」一行。范围和授权沿用父任务，需根会话派发的判断及干净上下文的例外见派发说明。
  • 从包装器进入。 使用 E:\.agents\tools\Invoke-ClaudeGptChild.ps1，-ParentHarness 默认 Claude。派 GPT 时 Start、Resume 走私有 AppServer（后台服务），派 Gemini 时走 agy acp 的会话协议（ACP，智能体客户端协议）；Start 默认独立执行，Resume 沿用已存方式。确需桌面身份可传 -Detached:$false，或只把凭据动作交根。运行中纠偏用同轮 Steer。不直接调用 codex exec、Codex 的 openai_child 或专用判断角色。共用容量和接续见分工与并行施工；-ParentHarness Codex、-ParentHarness Antigravity 分别供 Codex、Antigravity 主持时用，Claude 不借用。
  • 资料与权限。 Codex 子任务按正常 Codex 配置和当前授权工作，不复制 Claude 对话授权值，不另加沙箱或审批覆盖。独立执行者没有桌面祖先身份：真正依赖密码中心桌面身份的凭据步骤交回根会话，其余已授权步骤照常完成；不另行登录、转交秘密或改身份核验来补。资料需求、共享资料期和缺口交回按派子代理的原则“根核验规则和判断资料需求”一条。
  • 怎么派一单。 命令、单子模板、怎么等、怎么验收见 dispatch-work 技能；全部字段和参数见派发说明；修改仓库用任务专用工作树。
  • 和真人说话。 子任务要以本人身份和真人对话（客服、商家、卖家、房东、平台人工、微信联系人）或替本人拟要发出的消息时，派单必须写一行“和真人说话按 reply-as-me”；包装器在派单出现客服、商家、卖家、房东、人工、聊天等字样又没写这一行时自动补上，只是兜底。
  • 交代和交付。 子任务技术做法自己定；拿不准的需求或取舍把问题和建议写进留言，继续做不受影响的部分，不等回答，同一件事只问一次；没定的最终汇报再写一遍。交付简短结论、必要证据和汇报路径，除任务明确要求网页外，不做可视化，也不打开窗口。任务范围内的核对、验收或操作需要管理员时，直接按用户授权的静默提权做法执行。会影响其他会话的决定写到对应项目文件；仅在同改一处、发生事故或确需协调时发消息，不用中途进度刷屏。

命令参数按需查 Get-Help E:\.agents\tools\Invoke-ClaudeGptChild.ps1 -Full。Steer 长消息或含中文引号时用 -PromptFile，不同时传 -Message；用 Status 核对是否接受、是否被模型看到及汇报中的处理结果，不把入队当成完成。Resume 只用于已结束的原线程，沿用原型号、档位和脱离方式。

宿主接线

  • 技能：~/.claude/skills 是指向 ~/.agents/skills 的目录链接，和 Codex 共用同一个发现根和技能清单，不生成第二份副本。新技能写到 E:\.agents\skills 后走现有安装器，不在 ~/.claude/skills 下直接新建。
  • 临时目录：任务临时文件放 E:\Cache\Claude\Temp\<会话号前 8 位>，并把子进程的 TEMP|TMP|TMPDIR 指过去。子代理和主会话共用这个会话目录，所以子代理用自己的子目录（例如 <会话目录>\sub-<名字>）；运行中只清理自己建的内容，不批量清理共享会话目录及 personal-status 状态缓存。会话和子任务的临时目录按规则表由自动清理处理。宿主给的会话 scratchpad 路径超过 200 个字符，会让 pdftoppm、git 等工具报假失败，不当临时目录用。
  • 档位子代理：规范源是 templates/claude-home/agents/，~/.claude/agents 是指向它的目录链接。
  • 记忆：Claude 账号聊天记忆已关闭，Claude Code 的关闭配置为 ~/.claude/settings.json 中的 autoMemoryEnabled=false；需要留下的内容统一按共享经验的落点处理，Claude 工具的已核实教训归本专题。
  • MCP：用户级配置在 %USERPROFILE%\.claude.json（claude mcp add -s user）。Google 业务按能力与运行方式，走 PCConfig 的 google-workspace stdio 入口，不接 claude.ai 的云连接器。电脑 MCP 只认目标机登记过的客户端；Claude 的 OAuth 回调固定为 http://localhost:<端口>/callback，不能复用 Codex 的 127.0.0.1 客户端，要在目标机登记独立的 Claude 客户端和固定回调端口。主机上的 Claude 直接用本机工具，不连本机的电脑 MCP。
  • 浏览器：只读公开搜索、读取和不操作页面的只读站内搜索直接调用；网页操作、渲染、本地预览和截图默认经包装器派 GPT 走 AppServer，用本人 Chrome，型号和档位按模型清单「操作电脑和浏览器、截图」一行，截图交 Claude 看成品和抽查。具体通道、后台标签页、禁用的 Claude 浏览器、故障退路和 GPT 额度用完的后备先读 browser-control-continuity 技能；这是可由本人当场改的默认。
  • 要在新会话里验收的（MCP、技能）：用真正的新桌面会话，运行中的会话仍持旧 MCP。Hook 不用新开：运行中的会话安装后十几秒就换上新钩子（2026-11-07 看图上限实测，根会话和子代理都真触发了），当场真跑就能验。开验收会话或子代理都先想清楚档位并显式设定，不沿用根会话的档位（根会话的档位常比验收要的高；start_session 不传 effort、model 就沿用根会话的）：安装或触发检查按模型清单 routing.scenarios 的「Claude 装没装好的验收清单」一行；日常回答表现验收按通用档位，通常 medium，不开 max。也可以给可复制提示，首行注明型号和档位，让本人新开、选好后粘贴；结果交回或由根回读。MCP 原命令可按 %USERPROFILE%\.claude.json 的 mcpServers 跑 stdio 作补充，两种证据分开。嵌套 claude -p 没登录、也非新桌面会话，不能代替，不为它登录或转交凭据。
  • 权限：用户设置里全局使用 permissions.defaultMode=bypassPermissions，和 Codex 的完全访问对等；不用 auto 模式或 autoMode 条目复制授权。宿主固定拦截的操作（删除盘根或一级目录、Remove-Item 通配、前台长时间 sleep 等）不是停工理由：已确认可直接删除的对象用字面子路径，清理受阻按工程与交付办理；长等候用后台任务或 Monitor。
  • 给本人的回答写在回他那一轮的最后一段。 本人只看最终输出，不看思考摘要；两次工具调用之间的文字可能被缩成一句摘要，夹在中间的答案会被缩没。被子代理或命令唤醒的那一轮，本人等于没看见；那一轮得出的结论，留到他下一条消息时再说，或写进汇报页。本人在线等时可以先说一句结论，没核实的说成暂定；清理、登记放在写最后一段之前做，最后一段把答案完整再说一遍。
  • 桌面版自带说明里“提交、推送要先问”“收尾的小框里问要不要开工”这类，以约法为准，约法已经交给你的不问；收尾的小框用来问还没弄清的那一点。
  • 本人不在时不弹要他点的东西。 本人说去睡了、出门了，或说只看最终汇报时，不发新对话提议卡片，也不在收尾框里提问：提议卡片会让这个对话在侧栏显示“需要你”，本人会以为任务卡住了。要提的后续事项和问题写进最终汇报；本人睡着、出门也照常进实况、发通知和邮件，同一件事不用反复催。
  • 本任务的 AI 临时内容删不掉时按工程与交付留给自动清理。其他因 Claude 硬限制卡住的已授权事项，按Claude 受限的事项交给 Codex提醒本人并提供接手提示词。
  • 文件预览：工作区外的链接按 Claude 入口模板的文件预览要求办理；该模板随活动版本部署，命令行目录设置不能代替桌面预览权限。
  • 按命令文字拦截的删除：Claude 桌面版会拦住同一条 PowerShell 命令里同时出现 Remove-Item 和 E:\PCConfig 字样的调用；它只看命令文字，不看实际删什么，被拦时整条命令都不执行。删任务临时目录单独写一条命令，读 E:\PCConfig 的 git 命令放另一条。临时文件按工程与交付的清理入口处理。
  • 自动任务的结果送回等结果的对话：用 scheduled-tasks 建的任务到点在它自己的新会话里运行，本人看不见那个会话；桌面版 notifyOnCompletion 的完成通知只对 Dispatch 会话生效，Code 页的对话收不到。建任务时在任务说明里写一行 【结果送到】local_<完整会话号> 指定等结果的对话，确实不用送的写 【结果送到】不转发；没写这一行时按正文里“发给/转到 local_…”找，再没有就是建任务的对话。运行时送回和兜底由上下文 Hook提示，见该页的结果转发说明。
  • “联系某个对话”是发给已开着的那个对话：本人说联系、交给、转给某个对话（或“合适的对话”），是用 mcp__ccd_session_mgmt__send_message 把事发给那个已有对话，不新开对话；找不到是哪个时先按标题和最近活动找，仍不确定再问本人一句。
  • 写路径和中文的坑：Bash 工具会先把命令里的双反斜杠变成单个（单引号里也一样），Bash 再吃掉引号外的反斜杠，所以引号外的 Windows 路径写一个还是两个反斜杠都会坏（E:\\.agents\\skills 最后成了 E:.agentsskills，读不到文件，写文件则落到别处）；在 Bash 里写路径用正斜杠 E:/... 或放进单引号。内联脚本里的 Windows 路径会让 \3、\r 这类被当成转义、写出控制字符；PowerShell 工具的命令要整体再解析一次，双引号字符串里的中文弯引号“”会被当成引号，整条命令报语法错、一步都不执行。所以含 Windows 路径、中文引号的文字（脚本、提交说明、文档片段）先用 Write 工具写成文件，路径用原始字符串，写完检查没有控制字符。给 pwsh -File 传数组参数会被拼成一个字符串，要传数组就在当前会话里用 & 调用，或改用 -Command。

Hook 和个人资料状态

约法和导航由发布器渲染进用户级 ~/.claude/CLAUDE.md，加载入口时就已在上下文中。SessionStart 只核对入口与活动版本：一致只给短回执，不一致按提示先读本版根规则；不再注入约法全文或专题路径 JSON。

根会话压缩或恢复时按后台复核规则接摘要和新增原话。摘要和只读复核由同一后台任务完成；有实质问题在工具后、恢复或新消息时提示，正常工作不等。每轮仍递本人消息清单。触发与暂停见上下文 Hook 运维。

UserPromptSubmit 每条真实新消息带来会话坐标、可核实的型号和档位、共享资料状态及已核验的无限制授权。资料需求和本人验证由根负责，按个人资料锁与解锁和派子代理的原则“根核验规则和判断资料需求”一条执行；纯技术工作继续。同一条实况提醒、健康提醒每会话只提示一次或状态变化时再提示。

Stop 核对本轮真实 Report 的明确目标集合，未解锁的资料拦截、漏挂 Watch 或验收缺口可拦一次。根按原因解锁并重试或补做、补挂 Watch、补齐验收，子代理缺口须读完整报告；同轮第二次只提示。

根会话有 GPT 等候、原生后台 Agent 或 Bash/PowerShell 等未完成后台任务时，受管 Stop 用一个会话级 asyncRewake（异步唤醒）保活等待，按主代理最近真实活动加 55 分钟计时；新消息、主代理工具调用和下一次停止刷新活动，多个任务共用一次唤醒。未完成状态优先读宿主 background_tasks，GPT 执行器状态作补判；任务全结束或无法确认还在后台运行时以退出码 0 静默结束，仍有后台任务且主代理空闲达到 55 分钟时以退出码 2 叫醒。子代理自己的进度和 SendMessage 发出时刻不算主代理活动。连续 10 次叫醒都没有本人消息、也没有叫醒那一轮之外的主代理工具调用，就不再叫醒，任务完成通知照常，之后有本人消息或真实工具调用重新计数；GPT 子任务在跑却没有活的 Watch 时不受这个次数限制，仍然叫醒。长时间等候指一个命令或它等的事必须 7 小时后才执行、7 小时内必定不执行（例如定时 7 小时后才跑、邮件明确 7 小时后才到）；这时跑 python -B E:\.agents\tools\claude_root_runtime.py keepalive-skip-background --session-id <完整会话号>，后台任务不再触发保活，任务完成通知照常。随时可能结束或到来的等候（GPT 子任务、微信消息）不算，拿不准就不关。程序在本会话第一次挂后台命令时和每次因后台任务叫醒时都会提醒，不用记；本人发新消息后开关失效，下次叫醒会再提醒。该保活不改 Watch/Resume 的内部续等或子任务执行；宿主能力依据见官方 asyncRewake 与后台 Hook及 Stop 输入。

程序细节、部署和维护只见上下文 Hook 运维，验证等待见个人资料的锁和解锁。回执不放在回复开头，先回答本人当前的问题。

Stop 复用两宿主共同的版本、验收和缺口检查；资料与明确汇报验收问题合并原因，不生成 personal_data_need 状态，不启动任务。Hook 不授予资料或操作权限，不按关键词自动弹验证窗口。

Claude、本机、图形界面和电脑 MCP 共用资料状态。用 CheckPersonalDataAccess -PrivacyLevel factor，不必传 RootTaskId、PromptId；业务入口的 personal_data_access.py 已检查，不额外前置检查。Hook 缺失或投递不明时按状态不明处理，用 StatusPersonalEnvironment 正式回读，身份由密码中心核验。锁着或不明不取用私人资料；最高权限智能体自己锁上、还能恢复的先自己恢复（见个人资料与数据处理），其余本人自己的问题先验证解锁，通过后再查资料、派活和完整作答，不降级回答。

无限制授权

本人要给当前 Claude 对话开无限制授权时，Hook 识别明确请求，直接调用已安装的 Invoke-OwnerTakeover.ps1 -Operation Open -HostTaskId <session_id> -HostHarness claude-code；本人在窗口里只填时长和范围，并完成一次本人验证。只有根会话的真实提示会打开窗口，子代理和工作流子会话不会。模型不手动串 Configure/Prepare/Activate/Check，也不重复打开。

验证成功后，下一条真实提示由 Hook 用 CheckHost -HostHarness claude-code 回读。对话范围的授权只绑定发起它的 Claude 会话；子代理和工作流子会话共用同一个会话编号，所以在同一授权内。Codex 线程的对话授权不适用于 Claude，反之亦然；全局授权两者都能用。本地动作的子进程显式带 PCCONFIG_OWNER_SESSION_REF、PCCONFIG_OWNER_REQUEST_ID、PCCONFIG_OWNER_EXPIRES_AT 三个相同的值。

受信任 AI 的其他能力

和 Codex 桌面版一样，下面这些都由 SecretBroker 核验本人 Windows 账户和实际桌面祖先：

  • 已登记运行时在现役入口实际可用的密码中心动作和 SecretRef。浏览器密码盲填已退役，不再使用 AgentLogin；手机号和验证码登录按能力与运行方式及当前宿主真实能力处理。
  • AgentSecretFromStdin 运行时写入秘密，回执必须是请求的同一主体。
  • 无需验证因子的账号恢复登记，用 Claude 自己的解锁信封。
  • 电脑 MCP 凭据登记：在 Claude 会话进程树内、不提权运行 Manage-RemoteComputerMCP.ps1 -Action SetupCredentials -RuntimePrincipal claude-root。
  • 请本人验证的提示只能由根会话发出，因为子代理的文字不会显示在本人的对话里。

不同的地方：新设备管理恢复（RecoverFromPrivateGit）登记 Codex 桌面主体，Claude 在新设备上用 EnrollRuntimeAuthority 登记；电脑 MCP 登录不继承任何一方的身份。

官方升级

官方更新后仍按本人 Windows 账户、登记包族和桌面应用本体识别，不以应用版本号、引擎版本目录、构建号或运行时密钥续绑为门槛。新设备通过正式入口登记；当前进程链不能证明桌面来源时，只阻止依赖该身份的能力，不借另一桌面进程或环境变量补身份。撤销用 RevokeRuntimeAuthority -Query claude-root，不影响 Codex。受管 Hook 的内容哈希只保护 Hook 自身，不代表应用版本。
