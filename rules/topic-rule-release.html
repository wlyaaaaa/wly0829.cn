owner: E:\.agents

只在维护、发布或回退规则时读。平时约法随宿主入口加载，专题按当版绝对路径读取，不跑发布流程。本人要的是：规则能改、有历史、改坏了能一键退回，而且不能随便打开文件管理器就被改掉。

什么算活动规则

唯一的规范源是私有仓库 E:\.agents。每一次发布有一个递增、不重复使用的代号（E 加数字），对应默认分支上已推送并回读过的一个提交，以及这一版的完整文件集合和每个文件的校验值。源码、候选改动和没提交的工作区都不是活动规则；标题、记忆和旧快照不决定哪一版在用。

这一版包含哪些文件，由 config/control-plane-contract-catalog.json 里显式登记的规则条目和入口模板决定；文件夹里多出来的 Markdown 不会自动变成规则，文件数量也不固定。每次发布的记录保存那一版的精确集合。

读规则

约法和导航已随各家入口加载（Antigravity 的入口位置见Antigravity 适配），模型不用在开场手动运行核验或另读约法；专题按导航中的当版绝对路径读取。开场 Hook 用 tools/Invoke-EAgentRulesRelease.ps1 -Mode Inspect -Json 核对当前版本及文件校验值，并将该宿主入口与本版入口产物逐字节比较；一致只给一行核验回执，不再注入正文或路径 JSON，不一致则提醒先读本版 AGENTS.md 的绝对路径。入口缺失时按仓库指路桩的核验命令兜底。-Mode Resolve 给现有读取方提供同一个已核对的引用；required_rule_paths 只列真实可读路径。核对通过只说明文件没被改过，不代表已经读懂或可以做所有动作；读多少由当前判断需要决定。

规则源仓库里的 AI-CHARTER.md 只是待审材料，不能靠“目录更近”盖过活动规则。仓库根的 AGENTS.md、AGENTS.override.md 和 CLAUDE.md 是三家各自读取的短项目说明。它们指向用户级入口，并在用户级入口缺失时给出核验命令，不再复制一份完整入口。读取失败只影响依赖缺失内容的决定，不触发锁资料或其他保护。

厂商的东西排在这些规则前面，这是现实，不是本人定的：模型自身的训练和安全政策，OpenAI 给 Codex、Anthropic 给 Claude、Google 给 Antigravity 写的说明。钩子只替规则传话和拦动作，和规则不一致就改钩子。规则改了、AI 的行为没变，先查厂商说明和钩子。

发布和回退

  • 一次发布一批。 同一件事的相关修改合在一起、一次发布；已经造成实际错误的修复不为凑批等待。改的是文字就不跑测试，只有程序要读的那几份（模型清单、实况读的冻结项目表、三家入口模板）跑读它的那一项；改了程序按真实用法把改的那一处跑一次。定向提交，推送到默认分支并回读远端；相关的已登记测试在提交后、推送前放后台低优先级跑（推送后 -Changed 就选不到这次的改动），不等它推送和发布；报错当场修，修不好用发布入口的 -Mode Rollback 退回上一版。这一套连同发布由主持派子代理做：单子写明本人批准的范围和要发的提交，授权它在源检出上发布；它交回已验的提交、新的活动版本号和原样结果，停在哪一步也写清。主持核对批准范围、定发不发、读回报，不自己跑。
  • 只用一个发布入口。 发布用 Invoke-EAgentRulesRelease.ps1 -Mode Activate，回退用 -Mode Rollback。发布器从选定的提交取文件，生成这一版的集合和校验值，切换“当前”和“上一版”，再回读核对。只检查真正参与发布的文件有没有未提交的改动，不因为无关项目或技能的改动停下，也不把别人没做完的修改混进来。
  • 限制句按意思判断。 发布门对改变措辞、缩短、挪位置或改成指向同版仍有效的同一规则做一次 Sol medium 语义比对，限制的对象、范围、条件和强度都不变就自动放行，不请本人同意；判定为改写的旧句和目标版本证据写入发布回执及版本记录。真正放宽、删除限制，用下列来源提交本人批准。对话里本人在谈改规则（说到规则、约法或约法条号，例如“L14 必要时可改”），就是明确同意改规则，直接放行；对话的其他答复和汇报页答复由发布门做一次 Sol medium 比对，确认每处改动都符合本人真正想要的结果就放行，不另外问本人。规则写本意、不照抄字面：补全本意显然包含的同类对象和说法可以放行；违背本人意思、放宽到本意没涉及的对象，或只是 AI 自己提的、本人没反对的，不放行。比对不可用或拿不准时，按要本人同意处理。
  • 对话里的批准。 用 -OwnerApproval <源消息UUID>（可以列几条）。Claude、Codex、Antigravity 都按源消息编号核实。存档用于定位，由现行发布程序核实原生出处；摘要、注入、派单和仅存档无原生出处的文字不作批准。Antigravity 的发布批准从固定产品目录读取原生会话，核对桌面对话来源、显式用户输入和客户端消息编号，并逐字匹配正文；不采用档案自带的路径。
  • 汇报页上的批准。 本人在单选题里选同意项并交给 AI，就算点头。发布门核对该题最新提交和原题版本，用同意项、题面和该题的“我的说明”核对要发的改动。出题时把拟发布的改句写进题目正文，让本人在所答的题里看到完整句子。改了题目或要发的句子，更新题目并请本人重答。参数见发布入口用法。
  • 约法和各家入口。 改动 AI-CHARTER.md、templates/claude-home/CLAUDE.md、templates/codex-home/AGENTS.md、templates/antigravity-home/ 下入口模板的任何一句（加句、改句、删句），先给本人看这句，点头再发，按上面对应来源传批准。本人看过并同意的设计稿里列出的句子，算已经给他看过、点过头。对话答复只核对来源，他回“嗯”也行；本人同意的是不是这句改动，由改的模型自己核对。分工与并行施工的“本人定的分工和型号规矩”一节也一样。别的对话已经提交、推上主线还没发的规则改句（约法、入口和专题都算），默认算本人批准过（本人 2026-11-23）：给本人看、等他点头是推之前那个对话的事；发布时一起发，不为它停下等本人点头，也不回头核它批没批；发布门要依据时，把那边的批准一并传入。
  • 查打架。 动约法、各家入口结尾和本目录专题里讲 AI 怎么做事的句子，给本人看或发布之前，改句负责人安排没看过稿子的子代理核对一次；一句话同时动几处也只派一个；修坏了的（报错、命令和路径、写的和实际对不上）、技能和项目文档里的具体做法不用派。给它改前改后、约法全文、三家的入口结尾和讲同一件事的专题，不给拟句的理由，也不说这句是谁要的。它只报四样：和哪句说法相反；和哪句重复；哪个词在别处指的是另一个东西、哪个指代找不到；新句本身站不站得住（做不到、有漏洞、和事实对不上）。选人按模型清单 routing.effort_rule 的查打架施工项，交 Sol xhigh。起草人可改措辞；主持核对意思和范围，未定的取舍请本人定。发布程序不拦这一步。
  • 并发。 发布器会核对当前指针的校验值；如果别的任务刚发布过，先重读并把它的结果并进来，不覆盖。新的发布必须包含当前在用的那次提交。不为发布新建队列、后台服务或全局施工平台。
  • 失败和回退。 发布失败时恢复原来的指针和入口，旧版本照常可用。指针缺失但 releases 下仍有 E* 目录时，报 e_rules_current_pointer_missing；按现存目录的 release.json 重建指针后再核验。成功后只留“当前”和“上一版”两份可重建的目录，历史由私有 Git 保存。回退把正文、目录和入口模板一起恢复到上一版；不改写历史代号，也不重建同一个代号来冒充回退。
  • 入口模板随版本部署。 发布器将各家模板中的版本号和根规则占位符替换为本版代号与 AI-CHARTER.md 全文（约法和导航，发布产物仍叫 AGENTS.md），本版文件的相对链接改为发布目录下的绝对路径，锚点保留；非本版文件沿用源码绝对路径。渲染后的 templates/codex-home/AGENTS.md 写到发布器配置的 Codex home 的 AGENTS.md；渲染后的 templates/claude-home/CLAUDE.md 写到 ~/.claude/CLAUDE.md，根会话和加载用户级入口的子代理直接带上约法；渲染后的 Antigravity 模板写到 Antigravity 读的全局规则位置，约法整段进上下文，不被降成文件指针（位置和单文件大小限制见Antigravity 适配）。Hook 核对时优先用 CODEX_HOME 定位 Codex home，未设置时用 ~/.codex。release 记录、校验值和核验覆盖渲染后的字节，回退逐字节恢复上一版入口；无占位符的旧模板保持原样。笔记本约法同步由既有每周定时巡检处理，普通约法更新不单独登记实况本人事项，也不要求本人手动启动按需巡检；由笔记本从主机当前活动规则同步约法段，主机不反向写笔记本，连不上时保留笔记本现有规则。
  • 防随手改。 活动规则目录、指针和各家入口保留现有 SYSTEM 保护；发布器按需提权，完成后恢复保护并回读，不换成只有文件只读属性。发布不调用本人的秘密或本人验证，也不新增授权体系。

验证

发布前后分别核对：Git 回读、实际安装的文件和校验值、回退能用、入口模板到位；已登记的测试照上面“一次发布一批”那条，不挡发布。Inspect -VerifyPrevious 同时核验上一版完整文件，发布回执也带 verified_previous；核验指纹完好不冒充实际执行过回退。文件改好不等于入口已接通，测试通过也不等于回退和实际安装已验证。结构测试检查真实字段、来源、同版集合、引用和回退，不逐字锁句子、文件数量或固定编号。

修改《事实来源与任务上下文》的冻结和维护档位表时，发布前运行 tests/Invoke-AllTests.ps1 -TestId rule-dashboard-consumer：它直接调用 PCConfig 实况正在用的解析函数读取本次候选文件，不复制解析规则；快速发布也包含这项检查。解析器来源缺失或候选表读不出时如实报失败，不把跳过说成通过。

普通文字和已知的局部改动走现有的快速发布入口 Invoke-EAgentRulesFastRelease.ps1，改文字不先跑测试，程序要读的那几份只跑读它的那一项；身份、授权、保护、发布器本身或影响范围不清的改动走标准发布。快速入口 Inspect 返回的 path_supported 只说明快速入口认得这条路径，要不要走快速路径仍由模型判断。
