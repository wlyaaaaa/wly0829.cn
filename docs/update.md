# 网站怎么更新（一页规矩）

- **是什么：** 本人的个人网站 wly0829.cn：讲解页（项目、技能、规则）走排版程序，驾驶舱、授权页、首页是代码页。
- **入口：** 本人说“更新网站”（可点名项目）才更新；构建 `npm run build`，发布照 [发布与扫描](publish-and-scan.md)。
- **不做什么、归谁：** 不替别的项目修代码（归各项目）；驾驶舱数据归 PCConfig 状态服务；全局规则归 `.agents`。
- **改了留一句：** 改了这个仓库、对用的人有影响的提交，说明里单独一行以“变化：”开头，写对用的人变了什么（例：“变化：备份页不再手写上次运行时间”）。没影响的不写，提交说明是英文时这一行仍用中文。

**施工期间（2026-11 全站更新）：** 别的对话要更新网站，先找全站更新的总调度对话，不自己动手。

## 什么时候更新
1. 只有本人说“更新网站”才更新。别的项目改了，只在那个项目的提交说明里留“变化：”那一行，不开网站任务、不交接。
2. 不点名：动了的项目都进（账里记的任一来源仓库从上次核到现在有提交就算动了）；只在点名时更新的 5 个项目（learning、personal-health、cacb、codex-remote、personal-finance）不点名不进；冻结项目不核。仍由冻结字节提供的旧页，这次涉及、不换就明显过时的，同一次换成现在的排版页（做法见 [冻结页转换](frozen-conversion.md)），没涉及的不动。

## 时间（硬的三条）
3. 好了的页先发：每趟只带过关的页，不等别的页；之后每 3 小时发一趟。
4. 一页每次更新最多修 3 次（内容、程序、看屏哪一关退回都算），还不过就放下：草稿不合入，线上仍是旧版，草稿和原因留在本次目录，下次排最前。
5. 总上限从本人开口算：小改（点名不超过 3 页或只换数）3 小时，其余 12 小时。到点只做三件：放下没过关的、发已过关的、汇报“还剩什么”，等本人说。`update` 命令过了上限拒绝开新页、新修。
6. 每步用时只记不拦；钟不传给写稿和核对的 AI，过关标准不随时间变。

## 一次更新怎么走
| 步 | 做什么 | 谁 |
|---|---|---|
| 0 | 记截至时刻、列范围、新项目新技能合成一道多选题问本人（不等答案先做别的）、排先后、建本次目录 | 程序 |
| 1 | 取数、改数、提交进作者源；正文从这个提交起改，本次不再第二次改数 | 程序 |
| 2 | 按项目核和写：Sol 逐句对来源核、列全能力和入口；Opus 定讲不讲、怎么讲、写稿。改动是草稿，放本次目录 | Sol、Opus |
| 3 | 另一个工作副本套草稿试建，只建改了的页；程序查字被切、叠压、认不出块、缺图、新数没进页、链接、不该公开的词。一页不过只记这一页 | 程序 |
| 4 | 没看过的 AI 只看改了的屏和摆法翻了的屏，只报“坏” | Sol |
| 5 | 过关的页写进作者源并提交；整站成包、对账、预演、上传、发布、回读；回读成功才挪账里“核到哪” | 程序 |
| 6 | 汇报：上线的页（带链接）、放下的页和原因、用时表、流程这次改了哪一处 | 主持 |

断了能续：每步产出都是本次目录里的文件，新对话读状态文件接着做，已过关的页不重做。

## 拦什么
7. 只拦三类：事实和来源对不上（逐句核出的“不对”没改掉）；页面坏了（字被切、叠在一起、整屏空白、读不通，图里印的用法和字相反）；有不该公开的。
8. 别的不拦：别扭、不够好看、旧版就有的老毛病、摆法翻了但没坏，都记进“排版和好看”的单子，以后成批重排，先出图给本人看。
9. “查不到出处”只记不改；改不对的句子就删掉，不带已知的错上线。同一条能力讲在几页、改了说法的，这几页同进同退。

## 写什么
10. 每页先答三句：帮本人办成了什么事、怎么用、厉害在哪。精彩的排前，技术细节收到靠后。
11. 讲本事不讲流水账；一件事只在一处讲透，别处一句话加链接；说肯定的人话，限制只留真会坑人的。
12. 页上说能做的要现在真能做；例子哪个精彩用哪个，编的例子里用到的每个本事要真能做，写成情景，不编带日期的实测记录；不写“设想”“还没实际跑过”。例子要有难度或反差、具体，一页一个最好的，想不出就不举。
13. 讲解页上不手写“现在的状态”：会随时间自己变的（上次运行怎样、还没好的、要你做的事、回执）删，改成程序现取或只留去驾驶舱的按钮；发生过就不再变的留；数量和固定参数归数字登记，程序取。拿不准就问：下周不改它，它会不会变成假话。
14. 改哪屏就把这屏当整体读一遍，要通顺；放不下的新内容不加屏、不动构图，记“待加屏”排队。每周更新里没人手调 `layout.json`。

## 不许动
15. 更新期间不改共用排版层（`src/typeset/**`、量屏和转换程序、共用样式；构建开头有锁会拦）、构建发布检查程序、这一页规矩。工具坏了，受影响的页放下，收工后另开一件活修，最多 2 小时，修不好退回上一个能用的版本。
16. 构建、发布、检查程序和文档的改动，不许让任何页的成品变一个字节。
17. 仓库是公开的：本人的私事、原话、设计稿、每个项目的编辑底稿（账）不进仓库；账在私有伴随库 `public-project-private-backup` 的 `projects/wlyaaaaa/wly0829.cn` 下。
18. 网站内容工作可读本人的私人来源，不受个人资料锁限制，不因锁留 Unknown；能不能公开另按 [公开内容规则](design/panel-content-contract.md#public-content-gate) 判断。取不到的数保留原日期并写明 Unknown，不编。
19. 已有授权：核出来源项目自己的错，从来源项目修（含功能），不拿页面遮；所有关过了，照 [发布与扫描](publish-and-scan.md) 提交、普通推送现有 PUBLIC `main`、发布并回读，不再问本人。新的公开去处、花钱、密钥外露、强推、本人说先停的，不在授权里。
20. 不加守护进程、定时任务、轮询服务来让网站保持新。

## 分工
- 主持（Opus 对话）：听懂本人要什么、定取舍、收工汇报；只看每个项目一行的汇总，不逐张读核对单。
- Sol：逐句核、列能力和入口、对出处、整页查打架、看屏、出了岔子修程序。Sol 不判断讲不讲。
- Opus：批阅单句改法（medium）、讲不讲和写（high）、当第一次来的人读（没看过的 high）。
- 重画图：Opus 写提示、Luna 出图。每周更新不开工作流。

## 流程自己怎么改进
- 收工后（不在更新中）只改最费时间的一处：先删一步，再交给程序，最后才改一句规矩；改了什么在本页末尾记一行。
- 本页 80 行以内，加一句先删一句；只为真出过的事加检查，加的得是程序判得了的。
- 连着两次到总上限时放下的页超过三成：停下，带数据告诉本人这套流程不行，不再打补丁。

## 命令（做出来的单各自补自己的几行）
- `python -B -X utf8 tools/update.py numbers --run-dir <本次目录>`：先取全部已登记允许页的数字、写作者源和真实观察日并提交；`state.json`、`scope.json` 的 `author_base_commit` 是核写正文的起点，同次再改数会拒绝。`--budget` 默认300秒，只记用时；明确只换指定页数字时加 `--only 页名,页名`。数字随头一趟发布，此命令不发布、不挪已发布核对点。
- 未结：IPv6 资源地址的准备分支等下一次正式发布一起合入，见 [OSS 资源契约](oss-publication.md) 末节。
- `python -B -X utf8 tools/update.py start --requested-at <开口时间，含+08:00> --run-dir <公开工作树外的新目录>`：记来源提交、范围、一道多选题；`--project ID`、`--page 页名`可重复，点名时只列点名范围；`--scope <JSON数组文件>`提供周更范围名单，可与点名合用；均不填则列全部动了的项目，`--numbers-only`只换数。
- `start --first-pass`仅全站头一遍使用：全站每页入围，含5个手动项目；冻结项目只核冻结说明和去向，无总截止，三次修复上限照旧。续跑不重开start，改用`status --run-dir <原目录>`，读`scope.json`、`state.json`和`timing.md`。
- 同一命令的`begin/repair/drop --page 页名`开页、续修、放下（放下附`--reason`）；`step-start --page 页名 --step content|program|visual --budget 秒`开步骤，`pass/reject`收回执（通过附`--artifact 本次目录内文件`，退回附`--reason`）；同一退回后的重改只开一次`repair`，各关共用三次。
- 所有操作均带`--run-dir`，重发沿用`--event-id`；全局`step-start/step-end --step 步骤名`也记用时，结束附`--artifact`。截止后只可放下、记`publish/report`和已过关页的`record-published --page 页名 --artifact 发布回执`；登记不代替正式发布与账的回读核验。最终`finish --artifact 本次汇报`固定收工时间，保留未完成页，继续须新开一次。
- `batch-plan --run-dir <本次目录> --task-id <整件编号>`按私有伴随库 `docs/update-templates/` 开 a（每页）、b（每项目）；`--kinds ef --materials <JSON>`开改稿核对，JSON 按页短名填模板材料（`本页改动清单`、`改完的整页`、可选`页图片目录`），`*`可填共用的`块导出文件`。e 只开有改动清单的页，f 每周只开材料列到的页、头一遍全开；两阶段页稿快照分开。
- `batch-run --run-dir <本次目录> --max-running 10 --min-free-gb 6`作为一条后台命令：按路数与空闲内存补发、一个 Watch 等候并收回执；每单都带具体 RepeatReason，保留原派活拦截。Codex 主持须加`--parent-harness Codex --session-id <当前完整线程号>`；留言、失败或异常叫醒交主持，原命令可续，不重开已有单。
- `batch-collect --run-dir <本次目录>`只收不派；`batch-summary.md`每项目一行，JSON 另列计数、并发峰值、每张业务回执与包装器本轮汇报、Sol 已知工时及未知数（明细在`batch.json`）。只按当前阶段分流：零项结束、登记数交数字、单句合批阅、候选/整段/数变等进 c；`opus_to_open`列填好卡的路径和档位，由主持开，命令不调用 Opus。`host-notes.md`留失败、歧义和留言，内存不足留待补发；试建、看屏、合入、成包发布待 f3 到 f6 补。
- `python -B -X utf8 scripts/content-refresh/block_tool.py export 页名 --out 本次目录/块.json`：导出原文字符区间、横竖各自的块归属、字数与登记数；默认容量保守取原有字数（余量0），`--capacities 已测容量.json` 可按 `屏id/h或v/块索引（从0开始）` 提供已测上限。
- 同一工具的 `write 块.json 改法.json --run-dir 本次目录/草稿` 只写一页一目录的草稿；改法是 `[{"block":1,"action":"改成","text":"新原文"}]`，动作可为“不动、改成、删、其后加”，未列的块不动；嵌套引用和本屏登记数随原文区间重绑，错块或多义则整页报错。
- `python -B -X utf8 tools/update.py merge --run-dir <本次目录>`：只合入三关全过且草稿未再改动的 `drafts/<页名>/`；正文、摆法、素材行和数字定位一起提交，账中同能力的页同进同退。未合页的草稿与原因留原处，下次范围优先列出；结果在 `merge.json`。
- `python -B -X utf8 scripts/content-refresh/checks.py --input 本次目录/检查输入.json --out 本次目录/页检查.json`：只查输入中本次改页的未填模板、同值与加总关系、屏字数增长；输入和逐页回执见 [检查接口](../scripts/content-refresh/README.md#本次改页的程序检查)，超过三成只提醒。
- `publish --run-dir <本次目录> --dry-run`：首页重画先提交、整站构建、对账及扫描后预演；正式发布去掉`--dry-run`，同包预演后上传、发布、回读，成功才记账。仅首趟旧式基线加`--legacy-baseline-reason <整站换版理由>`，回执记“首发用旧式基准”；`--confirm <本趟live/publish-receipt.json>`在中断后只补记本趟账。
