# wly0829.cn 托管策略

- 状态：已确认
- 日期：2026-08-08
- 适用范围：`wly0829.cn` 与 `www.wly0829.cn` 的个人展示面
- 源码仓库：<https://github.com/wlyaaaaa/wly0829.cn>

## 目标

建立一个长期可访问、无需个人电脑持续在线的个人站点框架。站点当前只承载展示面和前端交互，不填充履历或项目数据，也不依赖数据库、登录或服务端密钥。

决策优先级如下：

1. 免费和无人值守优先。
2. 使用自有域名并启用 HTTPS。
3. 中国大陆网络应尽可能直接访问，但免费阶段不承诺大陆可用性 SLA。
4. 保留公开源码、提交历史和自动部署能力。
5. 不影响现有企业邮箱和其他公网能力。

## 已确认的托管路线

### 阶段一：GitHub Pages

GitHub 仓库是源码事实源，`main` 分支的批准变更通过 GitHub Actions 自动构建并发布到 GitHub Pages。

- 托管费用：免费。
- ICP 备案：不需要，站点不使用中国内地托管节点。
- 电脑在线要求：不需要；电脑只在本地编辑或主动提交代码时使用。
- 域名：最终接入 `wly0829.cn` 和 `www.wly0829.cn`。
- 适用性：当前站点为纯前端展示面，适合静态托管。

GitHub Pages 是当前默认选择。只有在真实大陆网络验收持续失败时，才进入下一阶段。

### 阶段二：EdgeOne Pages 全球可用区（不含中国大陆）

继续使用同一 GitHub 仓库作为源码事实源，由腾讯 EdgeOne Pages 自动构建和部署。

- 托管费用：优先使用长期免费套餐。
- ICP 备案：不需要。
- 电脑在线要求：不需要。
- 自定义域名：必须使用持久的自定义域名，不把临时预览地址作为正式入口。
- 预期收益：尝试获得比 GitHub Pages 更适合亚洲方向的境外边缘线路。

本阶段仍不使用中国内地节点，因此只作为免费线路优化，不承诺大陆稳定性。

### 阶段三：ICP 备案与中国大陆节点

只有阶段一、阶段二均不能满足实际访问需求时，才进入本阶段。

- 购买一项符合备案要求的中国内地云资源。
- 完成个人非经营性网站 ICP 备案及接入方要求的后续手续。
- 将站点切换到 EdgeOne Pages 中国大陆可用区，或当时更合适的中国内地静态托管/CDN。
- 在页面底部按要求展示备案编号和查询链接。
- 电脑在线要求：不需要。

本阶段的目标是获得真正的中国大陆节点，而不是继续依赖访客代理或跨境线路。

## 阶段切换条件

一次偶发超时不能触发迁移。满足以下任一条件时，才认为当前阶段不合格：

- 在不同日期和时段，从至少两个独立大陆网络持续出现连接失败、超时或非预期 4xx/5xx。
- 移动数据与家庭宽带均无法稳定完成首页加载。
- 自定义域名的 HTTPS 无法在合理传播时间后正常签发或保持有效。
- 托管平台的区域、产品或公开访问政策发生变化，导致正式域名不能持续公开访问。

每次切换前应先在测试子域完成部署和访问验收，再变更正式入口。

## DNS 与邮箱硬边界

域名同时承载企业邮箱。任何托管迁移都必须遵守以下规则：

- 变更前只读导出完整 DNS 基线。
- 不修改域名 NS，除非另有独立方案、完整迁移清单和明确授权。
- 不删除、覆盖或合并现有 MX、SPF、DKIM、DMARC、邮箱验证记录及 `mail`、`smtp`、`imap`、`pop3` 等邮箱记录。
- 只变更本次网站接入所需且已核对的 `@`、`www` 或专用测试子域记录。
- 根域已有 MX/TXT 时，不直接添加与其冲突的 CNAME；若平台只提供根域 CNAME，立即停止并改用受支持的 A、AAAA、ALIAS/ANAME、CNAME Flattening 或 `www` 主站方案。
- DNS 验证 TXT 只新增独立值，不替换已有 TXT。
- 回滚时只删除或恢复本次网站迁移所变更的记录，不覆盖整个 DNS 区域。

## 发布与验收

每个阶段都必须分别完成以下检查，不能用单一控制台状态代替公网验收：

1. **源码**：记录分支和提交哈希；工作树无意外修改；仓库中没有密钥、令牌或私有配置。
2. **构建**：生产构建成功；产物只包含公开前端资源；刷新和不存在路径行为符合预期。
3. **托管**：平台报告生产部署成功，公开地址与预期版本一致。
4. **DNS**：权威 DNS 与公共递归解析结果一致；网站记录正确；邮箱 DNS 与基线一致。
5. **TLS**：`wly0829.cn` 与 `www.wly0829.cn` 证书域名、证书链和有效期正确，无浏览器警告。
6. **HTTP**：两个正式域名返回预期页面或明确设计的跳转，不落入默认站、错误页或安全拦截页。
7. **大陆网络**：至少使用移动数据和另一条独立网络进行无代理访问；条件允许时覆盖不同运营商。
8. **回滚**：确认旧入口或上一阶段仍可恢复，并记录本次实际变更的 DNS 项。

## 明确不采用的方案

- 不把 OpenAI Sites 继续作为面向中国大陆访客的唯一主站。
- 不要求访客使用海外代理。
- 不使用 Tailscale Serve 作为公开站点，因为它只面向 tailnet 内设备。
- 不复用或覆盖当前 Tailscale Funnel 上已有的本地服务。
- 不为了当前静态空框架提前引入数据库、长期运行的个人电脑或必须维护的应用服务器。

## 当前状态

- 阶段一已于 2026-08-08 实施，公开 GitHub 仓库的 `main` 分支是源码事实源。
- GitHub Actions 会为每次批准并推送到 `main` 的变更生成独立静态产物并发布到 GitHub Pages；原托管平台构建保持可用，但不再承载正式域名。
- `wly0829.cn` 使用 GitHub Pages 官方的四条 A 记录，`www.wly0829.cn` 使用指向 `wlyaaaaa.github.io` 的 CNAME。
- GitHub Pages 已为根域和 `www` 签发证书并启用 HTTPS；`www` 自动跳转到根域。
- 企业邮箱的 SPF、三条 MX 以及 `mail`、`smtp`、`imap`、`pop3` 记录在迁移后保持原值。
- 技术验收已经通过。中国大陆不同运营商的长期稳定性仍以真实访问观察为准；只有达到本文的阶段切换条件时才进入阶段二。

## 决策摘要

```text
GitHub Pages
    ↓ 大陆网络持续验收失败
EdgeOne Pages 全球可用区（不含中国大陆）
    ↓ 仍持续失败或明确需要大陆节点
ICP 备案 + 中国大陆静态托管/CDN
```

除非目标或外部平台条件发生实质变化，后续实施应保持这一路线和 DNS/邮箱硬边界。
