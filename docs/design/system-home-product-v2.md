# 个人 AI 协作系统首页 v2

状态：内容取证与正式实现中

## 产品角色

`System` 成为 `/` 首页，解释一套个人 AI 协作系统怎样把通用 AI 与智能体能力、全部项目、现行规则、Skills、资料入口、电脑现场和验证恢复连接起来，让真实工作能够持续完成。

它不是当前十个项目的合集，不是项目关系图，不是营销落地页，也不是后台管理控制台。

通用 AI 与智能体能力是系统成立的底层生产力，包括自然语言理解、推理、搜索、视觉与文档理解、工具和代码执行、浏览器操作及并行协作。公网只使用厂商中立的能力描述，不写具体模型名或兼容运行层名称，也不把通用能力冒充个人项目开发成果。

个人系统的独特价值，是把上述通用能力与长期项目、规则、Skills、资料和领域事实、机器现场、执行工具、验证、保存和恢复连接起来。

## 四个页面的边界

- `/`：新的 System 首页，可使用独立的产品总览、真实工作分镜、系统依赖和动态介绍。
- `/projects/`：沿用当前项目索引 UI；项目卡、模块链接、状态与快照边界不重做。
- `/projects/<slug>/...`：沿用当前项目详情 UI、`速览 / 产品 / 技术` 阅读层和模块导航。
- `/rules/`：沿用当前单页规则工作台 UI；只同步 E95 和优化内容。
- `/skills/` 与 Skill 详情：沿用当前目录、单行分类和详情 UI；只优化快照与内容。

System 首页的设计不得扩散到项目、规则和 Skills 页面。

## 当前视觉基线

以 owner 最近提供的八张截图和长篇批注为最高视觉规格：

- 保留现有白底、深绿、细分隔线、慢速平行发丝、现有页头和字体体系。
- System 首页可独立使用真实工作案卷分镜、四泳道依赖图和有价值的动态高亮。
- 浏览器 100% 必须达到此前 125% 的阅读舒适度；不得用整体 `zoom` 伪装修复。
- System 有效内容宽度约 1160–1200px；正文基准 16–18px，实际系统名 20px 以上，信息文字不得低于 12px，交互目标至少 44px。
- 黑色详情面只在它形成稳定、自然、长度一致的证据说明时使用；否则回到白底编辑式说明。
- 节点深浅必须代表明确的当前场景是否参与，未参与节点仍保持至少 60% 可见，不制造“不可用”误解。
- 所有节点和目录项最终链接到真实页面；尚无页面的能力使用稳定锚点或 Skills 入口，不能使用假链接。
- 390px 与 320px 不缩小桌面关系图；改成纵向关系段、直接显示关系文字和展开说明。

## 内容原则

- System 首页使用深度原始来源：项目仓库 README、AGENTS、产品设计、架构、恢复、验证、关键代码与测试；规则使用活动 E95；Skills 使用 canonical `SKILL.md` 和当前公开指南。
- 现有网页摘要可以作为线索和已验快照，但不能作为唯一来源，也不能从一句短摘要扩写故事。
- 每个公开主张必须能回到原始来源、代码、测试或带观察时间的 Owner 事实；无法支持的内容保持 Unknown，不补故事。
- 首页产品总览优先人话，但不能省掉真实模块、复杂流程、失败恢复、依赖和证据。
- 任何规则、项目、Skill 或系统介绍必须回答：实际帮什么；阻止什么事故；普通人怎样说；内部怎样协作；最后得到什么；正常、发现问题、无法运行时分别怎样。
- 不使用具体模型名或兼容运行层名称；不忽略通用 AI 能力，也不把它们写成个人开发成果。
- 不展示维护分类、任务交接、内部 Owner 台账或其他施工词。
- 页面底部不使用“诚实范围”标题；真实性边界放进对应能力、场景与证据说明中。

## 首屏

推荐产品名：`个人 AI 协作系统`。

推荐主题：`AI 如何协助我完成工作`。

首屏必须讲清：

1. 通用 AI 能力负责理解、推理、研究和操作；
2. 个人系统提供真实资料、电脑现场、长期项目、规则和稳定入口；
3. 系统最后交回成品、证据、仍未确认的部分和可继续或恢复的位置；
4. 项目、规则和 Skills 不是智能来源，而是让通用能力长期、准确、安全地作用于个人工作。

禁止使用“系统”“不用记工具名”作为空洞主张，也禁止把库存数字作为首屏主角。

## 真实工作分镜

首个主视觉一次只讲一件真实复杂工作，不展示全系统蜘蛛网。每个场景直接呈现真实输入、实际系统、项目与 Skills、规则作用、交付结果和最重要边界。

计划场景：

1. **完成一个真实需求**：自然目标、原始项目文档与源码、项目规则、通用推理与工具、实现和测试、问题复现、独立验证、保留并发修改、最终可用结果。发布只在任务需要时作为末端，不把“项目发布”当日常开发主角。
2. **找到资料和媒体原件**：从时间、地点、人物、文件角色和内容线索出发，分别进入媒体与非媒体原件定位；只返回少量核对过的候选和真实入口，不全盘扫描、不复制原件，也不把零匹配写成绝对没有。
3. **微信工作记录与多媒体材料**：具名聊天、回复关系、语音、图片、文件和扫描附件进入有界任务，经材料/媒体定位、语音和扫描理解、来源核对，形成纪要、行动项、引用位置和待确认项。
4. **交付一份文档**：混合附件先按格式分流，扫描件保留版面，乱码回到原始字节诊断；可编辑源稿、PDF 生成和逐页视觉验收分别完成，不覆盖原件、不复用陈旧输出。
5. **电脑间歇故障诊断与安全修复**：通用推理、TimeAudit 历史、PCConfig 现场、系统事件和必要资料共同排查；不靠重启或单一指标猜根因，交付候选原因、证据、排除项、安全修复和观察计划。
6. **重装、迁移与完整恢复**：资产与软件清单、备份和哈希、项目、运行时、端口、计划任务、自启动、凭据、加密数据、DevConfig、登录和自然重启验收分层恢复；复制成功不冒充系统可用。
7. **健康协作**：病历、检查报告、设备数据、医嘱或订单、录音和权威资料形成当前证据；区分事实、意见、风险、未知和选项，帮助准备行动和沟通，急症与最终决定边界清楚。
8. **跨设备继续同一项 AI 工作**：个人开发的连续性产品把手机接到电脑上的同一任务、文件、审批和队列；不传桌面画面，不复制第二份聊天，最终仍由项目和 Git 事实证明是否完成。
9. **AI 协助研究和学习**：查权威来源、讲人话、接受反例、重新查证、必要时做最小真实验证；不监督、不评分、不自动推进。
10. **怎样证明 AI 真做成了**：真实任务、隔离环境、隐藏验收、独立验证和失败分类；不是排行榜，也不把测试数量当能力。

场景不自动轮播；切换只做 160–220ms 的淡入和最多 4px 位移。默认内容无需点击已经完整可读。

## 系统依赖

场景之后先展示“全部项目怎样组成个人 AI 协作系统”：本次项目总账中的全部 GitHub 仓库按稳定系统域进入能力版图；当前 10 个项目只是已有完整详情页的入口。能力版图使用自动高度的全宽系统域和紧凑资产项，不把所有仓库画成等权蜘蛛网，也不为未完成详情的项目生成占位页。计数必须带观察时间，未来项目先进入能力版图，再按 owner 顺序补齐详情。

“文书和材料制作”可以进入能力版图，公开产品表达说明合同、正式说明、申请、事件材料和提交包怎样进入原件核对、文书生成、格式验收、状态分层和恢复；不公开私人正文和个人结果，正文不出现“包装”施工词。

完整能力版图下方保留“核心基座与代表性协作链”。它只解释当前场景怎样调用代表性项目、Skills、资料和规则，不再承担全部项目清单。默认主干：

`通用 AI 与智能体能力 → 规则约束与 Skills → 资料/领域事实和全部项目工具 → 现实执行 → 分层验证与人类验收`

三大基座：

- `.agents`：规则、授权、能力使用和协作方式；不提供基础智能，也不替项目拥有业务事实。
- `PCConfig`：电脑、路径、端口、运行时、软件、任务、自启动、凭据、备份和恢复。
- `GitHub 总索引`：全部项目身份、公开性、工作树、同步、发布和正式回读。

实际系统包括但不限于 Password Center、材料库、媒体库、微信入口、固定云端工作入口、ChineseASR、LocalOCR、TimeAudit、PC Panel Hub、CACB、Codex Remote 和个人健康证据。它们是代表性系统，不构成全部项目清单。

默认总览不淡化任何节点；选择场景只突出精确节点和真实依赖。每条边必须有类型、可见标签、人话解释和证据入口。

## 目录连接

System 首页只负责解释和连接，不复制三个成熟目录的完整 UI：

- 规则：几句话解释每条规则在协作系统中保护什么、何时影响任务和一个日常例子，然后链接到 `/rules/`。
- 项目：几句话解释精选项目解决什么复杂工作、怎样进入系统、与谁协作和当前边界，然后链接到 `/projects/` 或具体项目。
- Skills：按人类动作展示入口，说明普通请求、所需输入、最终交付和不会做什么，然后链接到 `/skills/` 或具体 Skill。

其余 GitHub 项目进入带观察时间的安全聚合；没有获得项目页前不得生成占位介绍。

## 验收

- 5 秒：首次读者能说出这是通用 AI 能力与个人项目、规则、Skills、资料和电脑现场组成的个人协作系统。
- 20 秒：能复述一个场景使用了哪些真实系统、规则如何作用、最后交付什么。
- 60 秒：能切换场景、看懂依赖、点击真实项目/规则/Skill 并返回。
- 100% 缩放：内容密度不低于 owner 认可的 125% 视觉舒适度。
- 1440、1600、1920 有效内容均约 1180px；1024、768、390、320 无横向正文溢出。
- 项目、规则和 Skills 现有页面截图、结构和交互无回归。
- 无 JavaScript 时核心内容和关系完整可读。
- 当前规则为 E95；公网内容无具体模型名或兼容运行层名称，无维护标签、秘密或私人载荷。
