# MAP 共享信息架构 v1

status: accepted-for-implementation

accepted_at: 2026-08-30

owner: 吴乐阳

implementation_scope: shared-information-architecture-v1

## 目标

网站继续是面向本人的专业、人话、只读项目面板。共享结构必须让人快速回答：

1. 这里有哪些项目，它们分别解决什么问题；
2. 整个系统由谁负责什么，项目和能力怎样发生真实关系；
3. 当前页面依据了什么项目状态，网页快照又没有覆盖什么；
4. 不知道准确名称时，怎样从自然问题找到正确项目、规则、Skill 或项目内章节；
5. 第一次进入复杂项目时，怎样先看懂产品，再按需进入技术细节。

不得为了视觉包装删除技术事实，也不得把网站内部刷新策略、施工分类或 Owner
bookkeeping（内部施工台账）渲染到公网。

## 顶层信息架构

顶层固定为四项：

- `项目`：全部项目卡和项目详情；
- `系统`：跨项目责任、事实来源、消费关系和可调用入口；
- `规则`：五份当前规则的同页工作台；
- `Skills`：当前可使用的个人能力目录。

`系统` 是独立顶层，不属于某一个项目，也不在每个项目里重复。项目相关设计继续
留在项目或模块中；系统页只表达真实跨项目关系。

## 单一上下文搜索

全站始终只有页头一个搜索框，不再在正文增加第二个搜索框。

### 默认作用域

- `/`：`项目`，只返回项目实体；可匹配项目名、用途、模块和自然问题，但结果落到项目；
- `/system/`：`系统`，搜索责任源、关系、项目与能力入口；
- `/rules/`：`规则`，搜索规则和规则正文；
- `/skills/`：`Skills`，搜索全部 Skills；
- `/projects/<slug>/...`：当前项目，搜索该项目总览、模块和章节。

搜索框显示当前作用域。用户可主动切换到 `全站`；默认作用域不能成为逃不出去的硬锁。
`全站`结果按 `项目 / 系统 / 规则 / Skills` 分组。

### 发现与完整结果

- 聚焦空搜索框时显示当前作用域的可搜索内容和真实例子；
- 下拉面板最多预览 9 条，末尾必须提供 `查看全部 N 条结果`；
- 完整结果使用可直接打开和后退的 `/search/?q=<query>&scope=<scope>`；
- 支持键盘上下选择、Enter 打开、Escape 关闭和清晰焦点；
- 结果数变化通过 `aria-live` 播报；
- 搜索提示可以加长，不能用第二个输入框解释第一个输入框。

## 项目卡

项目卡保留现有两列布局、项目摘要、仓库/私有状态和全部可见模块入口。原来的纯数量
统计改为两类语义，不能互相冒充。

### 项目状态

`项目状态` 只来自该项目当前快照中的真实 Owner 结论，例如：

- 运行正常；
- 可用但有明确边界；
- 已发布并可使用；
- 当前不声明在线运行。

不得无证据默认写“运行正常”，也不得把网页是否验收当成项目状态。

### 快照边界

每张卡只显示一条浅黄色 `快照边界`，说明本页当前没有覆盖或不能证明的一个
决策相关事实，例如：

- 完整恢复本次未验；
- 以上次已验快照为准；
- 本页不承诺后台实时同步。

浅黄色表示阅读注意事项，不表示项目故障：

- 不使用警告图标；
- 不写“项目缺口”；
- 不把 `本次未验` 着成项目异常；
- 只有真实 Owner 已确认的项目问题才使用警告状态。

详细证据与未知项留在项目内部。

## 项目阅读层与模块

复杂项目的 Overview（总览）使用三层阅读入口：

1. `速览`：默认层。用总结和人话让人最快知道项目干什么、为什么需要、怎样使用、
   会得到什么，以及当前最关键的事实和边界；
2. `产品`：解释产品对象、真实场景、使用方式、角色、产品方向、职责、不负责什么、
   失败时怎样处理和怎样演化；
3. `技术`：组件、数据流、模型/Provider、技术使用流程、证据层、测试、命令、恢复和
   项目模块入口。

三层内容在初始 HTML 中完整存在。JavaScript 只做可访问的显示切换；无 JavaScript 时
按 `速览 → 产品 → 技术` 顺序连续显示。直接 hash 路由可以打开指定层。

项目模块继续保留，因为模块拥有真实责任边界、稳定直达 URL 和独立技术细节。模块不再
与三层阅读入口竞争：

- Overview 的 `技术` 提供模块索引；
- 项目卡继续显示全部模块入口；
- 模块页面继续是深入章节，不复制三套 Overview；
- 内容较短或不需要分层的项目可保持连续阅读，不机械制造空标签。

## Skills 分类

Skills 页面保留现有目录布局，只增加一条单行分类栏。标签、成员与顺序只由
`app/page.jsx` 的 `skillCategoryDefinitions` 维护；本文不复制 Skill slug、动态数量或
第二份分类清单。

- `全部` 默认选中；
- 分类只影响浏览，页头搜索始终覆盖全部 Skills；
- 分类栏在桌面保持一行，在窄屏水平滚动，不换成两行；
- 分类不改写现有价值排序，也不隐藏“全部”入口；
- 状态、来源和成熟度仍按真实证据展示。

## 系统页

`/system/` 直接回答三件事：

1. 谁负责什么事实；
2. 哪个项目消费哪些事实；
3. 用户最终从哪个 Skill 或项目入口使用能力。

默认布局为可读的列式关系表，不使用装饰性放射图：

`事实与控制 → 项目 → 可调用入口`

关系必须有名称和真实方向，例如：

- `.agents → 选择与约束 → Skills`；
- `PCConfig → 机器与运行事实 → TimeAudit / PC Panel Hub`；
- `GitHub 总索引 → 仓库与发布事实 → 项目`；
- `TimeAudit → 历史诊断证据 → timeaudit-diagnostics`；
- `ChineseASR → 中文语音处理 → chinese-asr`；
- `GitHub 总索引 → 项目入场事实 → project-entry-gate`。

页面不得显示网站内部维护类别、刷新方式或施工标签。所有已选项目都按真实可用形态
呈现：软件说明可运行能力，方法说明可直接照做，参考成果说明可阅读和复用；任何项目
都不得因此被虚构成当前在线服务。

未来项目只有存在真实、会改变理解的跨项目关系时才进入关系表；不自动把每个项目连到
每个控制面，也不为了视觉完整制造连线。

关系图下面必须继续提供人话解释，不能让图承担全部语义：

- `怎样读这张图`：说明实线、说明性关系和箭头方向；
- `三个责任源分别解决什么`：用普通问题解释 .agents、PCConfig 与 GitHub 总索引的分工；
- `三条典型使用链`：例如“昨晚电脑为什么卡”“怎样安全进入一个仓库”“怎样处理中文录音”；
- `出现问题先去哪里`：按事实类型给出最短入口，不要求用户先理解内部架构；
- `这张图不表示什么`：不把说明性关联冒充运行依赖，不把项目存在冒充当前在线。

上述解释复用关系数据和项目公开内容，不另建一套会漂移的事实副本。

## 公网语义

- 公网只显示对使用者有意义的产品事实和证据边界；
- Registry 内部项目分类、施工 Owner 与候选状态不得进入项目页、系统页或它们的搜索
  文案；专门负责看板刷新的 Skill 仍可准确解释自己的公开产品行为；
- “可用”按产品真实形态解释，不能等同于“当前在线”；
- 未实现设计必须标成设计，历史证据不能冒充本轮在线验收；
- 网页是最后一次明确刷新和发布的快照，不新增 watcher、轮询、数据库或后台同步；
- L1/L2 普通公开内容不因来源为个人而收紧；L3+ 与可复用秘密继续按活动授权合同处理。

## 响应式与可访问性

- 顶层四项在桌面同排；窄屏保持可读，并允许受控横向滚动或现有移动菜单；
- 页头只有一个搜索焦点；作用域必须进入可访问名称；
- 搜索、Skills 分类和阅读层支持键盘、触屏、焦点可见和状态播报；
- 状态不能只靠颜色；`项目状态` 与 `快照边界` 都有文字标签；
- 页面不得产生横向正文溢出；模块、分类和顶层导航的受控滚动不能撑宽页面；
- reduced motion（减少动态效果）继续停止背景运动。

## 反膨胀边界

- 不新增服务、数据库、后台任务、网络依赖或第三方搜索库；
- 复用现有静态路由、Registry、完整/紧凑搜索投影和共享增强脚本；
- 不为四个顶层区域分别复制搜索实现；
- 不把 Overview 三层复制到每个模块；
- 不把关系图做成独立可视化运行时；
- 新增字段必须有当前消费者和默认/缺失行为，未来项目无需修改共享组件；
- 项目增加到 17 项时，共享结构、搜索、分类与系统页不需要专用分支。

## 验收

实施完成必须同时证明：

- 顶层 `项目 / 系统 / 规则 / Skills` 与所有直接路由可用；
- 全站只有一个搜索输入，作用域、示例、9 条预览和完整结果真实可用；
- 项目卡明确区分项目状态与快照边界；
- Skills 默认全部、分类单行且搜索不受分类限制；
- 代表性复杂项目的三层阅读与模块技术深入不重复、不丢内容；
- 系统页不出现任何内部维护标签，关系方向有真实依据；
- 项目新增到 17 项只需添加内容/Registry/必要关系，不改共享布局；
- 首次 HTML 完整、无加载空壳，键盘、移动端、控制台、404、直接路由、构建与 PUBLIC
  内容门通过；
- 真实浏览器截图与选定设计目标完成同视口对比，`design-qa.md` 最终为 `passed`；
- normal push 后远端 main、Pages deployment 与公网回读都包含目标提交。
