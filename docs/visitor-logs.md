# 访客日志

沿用现有 OSS/SLS 日志、访客信标和本人设备标记，不另建采集系统。AI 回答“谁访问了／有什么人访问”先读仓库 `AGENTS.md` 中的查询入口；工具 `--help` 也说明新旧口径。

实况来访人数、打开次数、逐日、排行和设备分布只取能核对的站外页面信标。本人标记、有效配对、局域网预览、巡检、可识别的自动浏览器、爬虫和表单提交等非页面请求均排除。设备凭据只发给原认证域。认证失败、存储不可用或 `www` 无可确认身份的访问记未知。

现有实况巡检每 15 分钟向同一 OSS 对象发一次无页面计数的 IPv4 HEAD 请求。缓存只留本机已发随机编号，查询时用 OSS 中的真实地址和时刻还原观察点。相距不超过 45 分钟且出口相同的两个点之间，才统计其它公网 IPv4 上的合格信标。同出口、换址间隔、IPv6 和未闭合的新近时间段暂不计入。主机探针只证实该路径，无法确认其它出口路径或未自报的自动化身份。可核对的数仍是下限。

同一巡检约每小时用一次七日信标查询刷新项目页，在原有登记中写入两份汇总。`external_since` 是最早观察到的新分类信标时刻；未带分类的旧记录、无法核对出口的日期和缺日志的日期不作为零来访。

新站和旧站共用域名，以实际发布成功的时刻分界，不按路径猜站点。配置后，普通日期、月份、来源推断、`--cv` 和深读查询都只分析该时刻及之后的事件；输出 `site_scope` 给出本次口径。没配置时行为保持不变。新站的首次观察和入口归属使用独立历史文件，不继承旧站的首次入口；浏览器访客编号和本人设备标记仍沿用。

## 上线与冻结

新站发布成功后，在已配置 `.publish/private/live-project.json` 的发布工作副本执行：

```powershell
python -B -X utf8 tools/query-site-visitors.py start-site-era --execute
```

命令以当前北京时间登记 `site-era.json`，随即按新分界查询一次并刷新实况项目卡的公开版和本人版。稍后执行时加 `--launch-at`，传入成功上线的实际时刻（ISO 格式并带时区）。去掉 `--execute` 可先预演。已有分界时只接受同一时刻。若登记成功后刷新失败，以原时刻显式传入 `--launch-at` 重试。

日常查询和巡检都须使用包含新分界功能的版本，并和上线命令共用默认缓存 `E:\Cache\wly-site-visitors`，或统一指定同一个 `--cache-dir`。按需执行普通近七天查询的副本也须配置实况的两个登记路径。不要在公开仓库保存运行配置、访客记录、IP、设备编号或旧档。

上线成功至少 5 分钟后，由主持执行上线命令打印的 `--freeze-legacy` 命令。`--end` 已填实际上线日（北京时间）。

这条命令只导出早于 `launch_at` 的事件，保留本人、巡检、机器人等原有记录供以后显式查询；旧档是 gzip 压缩的 JSON，写完置只读，不覆盖、不追加、不写进公开仓库。正常查询、信标和巡检不打开它。需要重新导出时用新的文件名，保留原档。云端日志仍按原服务保留策略运行；冻结的是本机旧站快照，不是修改云端存储。

旧档记录查询窗口和来源，`complete: false` 表示不能证明覆盖所有真实访问；云端没有回填、已过保留期或未成功上报的记录不能凭空补齐。输入有损坏行则冻结失败，不把跳过坏行的结果当成成功档案。导出不更新访客历史、实况快照或邮件提醒。

## 查询

专用链接有两条。`https://wly0829.cn/cv` 打开网站首页，`https://wly0829.cn/cv/live` 打开实况首页。两条跳转只记入口，落地页各记一次打开。用 `--entry live-cv` 筛实况入口及其后续页面，`--cv` 继续查根入口的逐次记录。

```powershell
# 当前口径；上线配置存在时自动去掉上线前事件
python -B -X utf8 tools/query-site-visitors.py --days 7
# 专用链接：逐次入口、后续页面、停留；/cv 和 /cv/ 都支持
python -B -X utf8 tools/query-site-visitors.py --cv --days 30
# 某页的事件；忽略路径末尾斜线。/cv 的跳转计入口，不计阅读 PV 和停留
python -B -X utf8 tools/query-site-visitors.py --page /cv --days 30
# 带指定入口标记的事件（包含后续页面）
python -B -X utf8 tools/query-site-visitors.py --entry cv --days 30
# 只有明确要查旧站才使用；不联网，默认查整份档案，也可指定日期窗口
python -B -X utf8 tools/query-site-visitors.py --legacy-archive '<旧档.json.gz>'
```

`--page` 和 `--entry` 可组合，筛选查询不会写回首次观察历史或刷新整站实况快照。`--cv` 是已有的专用链接逐次访问模式，记录 `entry`、`cv-session` 并关联后续页面；没有脚本或信标未送达时不能证明零来访。会话存储不可用时仍保留浏览器编号、本人标记和 `/cv` 入口，后续会话关联保持未知。
