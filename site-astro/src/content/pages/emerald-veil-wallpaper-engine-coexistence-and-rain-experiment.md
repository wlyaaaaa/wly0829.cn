## 这项功能怎样使用

### 为什么需要它

泡泡底下需要一张像样的底图，而我平时的画面是 Wallpaper Engine（动态壁纸软件）在放；如果为了取底图去停它、再恢复，容易卡在过渡画面或恢复失败。另一个主动黑罩有自己的显示目的，不能由泡泡抢回来；这些冲突需要在各自入口处理。

### 举个实际例子

“动态壁纸别动，我打开主屏黑罩时泡泡也别冒出来。”泡泡进场时，程序在屏幕外开一个只给自己用的临时小窗，按虚拟屏的选择载入同一份壁纸材料，拍下一帧当底图；原来的动态壁纸一直在放。哪块屏挂着黑罩，那块屏就不放泡泡。

### 最后我会得到什么

Wallpaper Engine 的图片、播放列表和设置都不被改动，也不会被暂停；泡泡下面是进场那一刻的静止一帧。外部黑罩开启时让位，撤掉后仍按本来的空闲规则决定是否显示。

## 结果怎么看

### 正常工作

能认准虚拟屏上正在渲染的那份 Wallpaper Engine 材料时，用它拍底图；没有运行 Wallpaper Engine 就直接用虚拟屏的 Windows 壁纸。

### 发现问题

材料认不准或临时小窗开不起来时，改用虚拟屏的 Windows 壁纸并记下原因，不把泡泡出现当成用上了动态材料。

### 暂不可用

外部黑罩正在保护屏幕时，被盖住的那块屏主动让位；静态图片恢复仍可独立使用。

## 从哪里开始

启用泡泡后不用另外操作：进场时自动借用虚拟屏的壁纸材料拍底图，有黑罩标记的屏自动让位。会下雨的动态壁纸实验已停用，没有可运行的入口。

### 需要准备什么

- 是否要显示泡泡

- 看到底图不对或黑罩冲突时描述现象

### 从开始到拿到结果

1. **先检查占用**　看哪块屏挂着黑罩标记，被盖住的屏不放泡泡；静态壁纸恢复也不改 Wallpaper Engine。

2. **借材料拍底图**　能确认虚拟屏上唯一的那份材料时，在屏幕外临时小窗里载入它；认不准就用虚拟屏的 Windows 壁纸，画好后再启动原生泡泡。

### 关键规则与设计选择

1. 不全局停止、暂停、重放或重新配置 Wallpaper Engine，初始化失败也不发停播/续播命令；只读它的 config.json 里虚拟屏对应的选图和属性，不改播放列表、壁纸选择或持久配置。

2. 只有本会话里确实在虚拟屏上渲染的 wallpaper64 或 wallpaper32、桌面窗口与虚拟屏边界对得上、材料配置和实际文件也匹配时，才用这份材料；任何一项不成立就回退到虚拟屏的 Windows 壁纸、颜色和适配方式。

3. 外部黑罩用同会话命名句柄表示仍需保护，可以按屏挂，也兼容旧的全屏标记；持有方退出自动释放，避免一个忘记清理的文件让泡泡永久暂停。

4. 会下雨的动态壁纸实验已在 9 月 8 日终止、9 月 29 日删掉实验文件，只留下方向记录和认可的雨幕参数；现役静态壁纸和泡泡都没有因为这个实验改变。

## 当前怎样实现

- 底图来源先要求虚拟屏只有一个可确认的 Windows 底图来源；再看 Wallpaper Engine 的 config.json 里本人设的显示器对应关系和 MonitorN 选图及属性，三者对上才走材料路径。复制出来的临时材料音量设为 0，不影响原来的声音。

- 走材料路径时，开一个准确命名的官方离屏临时窗口 `EmeraldVeil.Background.<进程号>.<GUID>`，放在坐标 (-32000,-32000)，用 openWallpaper / playInWindow 载入、applyProperties 只作用于这个窗口，再用 DWM 缩略图合成进底图；每条控制命令限时 3 秒。WPF 渲染并 DwmFlush 后才启动泡泡，泡泡拿到的是这一帧。

- 退出时只关掉本次的命名窗口和缩略图；程序启动时清理一次真正没人管的旧临时窗口，不改桌面壁纸窗口。运行中材料或引擎状态变了，就撤掉旧画面重新走一遍进场；1 秒一次的背景检查不是持续抓画面，也不是每次都重启泡泡。

- 黑罩标记只探测存在性并马上关闭自己的探测句柄；按屏标记只排除对应屏，旧的全屏标记在没有按屏标记时排除全部目标。50ms策略轮询和界面应用前都会检查，共享的空闲计时继续走；不改 enabled、自启、360 秒或显示拓扑，也不把被盖住的实体屏改投到虚拟屏。

## 出问题时

解决什么

控制器缺失、进程不唯一、命令非零退出或超时会导致本轮初始化失败；本轮没有证明实际暂停/续播画面。

## 边界

- 不改Wallpaper Engine持久配置、选图或播放列表，不暂停它，也不提供通用壁纸引擎适配框架；当前只认 wallpaper64 / wallpaper32。

- 不识别ToDesk、Sunshine等远程产品来决定暂停；黑罩必须通过明确的标记合作。

- 雨景实验已停用，只有本人重新明确启动才重开；失败草稿不作为能力搬进网页。

## 失败与恢复

- **Wallpaper Engine 材料认不准或临时小窗开不起来**：回退到虚拟屏的 Windows 壁纸、颜色和适配方式，并记下回退原因；不随意停止其他壁纸进程。

- **虚拟屏底图来源确认不了，或原生泡泡初始化失败**：这一轮显示失败，撤掉底图，按启动失败冷却规则处理；不承诺画面已恢复。

- **外部黑罩持有者崩溃**：最后句柄关闭后标记自然消失，恢复已有的空闲规则；不留下持久暂停文件。
