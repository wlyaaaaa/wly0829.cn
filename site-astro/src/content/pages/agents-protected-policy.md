# 规则生效、资料解锁与重点保护，分别证明

〔回到项目 → AI 规则与技能基座〕　〔复制 AI 续作说明〕

.agents · 功能说明

重要操作不能靠一句“通过”把全部状态混在一起。规则看哪一版已生效；需要私人资料时看资料期是否还在；真正有严重后果的动作，先由够格的模型把关，必要时再由本人验证一次。普通代码工作不因此停下。

**当前情况：**当前生效的是 E258（2026-10-12 02:18 激活，10 月 12 日 04:41 核验通过）。重大动作现在按真实后果判断，不按字眼；资料期由密码中心统一记录。九月那套“磁盘加密视图、十分钟设备邀请、只认 codex-root”的方案已不是当前流程。

项目源码：私有仓库，源码未公开；用法与技术说明可在下面阅读。

## 这项功能怎样使用

用途与实际影响

## 为什么需要它

如果取消一次验证就把另一份有效授权也撤掉，人会反复受打扰；如果规则校验通过就当作资料、密码或仓库都能随便动，又会越过实际权限。把这些结果分开，才知道哪些工作可以继续、哪一步确实需要本人。

## 举个实际例子

“把这个私有仓库转成公开。”这属于 GitHub 重大动作：我有有效的无限制授权就不用重复验证，否则本人验证一次；私人资料有没有解锁都不影响这一点。如果是删仓库或转移仓库，AI 还会先核对全部本地分支，列出只在 GitHub 网页上有的 issue 和 Release 资产。反过来，“改几行代码、正常推送”不会因为说了“删除”两个字就升级成重大动作。

## 最后我会得到什么

我会知道目前生效的是哪套规则、私人资料是否仍在原期限内、这一步算不算重大动作以及要不要本人验证。取消一次验证不等于全部撤销，没执行或证据不足也会明说。

## 结果怎么看

## 正常时

当前活动版本有效；私人资料只在资料期内使用；重大动作有够格模型把关，需要时本人验证一次，然后执行并回读。

## 发现问题时

取消只终止本次验证，原资料期照旧到原截止；资料期结束后新的取用被挡住，但已打开的文件句柄仍能用，已交给外部的明文也追不回，这些都会如实说明。

## 入口不可用或证据不足时

Hook 缺失或投递不明时，资料状态按“不明”处理并重新读取，不自动锁资料或磁盘；当前模型不够格时，只等那一个不可撤回的最后一步，其余工作继续。

## 从哪里开始

在已接入活动规则的 AI 对话中直接说出要做的事；AI 判断它是普通工作、需要私人资料，还是重大动作。本人验证使用现有入口。

## 需要准备什么

- 要做的动作和目标

- 是否涉及私人资料、秘密、公开或删除

## 从开始到拿到结果

1. **分清需求**　AI 区分普通工作、需要私人资料和真正有严重后果的重大动作。需要私人资料的，由主对话先请本人解锁，再查资料、派子代理和作答；锁着时不给降级回答，子代理也不自己发起验证。

2. **把关与验证**　重大动作先由够格模型把关。GitHub 删仓库、转移、非公开转公开、新建公开仓库：有有效无限制授权不重复验证，否则本人验证一次，不看资料是否解锁；其他重大动作有有效无限制授权或在资料期内不重复验证，否则本人验证一次。

3. **告知实际结果**　分别说明规则版本、资料是否可用、动作是否执行和回读结果；取消一次验证不被说成全部撤销。

## 关键规则与设计选择

1. **重大动作按真实后果判断。** 源定义列出七类，例如批量导出或外发私人资料、取用秘密明文或银行卡、恢复或修改验证因子、关闭保护、删除或转移仓库与转公开、删除唯一数据等。普通改源码、测试、定向提交、正常推送、规则发布和可重建生成物清理，不因字眼升级。

2. **够格的模型把关。** Claude Opus 5.5 medium 以上，Codex 的 Sol 或 Astra High 以上；够格的主对话自己把关，否则派一个同样够格的子代理只做判断、不实施、不再委派。不够格时只等那一个不可撤回的最后一步。动作前把关只决定做不做、要不要本人验证，不能代替对重大改动或决定本身的独立上下文复核。

3. **本人验证不重复。** 有效无限制授权免重复；没开且资料锁着就验证一次；资料期内不重复（GitHub 四类除外，见第 4 条）。这些只适用受信任的桌面 AI（codex-root、claude-root）；其他 AI 做重大动作仍要本人验证。

4. **GitHub 四类单独验证。** 删仓库、转仓库、非公开转公开、新建公开仓库：有效无限制授权免重复，否则本人验证一次，不拿资料期代替。删或转之前自动核对全部本地分支，列出只在 GitHub 网页上有的 issue 和 Release 资产。已保留内容的分支或标签清理、改名、改默认分支、新建私库属于普通收尾，检查不过就停。回执用 `human_factor_performed` 区分复用和本次真人验证。

5. **发布防误删，按意思判断。** 标准和快速发布都调用 `tools/rule_release_guard.py` 比较整套规则。限制句只是改了措辞、缩短、挪位置，或改成指向同版仍有效的同一条规则时，用 Sol medium 做一次语义比对：限制的对象、范围、条件和强度都不变就自动放行，不请本人同意，判为改写的旧句和目标版本证据写进发布回执和版本记录。真正放宽、删除限制，或改动约法正文，仍要通过 `--owner <源消息UUID>` 核对本人的同意；比对不可用或拿不准时按意思变了处理。缺有效出处返回 blocked（标准错误 `e_rules_owner_approval_required`）。普通新增不受影响。

6. **资料期只有一个记录者。** 资料期由密码中心（PasswordCenter）唯一记录，PCConfig 只管安装、路径和机器接线；现役状态入口仍是 StatusPersonalEnvironment。默认时长当前为 24 小时（1440 分钟，可改的设置），范围 0.5–72 小时；改默认不改已有截止，各期限彼此独立。

7. **规则版本层层分开。** 发布版本、源码候选、指针、当前与上一版、ACL 各自核验；C 盘旧规则只是恢复历史，不能当活动规则。

## 出问题时（一）

解决什么

如果把源码草稿当成当前规则，就会让没完成的施工冒充规则；如果把每个带“删除”字眼的操作都当重大动作，又会无谓地打扰本人。模块要同时分清：哪版规则在生效、资料期是否还在、哪一步真的重大。

## 边界

- 普通代码与非私密状态不受资料锁定阻断。

- 资料解锁不授密码明文、恢复、本人接管或仓库权限；反过来也不延长资料期。

- 取消不复活已失效的期限，也不授权继续本人刚取消的事。

- 资料期结束挡的是新取用；已打开的句柄、已交出去的明文要如实说明。

- 规则错误、网络或程序故障不自动当作入侵，不自动锁资料或磁盘，也不建立新安全平台。

- 九月的 PCConfig P1/P2 安装、P3 加密合成实验、P4 恢复和“完整十分钟”设备邀请是旧方案；E257 的重大动作专题已没有这套邀请和磁盘自动保护架构，旧实验日期只代表当时，不推定今天已部署。

## 失败与恢复

| 情况 | 怎么办 |
| --- | --- |
| 本次资料验证取消或超时 | 结束本次请求；原有效资料期继续到原截止，不自动重开或换因子。 |
| Hook 缺失或投递不明 | 资料状态按不明处理并重新读取，不自动锁定。 |
