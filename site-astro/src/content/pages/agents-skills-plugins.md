# 个人 Skills 与插件供应链

〔回到项目 → AI 规则与技能基座〕　〔复制 AI 续作说明〕

.agents · 功能说明

它让我能按用途找回已经保留的能力：把选定图片放大到指定尺寸、分析一份 Windows 卡顿轨迹，或读取指定 .NET 方法的字符串。查清实际入口、运行条件和证据后再使用，不需要记住脚本名。它也防止同一个 Skill 出现几份漂移源码，或看见文件夹就被说成已经可用；每一层只证明自己的事。

**当前情况：**清单登记 32 个要安装的能力（个人 30 个、插件 2 个），比 10 月 22 日多了 10 月 30 日新加的生图技能 image-generation；Codex 和 Claude 共用同一个发现目录。10 月 22 日 07:31 核对过当时的 31 个链接都在、都指向正确来源；新加的生图技能 10 月 30 日只单独核对了它的链接指向源码、当前宿主能看到它，32 个整体没有重跑供应检查，也没有实际生图。安装器已简化为按清单重建链接，不再保留安装事务记录；浏览器自动填保存密码已退役。新任务能否发现、真实使用能否成功，仍各自验证。

项目源码：私有仓库，源码未公开；用法与技术说明可在下面阅读。

## 这项功能怎样使用

用途与实际影响

## 为什么需要它

一个能力写好了，不代表当前对话能找到它，也不代表它能在真实任务里工作。这里帮我按用途找到正确工具，并分清来源、安装、当前可见、下次新任务可见和实际完成。

## 举个实际例子

我可以说：“以前把图片放清楚的工具在哪？把这张图做成指定尺寸。”AI 先用本机工具目录按用途查到入口，确认原图、画幅和目标，再用已有工具交回新 PNG，原图保留。如果我问“这个 Skill 写好了，为什么新任务看不到”，才逐层查来源、链接、当前任务、新任务和真实场景，说明卡在哪一步。

## 最后我会得到什么

我会拿到真实入口、要提供的材料和已有的验证记录；实际运行才会产生新图片。工具找不到、登记了却缺入口，或新任务仍看不到时，会指出具体卡在哪一步。

## 结果怎么看

## 正常时

工具来源、安装链接和这次实际使用各有结果；只把已证实的那一步说成成功。

## 发现问题时

链接指错、目标缺失或新任务找不到时，只标受影响的入口和修法，不把全部能力都说坏。比如工具目录里还登记着已退役的 token-budget-advisor，但它的入口已不存在，会如实列成缺口。

## 入口不可用或证据不足时

来源或安装位置读不到时，明确说现在无法确认；旧文件、旧测试或旧的自报“通过”都不能证明它今天可用。

## 从哪里开始

在已接入能力目录的 AI 对话中直接描述用途，或在本站 Skills 页查入口；本机小工具可以用 `E:\Tools\LocalToolbox\Find-LocalTool.ps1 -Query '<用途>' -Json` 按关键词查。具体运行仍由对应工具完成。

## 需要准备什么

- 要做的事和材料类型

- 是否已有指定 Skill、插件或账号

## 从开始到拿到结果

1. **按用途找入口**　AI 在能力目录或本机工具目录中找真实入口，告诉你需要的材料、账号或本机环境；查找本身不执行、不采集、不联网。

2. **执行对应工作**　取得所需授权后由实际 Skill、工具或连接器处理，不把找到入口当成已安装且能完成。

3. **读回结果**　交回文件或操作结果；来源、安装、当前任务和真实使用分别说明，缺哪层只标哪层。

## 关键规则与设计选择

1. 每个能力只有一份维护源（个人 Skills 和插件两个根目录），用户目录里只放指向它的链接；Codex 和 Claude 共用同一个发现目录。

2. 安装器按清单工作：`-Name` 安装、更新，或按 install=false 移除一个；`-RetireName` 撤掉退役链接；不带名字就按清单整体收敛；不加 `-Apply` 只预演。链接随时可按清单重建，历史在 Git 里。

3. 旧的安装事务记录和“恢复胶囊”不再保留，旧 skill-junction-transactions 只是历史、不再读写。

4. 当前任务、新任务和端到端三层没有宿主证据时一律写“未知”；供应检查已停用外部存储的旧证据，不拿旧自报“通过”当宿主证据。

5. 不动未知目标的链接和同名普通目录，只删链接不删源；不从用户目录反向造源。退役名单现在为空，不等于从没退役过。

## 当前怎样实现

- **普通网页操作：** 只读的公开资料先用自带的网页搜索和读取，不开 Chrome；要用本人登录状态，或网页读取工具读不到的必要页面，才在本人正在用的 Chrome 里，经 Chrome 插件在 AI 自己新开的后台标签页中做，本人已开的标签页只读（本人点名要用的除外）；会新开页的链接先取地址，再在后台页打开，不把 Chrome 调到前台。一个任务连同它派出的子任务，同时最多开 10 个自己的标签页，读完就关，不建标签组；每轮结束前关掉本轮自己开的页（等本人登录的交接页除外），并报“新开几个、关了几个、保留几个”。登录、发码、提交这类关键按钮用按坐标的真实指针点击，点完看页面或网络请求确认生效（插件的无障碍点击在有些页面只聚焦、不触发）。网站要求同意用户协议时按长期授权直接同意；子代理的工具要本人确认时，由根会话在原授权内代确认。

- **浏览器登录：** 优先复用已授权、已登录的会话；同一网站已有看得出已登录、且本人允许用的原标签页时优先用它，不另开新页（同一个浏览器配置里新开的标签页不一定能用上那个网站的登录），也不搬 Cookie。需要密码、扫码或验证时，用本人平常的 Chrome 正常打开登录页（不用插件控制的任务页去开），把那一页当“登录交接页”留着，超时也不关；这是要本人在场时才切到前台的例外，普通网页操作仍在后台；不调用保存密码填充、不从密码中心自动取、不自动输入。本人在电脑前（桌面没锁、5 分钟内有操作，这是 AI 定的默认值，可调）时，把这一页所在的 Chrome 窗口真正切到最前，并用 Windows 实际前台窗口、标题和整屏截图核对；本人不在或说不清时不抢焦点、不反复催，只交回“需要本人在电脑前登录 X”。之后只读地等本人登录，共用一个 5 分钟期限，看到页面上明确的已登录标记才回到原来那一步；本人说已经登录、保留的页面却还显示未登录时，先把这一页刷新一次再看，仍没有才交回“刷新后仍未登录”；超时或本人离开就停在交接页，交回这一步，由根会话登记到驾驶舱。已授权的手机号登录可以用允许的号码和短信或邮件验证码及时填写（短信码用 PCConfig 的 `Invoke-SmsCode.ps1` 从无线 ADB 手机桥读），取不到就只交回那一步。Claude 要用本人已登录的 Chrome 时默认派 GPT AppServer；普通的独立新配置没有登录，不冒充本人。实测（10 月 19 日 22:27）：在一个普通百度页面上把任务页切到最前、核对窗口并关掉这一个任务页，共约 4.2 秒（4184 毫秒）；真实网站的登录交接、以及标签页报 `Debugger unattached` 时能否切到最前，还没验过。

- **上传与提交：** 判成功的原则不变：逐个读页面成功态，再从最终平台记录核对。页面读取或截图超时、页面空白时先当网页卡了：在原页等一会儿再刷新，可以连刷几次，读到内容就接着干，这种刷新不算下面那一次修复。浏览器真出故障时，按当时原生提供方的完整说明和观察到的具体失败层修一次，保留同一浏览器和本人未提交的内容；仍不通就停下需要网页的那一步，把失败层、实际报错和已做到哪里交回根会话，其余工作照做。不改用无头浏览器、任务临时配置、内置浏览器、别的浏览器或远程浏览器去开同一个网站（早先“Chrome 连不上时在同一个 Chrome 用无头任务配置继续”的做法已取消）；无头 Chrome 只用于把本机文件或本机回环服务渲染成图或 PDF 自检。本地 HTML 先用 HTTP 打开。

## 本模块用到的名词

| 名词 | 意思 |
| --- | --- |
| 唯一维护源 | 能力唯一可维护的正文；用户目录只是发现链接，不是第二份源码。 |
| 安装意图 | 清单要求安装，不等于宿主已经注入，也不等于真实场景已通过。 |
| 新任务验证 | 安装之后另起的任务真实看见该能力，不能由当前任务或旧回执替代。 |

## 出问题时（一）

解决什么

Skill 源码、用户目录能否发现、当前任务是否注入和真实自然语言使用是不同的事实。只看文件或链接存在就说能用，最终会得到一份看起来很满、实际没法判断的清单。

## 边界

- 不手工创建或修补发现链接，用安装器按清单做。

- 来源通过不能证明安装、任务注入或真实使用。

- 浏览器修复不授权登录、上传、验证码、删除或最终提交；不自动填保存的密码。

- 退役的 Skill 不会因为历史目录或测试还在就恢复。

- 插件分发单位和 Skill 触发入口不是同一层。

## 失败与恢复

| 情况 | 怎么办 |
| --- | --- |
| 来源缺失或链接指错 | 供应检查报错，按清单重建链接；不从用户目录反向复制成新来源。 |
| 工具目录登记了但入口不存在 | 如实列为缺口（如 token-budget-advisor），不说全部可用。 |
