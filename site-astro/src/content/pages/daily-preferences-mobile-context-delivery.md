# 手机与云端直接使用同一原库，独立文件按需导出

〔回到项目 → 个人理解库〕　〔复制 AI 续作说明〕

个人理解库 · 功能说明

在手机或云端继续使用同一份现行理解，保留重要经历、当前更正和限制；新认识也回到原库，不让旧文件变成另一份当前档案。

**当前情况：**手机经电脑连接共用原库的入口已确认；实际读取、回写和失败恢复仍按这次结果核对，不维护第二份当前档案。

具体测试保留各自日期，页面不实时探测运行状态。

项目源码：私有仓库，源码未公开；用法与技术说明可在下面阅读。

## 这项功能怎样使用

用途与实际影响

## 为什么需要它

定期搬一份背景文件到手机，改口后容易留下两套互相矛盾的“现在”。已接通电脑时直接取同一份理解，离线交接才需要完整导出。

## 举个实际例子

我在手机上的 ChatGPT 说：“结合你对我的了解帮我判断；我刚说的新想法也记回去。”AI 通过电脑 MCP 读取相关背景，再沿原库入口保存值得保留的原话或认识并回读。如果命令失败，就说明停在哪一步、哪些已经完成，从已有结果继续。

## 最后我会得到什么

得到与电脑同源的回答、依据和准确的回写结果；专业事实与当前行动仍由相应领域负责。若我明确需要离线材料或转交给未接入 MCP 的 AI，再得到《当前上下文.md》和《个人理解详述.md》两份完整文件。

## 可以用于当前帮助

手机或云端 AI 通过同一电脑来源取得相关背景，可靠的新认识保存并读回；普通提问不用先导出所有材料。

## 需要分辨

旧理解或人物时期说错时回到拥有该认识的原卡修正，不在手机另写一份当前结论。

## 当前不可用

连接或命令真实失败时说明已完成与失败位置，沿同一目标接续，不重做已完成步骤。

## 从哪里开始

在手机或云端 AI 中照常提问，需要时说把新认识记回原库。

## 需要准备什么

- 当前问题

- 值得保存的本人新原话或认识（如有）

## 从开始到拿到结果

1. **系统核对并处理**　通过同一电脑端原库取相关背景，核对后回写并读回；只有明确需要离线交接时才导出完整文件。

2. **交付与接续**　交回回答、依据与准确保存状态；连接或写入失败从已完成结果续作，不维护另一份现行档案。

## 关键规则与设计选择

1. 当前背景以原库正常入口为准；两份旧 Google Drive 文件只是注明日期的历史快照，不随每次交流、回写或增量重新生成、上传和回读。

3. 文件生成时间不代表所有经历或想法发生的时间；旧计划、假设和原材料中的操作安排不自动变成当前行动指令。

## 当前怎样实现

- 手机或云端 AI 经已接通的电脑 MCP 在电脑上运行 daily-preferences.ps1，按问题选择 profile/evidence/facts/original；重要新原话与认识沿 record/snapshot/snapshot-batch 正常回写并回读，不直接改内部表或生成视图。

- 手机与本机继续使用同一理解库和领域合同，不建立第二套画像或手机快照。独立MCP须先连接认证，再消费同一共享资料期；锁定时不借旧上下文或云端绕行。当前规则改变与旧Skill/运行链是否已迁移分层核对。

- tools/export_mobile_context.py 使用 Python 标准库，通过当前解释器子进程调用 daily_preferences.py profile --json；不直接读取内部表，不联网，也不加载分词器。

- build_documents 先拒绝空 cards 和重复 preference_key，再按本人背景、价值取舍与日常认识组织全部卡；主文件保留 value_text，详述保留 detail_text 或原摘要及 scope_text。

## 边界

- 不公开或在网页刷新中读取手机背景正文、原话及云文件 ID。

- 不建立手机接入层、后台同步或独立手机画像。

- 导出当前阅读内容不等于导出全部原件、数据库或历史。

- 本人已确认电脑 MCP 接通；普通命令先实际执行，不因手机、云端或缺少逐平台验收预判不可用。本页未执行新的手机会话，也不把合成测试当作真实设备结果。

- 阅读、整合和实际帮助仍分别判断，运行命令不替代必要理解。

## 失败与恢复

- **电脑 MCP 连接或原库命令真实失败**：说明精确失败步骤、已完成内容和必要报错；可修则继续，需电脑端接续时从同一目标和现有结果恢复，不重开项目或重做已完成工作。

- **没有当前卡或卡键重复**：在写文件前失败，不以空内容覆盖既有可用交付。
