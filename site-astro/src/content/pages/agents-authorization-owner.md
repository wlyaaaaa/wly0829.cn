# 长期授权、无限制授权与施工责任

〔回到项目 → AI 规则与技能基座〕　〔复制 AI 续作说明〕

.agents · 功能说明

它解决两个麻烦：已经明确允许的事，不必每一步重新问；多个任务同时干活时，又不能互相覆盖，或借一个大目标扩大到别的文件、账号或外部动作。

**当前情况：**长期授权和本人限时接管照常有效。九月那套集中登记“谁在施工”的机制（施工登记、领取、租约）已在 2026-09-27 删除；现在每个任务在自己的工作副本里改，合并时理解对方的改动，只在安装、发布这类单点动作上加短锁。本网页没有重新办理授权。

项目源码：私有仓库，源码未公开；用法与技术说明可在下面阅读。

## 这项功能怎样使用

用途与实际影响

## 为什么需要它

“把网站发布好”不等于任何子代理都能改任何仓库。两项任务若碰到同一文件，还可能互相覆盖、各自声称完成，或者在交接时把没做完的事丢掉。

## 举个实际例子

“这个网站修好后发布到原地址，别每次再问，也别盖掉其他任务。”这项授权跨轮次、压缩和子代理都继续有效。AI 在自己的工作副本里改，合并时先看懂别人的改动再并；真正扩大到新账号、公开、花钱或不可撤回的事，才另行判断。第一次公开发布 Release 要我明确同意，“保持最新”不算首次发布的同意。

## 最后我会得到什么

普通任务持续推进，谁改了什么、还剩什么清楚。限时授权返回真实范围、原到期时间和撤销状态；取消本次申请不会撤回其他有效权限，也不会替我执行下一项业务。

## 结果怎么看

## 正常时

原目标的授权和范围明确时直接继续；限时授权以真实本人验证、范围和原截止为准。

## 发现问题时

目标扩大只暂停对应动作；别人有未提交改动或不能快进合并时不硬推；有效期不会因为重连、换模型或开子代理而延长。

## 入口不可用或证据不足时

缺实际账号、工具或本人验证时不假报权限，已经可做的普通工作继续。

## 从哪里开始

在已接入规则的 AI 对话里说明要改什么项目、最终会影响哪里；已有的长期授权沿原范围使用。

## 需要准备什么

- 目标项目与具体动作

- 已有授权或本轮新增限制

- 可能影响的账号、公开目标或文件

## 从开始到拿到结果

1. **说出动作和影响**　AI 区分普通可逆修改、已有授权的外部动作和真正扩大的目标。

2. **在自己的副本里施工**　每个任务用自己的工作副本；合并时理解对方变更，安装、发布、改计划任务这类单点动作先取短锁。

3. **执行并回读**　在已获准范围内完成，正常推送后回读默认分支；授权或目标不符时只停对应动作并说明怎样接续。

## 关键规则与设计选择

1. 本机低风险、可逆、范围内的读取、编辑和测试直接推进；发消息、外部写入、发布、部署和付费需要明确授权。

2. 本人明确给出的长期授权，在原目标和范围内跨轮次、压缩、主对话、全部子代理和新顶层任务持续有效；项目只能定义客观前提，不能把它降为没有，也不能要求本人重说。现有长期授权还包括：替本人办已授权的事时，网站、平台、软件要求同意的用户协议、服务条款、隐私政策（含“继续即同意”）直接同意，不为协议问本人；派出的 GPT 等子代理因工具要求本人确认（含“当场确认”）停下时，只要那件事本人已经授权过，由派它的根会话当场代本人确认、让它接着做。这两条只省掉“再问本人”这一步，不扩大事情本身的授权：付费订阅、自动续费、付款、案件里的调解和解、重大动作仍照原规则找本人；工具规定必须本人亲手做的步骤（改密码、绕过浏览器安全警告、付款交易这类）交本人办。

3. 授权已覆盖、前提成立时，真实调用一次工具，不先猜平台会拒绝而停下；工具真的拒绝、要求再验证或报错，就按真实结果处理，不伪造成功。

4. 子代理和后续任务的范围、授权、沙箱和资料访问，只取本人授权、父代理授权、适用规则和宿主真实限制的交集，不能扩大。

5. Windows 提权、资料解锁、短锁和用户授权是四件事，互相不产生授权。本人给的长期提权许可也适用于子代理：宿主支持时可以静默提权，确实需要本人在场的，交回根会话安排。

6. 受信任的桌面 AI 现在有两个：codex-root 和 claude-root，各自登记、各自可撤销。密码中心按当前 Windows 账户和实际同账户的桌面祖先进程链认人；型号、管理员权限、工具名、环境变量、电脑 MCP 登录都不是桌面身份。这两个已登记的桌面 AI 可以免本人验证，做密码中心里已登记、且不属于重大动作的凭据操作；重大动作仍按保护策略办。这不会让隐藏的执行者获得桌面身份，也不扩大任务本身的动作授权。

7. 本人私人账号空间在没有公开或分享信号时，与本机私密目标同样可信；可信不等于已授权写入。公开个人数据只按唯一的公开分级表判断，项目想收紧 L1/L2 须本人对具体项目和范围明确指示。

- **无限制授权（本人接管）：** 本人主动要时，AI 直接调用已安装的 `C:\ProgramData\PCConfig\AuthorityHost\tools\Invoke-OwnerTakeover.ps1 -Operation Open`，回执写明 `grant_type=unrestricted`。本人在独立窗口填写有限时长并完成一种已登记因子，之后由宿主 Hook 自动消费，不要求 AI 手工串联内部步骤。默认只管当前对话，明确选全局才扩大；原截止不随新默认、重连、换模型或子代理滑动。

- **时长：** 范围 0.5–72 小时；当前默认设置为 1440 分钟（24 小时，16:37 观察），这是可改的设置，不是写死的值。

- **本人验证因子：** 只有 Passkey、TOTP、Recovery、Account 四类；Google、Microsoft 是 Account 的提供方，Windows PIN 和生物识别不是这四类之一。

- **协议同意与根会话代确认：** 派 GPT 做网站操作时，初次派单和续作都附上协议长期授权的现行结论和源消息编号（不附原句），并写清这次已授权的具体事情、网站或账号和涉及的内容；共用包装器自动附上协议授权，主持补齐本次业务范围，只附协议授权不能代替业务授权。子代理仍说工具要“当场确认”时，根会话先核对要确认的动作确实在长期授权或这次任务的授权里（例如同意协议、登录本人账号、往授权的网站填本人资料和验证码），再代本人确认；不在授权内的、属于重大动作的、工具规定必须本人亲手做的，照原规则交本人。

- **私有配套材料：** 维护或准备公开内容前，配套文档的查询交 GitHub 总索引；公开仓库里被忽略但有价值的私有材料，先复制并在私有默认分支回读，再用可回滚的方式保留原入口。收尾覆盖本任务真正改过的所有仓库，各自验证、定向提交、正常推送并回读。

## 出问题时（一）

解决什么

用户说要完成一件事，不等于任何代理都能对任何对象做所有动作。系统要分清：用户授权、操作系统权限、受信任身份、目标是否仍是原目标、别人是否正在改同一处，以及动作完成后有没有正式回读。

## 边界

- UAC（Windows 管理员确认）只提升进程权限，不扩大任务授权。长期提权许可对子代理同样适用；需要本人在场确认的，交回根会话安排。

- 受信任的桌面 AI 免本人验证的，只是密码中心里已登记、不属于重大动作的凭据操作；重大动作仍按保护策略把关和验证。

- 长期授权不覆盖系统、开发者和平台限制，也不扩大目标、账号、公开面、付费、秘密或不可逆边界；首次公开发布要本人明确许可。

- 工具要求确认，不等于一定要本人再说一遍：本人已授权过的事，由根会话在原授权内代确认；同意协议的长期授权也不把付费订阅、付款、重大动作或必须本人亲手做的步骤变成可以直接同意。

- 限时接管只用本人实际选的范围和原截止；新对话或另一台电脑不自动继承。

- 子代理、shell、worktree 和插件都不能绕过别人未提交的改动或不能快进的冲突。

- force-push、新公开面、付费和不可恢复动作不在默认授权内。

- 私有或可信目标不等于已授权写入。

## 失败与恢复

| 情况 | 怎么办 |
| --- | --- |
| 限时授权过期、撤销或会话、范围不匹配 | 停止使用这份临时优先权，普通已授权工作照常；不换编号、不借别的对话、不改原截止。 |
| 本人取消或验证未成功 | 结束本次请求，不自动重开、不换因子，也不撤回其他有效授权。 |

## 出问题时（二）

| 情况 | 怎么办 |
| --- | --- |
| 目标漂移 | 停用已变化的目标，重读后确认原授权是否仍覆盖；只继续确实可做的部分。 |
| 别人有未提交改动、真实同步冲突 | 不动对方成果，先理解变更再合并；不拿强推覆盖。 |
| 没有上游或不能快进，但只是本人仓库的普通收尾 | 新建本人私库、远端改到本人账号下、历史改写前先自动核对旧提交仍由其他分支或标签保留；核对过就直接做，核对不过就停下说明；可能丢提交的强推仍要本人明确同意。 |
| 短锁被占 | 等它释放或做不依赖这一步的准备工作；短锁不代表对方拥有业务权限。 |
| 长期授权已覆盖但平台结果未知 | 真实调用一次，按实际结果收口，不靠预判。 |
| 被中断的任务需要接续 | 先核对它的真实状态，交接或停止后再安排，避免替身重复执行；GPT 子任务的停止、删除、验收和归档以包装器真实回执为准。 |
| 私有配套迁移任一步失败 | 远端回读前不替换原件；替换后失败用同卷回滚恢复原件。 |
