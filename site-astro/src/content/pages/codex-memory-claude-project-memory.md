# Claude项目记忆按项目保存与恢复

〔回到项目 → AI 备份〕　〔复制 AI 续作说明〕

这项专门备份已经退役。它曾按项目保存 Claude 的长期说明和记忆，换电脑时放回对应项目；2026-09-28 23:10（北京时间）起不再生成新的记忆副本。旧副本还在，需要时仍可按项目手工找回某个版本。

**当前情况：**专门的记忆备份任务已停用（未删除，换机也不重建），Claude 的自动记忆开关本身也是关着的。Claude 的配置现在由开发配置备份每天带上；Claude 的使用记录改由 Codex 每日对话备份入口一起采集。

项目源码：私有仓库，源码未公开；用法与技术说明可在下面阅读。

## 这项功能怎样使用

用途与实际影响

## 为什么需要它

Claude 的项目笔记和完整聊天不是一回事。以前单独备份它，是为了换机后能找回各项目的长期说明。现在 Claude 自动记忆已关闭，配置交给开发配置备份，这条专门备份就停了；留下的旧副本仍是找回旧版本的唯一来源。

## 举个实际例子

我说“把这个项目 9 月份的 Claude 记忆找回来”。AI 会去旧副本里按项目找到对应的 memory 目录，挑一个版本，先保留目标位置现有的文件，再手工放回。它会先说明：这是 9 月 28 日以前的旧材料，不是现在还在更新的备份。

## 最后我会得到什么

我会得到那个项目的一份旧记忆版本，以及它保存于哪一天。附件要从本机或 G 盘的旧副本找（私有云只存了文字笔记）；登录、聊天和项目源码不在这里。现在的 Claude 能否加载它，要放回后实际确认。

## 结果怎么看

## 正常时

旧副本里确实有这个项目的记忆、并能说出保存日期，就可以按版本手工找回；但不会再有比 2026-09-28 更新的版本。

## 发现问题时

如果有人以为它还在每天备份，AI 会说明它已在 9 月 28 日退役；要找最新的 Claude 配置，去开发配置备份。

## 入口不可用或证据不足时

旧副本里没有这个项目，或私有目标读不到，就直接说缺少，不建空目录冒充找回，也不重新启用已停的任务。

## 从哪里开始

在已接入的 AI 对话中点名 Claude 项目，说明要找哪一份旧记忆。要的是现在的 Claude 配置，就改问开发配置备份。

## 需要准备什么

- 具体项目

- 想要的大致日期（旧副本最晚到 2026-09-28）

- 是否需要非 Markdown 附件

## 从开始到拿到结果

1. **按项目找到对应记忆**　在旧副本里定位这一个项目的 memory 目录，不混入其他项目。

2. **依介质选材料**　本机和 G 盘旧副本含完整目录；私有云仓库只有文字笔记，要附件仍看本机或 G 盘。

3. **手工放回并确认**　先保留目标现有文件再放回，确认当前 Claude 实际读到；聊天和登录不从这里恢复。

## 技术实现与依据（一）

## 关键规则与设计选择

1. 不再生成新的项目记忆副本；任务停用但不删除，换机不重建，重新启用须本人另提。

3. 旧副本照旧可用：本机和 G 盘是完整 memory 目录，私有云只有 Markdown，两者不假装一样完整。

4. 没有专用自动还原器；恢复前确认新旧项目路径对应，先留目标副本，再放回并让 Claude 实际读取。

## 出问题时

解决什么

防止把已停的记忆备份当成还在更新，防止项目之间的记忆重名覆盖，也防止把私有云里只有文字的副本说成完整副本。

## 边界

- 不是 Claude 完整环境、登录、项目代码或聊天的备份。

- 本机/G 盘旧副本可能含非 Markdown 文件，私有云没有；按实际介质选材料。

- 不承诺现在的 Claude 一定能加载旧格式记忆。

- 本轮没有打开任何记忆正文，也没有在新电脑上做恢复。

## 失败与恢复
