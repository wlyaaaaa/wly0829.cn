# 先查静态条件，再明确决定要不要花额度做真实测试

〔回到项目 → AI 工具配置管理〕　〔GitHub〕　〔复制 AI 续作说明〕

AI CLI Profile Manager · 功能说明

先用不发模型请求的体检找出配置或登录缺项；确需证明模型会回答、会用工具或能改文件时，再明确运行对应真实测试。

**当前情况：**可以先不花模型额度检查入口和缺项；三家厂商的钥匙体检只能证明“引用已配置”，钥匙本身是否有效要靠真实请求。真实文本、工具或文件任务测试需明确选择，并保留各自证据日期。10 月 28 日起所有需要 Key 的厂商都引用密码中心，其他已登记厂商也同样只能证明引用已配置；没跑 Live 测试的不算通过。

内容按 2026-10-11 14:00（北京时间）前的改动整理，源码对应 10 月 8 日 09:55 的提交；具体测试保留各自日期，页面不实时探测运行状态。

## 这项功能怎样使用

用途与实际影响

## 为什么需要它

程序能打开，不等于这次选中的模型真能回答或使用工具；每次排查都先发付费请求又浪费额度。先免费查设置，只有问题确实需要时才做真实调用。

## 举个实际例子

我可以说：“检查 codex-qwen3-8-max-paygo 现在缺什么；不要先扣费。静态条件都对以后，再由我决定是否做真实文本或任务测试。”我会先得到具体缺项和证据日期。

## 最后我会得到什么

先得到免费静态体检的缺项与下一步；明确选择真实测试后，才看到该模型是否回答、能否用工具或完成一个小文件任务。每一层都有自己的结果。

## 结果怎么看

## 正常时

本次选择的程序、模型、输出和清理都实际通过，才报告这一层可用。

## 发现问题时

静态设置齐全但尚未真实调用，或旧结果过期时写成待验证，不涂绿。

## 入口不可用或证据不足时

目标程序报错、模型身份不符或工具越界时停这条路线并给出原因。

## 从哪里开始

在本机运行 aicli doctor 检查指定 Profile；只有明确要做真实调用时才选择对应 Live 测试。

## 需要准备什么

- 待查 Profile

- 是否允许文本、工具或智能体实际测试

- 费用和工具副作用边界

## 从开始到拿到结果

1. **先免费查条件**　静态体检（Doctor）核对程序、模型配置、凭据引用与本地服务，给出具体缺项。三家厂商显示“可用但有限制：引用已配置，密钥未验证”，不会因为引用配好就涂绿。其他在密码中心登记过的厂商同样按这条处理。

2. **决定是否真实试用**　按需要选择文本、工具或智能体测试，先看可能的额度与动作影响。

3. **核对所选一条**　核对实际模型、输出、工具与清理；静态通过不能证明连通，一条 Profile 成功也不覆盖其他账号。

## 关键规则与设计选择

1. all 只运行 text+tool，不会暗中启动更长的 agent。

2. agent 只支持 Codex，且 Codex harness 是完全访问；明确授权后才能运行。

3. 旧回执只证明对应模型、配置和执行协议。新版本先按声明接口和实际身份检查受影响范围，不单凭版本号要求全量重验或宣称兼容。

## 当前怎样实现

- DoctorService 读取平台、CLI（命令行工具）、Profile、凭据引用、配置层和本地服务，不自行发模型请求；9 月 29 日两个代理退役后已不再检查代理。所有引用密码中心的已登记厂商，引用只算“已配置”，钥匙值的有效性单独记为未验证。

- LiveTestService 在随机临时目录调用真实目标 CLI（命令行工具），并绑定 Profile 指纹与实际版本。

- 文本层要求最终正文严格等于 PONG；首个非预期工具事件使 Codex 文本测试失败。

- AgentAcceptance 构造确定性文件任务，独立计算排序、去重、频次、总和与 SHA-256，不接受模型自述。

- diagnose --json输出aicli.runtime-diagnostics.v1，可用--bridge-registry指定既有PCConfig登记；不初始化状态、读密钥或发网络/模型请求。有效源、安装载荷和能力声明分别报告，不能用SYSTEM空目录推断登录用户未配置。

## 出问题时

解决什么

防止静态配置、历史回执和当前真实能力被压成一个模糊绿色状态。

## 边界

- Doctor 不证明模型连通，也不证明厂商钥匙有效。

- 单个 Profile 的 Live 不代表其他模型或账号。

- 网页只引用注明日期的测试、真实桌面验收和只读诊断；10 月 11 日没有重新发起全部 CLI（命令行工具）体检或付费 Live。

## 失败与恢复

- **工具无法证明与私人配置隔离**：跳过 tool 并降为有限制，不冒充完整工具能力。

- **版本或 Profile 指纹变化**：按实际身份和受影响的接口分层检查；旧回执留作历史，不能当成新的 Live，也不只因版本号变了就要求 21 条路线全部付费重测。

- **临时目录或进程树未确认清理**：保留原失败和残留定位，不标成功。
