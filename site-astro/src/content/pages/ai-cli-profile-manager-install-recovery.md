# 安装可回退，卸载也必须说清保留什么、删除什么

〔回到项目 → AI 工具配置管理〕　〔GitHub〕　〔复制 AI 续作说明〕

AI CLI Profile Manager · 功能说明

安装和升级先在旁边验新版本，失败保留旧版；卸载时明确哪些个人配置与本机密钥保留，远端登录授权另行处理。

**当前情况：**本机装的是 0.3.19，GitHub 上最新的正式发行仍是 9 月 22 日的 0.3.18；Codex 桌面版的桥接发行另行登记：10 月 22 日读到配置选中的是 ee35736204370d9b（10 月 20 日 18:04 写入），只核到配置和程序文件存在；10 月 11 日核对一致的是此前的 b47fea3ce81f7a67。升级、旧版回退与真实模型运行分别验收，不由安装成功包办。旧 Qwen3.7 的一次性迁移脚本已经从源码删除，安装成功后改为直接清理身份对得上的旧模块。

内容按 2026-10-11 14:00（北京时间）前的改动整理，源码对应 10 月 8 日 09:55 的提交；本机模块版本、桌面桥选中状态和已删除的脚本按 10 月 22 日只读核对更新；具体测试保留各自日期，页面不实时探测运行状态。

## 这项功能怎样使用

用途与实际影响

## 为什么需要它

直接覆盖旧安装可能留下半套文件；卸载时一句“完成”也可能让人误以为所有模型、账号授权和个人配置都没了。安装先验候选，卸载明确保留范围。

## 举个实际例子

我可以说：“把 main 的最后修复装上；若遇到未知旧文件就先停。以后普通卸载保留我的 Profile 和密文，只有我明确彻底清理时才删本工具数据。”我会得到安装、保留内容和可回退位置的明确结果。

## 最后我会得到什么

拿到当前用户可用的 aicli 命令和已核对的安装版本；失败有旧版可回退。普通卸载保留配置和本机密钥，明确彻底清理才删本工具数据，远端账号授权还要到服务侧另办。

## 结果怎么看

## 正常时

候选安装、切换和新命令窗口回读都通过后，说明本工具安装完成。

## 发现问题时

旧模块还在使用或上游变更时提示关闭旧窗口、更新对应部件或暂用旧版。

## 入口不可用或证据不足时

未知旧文件、候选不完整或安装目录被占时不做半套替换，保留原安装。

## 从哪里开始

在本机用项目安装器处理已核对的源码或 Release 包；卸载时明确普通保留还是彻底清理本工具数据。

## 需要准备什么

- 可信安装包或源码

- 现有 Profile 和密文是否要保留

- 已知旧版及回滚位置

## 从开始到拿到结果

1. **先预检旧状态**　检查已有安装与退役对象，未知用户文件先停下核对。

2. **安装可回退候选**　构建独立候选并切换，失败时恢复旧版。

3. **新开终端验入口**　重新打开命令窗口，检查版本、保存的配置档、静态体检和启动预览；普通卸载保留本工具数据，彻底清理与远端账号授权撤销分开办理。

## 技术实现与依据（一）

## 关键规则与设计选择

1. 源码版本、发布包、当前用户模块和桌面内容寻址发行是不同对象；模块升级不会自动重建或切换正在工作的桌面发行。

2. 旧 Qwen3.7 对象当初只把可验证的移入 quarantine（可恢复隔离区），SecretRef 和 Key 不参与；这次一次性迁移已经做完，迁移脚本已从源码删除，现在安装成功后直接清理身份对得上的旧模块。

3. 普通卸载保留 Profile 和 DPAPI 密文，也不动密码中心里的厂商钥匙；--purge-user-data 才删除本工具数据，仍不代表远程 OAuth（账号授权协议） 撤销。两个已退役代理留下的旧资料不再由卸载程序当作现役功能管理。

## 当前怎样实现

- Install.ps1 从当前 PSModulePath 选择 CurrentUser 模块根，在临时候选中导入验证，再对同一父目录执行原子重命名。

- 原来的 Invoke-AiCliRetirementMigration.ps1 只移动 marker、路径、内容 hash（内容指纹） 与 state 都闭合的退役 Qwen3.7 对象，未知项在写前阻断。它是一次性迁移，已经从源码删除（变更记录写在尚未正式发行的“未发布/移除”段落），10 月 22 日 scripts 目录里已没有这个文件，不再是可用入口。

- UpdateService 识别实际启动入口和安装渠道；只读检查与指引不静默升级上游。

- Uninstall.ps1 移除模块、shim（受保护入口垫片）、PATH 与受管 Profile 块；用户数据和上游产品默认保留。两个代理 9 月 29 日退役后，它只在模块已不可用、却发现旧代理状态文件时拒绝盲删，这是遗留的安全收口，不是代理管理入口。

- 《AI CLI（命令行工具） Profile Manager 使用手册》讲产品安装、Profile、Doctor/Live、更新、卸载与排障；《Codex、Claude Code 与 Open Interpreter CLI（命令行工具） 中文手册》讲上游会话内模型、effort（思考等级）、权限、上下文、恢复和命令差异。当前部分用户手册段落仍写着旧的“configure 询问 Key”和 Toolkit 同步，以当前实现为准。

## 出问题时

解决什么

防止升级造成半套模块、退役误删用户配置，以及卸载把多个独立生命周期说成一个动作。

## 边界

- 10 月 11 日的整理不创建新的 GitHub Release，也不安装或卸载。

## 失败与恢复

- **同版本已经安装但未给 -Force**：默认拒绝覆盖，避免意外替换正在使用的版本。

- **退役对象无法证明归属**：安装在任何迁移前阻断，保留原件供人工审阅。

- **安装后当前 shell 仍加载旧模块**：关闭重开 PowerShell，或 Remove-Module 后强制 Import-Module，再核对路径和版本。
