# 先判断是否值得建包，再冻结本人明确选择的来源

〔回到项目 → 工作支持与交付〕　〔复制 AI 续作说明〕

工作支持与交付 · 功能说明

同一件工作要反复使用几份会变化的资料时，先由我明确选定2至5份文件及目标，并保存它们本轮的版本。以后补充判断或修改交付物，都能回到这一组来源。

**当前情况：**已有把选定的2至5份资料建成持续交付包的功能；保存它们的本地数据库从 9 月 29 日起固定在同一个默认位置，不再跟着当时所在的文件夹走。当前输入主要是本地文字和表格文本，不自动读取未选文件。

源码事实核对截至 2026-10-11 14:00（北京时间）；历史测试保留各自日期；页面不实时探测运行状态。

项目源码：私有仓库，源码未公开；用法与技术说明可在下面阅读。

## 为什么需要它

3. **交回可接续的包**　说明本轮冻结了哪些版本、接下来要核对哪些事实。来源数量或身份不合要求时不留下半成品，改正选择后再开始。

## 技术实现与依据（一）

这里保留实现、关键条件、精确入口、历史记录和验证结果。

0.2.0 已提供稳定 batch 新建、逐步 CLI（命令行工具）、不可变来源版本与未选文件隔离；数据库默认位置自 2026-09-29 起固定；输入类型仍以本地文本、Markdown 和 CSV 为主

## 关键规则与设计选择

1. 一次性单文件、普通文本 PRD、学习和私人正式材料绕过。

2. 来源必须是本人本次明确选择的 2–5 份文件。

3. 同一 package ID 第二次 batch 是明确错误。

4. 已有包用 update-source、impact、review、build、verify 和 artifacts 继续。

5. 默认简体中文、Asia/Shanghai、YYYY-MM-DD 与人民币 CNY；中国企业角色和 PRD 章节结构是当前产品合同，不是调用方随意显示文本。

6. 正式输出使用标准 OOXML，兼顾 WPS 与 Microsoft Office；核心不保存个人/公司配置分支。

7. DOCX/PDF、邮件和在线文档当前先经对应能力读取或导出。

## 真实入口

- `PRIVATE product contract · user path`进入条件、2–5份来源和绕过边界

- `PRIVATE source · batch.py`batch schema（数据结构）、预校验、稳定ID、事务内新建与固定默认库位置

- `PRIVATE source · store.py`Package与SourceSnapshot持久化、文本编码识别

## 如何验证

- 重复 ID 在新增事实前拒绝。

- 未选文件不被枚举或读取。

- 中文文件名与 GB18030、带 BOM 的 UTF-16 来源可追溯（测试定义于 2026-10-11 读源码确认，本轮未重跑）。

- schema（数据结构）/example 与 live parser 一致。

- 任意 Office、邮件和在线来源仍为当前 gap。

## 与其他模块的关系

本模块形成稳定 package 和来源版本；证据、事实和正式质量由下一模块拥有。
