# site-astro：内容页（区块照现在的网站，排版在浏览器里自动做）

内容页每页一个内容文件 `src/content/pages/<页>.md`，通常由 `tools/convert_page.py` 从 `sources/pages/<页>/page.json`（和 `layout.json`）生成。直接编辑 Markdown 也会生效；构建记住这次编辑（每页另记作者目录及其依赖的指纹 `author_fp`），只有转换器自身变化时照旧保留它。之后若该页 `page.json`（或它引用的页、`layout.json`）又改了，构建直接停下并列出页名，因为 JSON 的新改动到不了网页：先统一作者输入——以 JSON 为准就运行 `python tools/convert_page.py <页>` 覆盖 Markdown，要留 Markdown 里的新内容就先把它并回 `page.json` 再转换，然后重新构建。页头、页尾、目录条、翻页过渡、小鸟、落叶、水彩照现在网站。

## 为什么这样做（第四轮）

现在网站每一屏的整屏图，就是共用区块库 `src/typeset/components`（HTML + CSS）在固定画布上排好再截的图（电脑画布 1672 宽、手机画布 941 宽）。
新站直接用同一套区块库、同一份样式在浏览器里排，不再截图：

- 区块（卡片、数字卡、步骤和箭头、时间线和蛇形连线、对话气泡和小尾巴、例外虚线、右侧栏、术语表、按钮、编号标注截图……）的字号、间距、边框、配色、装饰和现在完全一样，因为是同一份代码；
- 不写坐标：构图只写“用哪些区块、哪几块同一行、各占多宽”，浏览器按构图排；没写构图的屏由区块库自动分块；
- 每个位置用哪张图（图标、插画、毛笔标题）在内容文件里逐条写明；内容文件由转换器生成，改内容改 `page.json`、改构图改 `layout.json`，再重新转换；
- 文字是真文字（能选、能搜、读屏能读），字体是出图时用的同一个字体文件按本页用字抽的子集。

画布排好以后按栏宽整体等比缩放显示（宽于 768 用电脑那份，窄于 768 用手机那份），所以 960、1280 宽时和现在一样是缩小显示。

首屏关键插画和标题直接以高优先级加载；其他正文图片与 SVG 图像按实际视口加载，无 JavaScript 时保留完整原图。资源按内容指纹发布；静图与动画纹理的尺寸、色彩信息和解码像素完全相同时，复用已有原文件中较小的一份，不重新编码。可见静图显示后，浏览器空闲便开始加载环境动画和小鸟；第一帧画好后无缝接手，不额外等待。滚动、点击或键盘操作会提前启动，浏览器往返缓存恢复时立即恢复。这个时机在 `src/scripts/living-mount.js` 中调整。

## 首页、授权页和驾驶舱

首页和授权页保留候选站原 HTML、原图和动效，由 Astro 静态路由输出：入口直接读 `sources/retained-home-cockpit/home.html`、`computer-access.html` 的已接受源码，附加样式和交互保持原样。普通构建不再复制到 `src/chrome/retained`，也不从旧站生成运行件。

首页按本人 10 月 23 日决定解除锁定：构建不再保留上一版首页字节，首页连带变化和其他页一样只打印“连带变化”，照常扫描和发布回读。首页亮点屏 `home-04` 的数字来自 `sources/creative/static-home/highlights-page.json` 绑定的各项目登记；每次构建在准备保留页之前，先用纯文本比较 `home.html` 里 home-04 的嵌入转写与当前 `expected_text(...)`，一致就跳过（不启动浏览器）；不一致就自动运行 `scripts/prepare-home-highlights.py` 的重画（暂存在 `.cache/home-highlights`），打印一行说明后继续，保留页指纹随之变化、首页重建；重画失败或重画后仍不一致则构建失败，不沿用旧首页。重画会改写入库的作者输入（`sources/retained-home-cockpit/home.html`、`dependencies.json`、`assets/` 新图、`sources/frozen-site/manifest.json`），和构建重新生成的 Markdown 一样，随后一并提交。

驾驶舱是 Astro 原生页，不再读保留 HTML：入口 `src/pages/cockpit/index.astro`，外壳、页头、目录条、页尾和全站一样。

- 数据：PCConfig 状态服务的精简视图（`pcconfig.cockpit-view.v1`，线上 `live.wly0829.cn/computer-access/state?view=cockpit`，退到 `mcp.wly0829.cn`）。`src/cockpit/model.js` 把视图整理成页面要的样子，构建时和浏览器里共用；格式不符时按读不到处理。
- 首帧：构建时读一次最新视图（读不到用仓库里的 `src/cockpit/snapshot.json`），`src/cockpit/render.js` 画好整页。首帧明写“这是 HH:MM 的数，不是现在的，正在读最新…”，数字和灯整体灰着，不冒充现在。
- 浏览器里：`src/cockpit/client.js` 每分钟读一次（页面在后台不读），用同一组 `render.js` 函数原地换每块里面的字，不换版式；右下角刷新按钮（`refresh-button.js`）叫醒电脑重读。读不到电脑时事实卡变淡、灯灰、写“读不到（最后 HH:MM 读到）”，图表链接先收起。
- 首屏：一句话结论（要你做几件、是什么，点标题跳到那张卡；其余三格各一句），电脑 / 自动任务 / 备份三格，电脑健康分小字，安全和授权一行。颜色只看要不要你出手：要你做的红黄；有状况但 AI 在管的用中性蓝灰写“AI 在管”；数据源停了、读不到的灰。手机首屏按“结论 → AI 正在跑 → 你得知道 → 三格 → 安全和授权”排，健康分不上手机首屏。
- AI 正在跑（后端 `ai_running`，字段在才出，没有就整块不显示）：放在结论和“你得知道”之间，每件在跑的 AI 活一行，状态用颜色加符号（在跑绿●、网络在重连黄◐、额度用完和登录失效红○、等你回蓝◆、停了灰■、判断不了灰？），第二行小字“型号 · 一句话”，卡住的在前；一个都没有时只写“现在没有 AI 在跑”。结论句里同时加一段“AI 在跑 N 个（M 个卡住）”。公开版标题由后端换成“一件 AI 活”，前端照显示。
- 你得知道最多 5 行（本人 10 月 29 日）：几条“××已恢复”合成一行、点开看是哪几项；“AI 已定”合成一行“AI 自己定了 N 件技术问题”、点开才看全部（每条仍可复制给 AI 改）；汇报只露第一句、后面收进展开；“AI 在修”和其他影响本人的事排前，合完还多的折成“其余 N 条”。折叠都是原生 details，键盘可开合，每分钟换字时按 id 保持展开。
- 总览打分和各区的灯由后端 `overview` 给，共用脚本 `public/_overview/overview-screen.js`（首页小屏也用它）。自动任务的“今天的河”是 `scripts/today-river.js`，图在 `sources/creative/today-river/assets2/`；驾驶舱的标题图、插画、图标在 `sources/assets/cockpit/`；首屏插画上的小鸟配置是 `src/cockpit/bird.config.json`。
- 测试：`tests/test_cockpit_*.py`（浏览器测试底座 `tests/cockpit_native_harness.py` 照 `index.astro` 拼页，数据全部虚构、只在 127.0.0.1 上跑）和 `tests/test_today_river.py`。

33 个仍由冻结字节提供的页（4 个冻结项目 31 页，加 `/search/`、`/system/`）及其本地小资源存入 `sources/frozen-site`。其 `manifest.json` 列明完整路由、冻结页指纹和资源来源：已有仓库文件直接复用；标题图按既有配方重建；确切的外壳依赖放入本地 `vendor-deps`，原图和视频保持原字节。原远端依赖已一次性入库到 `sources/vendor-deps/<原相对路径>`，按依赖清单核验 SHA 和字节数；所有构建只读本地，缺文件就报具体路径，不联网补取。以后迁移一页时，同步从 `pages` 清单删除对应冻结条目和 HTML；旧字节留在 Git 历史，需要重转时从历史取。普通构建不运行旧生成器。
首页每次新加载、刷新都从纸色播放原开场；图片到达后 3 秒未开播，或开场连续 5 帧超过 100 毫秒，就跳到完成图并恢复环境动画。后退缓存与减少动态不播。顶栏固定用原 WebP 背景，避免显示途中切换未接收完的 AVIF；加载占位和标签行布局在首绘前确定，不用低清预览。

## 一次完整生成

在仓库根执行：

```powershell
npm ci --prefix site-astro   # 只在首次安装或锁文件改变时
npm run build               # 完整静态站 + 公开内容检查
npm run dev -- --host 127.0.0.1 --port 4173
```

`dev` 先运行同一完整构建，再用 `tools/preview_site.py` 预览仓库根 `dist`；打开的就是正式准备会复制的成品，包括所有冻结模块、搜索、规则、兼容路径和 404。修改内容后重新运行；当前入口不承诺热更新。

`python scripts/build-site.py` 是两处 npm build 共用的构建实现：恢复版本化资产 → 转换当前作者源 → 更新原生运行件 → 区块增量排版 → Astro → 完整路由/搜索/翻页预热/站点地图 → 最终资源处理与公开检查。区块没变就复用结果，实际浏览器并行最多 2 个。源码、素材和字体首次准备的时间另计，完整站的计时写在 `dist/.build-receipt.json`。

`scripts/prepare-astro-release.py` 现在只保留规则源 `refresh`，旧 `prepare` 拼装入口已移除。后续发布接线由 G2 读取仓库根 `dist` 和 `.build-receipt.json`；当前构建不上传、不封存、不切换线上版本。

构建最后调用 `python scripts/prepare-oss-release.py finalize-dist --dist dist`，离线完成上线前资源地址处理，再检查公开内容和记录所有最终文件的 SHA。该命令由 G2 提供；尚未合入、命令不存在或执行失败时，构建明确失败，不保留旧成功回执，也不省略这一步。

`public/` 中的依赖、冻结路由和控制文件，以及 `.cache/`、`src/content/rendered/` 是可重建工作文件，不另入库；维护输入在 `sources/frozen-site`、`sources/retained-home-cockpit`（首页和授权页）、`src/cockpit`（驾驶舱）、仓库原件和各原生脚本。公开规则源仍从版本化 `sources/rules` 生成。

## 内容文件怎么写

开头是 JSON 字段：`title`、`kind`、`url`、`toc`、`page`（页面级字段）。每一屏：

````markdown
::screen{#<屏号> section="<分节>"}

```typeset
{ "screen": {链接、按钮、截图等这一屏的字段},
  "layout": {"h": {电脑构图}, "v": {手机构图}},
  "images": [{"role": "icon", "slot_ordinal": 1, "asset": "_library/icons/齿轮.png"}, ...] }
```

这一屏的文字（Markdown）
````

常规维护改 JSON 作者源再转换（`python tools/convert_page.py <页>`）；若已直接改过 Markdown，先人工统一两份作者输入，再恢复自动转换：

- 改字、数字、链接：改 `sources/pages/<页>/page.json` 里那一屏的 `text`、`links`。
- 改图：改素材表 `sources/assets/_library/asset-map.jsonl` 里这一屏这个位置的行（转换时写进 `images`，路径相对 `sources/assets`）。同一次提交把 `sources/assets/_library/REQUESTS-READY.json` 的 `asset_map_sha256` 改成新素材表的 SHA-256；两者对不上时排版引擎当素材库还没发布完，退回旧抠图清单，标题图和新插画都会找不到（`tests/test_asset_library_marker.py` 会拦）。
- 改构图：改 `sources/pages/<页>/layout.json`：`h.blocks` 里每块的 `type`（区块名，见 `src/typeset/components`）、`row`（同一行的块写同一个名字）、`width`（这一栏占多宽）。手机构图不写时自动竖排。
- 全新的页（只有 `page.json`、没有 `layout.json`）：转换器照样出内容文件，区块库按文字自动分块，电脑、手机两份都会排出来（毛笔标题、正文、编号步骤卡、列表、表格）；但没有插画、分组图标和左右分栏，要和现有页一样图文并排，得补素材表里的图、写 `layout.json`。
- 改了地址的页：`page.json` 的 `url` 写现在的地址，旧地址列在 `old_urls`。旧地址出一句话的去向页（两秒后跳到现在的地址、不收录），站内链到旧地址的链接在排版时改指现在的地址。
- 退役技能的去向页（`kind: skill-redirect`，`page.json` 只有一屏：标题加一句话）：转换器不用各页旧的构图，照共用版式排这一屏（`convert_page.py` 的 `redirect_layout`）——电脑一行两栏，左栏和全站一样的毛笔大标题（没有同字标题图，排版时用行楷字截图）和那句话（〔〕括起的词按 `links` 变成能点的链接），右栏一张小图标（素材库“工具箱回收站”），图按文字高度定大小；手机从上到下：标题、图标、那句话。卡片按内容高，不留大块空；不收录（noindex），不自动跳（要让人看清为什么退役）；不用旧技能页的运行件（旧目录条指向已经撤下的小节）。
- GitHub 个人主页稿（`/github-profile/`，`kind: github-profile`）照常构建，给 GitHub 主页用，站内没有入口；页面加 noindex。站点地图由当前原生路由构建生成，noindex 页不进入地图。
- 构图认块用的 `text_ref` 写的是这一块开头的原话；内容刷新了数字以后，只差数字的转换器按源里现在的写法认（打印“只差数字”），别的认不出的打印出来，要改 `layout.json`。

### 首屏先放状态（K1-A，本人 10 月 10 日选 A）

项目页、技能页的第 1 屏由转换器统一调整（不逐页手摆、`layout.json` 不用改）：标题（连同紧跟的标签、加粗大字副标题）下面先放状态——“现在”实时条（实时位由 `live-dom.js` 填，“运行”那一格读到时带上次运行时间），再放首屏的数字卡（连同卡前、卡后给数字注日期、来源或现状的那一句：“数字卡片……”“截至……”“数字截至……”标题或小字、`source_note` 来源注、“偶尔用：……”）；讲解、插画、清单和按钮按原顺序往后挪，一字不删。只挪现有的块，样式、颜色、字号不变。标题原来和插画并排的，标题挪出来占整行、照原样靠左（不居中），原来那一栏的宽度交给这一行剩下的块；和标题用 `inline_row` 并排的品牌小图标跟着标题走；标题那一块顺带装着的介绍段（构图里没给它单独一块）补成单独一块，留在原栏和插画并排；右栏插画后面原来同栏的块挪到这一行下面。数字卡原来和截图并排成一行的（Typora 薄荷主题），整行一起挪到标题下，照旧并排。

挪完以后首屏里“文字一栏 + 图一栏”（一幅插画，或一张截图连同图注）的行标上 `row_fit_illustration`：文字顶对齐，排版时（区块库 `typeset_apply.js` 的 `fitIllustrationRows`）按实测高度定图的大小——图比文字高出一截时，先把紧跟这一行的按钮行或一张短说明挪进文字栏底部，再收窄图栏、加宽文字栏（文字栏最多 1.6 倍宽，图最小到原高的 45%、不低于 260 画布像素）让两栏一样高，还差太多时插画按文字高度再缩、在栏里居中；文字比图高时加宽图栏。只改栏宽和图的显示大小，图文件不动、不裁。图在一栏最后（上面是对话气泡等）的行，插画按这一栏空出来的高度放（看驾驶舱技能页首屏）；这样放图比栏窄得多、两边各空 120 画布像素以上时，图再放大一点，另一栏底下最多多空约 120 屏幕像素。本人定过“除非这个地方留着是放实时数据的，不然不要空着”：改完用 1440、1920 两种宽度扫一遍内容区，不是实时位、超过约 120 屏幕像素的空白都要收掉。

没有实时条的在用项目页和技能页，状态写在 `page.json` 顶层的 `status_line`（按需更新，主持 10 月 10 日 08:00 定）：

```json
"status_line": {"state": "在用", "last": {"label": "上次使用", "at": "2026-10-08"}, "facts": ["近 7 天 AI 用了 14 次"], "as_of": "2026-10-10", "source": "AI 使用小记录"}
```

`state` 一个短词（在用、常用、偶尔用、待验收……，和项目首页、技能首页的分组说法一致）；`last` 上次运行、上次使用或上次更新，`at` 写到日期或分钟（北京时间），查不到整项省略；`facts` 0—2 条，每条最多一个数字，首屏数字卡已有的不重复；`as_of` 核对日期，`source` 一句话来源（可省）。转换器把它变成和实时条一样的一条（区块 `live_strip` 的静态写法 `static_items`、`static_note`）：“现在　● 在用 · 上次使用 10 月 8 日　● 近 7 天 AI 用了 14 次”，下面一行小字“截至 10 月 10 日 · AI 使用小记录”（来源常自带括号，用“ · ”隔开，不套两层括号）；年份和 `as_of` 同年时不写。电脑版放在标题行右半边：状态这一栏的左边缘对齐下面的第二栏（技能页“怎么跟 AI 说”框、项目页第 3 张数字卡；取下面第一个多栏的东西——并排行的第二栏，或数字卡里左边缘最靠近中线的那张；`typeset_apply.js` 的 `fitHeadRow`，主持 10 月 10 日 09:33），标题比这条线还宽时状态紧跟标题；状态几项上下排。手机放在标题下面。都在数字卡前面。原来和标题同一行的插画，标题挪走以后旁边只剩一句短话（技能名那一行，≤60 字）或什么都不剩，或整屏只有一幅单独占一行的小插画（两边空着），插画挪进标题行，放在标题右边（标题那一栏剩的宽度不到 120 画布像素才放到状态右边），高度跟状态一样、宽按图的比例。数字卡下面只写日期的那一句（“截至 10 月 10 日”“截至 2026 年 10 月 10 日（北京时间）”“数字截至……”）和状态行的截至日期是同一天时，转换时从这一屏正文里拿掉、不再单独显示；日期不同或这一句还带别的话的照旧（page.json 不动，以后状态行日期变了这句照样出来）。首屏多列对话框气泡数不是列数整数倍的（最后一排空一两格），转换器按 `row_counts` 把气泡平均分到各排（如 5 条 2 列排成 2、2、1，最后一条占整行），每排排满。第一项的圆点颜色按 `state`：在用、常用、偶尔用绿色，待验收、待实施黄色，已停用、已冻结灰色；事实项（近 7 天用了几次等）用中性浅色圆点。有实时条的页实时条优先，不显示 `status_line`。以后由按需更新程序（`scripts/content-refresh`）重取能自动取的项，`as_of` 超过 7 天列进待更新。

不加状态行的页：冻结页（状态就是标题下的“已冻结”标签，数字是冻结前的历史数）、去向页，以及既没有实时位、数字卡，也没有 `status_line` 的页。转换时打印每页状态行里有什么（“实时”“状态行”或只有“数字”）。要出“改前”对照时设 `CONVERT_NO_STATUS_FIRST=1` 再转换。

### 全新的页

只有 `page.json` 的新页照样能转换、排版（见上）。要和同类页一样图文并排：照结构相同的页写 `layout.json`（例如看驾驶舱技能页照查电脑卡顿技能页），图在素材表 `sources/assets/_library/asset-map.jsonl` 里给这一页每屏补行（屏号、位置、图），用素材库已有的图；没有同字标题图的大标题排版时自动用毛笔字截图。
- 分组标题图标按原 scene 短语认图、品牌图标按“<品牌>标志”认图，所以 `images` 里这两种还写明 `source_phrase` 和 `sha256`；品牌图标行带 `"via": "brand"`，不占这一屏的图位。
- 页里引用的数字和链接（`{{scale.total}}`、`{{group_counts.…}}`、`{{stories.…links}}` 等）在转换时用区块库的 `bound_json` 算好写进内容文件，和现在出图时冻结的时机一样；数据变了重新转换这一页。
- 连续的独立卡（`shape: card`）放进两列网格（手机一列），中间别的屏（如分类标题条）把网格断开、占满整行。
- 项目注册表生成的“画廊”屏，标题统一成和别的小节一样的毛笔大标题（`chapter_title`，用素材库里同字的标题图）。
- “全部功能”卡片按源里的顺序（编号从小到大）逐行排，不再按状态重排。
- 截图等高排（`equal_row_height`）时每排几张默认按“最窄一张不小于 14 个字宽”自动断排；构图要指定的写 `row_items`（手机 `row_items_v`），如照片视频页“我拍的风景”写 `[5, 5]`：两行、每行 5 张、同一行等高。
- 数字卡的大号数一行读完：一行放不下的（如“4366 件 · 近 99 GB”“三块硬盘 + 云端”“6 张看板 · 80 个图”），排版时（`typeset_apply.js` 的 `fitStatValues`）按比例缩小这一张卡的大号字，最小到名称字号；不是数字的（放不下时）先用小一号的字。一行放得下的不动，不改字、不删字。

## 规则原文

按需更新时，`scripts/astro_rules.py` 从核验通过的活动规则生成 `sources/rules` 和各规则页的原文分段；活动原件、公开副本、catalog、指针和入口模板分别绑定 SHA。普通转换和构建只读这份已提交的规则源，不读取私人过滤文件，也不在构建时把本机的新版本写进网页。

页面上只出网页字原文（横版原文卡正文，经 `project_original_html` 公开投影，放在素材库 `rule-paper` 的水彩框里），上面一行版本标签；规则文件开头给维护者看的 owner 行不显示，排好的原文卡也不再另出一份（原文只出现一遍）。

按需更新活动规则：在仓库根运行 `python scripts/prepare-astro-release.py refresh --output <审计JSON>`，再全量转换和构建。转换器按每页现有的原文屏重建分段，保留完整正文和顺序；渲染器从当前 Markdown 生成单份 article 和版本标签。发布前核验活动原件是否仍与这份规则源一致，正文、模板、分段或当前版本不匹配时阻断发布。

只想试排、不碰站点时，用环境变量把目录换到别处：`CONVERT_OUT_MD=<目录>`（转换结果，公开入口模板写在它下面的 `public/`），`BLOCK_MD_DIR`、`BLOCK_OUT_DIR`、`BLOCK_PUB_DIR`、`BLOCK_WORK_DIR`（区块排版读的内容、写的结果、发布文件和排版缓存；和站点排版同时跑时缓存要分开）。

## 毛笔标题

素材库里没有同字标题图的大标题（`chapter_title` 退到 `title-font`），区块库用本机的行楷字体（`src/typeset/style/base.css` 的 `Brush`）排字。网页不能带这个字体，所以排版时把这几个字在 2 倍分辨率下单独截成透明 PNG（`.publish/typeset-out/_cache/brushfont-<内容摘要>.png`，发布到 `/assets/_titles/`），换掉页面里的字；原字留作透明文字，能选、能搜、读屏能读。

## “现在”实时位

区块库排好的实时位（`[data-hot="live"][data-href=<键>]`）由 `src/scripts/live-dom.js` 填（排版时复制到 `/_living/live-dom.js`）：借现在网站运行件对外的 `SiteLiveRuntime.readStatus / parse` 取数（授权与状态、连接电脑两页借 `SiteB2`），一分钟一次，切回页面时立刻读。读不到时照驾驶舱的做法：页面上只说一次“暂时读不到电脑，保留最后一次读到的状态（北京时间）”，实时位显示上次读到的值、整体变淡；从没读到过就安静占位，不出“读不到”；读到后自动恢复。上次读到的值只在真正读到时存（浏览器本地 `site-live-dom:v1:<页>`）。实时位放在哪一屏都一样填，挪到首屏标题下的状态行也不用改脚本。

## 唯一构建入口与回执

在仓库根运行 `npm run build`。内部只有 `scripts/build-site.py` 一条链，输出完整 `dist`；`site-astro` 的 npm 命令只转发到根入口。`npm run dev -- --host 127.0.0.1 --port 4321` 先走同一构建，再用 `tools/preview_site.py` 预览同一目录，包含冻结页和三个关键页。

同一工作树的 `dist` 只有一个写入者；连续构建等前一轮结束再启动，独立任务用各自工作树。宿主 `Invoke-HeavyTaskSlot.ps1` 当前只检查物理内存，不提供同一输出目录的互斥；预览读取独立且核过指纹的快照时，可以与另一工作树的构建并行。

`npm run build -- --pages /how/,/projects/agents/` 在已有完整成品上选择这些路由。未变页不重新排版；页面 Markdown、版式和 `src/typeset/**` 的引擎内容共同决定每屏缓存。页面外壳变化会更新相关页，首页和授权页的附加注入仍由 `src/retained-page.ts` 承接。`src/content/rendered/`、`.cache/` 与 Astro 暂存输出是生成物，不提交。

首页和授权页直接从 `sources/retained-home-cockpit/*.html` 读取；驾驶舱是原生页（见上面“首页、授权页和驾驶舱”）。首页首帧脚本与首页包按 `manifest.json` 的 `bundled` 发布路径拷贝，带指纹文件名由清单提供；构建没有写死文件名。当前相册、环境动画和屏幕缓存仍沿用现有源码算法，六个保留页补丁不再构建时重跑。

每次成功构建写 `dist/.build-receipt.json`，格式为 `wly.site-build-receipt.v1`：

- `status`：`built`；`prepared_at_beijing`：带 `+08:00` 的观察时间；`seconds`：整个构建秒数。
- `steps`：按执行顺序列出 `{name, seconds}`，包括来源、指纹、依赖准备、运行件、屏幕排版、Astro、收尾、公开门与文件清单。
- `rebuilt_pages`：本次按源码指纹选择重建的路由数组；它不代表最终资源处理后所有字节变化。实际变化由两轮 `files` 中同路径的 SHA 对比得到。`html_files`：完整成品 HTML 数；`output`：实际输出目录。
- `files`：完整文件数组，每项 `{path, bytes, sha256}`；路径相对 `dist`，SHA256 为实际成品字节。回执自身不进入清单，避免自引用；`release-manifest.json` 属于实际成品文件并列入。

G2 的发布与扫描直接消费这份回执。旧全站拼装命令已移除；仍被其他工具导入的素材与引用检查函数不承担构建。冻结源 HTML 保留 probe03 原字节，旧发布目录地址由来源清单先映射到当前资源；构建最后通过 G2 的唯一 `finalize-dist` 命令完成部署资源引用与发布策略，回执绑定最终字节。没有实际 script 归属的旧 B2 运行件和对应预热引用从成品退出；当前 OSS 地址下仍被引用的脚本照常保留。相册更新只新增当前指纹表，仍被引用的旧表保留，已最终处理的表不会在下一轮被解开当前地址。

## AI 刷新作者源

`npm run refresh:ai -- --project <id>` 从 Registry 定位实际作者输入：原生项目的 `sources/pages/<页>/page.json`、所属模块、布局和当前 `src/content/pages/*.md` 共同进入指纹。仍由冻结字节提供的项目列出其全部冻结 HTML；迁移后再更新登记。Rules 读取 `sources/rules` 和规则页面源，Skills 读取当前能力目录与详情源，System 已并入保留首页。根目录 `app/` 只保留搜索解码/匹配、公开搜索字段投影、电脑授权状态模型三个仍复用的小模块；不再包含 React 页面、第二套项目正文或 Vite 渲染入口。
