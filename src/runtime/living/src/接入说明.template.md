# 把每页首屏的活画接进网站

这份包让新排版页首屏的插画“活”起来：叶子轻轻晃、这一页自己的招牌小动作、一只小鸟飞进来落脚。活画只盖在首屏整屏图的**插画框**那一块上，页面上原来那张整屏图始终在下面：没有脚本、配置读不到、图读不到、没有 WebGL、系统设了“减少动态”、防卡死保险触发，看到的都是那张静止的原图。哪里不动，画布就是透明的，原图原样露出来。

整件事分四步：放文件 → 页面挂载 → 配跨域 → 翻页和撤回。

## 一、包里有什么、放到哪

| 文件夹 | 内容 | 上线后的路径 |
| --- | --- | --- |
| `_engine/` | 引擎 `living.<指纹>.js`、样式 `living.<指纹>.css`、小鸟模块文件夹 `bird.<指纹>/`（`bird.js` 和 `bird-atlas.webp`）、`files.json`（本版各文件名，给构建流程读） | `/_living/_engine/` |
| `<页名>/` | 这一页的 `config.json` 和一两张范围图 `m0.<指纹>.webp`、`m1.<指纹>.webp` | `/_living/<页名>/` |
| `home/` | 首页（另见首页那份说明） | 照首页接入包 |

- 全部相对路径。引擎按自己脚本的地址找到同目录的 `bird.<指纹>/`，用到小鸟时才读，页面不用另挂小鸟脚本。
- `config.json` 里横版 `h`、竖版 `v` 各一份，坐标是约定清单 `first-screens.json` 里那张整屏图的比例。范围图也是相对 `config.json` 的路径。
- 带指纹的文件可以长缓存（`Cache-Control: public, max-age=31536000, immutable`）；**`config.json` 名字固定，不要长缓存**（`no-cache` 或几分钟），换版时它会指向新的范围图文件名。
- 没有文件夹的页（`typora-theme-pack` 没有插画，`steam-millennium-config-backup` 只有商标）不挂；挂了也没事，配置读不到就什么都不做。

## 二、页面怎么挂

每个新排版页的 `<head>` 里挂一次样式，页尾挂引擎，然后对首屏那一节挂载：

```html
<link rel="stylesheet" href="/_living/_engine/living.<指纹>.css">
...
<script src="/_living/_engine/living.<指纹>.js" defer></script>
<script>
  document.addEventListener('DOMContentLoaded', () => {
    if (!window.LivingArt) return;                    // 脚本没读到：原图已经在那里
    const first = document.querySelector('.typeset-screen');   // 首屏那一节，里面有横版、竖版两个 .typeset-part
    window.pageLiving = LivingArt.mount(first, { config: '/_living/<页名>/config.json' });
  });
</script>
```

- **挂在首屏那一节上**（`.typeset-screen`，里面横版 `.typeset-part[data-orientation=h]`、竖版 `[data-orientation=v]` 各一个）。引擎自己挑当前显示的那个（看得见的那个），转屏或改窗口宽度换了显示的那个，它就拆掉重挂到另一个上。也可以只传单个 `.typeset-part`。
- 引擎拿 `.typeset-part` 里那张 `<img>` 当贴图，不另带底图。图是懒加载（`data-src`、`loading=lazy`）的也行：引擎等它加载完才开始。
- 引擎在 `.typeset-part` 里、`.overlays` 前面插一层 `.living-layer`（`position:absolute; z-index:0`，自成一层，整层 `pointer-events:none`，`aria-hidden`）。热区、按钮、卡片都在 `.overlays` 里，照旧在画的上面、照旧能点。小鸟身上有一小块能点的热区（点了会叫一声，阻止事件往外传）。
- 挂载返回的对象：`ready`（Promise）、`leave()`（Promise，小鸟飞走后兑现，给翻页转场用）、`destroy()`（前端路由离开这一页时调用）、`diagnostics()`（看状态，`phase` 是 `live` 或 `static`，`reason` 是退回静态的原因）。
- 默认全效果，没有任何开关，没有配乐（点小鸟才有一声叫）。整体速度只有引擎里的 `speed = 2.5` 一个数；叶子幅度只有 `LEAF_AMP = 0.0105` 一个数，`LivingArt.leafAmplitude` 可读。旧页配置中的 sway.amp 不再改变叶幅，范围、频率、周期、阵风仍按每页配置。2026-10-04 本人要求让叶子更看得出在动，本版将原 `0.005` 放大到 `0.0105`；旧检查和录像保持各自真实源码 SHA，旧默认兼容证据不能作为这次视觉全等证明。新幅直接补查见 `../叶幅升级说明.md`。
- 404 使用原画里的鸟，不配置 `bird`、不挂第二只。局部 `part` 可选写有限数字 `sleepValue`：进入引擎已有的鸟睡眠时段时，最终形变值固定为它；未设置则昼夜都沿用原来的公式。404 的头部 `rock` 写 `sleepValue:0`，独立眼区 `squash` 写 `sleepValue:0.9`。白天仍按该动作的 `amp/time/period` 运行；这是配置参数，不增加界面开关。
- 开场默认自动判断：原图已经完整显示、或者准备素材期间已获得一次显示机会时，直接进入活画，保留已经看到的图。只有很早挂载且在图首次显示前就准备好时才演晕开。`intro: false` 明确关闭；`intro: true` 明确要求演开场。晚挂载也能直接使用默认接口，无须接入方另外判断。`diagnostics().intro` 返回 enabled 和 reason（image-already-visible、early-mount、explicit-off 或 explicit-on）。

### 翻页转场

翻页前先让小鸟飞走，再翻：

```js
await window.pageLiving?.leave();   // 鸟不在画里时立刻兑现；只兑现不拒绝
// 然后开始翻页转场；离开这一页时 pageLiving.destroy()
```

新页面尽早挂载，开场按上述自动判断执行；小鸟从画外飞进来。预览用 seek 可定格开场，实际晚挂载会自动省去开场。

## 三、跨域（图和活画文件在 OSS 另一个域名时必须看）

引擎要把首屏整屏图交给显卡（WebGL），浏览器只允许交按跨域方式读到、服务器明确许可的图；配置、范围图、小鸟图集也都按跨域方式读。

**OSS 的跨域规则**（Bucket → 数据安全 → 跨域设置）：来源填 `https://wly0829.cn`、`https://www.wly0829.cn`（本地预览地址也加上）；方法 `GET`、`HEAD`；允许头 `*`；缓存时间 `86400`；能勾“返回 Vary: Origin”就勾上。范围：`_typeset/`（首屏整屏图）和 `_living/`。

**页面那张首屏图要不要加 `crossorigin="anonymous"`**——实测（两个本机端口模拟“网页一个域名、图在另一个域名、不回 Vary: Origin、图先被普通方式取过”，结果在 `work/cors-results.json`）：

| 场景 | 结果 |
| --- | --- |
| A 图带 `crossorigin="anonymous"`，OSS 已开跨域许可 | 活画正常；**首屏图只下载一次**（引擎直接用这个元素当贴图） |
| B 图不带跨域属性，OSS 已开许可但不回 `Vary: Origin` | 活画正常；引擎带跨域声明、地址后加 `?living-cors=1` 另取一次（**多下载一次**） |
| C 同 B，但引擎不加那个小参数 | 失败：浏览器拿缓存里那份不带许可的响应，图被判跨域，活画退回静态（这就是要加小参数的原因；现在的引擎会加） |
| D OSS 没开跨域许可，图不带跨域属性 | 安静退回原图，页面没有报错 |
| E **OSS 没开跨域许可，图却带了 `crossorigin`** | **首屏图本身显示不出来**（浏览器拒收） |

所以：
1. **首选**：OSS 跨域规则配好之后，生成页面时给首屏那两张 `<img>`（横、竖）加 `crossorigin="anonymous"`。只下载一次。
2. **兜底**：不加也能用，引擎自己另取一次（地址后加固定的 `?living-cors=1`，各页共用这份跨域副本的缓存）。
3. **千万别在 OSS 跨域规则生效之前给图加 `crossorigin`**（场景 E）。
4. OSS 前面有 CDN 时，要让 CDN 回源带 `Origin` 并按 `Vary: Origin` 区分缓存，或在 CDN 上配同样的跨域头。

没配好不会白屏、不会报页面错误，就是静止的原图；`diagnostics().reason` 是 `cors`（图不许交给显卡）、`asset-or-webgl-error`（素材读不到）或 `no-config`（配置读不到）。

## 四、减少动态、防卡死、看不见时

- 系统设了“减少动态”：不演开场、不放小鸟，画面就是原图（逐像素一致）。
- 页面在后台、或首屏滚出屏幕：暂停，回来接着走。
- **防卡死的保险**与首页接入包同一口径（代码原样照搬）：只看页面可见、画在屏幕内、动画在播时实际画出来的帧，满足任意一条才退回静态原图——最近约 6 秒、至少 5 个帧间隔里帧间隔中位数超过 100 毫秒；或连续 3 帧以上每帧都超过 1 秒且加起来超过 5 秒。头 2 秒、滚动中和停止滚动后 1.5 秒、页面隐藏或滚出屏幕都不算。只管这一次这一页，不写任何浏览器存储，刷新就恢复。触发时控制台留一句原因。
- WebGL 上下文丢失：立即退回静态。
- 页面上的图换了一代（排版重出、插画位置变了）而配置没跟着换：引擎按配置里的取样点核对图，对不上就不盖（`reason: image-mismatch`），不会盖出一块错位的画。

## 六、撤回

- 只撤活画：删掉挂载代码、引擎脚本和样式这三处引用，页面就是原来的静态整屏图。
- 单独一页不要活画：不挂载这一页，或删掉它的 `/_living/<页名>/`（配置读不到就什么都不做）。
- 建议接入时“挂样式和脚本 + 挂载 + 给首屏图加 crossorigin”做成网站仓库里单独的一次提交，退回时 `git revert` 这一次。

## 七、首页（拆分后的版本，`home/`）

首页那幅活的画拆成两份：**通用部分**就是 `_engine/living.<指纹>.js`（防卡死保险、看得见吗/减少动态/滚动/尺寸、跨域读图、杭州时间和日出日落，和每页活画共用同一份代码）；**首页专用部分**是 `home/home-scene.<指纹>.js`（整幅画的着色器、画里屏幕那一层、首页的鸟和开场），配置和素材同原首页接入包（`home/home.files.json` 列了文件名）。

接法和原首页接入包一样，只是多挂一个通用脚本、而且要先挂它：

```html
<link rel="stylesheet" href="/_living/home/hero-live.<指纹>.css">
<script src="/_living/_engine/living.<指纹>.js" defer></script>
<script src="/_living/home/home-scene.<指纹>.js" defer></script>
<!-- 挂载代码不变：HeroLive.mount(document.querySelector('#home-hero'), { plateImage: ..., status: ... }) -->
```

既有首页包在原位置的历史对照：拆分前后用首页验收页逐像素比过：横版、竖版各 8 个时刻（开场 0.8/1.6/2.6/3.9 秒、白天、傍晚、夜里、睡觉）全部完全一样（最大差 0）；减少动态、防卡死触发也一样（`work/home-compare.json`）。本轮没有重跑首页；迁移工具显式要求 `--home-source` 指定只读来源。原首页接入包（`p1/dist`）不受影响，也可以继续用。

## 八、实测环境和没测到的

本机安装的 Chrome 无头运行、独立 E 盘临时配置；RTX 5090 D。电脑 1440×1000、DPR 1，另测桌面处理器减速 4 倍；手机 412×915、DPR 3.5。同时对 393 和 412 宽分别回归 DPR 1、2、3、3.5，原约 0.5 CSS 像素横向偏移已修复：根层用整数 CSS 外接矩形，着色器保留精确插画坐标，分辨率保持。逐项数值和残余的强制整框过滤差见 `../修复汇报.md`。Safari、Firefox、真机手机尚未验证。
